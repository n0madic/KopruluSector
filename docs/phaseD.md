# The original data at run time

Design: [ADR 0018](adr/0018-original-data-at-run-time.md). The plan was approved on 2026-11-10: StormLib and CascLib, structures built in memory with no KPF between, no cache on disk, a `koprulu*.mpq` repack before the install, Remastered's WebM played as is, Smacker audio of our own, old saves refused, sounds in the repack as Ogg Vorbis where that is smaller.

| Stage | What | State |
|---|---|---|
| D0 | ADR 0018; StormLib, CascLib, zlib, bzip2 fetched and built on every platform; `kp_sha256`; `kp_data_probe` and its measurements | done 2026-11-10 |
| D1 | `kp_res`: the MPQ backends (install, repack) and CASC, the repack's priority, the check against the manifest, `--data`, which source a folder is, `--res-log` | done 2026-11-11 |
| D2 | `defs/` as C tables (`tools/defs_c.py`, `--check` in CI): the DAT layouts, the requirements, the interface's and the campaign's tables, `SLOT`; the readers take a container's section, else the compiled table | done 2026-11-11 |
| D3 | The game data from the original files: DAT, iscript, AI scripts, strings, palettes, fonts, tilesets, GRP geometry and opacity, the interface, sounds, portraits, campaign | done 2026-11-11 |
| D4 | Missions from CHK, the walk raster, regions and contours in C | done 2026-11-11 |
| D5 | The pages built from GRPs when a mission starts, WAV sounds, music streamed from the archives; the app and `kp_ui` take D3's structures (`KpUiData`, the tileset's sheet as indices) when `--data` names an install or a repack | done 2026-11-11 |

| D8 | `converter repack`, the bundles, the web's groups; the SD containers and their loaders removed | |

## D5 as built

- **The app over the original data** (`native/kp_app/sdl`): when `--data` names an install or a repack (`kp_res`), `kp_app_load_data` builds what every game and the interface read from the files instead of `generated/data`: the data set's DAT (`kp_dat_from_files`), the shared grpmeta, iscript and AI scripts (`kp_host_shared_from_files`), the palettes, the campaign and the interface's data (`kp_ui_data_from_files`); the executable's `MUSI` names the music. The vector fonts are not original data: they are read from the program's `fonts/` folder, else the working directory's `third_party/fonts/` (a TODO for D8's bundles). The catalog is the campaign's mission directories by mapdata index (`kp_flow_missions_campaign`: the names, saves' names and campaign rows of `generated/missions/index.txt`), and the converted data's test scenarios when there is a `generated/scenarios/index.txt`.
- **A mission** (`kp_flow.c` `load_original`): its scenario's `KpMission` (`kp_mission_from_files`) moved into the game over a copy of the data set's DAT (`kp_dat_copy`, `kp_game_data_from`, `kp_host_game_load_from`, `kp_session_load_from`); the game reads the tileset's CV5 and VF4 (`kp_host_game_tileset_files`; `kp_start` counts the megatile flags from the VF4) instead of the tileset's container. A test scenario is still its `.kpm`.
- **The world** (`kp_app_world.c`): the tileset from its files (`kp_tileset_from_files`: the sheet and creep's edges as indices, no PNG), each pack the mission names packed when the mission starts (`kp_pack_build`, `native/kp_present/kp_pages.c`: grpmeta's atlases of the pack in order, each GRP's frames read through `kp_res` and decoded, equal frames sharing a rectangle, the frame records and the pages' indices; `kp_pages_pack` is the skyline of `converter/emit/pages.py`). `kp_grpmeta_afrm` computes each GRP's first frame within its atlas from `GRPS` (`kpd.atlas_frame_offsets`) rather than reading `AFRM`, which the files' grpmeta has no bytes for. A lost context uploads the same pages again.
- **The sound** (`kp_app_audio.c`): an sfx id plays `sfxdata`'s WAV (`KpUiData.sound_paths`), a trigger's WAV the file its string names in the scenario's directory (`kp_mission_sound_path`), both read whole through `kp_res` and decoded by SDL3_mixer; the music is MUSI's file streamed through `kp_res`'s own handles on the mixer's thread (`kp_res_stream_*` behind an `SDL_IOStream`; kind 1 loops). `kp_app_res_close` now runs after `kp_audio_free`, which closes the stream.
- **The interface** (`kp_ui_new_data`, `kp_interface_new_data`): `kp_ui` reads a `KpUiData` (borrowed), whichever data it was built from; `kp_ui_new` is `kp_ui_data_from_kpf` and it. The sounds' and the portraits' setters take their parts (`kp_ui_set_sound_records`, `kp_ui_set_portrait_parts`), which `kp_ui_set_sounds` and `kp_ui_set_portraits` take from the containers. The executable's tables come from `KpUiData.profile` (`kp_ui_data_table`), the cheats and the campaign's tables from the profile's compiled `CHEA` and `TABL`.
- **What stays the converted data's**: the HD art, `console.kpd`, the cinematics, the languages' overlays (a mission's text overlay keeps the WAV strings, so it applies; a language's speech does not: its triggers time the converted speech's WAVs) are read from the converted root (`--data`'s or the working directory's `generated/`) when it has them. The save identity is the profile's id and the SHA-256 of the data set's DAT (the games' CRCs check the rest on a load): a save of the converted data is refused by the original data's game and back, until D8's identity of the simulation's inputs.
- **Remastered** builds the game data and the missions, but its interface comes from XML, DDS and WebM: the app refuses it with the first file it lacks (`rez\ttextbox.bin`) until stage D6.
- **Checked**: `test_original` (the interface over the files holds what the containers' does: the dialogs' records and texts, the files, the fonts, the tables, the strings, the sounds' records, the portraits; the catalog equals the index's 64 missions; terran01 from the 1.17 install and zerg02 from Remastered play 480 steps as their `.kpm` does, state CRCs category by category; each WAV a mission finds is the file its string names), `test_data` (the computed AFRM equals `generated/data`'s), the product's scripts over the 1.17 install (`tools/ci.sh` with `KOPRULU_ORIGINAL`: `determinism.kps` and `play_4.kps` write the converted data's states, frames and profile byte for byte, the same sounds counted and the trigger WAVs streamed; by hand all the product's scripts pass, and a mission runs from a folder with no `generated/`). The packs build in 130 to 150 ms when a mission starts (ADR 0018).

## D4 as built

- **`kp_chk`** (`native/kp_core/src/core/kp_chk.{h,c}`): a scenario read by the original's loader tables as `converter/formats/chk.py` reads it, the same checks in the same order with the same messages: the chunks as `0x4c1170` enumerates them (a negative size refused), the version's descriptor, every chunk read by the campaign's groups (header, briefing, use-map-settings) or allowlisted, the required sections present and none repeated, each read payload by its handler's rule (exact size, at most, a multiple, the VCOD block's SHA-256), the sections in the dispatch order of `0x4c12e0`, the ERA gate. The tables are the profile's compiled `CHKL` (`chk.loader_section`: per descriptor its version, whether it needs Brood War and its rows `tag, required, reads, vcod, eq, max, multiple`; the ignored tags; the executable's VCOD digest).
- **`kp_derive`** (`kp_derive.{h,c}`): `converter/derive/` in C with the same control flow: the tile import of `ImportMapTiles 0x445720` and the console strips of `0x469170`, the walk raster (`0x48b1c0`), the region graph (`0x48f060`: rectangles, merges, compaction, the split cells, the cut ranks of `0x48f0e0`; more than 5,000 regions refused as the original refuses them) and the collision contours (`0x48af10`, sorted as the CRT's `qsort` sorts them, with the capacities the original's arrays grew to). The payloads are the `.kpm`'s `WALK`, `RGNS` and `CONT` bytes. `kp_present`'s `kp_terrain_import` is `kp_derive_import` without the flags.
- **`kp_mission_from_files(m, files, directory, err)`** (`kp_mission.c`): `<directory>\staredit\scenario.chk` read by `kp_chk`, its triggers validated (`converter/analyze/triggers.py validate`: a reachable condition or action past the original's tables, Opponents, Modify Unit Resource Amount and Hangar Count, an Order past 255 locations, a Move Unit to location 256), `META`, the override sections in dispatch order (`RULE`), the WAV strings of `TRIG` and `MBRF` and their files' headers (`WAVS`, `kp_files_wav`: a file missing, unreadable as the manifest lists it or refused by the original's parser plays nothing), `WALK`, `RGNS` and `CONT` from the tileset of `ERA & 7`, and `PACK` from the profile's compiled `MPAK`. The blob holds the scenario and those parts; `kp_mission_take` and it share the parsing (`assemble`).
- **The packs** are the one part the C does not compute: `converter/analyze/profile.py` reads the scripts, DATs and requirements to find them. `python3 -m converter scr-manifest` records each campaign mission's from the reference install in `defs/campaign/packs-<profile>.json` (`missions.write_packs`); `tools/defs_c.py` compiles it as `MPAK` (per mission its lowercased directory and its `PACK` payload, `kpm.packs_payload`). The scenarios are the same bytes in both installs, so the packs are too.
- **`test_chk`**: the converter's fixture scenario (`mission.chk`, the CHK of `mission.kpm`, read with the compiled `CHKL` but the fixtures' VCOD) gives the fixture's mission, every part equal; its variants are refused as `test_chk.py` refuses them (sizes, VCOD, a missing or repeated section, an unknown tag, version 57, no Brood War, a payload past the end, a negative size); the trigger validation and its ignored entries; every campaign mission from the 1.17 install and from Remastered equals `generated/missions` (64 each: the scenarios, `META`, `RULE`, `WALK`, `RGNS`, `CONT`, `PACK`; the WAV records from the 1.17 install, the string ids alone from Remastered, whose speech is its own). The 128 missions build in under a second.
- The app loaded the `.kpm` files until stage D5.

## D3 as built

- **`KpFiles`** (`native/kp_core/src/core/kp_files.h`): what the builders read the original files through, by their MPQ names. `read` answers a malloc'd copy (NUL terminated past its size), NULL with an empty error for a file the data does not have, NULL with the reason otherwise; `head` (optional) the first bytes and the whole size (the WAV headers: `kp_files_head` reads the whole file without it). `kp_res_files(r, f)` gives `kp_res`'s: `kp_res_read`, and `kp_res_head` over the install's archives already open (a stream would open the archive per file).
- **The formats' readers** in `kp_core`: `kp_grp` (the header, a frame's rows decoded, the opacity, a frame copied out as a one-frame GRP: the ghosts' images), `kp_wav_info` (the format and the `data` chunk from the first bytes; -2 when the chunk lies past them), `kp_text_table_utf8` (a TBL's windows-1252 text to UTF-8 with its offsets moved as `kpd.table_utf8` moves them), `kp_terrain_megatile_flags` (a VF4's megatile flags, `terrain.megatile_flags`).
- **A builder beside each loader**, the converter's rules in C, filling the same structures:
  - `kp_dat_from_files` (`arr\*.dat` with the compiled `COLS` and `RQ**`), `kp_iscript_from_files` (`scripts\iscript.bin`, the first header of each id, `SLOT`), `kp_ai_bins_from_files` (`aiscript.bin`, `bwscript.bin`, their directories checked), `kp_campaign_from_files` (the mission directories from `mapdata.dat` and `mapdata.tbl`);
  - `kp_grpmeta_from_files` (`images.dat`'s GRPs and LO files, deduplicated without regard to case; the atlases by pack within the converter's budget, the frame records and opacity runs, the animation ids);
  - `kp_palettes_from_files` (`kp_present`: each tileset's remap PCXs, `dark.pcx` and `shift.pcx` rows, `tunit`, `tminimap`, `tselect`, `thpbar`), `kp_tileset_from_files` (`.cv5`, `.vx4`, `.vr4`, `.vf4`, `.wpe`, `.grp` (the creep edges): the palette, the compiled cycles `CYCn`, the CV5, the megatile flags, the minimap's MMNI; the megatile sheet and the creep edges as palette indices where the container holds PNGs);
  - `kp_ui_data_from_files` (`kp_core/src/core/kp_ui_data.{h,c}`, `kp_ui_dialogs.c`): `KpUiData`, the parts `kp_ui` reads, from the files: the dialogs' records and texts from their BINs in the loader's traversal order (`kp_ui_dialogs_build`, with our own dialogs, the records appended to the original's and the labels), the dialog GRPs, PCXs and glue files a BIN names (`kp_ui_bin_files`), the ghosts' frames, the theme fonts and effects, the FNT fonts, `tFontGam.pcx`'s rows, the six TBLs in UTF-8, the sound records from the WAV headers and their packs, the music lengths, the portrait rows and their SMKs. `kp_ui_data_from_kpf` takes the same parts from the five containers.
- **`tools/defs_c.py`** also compiles the lists those builders start from (`built_tables()`, no container carries them): the interface's file lists (`UBIN`, `UTHM`, `UTHF`, `UDGR`, `UGRP`, `UPCX`, `UGLF`, `UCRD`), our own dialogs as BINs (`KBIN`), the records appended (`KEXT`), the labels (`KLAB`), the fonts' plaintext files (`FNTP`), each tileset's cycles (`CYC0`..`CYC7`).
- **`test_original`**: each builder over a real install equals the loader over `generated/data` (the converter makes those containers byte for byte the same from the 1.17 install and from Remastered): DAT, iscript, the AI scripts, the campaign, grpmeta, the palettes, the 8 tilesets (the sheets and edges against the containers' PNGs, decoded by the test with zlib) and the interface's data from the 1.17 install; the same but the interface from Remastered (its BINs, strings, fonts and portraits are XML, DDS and WebM there: stage D6). From the 1.17 install grpmeta builds in 0.12 s, the interface's data in 0.11 s. **`test_formats`**: the readers over synthetic files (a frame out of a GRP, a WAV header from its first bytes, a TBL to UTF-8, a BIN's files, a VF4's flags).
- The app and `kp_ui` took these structures at stage D5; the tools still load the containers, and the loaders of the SD containers go at D8.

## D2 as built

- **`tools/defs_c.py`** also compiles the executable's tables the runtime reads (`tables()`), serialized by the converter's own functions into the same bytes as its container sections: `COLS` (the DAT layouts), the requirement bytecode `RQOR`, `RQRS`, `RQTU`, `RQUN`, `RQUP`, the interface's `BTNS`, `STLY`, `MUSI`, `VOLT`, `ACCL`, `ESTB`, the campaign's `TABL` and `CHEA`, the iscript header types' `SLOT`. They are `KpDefsProfile.tables` (sorted by fourcc); `kp_defs_profile(id)` finds a compiled profile, `kp_defs_table(p, fourcc)` a table.
- **`kp_kpf_table(c, fourcc, &size, err)`**: a container's section of that name, else the compiled table of the container's profile, else an error naming both. `kp_kpf_table_in(data, size, fourcc, &n)` does the same over a container's bytes. The readers of those tables go through it: `kp_dat` (`COLS`, the requirements), `kp_iscript` (`SLOT`), `kp_campaign` (`TABL`, `CHEA`), the interface (`kp_ui_core.c`: `BTNS`, `STLY`, `MUSI`, `VOLT`, `ACCL`, `ESTB`; `kp_hud.c`'s campaign tables; `kp_oracle_ui`). A container keeps its sections until stage D8 (the converter still writes them; the tests' fixtures carry synthetic tables of their own).
- **`kp_campaign_from`**: the campaign from its tables and the mission directories, the parts `kp_campaign_load` reads from `campaign.kpd` (stage D3 builds the directories from `mapdata.dat` and `mapdata.tbl`).
- The converter's sections and the compiled tables come from the same functions (`campaign.tables_section`, `campaign.cheats_section`, `kpd.slots_section`, `kpd.columns_section`, `kpd.ui_table_sections`, `requirements.section`); `test_data.defs_tables_equal_the_converted_sections` checks every compiled table against `generated/data`'s section byte for byte, `kpf_table_falls_back_to_the_compiled` the order (a section first, the profile's table, none for another profile).

## D1 as built

- **`native/kp_app/kp_res.{h,c}`** (in `kp_app_core`): `kp_res_open(dirs)` takes the folders the player names; `kp_res_detect` tells a repack (`koprulu.mpq`, or `koprulu-core.mpq` and the groups its listing names), a 1.17 install (the profile's executable or first archive; a name as given, in lower or in upper case) and a Remastered install (`.build.info`). One install (the first; another is logged and ignored), any number of repack archives (`kp_res_add_repack`: the web adds a group once fetched).
- **Reads** (`kp_res_read`, any case, `\\` or `/`): the manifest's unreadable and absent names first (nothing read); then a repack's copy, equal to its listing, else the install's:
  - 1.17: the first copy in the profile's order, refused (`KP_RES_REFUSED`, the archive, the name, both sizes and digests in the error) when it differs from the manifest; a name the manifest does not hold is read unchecked and logged; a missing campaign archive (the CDs': music, movies, speech) leaves its files missing, a missing core archive refuses the install;
  - Remastered: `ScrSource`'s order and statuses in C: the moved names, the four prefixes, `.vx4ex`; `exact`, `derived` (a grown tileset's 1.17 prefix with the CV5 groups Remastered filled zeroed, `.vx4` from `.vx4ex`: `kp_res_casc_rebuild`), `differs` (the first readable copy), `unlisted`. The rebuilds from DDS, `dds.grp`, XML and WebM are stage D6's (`missing` until then).
- **Streams** (`kp_res_stream_open`, `_read`, `_close`): handles of their own for another thread; an install's file has the manifest's size and its sectors' CRCs checked as they are read (StormLib's `MPQ_OPEN_CHECK_SECTOR_CRC`).
- **The repack's listing** `(koprulu)`: `koprulu repack 1`, `profile <id>`, `group <file>` lines, then `<sha256> <size> <name>` a file. A copy that differs from its listing, or a repack of another profile, falls back to the install (logged).
- **`native/kp_app/kp_mpq.{h,c}`**: StormLib alone in a file (its `windows.h`); read, read in pieces, and write (`kp_mpq_create`, `kp_mpq_add`: the tests' archives, the repack of D8). `kp_casc` reads in pieces too.
- **`tools/defs_c.py`** writes `native/kp_core/src/defs/` (in `kp_core`): the profile's archives and executable, the input manifest's files (normalized names, sorted; the 16 spellings that normalize alike name the same bytes and are kept once), its absent and unreadable names; `--check` in CI. `kp_defs_input`, `kp_defs_listed` look them up.
- **The app**: `--data DIR` any number of times: a folder with `generated/` is the converted data's root as before, one with a repack or an install goes to `kp_res` (a bundle's `data/` may be both); `--res-log PATH` writes the list of the files read (`name<TAB>status<TAB>source`, by name) when the program ends, and the counts by status go to the log. Nothing in the game reads through `kp_res` yet (stage D3 builds the structures, the app takes them at D5).
- **`kp_data_probe DIR... [--res-log PATH]`** reads every manifest file through `kp_res` and counts each kind's statuses (the CI step "data readers"): the 1.17 install 4,368 files exact (the core's 155.4 MB in 1.5 s with the checks); Remastered 2,380 exact, 29 derived, 11 differ and 823 missing in the core (the converter's statuses for every file both read: its exact, derived and differs are the same names from the same CASC copies; the 823 are its rebuilds), 451 exact and 654 differing of the missions' speech, 20 differing music tracks.
- **`test_res`**: archives the tests write with StormLib: a 1.17 install of a test profile (the first copy, a refused copy, unlisted, absent, unreadable, missing; a missing campaign archive, a missing core archive, a folder with no data), repacks (before the install whatever the folders' order, a broken copy back to the install, another profile's ignored, groups joining the core), streams, the log, the tileset rebuilds; with `KP_TEST_ORIGINAL` and `KP_TEST_SCR` (`tools/ci.sh` passes `KOPRULU_ORIGINAL`, `KOPRULU_SCR`) the real installs: `units.dat`, a music track in pieces, `.vx4` from `.vx4ex`, `desert.cv5`'s prefix, a moved font.

## D0 as built

- **`tools/toolchain/fetch.sh data`**, fetched by default: StormLib 9.40, CascLib 3.0, zlib 1.3.2, bzip2 1.0.8, each pinned by SHA-256.
- **`third_party/data/kp_data.cmake`:** `kp_zlib`, `kp_bzip2`, `kp_jenkins` (StormLib's lookup3), `kp_storm`, `kp_casc`, with the libraries' own source lists at these versions; their bundled zlib and bzip2 left out. CascLib 3.0's CMakeLists.txt asks for CMake 3.2, which CMake 4 refuses: our list avoids it.
- **`native/kp_app/kp_casc.{h,cpp}`** (`kp_casc_c`): CascLib for C (open, has, read).
- **`native/kp_core/src/core/kp_sha256.{h,c}`**, with `tests/c/test_res.c` (FIPS 180-4's examples, a million `a` in pieces of 1 to 130 bytes, the padding's edges at 55, 56 and 64 bytes).
- **`native/kp_core/tools/kp_data_probe.c`**: `mpq DIR` and `casc DIR`, every file of the input manifest read and checked, timed by kind; the CI step "data readers".
- The measurements are in ADR 0018.

### Differences from the plan

- D2: the CHK loader's tables, the packs' rules and `MOVED` are compiled with the stages that read them in C (D4 the missions and each mission's packs, recorded rather than computed in C, D5 the packs' rules; `MOVED` and the CASC prefixes are kp_res's own C since D1). `FLUF`, `CURS` and `RECT` are not compiled: no C code reads them.
- D1 (found by a security review after the commit): a repack's copy is checked against its own listing only, so a repack rewritten together with its listing replaces any file the game reads. The listing will name each file's status with the repack's writer (D8), and an exact or derived copy will be checked against the manifest too (`TODO` in `kp_res.c`).
- D1: the profile and the input manifest became C tables in D1 (`tools/defs_c.py`), not D2: the check needs them. D2 adds the other tables to the same generator.
- D1: the repack's files are checked against SHA-256 digests in its own listing `(koprulu)`, not against StormLib's `(attributes)` MD5 (`SFileVerifyFile` reads a file a second time; the SHA-256 is already there for the installs). The archives are opened without loading `(attributes)` and the repack is written without one: StormLib reads and writes its 64-bit file times at unaligned addresses (`SFileAttributes.cpp`), undefined behaviour UBSan stops on, and nothing reads it. CascLib's sources are built under ASan only (`-fno-sanitize=undefined`): its code rests on null-pointer idioms UBSan stops on (`CascPort.h`'s `FIELD_OFFSET`, `Path.h`'s pointer arithmetic before its null check); the project's wrapper `kp_casc.cpp` keeps UBSan.

- nestegg, libogg and libvorbis are fetched with the stages that use them (D6, D7), not in D0: no library is built before its code.
- zlib and bzip2 are fetched too: the libraries' bundled copies are old (zlib 1.2.5 and 1.2.11, bzip2 1.0.5) and would be linked twice.
- The GRP pages' and the WebM portraits' timings move to D5 and D6, measured on their C code (D5's in ADR 0018).
- D5: the app's languages' speech and HD art, the console art and the cinematics stay the converted data's (the plan defers the locales and the speech from CASC past this phase; the cinematics are D7's). The save identity of the original data is a stopgap until D8 (the profile and the DAT's SHA-256).
- Not run: CASC on Linux (Docker Desktop does not share `/Applications`), the Windows, Android and iOS builds (linked only).
