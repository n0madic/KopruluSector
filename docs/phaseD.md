# The original data at run time

Design: [ADR 0018](adr/0018-original-data-at-run-time.md). The plan was approved on 2026-11-10: StormLib and CascLib, structures built in memory with no KPF between, no cache on disk, a `koprulu*.mpq` repack before the install, Remastered's WebM played as is, Smacker audio of our own, old saves refused, sounds in the repack as Ogg Vorbis where that is smaller.

The plan is done: the game, its tools and its suites read the original files (an install or the repack); the converter writes the repack and what a platform needs built (the HD files, the cinematics' packs, the console's pieces, the languages' overlays).

## After the plan: the review (2026-11-11)

A review of the phase's diff (a71f36f..2224d72) fixed:

- **A refused listing leaves nothing behind** (`kp_res.c` `listing_check`): its magic and profile line are checked before any line applies. Before, a listing with no `profile` line had already put its files in the table and added the groups it names when it was refused: the files pointed at the closed archive (a read of one dereferenced it), and the slot dropped was the last group's, not the core's. `test_res.res_repack_without_its_profile_leaves_nothing`. A blank line of a listing is skipped (it ended the listing before).
- **A stream skips a CASC copy that is not installed** (`open_file`): a copy named but offline (its size does not read) is logged and the next tried, as a whole read does; `kp_res_head` failed there, which failed the interface's sounds. Its source in `--res-log` is `CASC <name>`, as a whole read's.
- **The catalog skips a mapdata row with no scenario** (`kp_data_catalog`), as `converter/catalog.py` does; it ended at the first such row.
- **A group already there is opened in place** (`kp_app_group`): beside the core on a computer or a phone, in memory once fetched on the web. Before, it was read whole first (fetched again on the web after a failed add).
- **A Smacker palette record is bounded by its own length** (`kp_smk.c`), not the frame's end.
- **Cleanups**: `kp_hex_decode` (`kp_sha256`) for the three hexadecimal parsers of `kp_res.c` and `kp_res_scr.c` (`test_res.sha256_hex_decodes`); `kp_kpf.h`'s little-endian helpers in `kp_scr.c` and `kp_ui_data.c`; `kp_res_casc_exact` is `read_casc`'s exact pass; the unused Vorbis `prev_mask` and `palette_of_pcx` removed.

Then **the hashes kept where they decide** ([ADR 0018](adr/0018-original-data-at-run-time.md), item 2): a 1.17 install's file is hashed when the simulation is built from it (`simulation_input`: DAT, the scripts and dialog BINs, CHK, CV5, VF4, GRP, LO, TBL), checked by its size when it only shows or plays; a repack's file by its size (its groups' SHA-256 checked when Android copies them out of its APK); a movie by its size against `CINM` (so the double hash the review found is gone); Remastered's files stay hashed (the digest picks the copy and the rebuild). `kp_data_probe` checks every exact or derived file to the byte. `test_res.res_hashes_only_what_the_simulation_reads`. Measured with the probe: the repack's core 0.39 to 0.19 s, the 1.17 install's core 1.51 to 1.22 s. On the Fold7 the debug APK's 70 groups (139.9 MB) were copied out and hashed in 0.46 s, then `play_1` ran at 0 failures from them.

## D8 design

D8 is four commits, each with the full CI:

- **D8a, the repack**: `converter repack` writes the files the game reads into `koprulu*.mpq` (StormLib), with a listing that names each file's status; `kp_res` checks an exact or derived file's listed digest against the manifest (stage D1's `TODO`) and answers a WAV stored as Ogg Vorbis with the WAV's header.
- **D8b, the products over the repack**: `tools/product.sh` stages the repack (the desktops one `koprulu.mpq`, the phones and the web its groups); the app reads its SD data from a repack or an install only (the converted data's SD path goes); the web fetches a mission's group before the mission starts; Android copies the repack out of its APK (StormLib reads files); the vector fonts lie beside the repack; the save identity is that of the structures built from the original files.
- **D8c, the tools and the suites over the original data**: `kp_runner`, `kp_oracle` and the C suites read through `kp_res` (the 1.17 install or a repack) as the app does, the test scenarios are CHK files; the twins (the structures built from the files against the containers') and the containers' loader tests stay until D8d.
- **D8d, the SD containers removed**: the SD emitters (`data` but `console.kpd`, `missions`, `scenarios`' `.kpm`, `resources`) and the C loaders of their containers go, with the twins and the fixtures they read; the languages' and the speech's base is computed in memory.

**Groups** (unlike the plan's, the races' art is no group of its own): `koprulu-core.mpq` holds what the program reads when it starts, which is every GRP (grpmeta's frames and opacity), every sound's header and every portrait (the interface's data); a group per mission directory (68: its CHK and speech, `koprulu-<campaign>-<mission>.mpq`), `koprulu-music.mpq`, `koprulu-cinematics.mpq` (the 1.17 install's Smacker files; Remastered's WebM are not repacked: a desktop reads them from the install, the phones and the web play the cinematics packs).

## D8a as built

- **`converter repack --data DIR|--scr DIR [--out generated/repack] [--single] [--res-log FILE] [--wav]`** (`converter/repack.py`): the input manifest's files but its absent and unreadable names, in the compiled manifest's order (a Remastered rebuild's palette is kept for the files after it, as `kp_res` reads them), then the 1.17 install's 28 cinematics (`CINM`'s, read as the converter checks them), then the names a `--res-log` read unlisted. From Remastered (`ScrSource`) each file keeps its status (exact, derived, differs, equivalent, colour-equal, approximation); a file it lacks is left out and reported. Written by StormLib through ctypes (`converter/mpq/stormlib.py NewArchive`: version 1, a `(listfile)`, no `(attributes)`), zlib file by file, an Ogg or a movie stored as it is; the `koprulu*.mpq` already in the folder removed first.
- **A WAV as Ogg Vorbis** when that is smaller: oggenc at the packs' quality (`sound.OGG_QUALITY`), the CRC-32 of its normalized name as the stream's serial, each encoded once into `generated/cache/repack-ogg/` (by the WAV's SHA-256, the quality and the serial). A WAV the original's parser refuses (`formats/wav.py`), or whose header runs past `kp_files.c`'s `WAV_HEAD` (4,096 bytes), stays a WAV.
- **The listing** `(koprulu)` ([the format](formats/repack.md)), a line each: `koprulu repack 2`, `profile <id>`, `source <1.17|remastered>`, the core's `group <file> <prefix>` lines (each group with the normalized prefix of its names), then `<sha256> <size> <status> <name>`, or for an Ogg `<sha256> <size> <status> ogg <wav sha256> <wav size> <wav header in hex> <name>`; the digest and size are the stored bytes'.
- **`kp_res`** (`kp_res.c`): reads listing 2 (listing 1 is refused: no such repack was written). - **`tools/defs_c.py`** also compiles the executable's tables the runtime reads (`tables()`), serialized by the converter's own functions into the same bytes as its container sections: `COLS` (the DAT layouts), the requirement bytecode `RQOR`, `RQRS`, `RQTU`, `RQUN`, `RQUP`, the interface's `BTNS`, `STLY`, `MUSI`, `VOLT`, `ACCL`, `ESTB`, the campaign's `TABL` and `CHEA`, the iscript header types' `SLOT`. They are `KpDefsProfile.tables` (sorted by fourcc); `kp_defs_profile(id)` finds a compiled profile, `kp_defs_table(p, fourcc)` a table.
- **`kp_kpf_table(c, fourcc, &size, err)`**: a container's section of that name, else the compiled table of the container's profile, else an error naming both. `kp_kpf_table_in(data, size, fourcc, &n)` does the same over a container's bytes. The readers of those tables go through it: `kp_dat` (`COLS`, the requirements), `kp_iscript` (`SLOT`), `kp_campaign` (`TABL`, `CHEA`), the interface (`kp_ui_core.c`: `BTNS`, `STLY`, `MUSI`, `VOLT`, `ACCL`, `ESTB`; `kp_hud.c`'s campaign tables; `kp_oracle_ui`). A container keeps its sections until stage D8 (the converter still writes them; the tests' fixtures carry synthetic tables of their own).
- **`kp_campaign_from`**: the campaign from its tables and the mission directories, the parts `kp_campaign_load` reads from `campaign.kpd` (stage D3 builds the directories from `mapdata.dat` and `mapdata.tbl`).
- The converter's sections and the compiled tables come from the same functions (`campaign.tables_section`, `campaign.cheats_section`, `kpd.slots_section`, `kpd.columns_section`, `kpd.ui_table_sections`, `requirements.section`); `test_data.defs_tables_equal_the_converted_sections` checks every compiled table against `generated/data`'s section byte for byte, `kpf_table_falls_back_to_the_compiled` the order (a section first, the profile's table, none for another profile).

## D1 as built

- **`native/kp_app/kp_res.{h,c}`** (in `kp_app_core`): `kp_res_open(dirs)` takes the folders the player names; `kp_res_detect` tells a repack (`koprulu.mpq`, or `koprulu-core.mpq` and the groups its listing names), a 1.17 install (the profile's executable or first archive; a name as given, in lower or in upper case) and a Remastered install (`.build.info`). One install (the first; another is logged and ignored), any number of repack archives (`kp_res_add_repack`: the web adds a group once fetched).
- **Reads** (`kp_res_read`, any case, `\\` or `/`): the manifest's unreadable and absent names first (nothing read); then a repack's copy, equal to its listing, else the install's:
  - 1.17: the first copy in the profile's order, refused (`KP_RES_REFUSED`, the archive, the name, both sizes and digests in the error) when it differs from the manifest; a name the manifest does not hold is read unchecked and logged; a missing campaign archive (the CDs': music, movies, speech) leaves its files missing, a missing core archive refuses the install;
  - Remastered: `ScrSource`'s order and statuses in C: the moved names, the four prefixes, `.vx4ex`; `exact`, `derived` (a grown tileset's 1.17 prefix with the CV5 groups Remastered filled zeroed, `.vx4` from `.vx4ex`: `kp_res_casc_rebuild`), `differs` (the first readable copy), `unlisted`. The rebuilds from DDS, `dds.grp`, XML and WebM came with stage D6 (`missing` until then).
- **Streams** (`kp_res_stream_open`, `_read`, `_close`): handles of their own for another thread; an install's file has the manifest's size and its sectors' CRCs checked as they are read (StormLib's `MPQ_OPEN_CHECK_SECTOR_CRC`).
- **The repack's listing** `(koprulu)`: `koprulu repack 1`, `profile <id>`, `group <file>` lines, then `<sha256> <size> <name>` a file. A copy that differs from its listing, or a repack of another profile, falls back to the install (logged). Listing 2 replaced it with the repack's writer (D8a).
- **`native/kp_app/kp_mpq.{h,c}`**: StormLib alone in a file (its `windows.h`); read, read in pieces, and write (`kp_mpq_create`, `kp_mpq_add`: the tests' archives, the repack of D8). `kp_casc` reads in pieces too.
- **`tools/defs_c.py`** writes `native/kp_core/src/defs/` (in `kp_core`): the profile's archives and executable, the input manifest's files (normalized names, sorted; the 16 spellings that normalize alike name the same bytes and are kept once), its absent and unreadable names; `--check` in CI. `kp_defs_input`, `kp_defs_listed` look them up.
- **The app**: `--data DIR` any number of times: a folder with `generated/` is the converted data's root as before, one with a repack or an install goes to `kp_res` (a bundle's `data/` may be both); `--res-log PATH` writes the list of the files read (`name<TAB>status<TAB>source`, by name) when the program ends, and the counts by status go to the log. Nothing in the game reads through `kp_res` yet (stage D3 builds the structures, the app takes them at D5).
- **`kp_data_probe DIR... [--res-log PATH]`** reads every manifest file through `kp_res` and counts each kind's statuses (the CI step "data readers"): the 1.17 install 4,368 files exact (the core's 155.4 MB in 1.5 s with the checks); Remastered 2,380 exact, 29 derived, 11 differ and 823 missing in the core (the converter's statuses for every file both read: its exact, derived and differs are the same names from the same CASC copies; the 823 are its rebuilds), 451 exact and 654 differing of the missions' speech, 20 differing music tracks.
- **`test_res`**: archives the tests write with StormLib: a 1.17 install of a test profile (the first copy, a refused copy, unlisted, absent, unreadable, missing; a missing campaign archive, a missing core archive, a folder with no data), repacks (before the install whatever the folders' order, a broken copy back to the install, another profile's ignored, groups joining the core), streams, the log, the tileset rebuilds; with `KP_TEST_ORIGINAL` and `KP_TEST_SCR` (`tools/ci.sh` passes `KOPRULU_ORIGINAL`, `KOPRULU_SCR`) the real installs: `units.dat`, a music track in pieces, `.vx4` from `.vx4ex`, `desert.cv5`'s prefix, a moved font.

### Differences from the plan

- D2: the CHK loader's tables, the packs' rules and `MOVED` are compiled with the stages that read them in C (D4 the missions and each mission's packs, recorded rather than computed in C, D5 the packs' rules; `MOVED` and the CASC prefixes are kp_res's own C since D1). `FLUF`, `CURS` and `RECT` are not compiled: no C code reads them.
- D1 (found by a security review after the commit): a repack's copy is checked against its own listing only, so a repack rewritten together with its listing replaces any file the game reads. Done with D8a: the listing names each file's status, and an exact or derived copy whose listed digest is not the manifest's is dropped for the install's; a copy listed with another status is the repack's own (a Remastered rebuild), vouched for by its listing only.
- D1: the profile and the input manifest became C tables in D1 (`tools/defs_c.py`), not D2: the check needs them. D2 adds the other tables to the same generator.
- D1: the repack's files are checked against SHA-256 digests in its own listing `(koprulu)`, not against StormLib's `(attributes)` MD5 (`SFileVerifyFile` reads a file a second time; the SHA-256 is already there for the installs). The archives are opened without loading `(attributes)` and the repack is written without one: StormLib reads and writes its 64-bit file times at unaligned addresses (`SFileAttributes.cpp`), undefined behaviour UBSan stops on, and nothing reads it. CascLib's sources are built under ASan only (`-fno-sanitize=undefined`): its code rests on null-pointer idioms UBSan stops on (`CascPort.h`'s `FIELD_OFFSET`, `Path.h`'s pointer arithmetic before its null check); the project's wrapper `kp_casc.cpp` keeps UBSan.

- nestegg is fetched with the stage that uses it (D6), not in D0: no library is built before its code. libogg and libvorbis are not used at all (D7): a WebM's Vorbis packets are put into Ogg pages by our own code (`kp_webm_streams`) and SDL3_mixer's stb_vorbis decodes them, as it decodes the packs' sound.
- zlib and bzip2 are fetched too: the libraries' bundled copies are old (zlib 1.2.5 and 1.2.11, bzip2 1.0.5) and would be linked twice.
- The GRP pages' and the WebM portraits' timings move to D5 and D6, measured on their C code (in ADR 0018).
- D5: the app's languages' speech and HD art, the console art and the cinematics stay the converted data's (the plan defers the locales and the speech from CASC past this phase; the cinematics are D7's). The save identity of the original data is a stopgap until D8 (the profile and the DAT's SHA-256).
- Not run: CASC on Linux (Docker Desktop does not share `/Applications`), the Windows, Android and iOS builds (linked only).
