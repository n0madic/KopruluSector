# The original data at run time

Design: [ADR 0018](adr/0018-original-data-at-run-time.md). The plan was approved on 2026-11-10: StormLib and CascLib, structures built in memory with no KPF between, no cache on disk, a `koprulu*.mpq` repack before the install, Remastered's WebM played as is, Smacker audio of our own, old saves refused, sounds in the repack as Ogg Vorbis where that is smaller.

## D8 design

D8 is three commits, each with the full CI:

- **D8a, the repack**: `converter repack` writes the files the game reads into `koprulu*.mpq` (StormLib), with a listing that names each file's status; `kp_res` checks an exact or derived file's listed digest against the manifest (stage D1's `TODO`) and answers a WAV stored as Ogg Vorbis with the WAV's header.
- **D8b, the products over the repack**: `tools/product.sh` stages the repack (the desktops one `koprulu.mpq`, the phones and the web its groups); the app reads its SD data from a repack or an install only (the converted data's SD path goes); the web fetches a mission's group before the mission starts; Android copies the repack out of its APK (StormLib reads files); the vector fonts lie beside the repack; the save identity is that of the structures built from the original files.
- **D8c, the SD containers removed**: `kp_runner`, `kp_oracle` and the C suites read through `kp_res` (the 1.17 install or a repack), the test scenarios are CHK files, the fixtures synthetic original files; the SD emitters (`data`, `missions`, `scenarios`, `resources`) and the C loaders of their containers go.

**Groups** (unlike the plan's, the races' art is no group of its own): `koprulu-core.mpq` holds what the program reads when it starts, which is every GRP (grpmeta's frames and opacity), every sound's header and every portrait (the interface's data); a group per mission directory (68: its CHK and speech, `koprulu-<campaign>-<mission>.mpq`), `koprulu-music.mpq`, `koprulu-cinematics.mpq` (the 1.17 install's Smacker files; Remastered's WebM are not repacked: a desktop reads them from the install, the phones and the web play the cinematics packs).

## D8a as built

- **`converter repack --data DIR|--scr DIR [--out generated/repack] [--single] [--res-log FILE] [--wav]`** (`converter/repack.py`): the input manifest's files but its absent and unreadable names, in the compiled manifest's order (a Remastered rebuild's palette is kept for the files after it, as `kp_res` reads them), then the 1.17 install's 28 cinematics (`CINM`'s, read as the converter checks them), then the names a `--res-log` read unlisted. From Remastered (`ScrSource`) each file keeps its status (exact, derived, differs, equivalent, colour-equal, approximation); a file it lacks is left out and reported. Written by StormLib through ctypes (`converter/mpq/stormlib.py NewArchive`: version 1, a `(listfile)`, no `(attributes)`), zlib file by file, an Ogg or a movie stored as it is; the `koprulu*.mpq` already in the folder removed first.
- **A WAV as Ogg Vorbis** when that is smaller: oggenc at the packs' quality (`sound.OGG_QUALITY`), the CRC-32 of its normalized name as the stream's serial, each encoded once into `generated/cache/repack-ogg/` (by the WAV's SHA-256, the quality and the serial). A WAV the original's parser refuses (`formats/wav.py`), or whose header runs past `kp_files.c`'s `WAV_HEAD` (4,096 bytes), stays a WAV.
- **The listing** `(koprulu)` ([the format](formats/repack.md)), a line each: `koprulu repack 2`, `profile <id>`, `source <1.17|remastered>`, the core's `group <file> <prefix>` lines (each group with the normalized prefix of its names), then `<sha256> <size> <status> <name>`, or for an Ogg `<sha256> <size> <status> ogg <wav sha256> <wav size> <wav header in hex> <name>`; the digest and size are the stored bytes'.
- **`kp_res`** (`kp_res.c`): reads listing 2 (listing 1 is refused: no such repack was written). An exact or derived file whose listed digest (an Ogg's: its WAV's) is not the manifest's is dropped from the table when the listing is read, logged, and the install's copy read; the bytes are checked against the listing's digest when read, as before. `kp_res_head` answers an Ogg's WAV header and size from the listing (`kp_files_wav`, the durations the game computes from it); `kp_res_read` and the streams give the Ogg's bytes (SDL3_mixer tells the formats apart). `kp_res_group_wanted(r, name, out)` names the group a name's prefix falls in while it is not open, `kp_res_repack_dir` the core's folder (the web fetches a group beside it and adds it, `kp_res_add_repack`); up to 128 archives. A line that is not a file's is counted and logged.
- **Measured** (`converter repack`, the M-series Mac): the 1.17 install (1.2 GB of archives) gives 4,396 files (4,368 of the manifest, the 28 cinematics), all exact, 742 MB: the core 49.8 MB, the music 28.9 MB, the 68 missions' groups 61.2 MB together (0.1 to 1.4 MB each), the cinematics 605 MB; 2,236 WAVs as Ogg Vorbis, 101.5 MB for 888.0 MB, 8 kept (their Ogg larger); written in 45 s with the encoding, 18 s with the Oggs cached. Remastered gives one `koprulu.mpq` of 131 MB: 4,368 files, 2,831 exact, 234 derived, 682 differ (its speech and music recordings among them), 6 equivalent, 19 colour-equal, 596 approximations; 2,236 WAVs as Ogg, 96.4 MB for 824.2 MB; 28 s.
- **Checked**: `test_res` (listing 2's statuses, an exact copy whose listing is not the manifest's dropped for the install's, an Ogg's WAV header and size from its listing, a group named by a name's prefix while it is not open and added after); the converter's `test_repack` (the groups and their listings, one file with `--single`, the statuses, the unlisted names, an Ogg kept only when smaller and its header, the cache). `tools/ci.sh` with `KOPRULU_APP` and `KOPRULU_ORIGINAL`: the 1.17 install's repack in groups, `determinism.kps` and `play_4.kps` over it alone write the converted data's states, frames and profile byte for byte and play the same sounds, the music streamed from `koprulu-music.mpq`'s Ogg; with `KOPRULU_SCR`: Remastered's `koprulu.mpq`, `determinism.kps` over it writes what it writes over the install.

## D7 as built

- **Smacker's palette and sound** (`kp_smk.{h,c}`): a frame's palette record is applied as FFmpeg's `smacker` decoder applies it (its length the count byte times 4, read to the frame's end; bit 7 skips entries, bit 6 copies a run of the old palette, else a new entry, each 6-bit level `v << 2 | v >> 4`; a rewind starts from black). `kp_smk_sound_format` reads a track's `AudioRate` (packed, 16-bit, stereo, the rate; Bink's audio refused) and `kp_smk_sound` decodes the track of every frame: PCM as stored, or Smacker's DPCM, the chunk's unpacked size, its flags, `1 << (16-bit + stereo)` Huffman trees, the first samples, then the deltas, as 16-bit or 8-bit little-endian PCM.
- **`CINM`** (`converter/emit/cinematics_smk.py` `catalog_section`, compiled by `tools/defs_c.py built_tables`): the profile's 28 movies in the table's order, each with the size and SHA-256 of its copy in the reference 1.17 install (`defs/campaign/cinematics.json` `smk`), and the (cinematic, prelude) pairs. `kp_cine_catalog` reads it, `kp_cine_catalog_check` checks a copy as the converter's `Resolver.read_expected` does.
- **A movie in memory** (`KpCineMovie`, `kp_cine.{h,c}`): `kp_cine_movie_smk` (the header's rate as an exact fraction, -6666 is 50000/3333; the first track as a WAV; each frame's indices through the palette as G, B, R planes, sRGB; a 320-wide movie shown 640 wide as the packs show it), `kp_cine_movie_webm` over `kp_webm_streams` (nestegg: the VP9 packets and their frame table as a pack lays them out, the rate from the track's `DefaultDuration`, else the mean of the frames' times, as a continued fraction with terms up to 10^6; the Vorbis track put into Ogg pages of the clip name's CRC-32 as their serial, a page closed at 4,096 bytes, each page's granule from Vorbis's block sizes, the last one's less the last block's `DiscardPadding`), `kp_cine_movie_subtitles` (an `.srt` by `converter/formats/srt.py`'s rules: UTF-8 with an optional BOM, blocks apart at a line of blanks, the number and the times, a cue without text left out, sorted by start), `kp_cine_open_movie` (the player over the movie, Smacker's frames decoded by `kp_smk`) and `kp_cine_movie_read` (its bytes as a pack's).
- **The run over an install** (`kp_cine_index_original`, `KpCineHost.load`): the index lists the catalog's movies the install has, named and numbered as a pack's clips; the run asks the host for each movie as it begins and gives the host its sound in memory (`KpCineHost.sound`'s data: the WAV or the Ogg), stopping the sound before the movie is freed.
- **The app** (`kp_app_cine.c`): with an install or a repack in `--data` the movies are the install's. A 1.17 install's (or a repack's) Smacker files are read through `kp_res` and checked against `CINM`; Remastered's WebM, its HD2 set first (`--cinematics sd` takes its SD set), only the files the install holds (`kp_res_casc_held`: Remastered downloads some languages only, the others named but offline, CascLib's `ERROR_FILE_OFFLINE`). The subtitles are the `.srt` of `--locale`'s language (not the base's), else as the packs chose them: of the install's text locale (`kp_res_text_locale`, `.build.info`'s Tags as `converter/emit/cinematics.py text_locale` reads them), else enUS, the first held. Without an install the packs play as before; `--cinematics hd2` over a 1.17 install takes the packs.
- **Measured** (`--cine-check`, the macOS RelWithDebInfo build): the 1.17 install's 28 movies, 30,211 frames, 0 failures in 21 s, the longest movie loaded in 0.31 s (its 79 MB read, hashed and its sound decoded at the start; a `TODO` to stream it for the phones and the web with D8's repack); Remastered's SD set 30,211 frames and HD2 set 31,156 frames, 0 failures, each WebM loaded in at most 29 ms, its subtitles drawn (deDE, the install's text locale: its enUS files are offline).
- **Checked**: `test_movies` (a synthetic SMK's palette records, packed 16-bit stereo and 8-bit PCM tracks and a malformed chunk; the movie played by the player and by a run whose host loads it; the fixture's WebM; the subtitles' rules and refusals; the fixtures' pack `cine.kpd` against the WebM it was split from, `cine0.webm`, `cine1.webm` and `cine1.srt`), with `KP_TEST_ORIGINAL` the 28 movies' frames (indices and palette as FFmpeg's `pal8`) and sound equal to FFmpeg's decodes byte for byte (`tests/golden/oracle/cinematics/smk_ffmpeg.json`, private, from `tools/oracle/export_smk_ffmpeg.py`), with `KP_TEST_SCR` Remastered's 56 WebM equal to the converted packs' clips: the packets and the frame table byte for byte, the Vorbis packets but the comment header (FFmpeg's Ogg muxer writes its own vendor and tags), the end within a millisecond's samples (FFmpeg's from the WebM's millisecond times; Remastered's packs end past the samples their blocks decode to, which a decoder does not trim), the subtitles cue for cue; `test_res` (the text locale of `.build.info`'s rows and groups, the install's held files); `test_cine` (the run's sound with no data for a pack's file); the converter's `test_the_catalog_section_holds_the_table_and_the_reference_copies`. `tools/ci.sh`: the golden's `--check` with `KOPRULU_ORIGINAL`, the product's cine check over the 1.17 install and Remastered's SD set (HD2 with `KOPRULU_CINEMATICS`).
- **Not done**: the 1.17 install has no subtitles; the packs stay for the builds without an install (the phones, the web) until D8 decides their repack.

## D6 as built

- **`kp_scr`** (`native/kp_app/kp_scr.{h,c}`): `converter/casc/rebuild.py` in C, Remastered's own formats read back as 1.17's files: DDS (uncompressed, DXT1, DXT5) and `*.dds.grp` containers to RGBA, `rebuild.fit` (a block-compressed image's padding cut, an HD multiple sampled at each block's top left, a shorter image kept as the bottom rows), a PCX written as 1.17's are (the standard RLE, the header's bytes from the original's), a GRP of plain rows (the glue's `Dlg.grp`) and a row-compressed GRP drawn again in another palette through its WPE, Remastered's XML strings (and `RC3.xml`'s escapes) to windows-1252, a TBL's spans and the TBL written again, a dialog BIN from its skeleton with its texts put back (in place when a text has its length, else appended with its pointers moved).
- **`kp_index_map`** (`native/kp_core/src/core/kp_index_map.{h,c}`): the rule a colour becomes a palette index by, `IndexMap`'s, now in `converter/formats/palette.py` (moved from `rebuild.py`): alpha 0 is index 0; an opaque pixel the lowest index of its colour, a translucent one the highest; a colour the palette lacks the nearest one (least squared distance, the lowest index of equals). Kept per colour as it is first asked for.
- **`kp_res_scr`** (`native/kp_app/kp_res_scr.{h,c}`, internal to `kp_res`): `ScrSource._remake` over `kp_scr`, by the profile's compiled tables `SPAL`, `SPCX`, `SGRP`, `SSMK`, `STBL`, `SBIN` (`tools/defs_c.py built_tables`): a file no CASC copy brings to the manifest's digest is rebuilt from the formats Remastered keeps it in. The statuses are the converter's: `derived` (the manifest's bytes), `equivalent` (a PCX of the same pixels in another palette's bytes), `colour-equal` (a PCX of the same colours), `approximation` (lossy art, edited texts, a KPW1). `kp_res_casc_file` reads an install's own file by its CASC name, unchecked (the HD portraits). `SBIN`'s dialog skeletons are zlib-compressed, so `kp_app_core` links `kp_zlib` on every platform (the web's build lacked `zlib.h` before).
- **KPW1** (`converter/formats/kpw.py`, `kp_smk.h`) replaces KPV1, which is gone from the converter and `kp_smk.c`: an SMK only Remastered's WebM has is that WebM as it is behind a header ("KPW1", width, height, frames, frame rate, ring flag) and its screen's palette; `kp_smk` plays it through the codec the host gives (`kp_smk_set_video`; the app's and the tests' is `kp_webm_smk_video`), each pixel its colour's index by `kp_index_map`, transparent below alpha 128, frame n the WebM's frame n (its last past its end). Width and height are the WebM's (`kp_webm_size`, `kpw.webm_size`): Remastered drew 4 of the 549 movies narrower than their SMKs (`glue\mainmenu\multion.smk` 240 x 224 for 356 x 224), so the manifest's `SSMK` keeps frames, rate and ring only.
- **`kp_webm`** (`native/kp_app/kp_webm.{h,c}`): a WebM in memory demuxed by nestegg and decoded by libvpx (VP8 and VP9), frame n as RGBA (decoded on, or from the first frame again for an earlier one); an alpha stream (Matroska's `BlockAdditional` 1, as FFmpeg's libvpx wrapper reads it) gives the opacity. nestegg's read callback answers the bytes read (a short read at the end, 0 past it). The colour conversion moved from `kp_cine.c` to `kp_vpx_rgba`, `kp_vpx_usable` and `kp_vpx_yuv_rgb`, which the cinematics' player and the WebM share.
- **libvpx's VP8 decoder and nestegg are built everywhere** (`third_party/vpx/kp_vpx.cmake`, `tools/toolchain/fetch.sh` fetches them by default: nestegg has no releases, a commit pinned by SHA-256); `KP_CINEMATICS` is gone, so the cinematics' player is in every build too.
- **The HD portraits**: `portraits.kpd`'s `HDPV` clips are Remastered's WebM as it is (`converter/emit/hd_video.py`): 621 clips, 72.8 MB against 281 MB as KPV1, and no cache: the converter no longer writes converted movies to `generated/cache/scr` (the portraits' and the KPW1s'; an old checkout's folder is left unread). The app decodes them with `kp_webm`; with a Remastered install in `--data` it reads the WebM from CASC instead (`kp_app_hd_ui.c`: HD2's, else HD's).
- **The twin**: `kp_data_probe DIR --digests PATH` and `python3 -m converter scr-digests --scr DIR --out PATH` write each manifest file's normalized name, status and SHA-256 in the same order (the palette's memo depends on it). Over `/Applications/StarCraft` the two lists are equal on all 4,368 files; `tools/ci.sh` with `KOPRULU_SCR` compares them.
- **Remastered's statuses** (`kp_data_probe`, the core's 3,243 files in 1.1 s): 2,380 exact, 234 derived, 8 differ, 6 equivalent, 19 colour-equal, 596 approximation, none missing; the missions' speech 451 exact and 654 differ, the music 20 differ.
- **Measured** (the macOS release build): the 549 KPW1 movies, 6,603 frames, decode and map in 2.39 s (0.36 ms a frame, opening included). Against the converter's KPV1 frames (FFmpeg's libvpx and swscale): the 519 portraits (VP9 4:4:4 sRGB) equal frame for frame; the 30 glue movies (VP8 4:2:0 with alpha) 94.7% of their pixels equal on average, the lowest 78.9% (`glue\readyt\proj.smk`): the YUV to RGB rounding differs from swscale's, and a colour one step off maps to another index. The app loads its data from Remastered in about 2.9 s (2.25 s from the 1.17 install).
- **The app plays Remastered**: the interface is built from its files (D5's refusal is gone: the BINs are rebuilt), `determinism.kps` over `/Applications/StarCraft` writes the converted data's states (its frames differ: Remastered's art), the main menu shows its KPW1 overlays, `hd_game.kps` on zerg02 shows the HD portraits from CASC and from `portraits.kpd`.
- **Checked**: `test_scr` (`kp_scr` over the converter's fixtures `tests/fixtures/generated/kpf/scr/`: DDS decoded and mapped, the container's entries, fit's three cases, PCX, TBL spans and encoding, XML strings, a dialog rebuilt, a plain GRP, a remapped GRP; each `.expect` written by `rebuild.py`), `test_ui_data` (the fixtures' KPW1 movies, VP9 sRGB and VP8 with alpha, play their indices; a cut WebM or palette and a wrong size refused), `test_original` (Remastered's interface has the 1.17 parts: the dialogs, their widgets and movies, the files, fonts, sounds, portraits and tables; each portrait movie a KPW1), `test_data` (the six SCR tables), the converter's `KpwTest`.

## D5 as built

- **The app over the original data** (`native/kp_app/sdl`): when `--data` names an install or a repack (`kp_res`), `kp_app_load_data` builds what every game and the interface read from the files instead of `generated/data`: the data set's DAT (`kp_dat_from_files`), the shared grpmeta, iscript and AI scripts (`kp_host_shared_from_files`), the palettes, the campaign and the interface's data (`kp_ui_data_from_files`); the executable's `MUSI` names the music. The vector fonts are not original data: they are read from the program's `fonts/` folder, else the working directory's `third_party/fonts/` (a TODO for D8's bundles). The catalog is the campaign's mission directories by mapdata index (`kp_flow_missions_campaign`: the names, saves' names and campaign rows of `generated/missions/index.txt`), and the converted data's test scenarios when there is a `generated/scenarios/index.txt`.
- **A mission** (`kp_flow.c` `load_original`): its scenario's `KpMission` (`kp_mission_from_files`) moved into the game over a copy of the data set's DAT (`kp_dat_copy`, `kp_game_data_from`, `kp_host_game_load_from`, `kp_session_load_from`); the game reads the tileset's CV5 and VF4 (`kp_host_game_tileset_files`; `kp_start` counts the megatile flags from the VF4) instead of the tileset's container. A test scenario is still its `.kpm`.
- **The world** (`kp_app_world.c`): the tileset from its files (`kp_tileset_from_files`: the sheet and creep's edges as indices, no PNG), each pack the mission names packed when the mission starts (`kp_pack_build`, `native/kp_present/kp_pages.c`: grpmeta's atlases of the pack in order, each GRP's frames read through `kp_res` and decoded, equal frames sharing a rectangle, the frame records and the pages' indices; `kp_pages_pack` is the skyline of `converter/emit/pages.py`). `kp_grpmeta_afrm` computes each GRP's first frame within its atlas from `GRPS` (`kpd.atlas_frame_offsets`) rather than reading `AFRM`, which the files' grpmeta has no bytes for. A lost context uploads the same pages again.
- **The sound** (`kp_app_audio.c`): an sfx id plays `sfxdata`'s WAV (`KpUiData.sound_paths`), a trigger's WAV the file its string names in the scenario's directory (`kp_mission_sound_path`), both read whole through `kp_res` and decoded by SDL3_mixer; the music is MUSI's file streamed through `kp_res`'s own handles on the mixer's thread (`kp_res_stream_*` behind an `SDL_IOStream`; kind 1 loops). `kp_app_res_close` now runs after `kp_audio_free`, which closes the stream.
- **The interface** (`kp_ui_new_data`, `kp_interface_new_data`): `kp_ui` reads a `KpUiData` (borrowed), whichever data it was built from; `kp_ui_new` is `kp_ui_data_from_kpf` and it. The sounds' and the portraits' setters take their parts (`kp_ui_set_sound_records`, `kp_ui_set_portrait_parts`), which `kp_ui_set_sounds` and `kp_ui_set_portraits` take from the containers. The executable's tables come from `KpUiData.profile` (`kp_ui_data_table`), the cheats and the campaign's tables from the profile's compiled `CHEA` and `TABL`.
- **What stays the converted data's**: the HD art, `console.kpd`, the cinematics, the languages' overlays (a mission's text overlay keeps the WAV strings, so it applies; a language's speech does not: its triggers time the converted speech's WAVs) are read from the converted root (`--data`'s or the working directory's `generated/`) when it has them. The save identity is the profile's id and the SHA-256 of the data set's DAT (the games' CRCs check the rest on a load): a save of the converted data is refused by the original data's game and back, until D8's identity of the simulation's inputs.
- **Remastered** built the game data and the missions, but its interface comes from XML, DDS and WebM: the app refused it with the first file it lacked (`rez\ttextbox.bin`) until stage D6 rebuilt them.
- **Checked**: `test_original` (the interface over the files holds what the containers' does: the dialogs' records and texts, the files, the fonts, the tables, the strings, the sounds' records, the portraits; the catalog equals the index's 64 missions; terran01 from the 1.17 install and zerg02 from Remastered play 480 steps as their `.kpm` does, state CRCs category by category; each WAV a mission finds is the file its string names), `test_data` (the computed AFRM equals `generated/data`'s), the product's scripts over the 1.17 install (`tools/ci.sh` with `KOPRULU_ORIGINAL`: `determinism.kps` and `play_4.kps` write the converted data's states, frames and profile byte for byte, the same sounds counted and the trigger WAVs streamed; by hand all the product's scripts pass, and a mission runs from a folder with no `generated/`). The packs build in 130 to 150 ms when a mission starts (ADR 0018).

## D4 as built

- **`kp_chk`** (`native/kp_core/src/core/kp_chk.{h,c}`): a scenario read by the original's loader tables as `converter/formats/chk.py` reads it, the same checks in the same order with the same messages: the chunks as `0x4c1170` enumerates them (a negative size refused), the version's descriptor, every chunk read by the campaign's groups (header, briefing, use-map-settings) or allowlisted, the required sections present and none repeated, each read payload by its handler's rule (exact size, at most, a multiple, the VCOD block's SHA-256), the sections in the dispatch order of `0x4c12e0`, the ERA gate. The tables are the profile's compiled `CHKL` (`chk.loader_section`: per descriptor its version, whether it needs Brood War and its rows `tag, required, reads, vcod, eq, max, multiple`; the ignored tags; the executable's VCOD digest).
- **`kp_derive`** (`kp_derive.{h,c}`): `converter/derive/` in C with the same control flow: the tile import of `ImportMapTiles 0x445720` and the console strips of `0x469170`, the walk raster (`0x48b1c0`), the region graph (`0x48f060`: rectangles, merges, compaction, the split cells, the cut ranks of `0x48f0e0`; more than 5,000 regions refused as the original refuses them) and the collision contours (`0x48af10`, sorted as the CRT's `qsort` sorts them, with the capacities the original's arrays grew to). The payloads are the `.kpm`'s `WALK`, `RGNS` and `CONT` bytes. `kp_present`'s `kp_terrain_import` is `kp_derive_import` without the flags.
- **`kp_mission_from_files(m, files, directory, err)`** (`kp_mission.c`): `<directory>\staredit\scenario.chk` read by `kp_chk`, its triggers validated (`converter/analyze/triggers.py validate`: a reachable condition or action past the original's tables, Opponents, Modify Unit Resource Amount and Hangar Count, an Order past 255 locations, a Move Unit to location 256), `META`, the override sections in dispatch order (`RULE`), the WAV strings of `TRIG` and `MBRF` and their files' headers (`WAVS`, `kp_files_wav`: a file missing, unreadable as the manifest lists it or refused by the original's parser plays nothing), `WALK`, `RGNS` and `CONT` from the tileset of `ERA & 7`, and `PACK` from the profile's compiled `MPAK`. The blob holds the scenario and those parts; `kp_mission_take` and it share the parsing (`assemble`).
- **The packs** are the one part the C does not compute: `converter/analyze/profile.py` reads the scripts, DATs and requirements to find them. `python3 -m converter scr-manifest` records each campaign mission's from the reference install in `defs/campaign/packs-<profile>.json` (`missions.write_packs`); `tools/defs_c.py` compiles it as `MPAK` (per mission its lowercased directory and its `PACK` payload, `kpm.packs_payload`). The scenarios are the same bytes in both installs, so the packs are too.
- **`test_chk`**: the converter's fixture scenario (`mission.chk`, the CHK of `mission.kpm`, read with the compiled `CHKL` but the fixtures' VCOD) gives the fixture's mission, every part equal; its variants are refused as `test_chk.py` refuses them (sizes, VCOD, a missing or repeated section, an unknown tag, version 57, no Brood War, a payload past the end, a negative size); the trigger validation and its ignored entries; every campaign mission from the 1.17 install and from Remastered equals `generated/missions` (64 each: the scenarios, `META`, `RULE`, `WALK`, `RGNS`, `CONT`, `PACK`; the WAV records from the 1.17 install, the string ids alone from Remastered, whose speech is its own). The 128 missions build in under a second.
- The app loaded the `.kpm` files until stage D5.

## D3 as built

- **`KpFiles`** (`native/kp_core/src/core/kp_files.h`): what the builders read the original files through, by their MPQ names. `read` answers a malloc'd copy (NUL terminated past its size), NULL with an empty error for a file the data does not have, NULL with the reason otherwise; `head` (optional) the first bytes and the whole size (the WAV headers: `kp_files_head` reads the whole file without it). `kp_res_files(r, f)` gives `kp_res`'s: `kp_res_read`, and `kp_res_head` over the install's archives already open (a stream would open the archive per file).

## D2 as built

- **`tools/defs_c.py`** also compiles the executable's tables the runtime reads (`tables()`), serialized by the converter's own functions into the same bytes as its container sections: `COLS` (the DAT layouts), the requirement bytecode `RQOR`, `RQRS`, `RQTU`, `RQUN`, `RQUP`, the interface's `BTNS`, `STLY`, `MUSI`, `VOLT`, `ACCL`, `ESTB`, the campaign's `TABL` and `CHEA`, the iscript header types' `SLOT`. They are `KpDefsProfile.tables` (sorted by fourcc); `kp_defs_profile(id)` finds a compiled profile, `kp_defs_table(p, fourcc)` a table.
- **`kp_kpf_table(c, fourcc, &size, err)`**: a container's section of that name, else the compiled table of the container's profile, else an error naming both. `kp_kpf_table_in(data, size, fourcc, &n)` does the same over a container's bytes. The readers of those tables go through it: `kp_dat` (`COLS`, the requirements), `kp_iscript` (`SLOT`), `kp_campaign` (`TABL`, `CHEA`), the interface (`kp_ui_core.c`: `BTNS`, `STLY`, `MUSI`, `VOLT`, `ACCL`, `ESTB`; `kp_hud.c`'s campaign tables; `kp_oracle_ui`). A container keeps its sections until stage D8 (the converter still writes them; the tests' fixtures carry synthetic tables of their own).
- **`kp_campaign_from`**: the campaign from its tables and the mission directories, the parts `kp_campaign_load` reads from `campaign.kpd` (stage D3 builds the directories from `mapdata.dat` and `mapdata.tbl`).
- The converter's sections and the compiled tables come from the same functions (`campaign.tables_section`, `campaign.cheats_section`, `kpd.slots_section`, `kpd.columns_section`, `kpd.ui_table_sections`, `requirements.section`); `test_data.defs_tables_equal_the_converted_sections` checks every compiled table against `generated/data`'s section byte for byte, `kpf_table_falls_back_to_the_compiled` the order (a section first, the profile's table, none for another profile).

## D1 as built

- **`native/kp_app/kp_res.{h,c}`** (in `kp_app_core`): `kp_res_open(dirs)` takes the folders the player names; `kp_res_detect` tells a repack (`koprulu.mpq`, or `koprulu-core.mpq` and the groups its listing names), a 1.17 install (the profile's executable or first archive; a name as given, in lower or in upper case) and a Remastered install (`.build.info`). One install (the first; another is logged and ignored), any number of repack archives (`kp_res_add_repack`: the web adds a group once fetched).
- **Reads** (`kp_res_read`, any case, `\\` or `/`): the manifest's unreadable and absent names first (nothing read); then a repack's copy, equal to its listing, else the install's:
  - 1.17: the first copy in the profile's order, refused (`KP_RES_REFUSED`, the archive, the name, both sizes and digests in the error) when it differs from the manifest; a name the manifest does not hold is read unchecked and logged; a missing campaign archive (the CDs': music, movies, speech) leaves its files missing, a missing core archive refuses the install;
  - Remastered: `ScrSource`'s order and statuses in C: the moved names, the four prefixes, `.vx4ex`; `exact`, `derived` (a grown tileset's 1.17 prefix with the CV5 groups Remastered filled zeroed, `.vx4` from `.vx4ex`: `kp_res_casc_rebuild`), `differs` (the first readable copy), `unlisted`. The rebuilds from DDS, `dds.grp`, XML and WebM came with stage D6 (`missing` until then).
- **Streams** (`kp_res_stream_open`, `_read`, `_close`): handles of their own for another thread; an install's file has the manifest's size and its sectors' CRCs checked as they are read (StormLib's `MPQ_OPEN_CHECK_SECTOR_CRC`).
- **The repack's listing** `(koprulu)`: `koprulu repack 1`, `profile <id>`, `group <file>` lines, then `<sha256> <size> <name>` a file. A copy that differs from its listing, or a repack of another profile, falls back to the install (logged). Listing 2 replaced it with the repack's writer (D8a).
- **`native/kp_app/kp_mpq.{h,c}`**: StormLib alone in a file (its `windows.h`); read, read in pieces, and write (`kp_mpq_create`, `kp_mpq_add`: the tests' archives, the repack of D8). `kp_casc` reads in pieces too.
- **`tools/defs_c.py`** writes `native/kp_core/src/defs/` (in `kp_core`): the profile's archives and executable, the input manifest's files (normalized names, sorted; the 16 spellings that normalize alike name the same bytes and are kept once), its absent and unreadable names; `--check` in CI. `kp_defs_input`, `kp_defs_listed` look them up.
- **The app**: `--data DIR` any number of times: a folder with `generated/` is the converted data's root as before, one with a repack or an install goes to `kp_res` (a bundle's `data/` may be both); `--res-log PATH` writes the list of the files read (`name<TAB>status<TAB>source`, by name) when the program ends, and the counts by status go to the log. Nothing in the game reads through `kp_res` yet (stage D3 builds the structures, the app takes them at D5).
- **`kp_data_probe DIR... [--res-log PATH]`** reads every manifest file through `kp_res` and counts each kind's statuses (the CI step "data readers"): the 1.17 install 4,368 files exact (the core's 155.4 MB in 1.5 s with the checks); Remastered 2,380 exact, 29 derived, 11 differ and 823 missing in the core (the converter's statuses for every file both read: its exact, derived and differs are the same names from the same CASC copies; the 823 are its rebuilds), 451 exact and 654 differing of the missions' speech, 20 differing music tracks.
- **`test_res`**: archives the tests write with StormLib: a 1.17 install of a test profile (the first copy, a refused copy, unlisted, absent, unreadable, missing; a missing campaign archive, a missing core archive, a folder with no data), repacks (before the install whatever the folders' order, a broken copy back to the install, another profile's ignored, groups joining the core), streams, the log, the tileset rebuilds; with `KP_TEST_ORIGINAL` and `KP_TEST_SCR` (`tools/ci.sh` passes `KOPRULU_ORIGINAL`, `KOPRULU_SCR`) the real installs: `units.dat`, a music track in pieces, `.vx4` from `.vx4ex`, `desert.cv5`'s prefix, a moved font.

### Differences from the plan

- D2: the CHK loader's tables, the packs' rules and `MOVED` are compiled with the stages that read them in C (D4 the missions and each mission's packs, recorded rather than computed in C, D5 the packs' rules; `MOVED` and the CASC prefixes are kp_res's own C since D1). `FLUF`, `CURS` and `RECT` are not compiled: no C code reads them.
- D1 (found by a security review after the commit): a repack's copy is checked against its own listing only, so a repack rewritten together with its listing replaces any file the game reads. Done with D8a: the listing names each file's status, and an exact or derived copy whose listed digest is not the manifest's is dropped for the install's; a copy listed with another status is the repack's own (a Remastered rebuild), vouched for by its listing only.
- D1: the profile and the input manifest became C tables in D1 (`tools/defs_c.py`), not D2: the check needs them. D2 adds the other tables to the same generator.
- D1: the repack's files are checked against SHA-256 digests in its own listing `(koprulu)`, not against StormLib's `(attributes)` MD5 (`SFileVerifyFile` reads a file a second time; the SHA-256 is already there for the installs). The archives are opened without loading `(attributes)` and the repack is written without one: StormLib reads and writes its 64-bit file times at unaligned addresses (`SFileAttributes.cpp`), undefined behaviour UBSan stops on, and nothing reads it. CascLib's sources are built under ASan only (`-fno-sanitize=undefined`): its code rests on null-pointer idioms UBSan stops on (`CascPort.h`'s `FIELD_OFFSET`, `Path.h`'s pointer arithmetic before its null check); the project's wrapper `kp_casc.cpp` keeps UBSan.

- nestegg is fetched with the stage that uses it (D6), not in D0: no library is built before its code. libogg and libvorbis are not used at all (D7): a WebM's Vorbis packets are put into Ogg pages by our own code (`kp_webm_streams`) and SDL3_mixer's stb_vorbis decodes them, as it decodes the packs' sound.
- zlib and bzip2 are fetched too: the libraries' bundled copies are old (zlib 1.2.5 and 1.2.11, bzip2 1.0.5) and would be linked twice.
- The GRP pages' and the WebM portraits' timings move to D5 and D6, measured on their C code (in ADR 0018).
- D5: the app's languages' speech and HD art, the console art and the cinematics stay the converted data's (the plan defers the locales and the speech from CASC past this phase; the cinematics are D7's). The save identity of the original data is a stopgap until D8 (the profile and the DAT's SHA-256).
- Not run: CASC on Linux (Docker Desktop does not share `/Applications`), the Windows, Android and iOS builds (linked only).
