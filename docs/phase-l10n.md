## L1 as built

- **`kp_text`** decodes on top of `kp_utf8`: a valid sequence is its code point, any other byte its windows-1252 code point. Bytes below `0x80` stay bytes in every scan, so the control codes, the highlight's prefix and its caret byte `0xA6` are found before anything decodes.
- **The engine:** `kp_ui_text.c` steps by character (`char_step`, the span's `next`); a character of a valid sequence with no glyph has width 0 and the text goes on, in the drawing as in the measuring (`text_skips_a_character_with_no_glyph`); a stray byte whose slot is empty still ends a drawn text as the original's does. `kp_ui_glyph` and `kp_ui_char_width` stay byte slots for the probes. The glyph log and `KpUiCanvasGlyph` hold an `int32_t` code point. `kp_vtext` keeps its 256 slots and finds them with `kp_text_byte`, so enUS's atlas is packed as before; `kp_ui_canvas.c` asks the same slot.
- **Input:** `KP_UI_CHAR`'s `key` is the code point (the Basic Multilingual Plane). `& 0xff` is gone from the character handlers, where U+041B would be Escape; `kp_ui_edit.c` steps, deletes and overwrites by character, its cursor and scroll stay bytes at characters' starts, `kp_ui_edit_set_text` moving the old scroll onto the new text's.
- **Hotkeys:** `kp_hud_text_key` turns a non-ASCII character outside an edit box into the physical key's Latin letter, once a text event (an IME's commit or a ligature is one hotkey), and drops it for a key that is no letter or for a soft keyboard. `KpApp.text_vk` comes from every press's scancode at the top of `kp_input_event`: 0 for a key with no virtual key (`;`, `,` and the other punctuation keys) and under Alt, Option, AltGr, Ctrl or Command, whose characters are the layout's symbols. The touch check's `key_letter`, `key_no_letter` and `key_option` steps send these through `kp_input_event`.
- **Limits and buffers:** a name's limit counts characters (24 for an ID, 27 for a save, 78 for the message line); `KP_UI_NAME` is 97 bytes, `KP_UI_SAVE_NAME` 109, `KP_UI_ROSTER_FORCE` 117, `KP_UI_LINE_SIZE` 436; tooltips, formats, status lines and `KP_UI_POPUP_TEXT` are doubled, the credits' texts 4096. The save and load commands' name is limited by the event's text, the dialog's limit being the one that counts. Copies cut on a character's start (`kp_text_copy`, `kp_text_floor`); the score roster keeps the original's cut in characters, 24 for a name and 29 for a force (`kp_text_copy_chars`), so enUS's 30-byte force name loses its last letter as it did.
- **The profile:** schema 7. A profile before it reads its names as windows-1252. `old_save_files` says `KP_SAVE_FILES_BEFORE_IDS` or `KP_SAVE_FILES_BYTES`, and `kp_profile_rename_old_saves` finds the old file names from `kp_text_to_legacy`.
- **File names:** a part past 84 characters of `_xx` (`FILE_PART_MAX`, which no name of the old limits reaches) is `_h` and a 64-bit FNV-1a of its ASCII-lowered bytes.
- **The converter:** `kpd.table_utf8` and `kpd.text_utf8`: on the 1.17 data `GHST` grows 10 bytes (5 × `0x92`), `POOL` 2 (2 × `0xA9`), `DLGS` keeps its size with its offsets moved; nothing else in `generated/data` changes. A table already in UTF-8 stays as it is, and an offset past a table's end stays past it.
- **Checked (2026-11-07):** `tools/ci.sh` with `KOPRULU_ORIGINAL`, `KOPRULU_SCR` and `KOPRULU_APP`: 420 C tests natively, under ASan and UBSan, under LLVM's sanitizers and in wasm, 285 converter tests, the touch check's 8 steps, no golden regenerated. Screenshots of the last commit's build and this one's over their own data are pixel-identical: the main menu and terran01's console, at the original font and the vector font (repeated runs, since the menu's movies differ by phase within either build).
- **Not looked at on screen:** the mission history, the one screen whose text changed bytes, is covered by the width and glyph tests only. No device run, nothing here is phone-specific; a Russian layout's hotkeys are tested through `kp_hud_text_key` and synthetic SDL events, not a real keyboard.

## L2 as built

- **`converter locale --scr DIR --locale LOC --out DIR`** (`converter/emit/locale.py`): after `data` and `missions`, whose packs it measures the language against. Every check runs first and all failures go to `reports/locale-<loc>.json`; with any failure nothing else is written. An unknown locale and the base are refused. `converter dump` reads the new sections.
- **The checks of a row:** UTF-8; the same printf conversions in the same order, unless `defs/l10n/locales.json` lists the row (ruRU's `STAT STR_PERCENT`, a bare `%` no format reads); the same NULs; no control byte the base's table does not use; none of Remastered's `{Template}` substitutions; a TBL's button keeps an ASCII hotkey and its mode byte. **Colours are not compared**, contrary to the plan's "form of the control bytes": the translators dropped the highlight of a button's letter in 254 rows of `stat_txt`, so colours may move or go. A dialog's hotkey must be ASCII; its button form varies (`rОК`, `nОтмена`).
- **What keeps the base's text:** a row the language lacks, a `<<PLACEHOLDER>>`, a row empty in the base, names of files and dialogs, a dialog record's every number (compared field by field against the base's) and the map strings looked up by their text: WAV paths and Set Next Scenario's name. A script may name no file the base's `GFIL` lacks.
- **Reading Remastered's XML:** every value is escaped as `RC3.xml`, decimal `\\N` of up to 3 digits (`\\0041` is byte 4, then `1`); codes past ASCII are windows-1252 characters (`\\169`, ©) and become UTF-8. A span's NUL is written `0x07`, also a colour code; `with_nuls` tells them apart by the base's row. `stat_txt` goes by row number up to Remastered's TBL's count, the others by the manifest's ids.
- **ruRU's result:** `STAT` 1539 of 1547 rows (70,978 bytes, past u16), `NETW` 168, `GLUA` 202, `GHST` 87, `TIPS` 102 of 104, `HELP` 37 of 52; 301 dialog texts, 10 kept; all 64 scripts; 64 missions with 6937 strings translated and 1152 kept (each a WAV path or a scenario name); 20 movies' subtitles; 148 glyphs per font, none dropped. `generated/locale` is 1.3 MB, 376 KB of it `glyphs.kpd` with the two TrueType fonts. It is ignored by git like the rest of `generated/`.
- **The supplement** (`kp_fnt_make`, `native/kp_present/kp_fnt_make.c`) comes from Eurostile and Eurostile Extended, the user's choice at F0, not "first from Exo 2" as the plan had it. Style from the FNT's masks: edges at coverage 170, 120, 70, 30, drawn over 80, the shadow's entry from its font. Each glyph takes the sharpest of 4 horizontal subpixel positions. Its columns are trimmed to ink, its cell is the ink plus the shadow, and the horizontal scale is searched so the font's own Latin letters, made the same way, take the FNT Latin's widths: a word laid in cells wider than its letters would show as big word gaps in the vector text, which lays words out on FNT cells. A code either TrueType font lacks leaves all five sections; the same code in a language's text is a failure. A later language keeps the codes of the ones before it.
- **Loading** (`kp_ui_set_locale`, `kp_host_game_text`, `kp_cine_subs_overlay`, `--locale LOC` with the packs under `generated/locale`): a pack of another kind or schema, a damaged one, a table of another row count or section schema, other dialogs or a malformed section is refused on its own and logged once; the base stays. `kp_host_game_text` goes between the mission's load and its start, and the game owns the overlay. Packaging for the bundles, the web and the phones is stage L4; the dialog is too.
- **Fixed on the way:** `stbtt_InitFont` reads out of bounds on bytes that are no font, since `stbtt_GetFontOffsetForIndex` gives -1 and nothing checked it; `kp_vtext_init`, `kp_caption_render` and `kp_fnt_supplement` now open a font through `kp_ttf_open`. A text's time counts characters (`text_duration`), so Cyrillic's two bytes do not double it.
- **The atlas at scale 4 (ADR 0016's open measure):** with Eurostile and the 148 glyphs the vector atlas is 1024 × 725 at scale 2 (725 KB), 2048 × 788 at 3 (1.5 MB), 2048 × 1291 at 4 (2.6 MB), well under `ATLAS_MAX` 4096. Not yet measured on a phone.
- **Acceptance:** `missions_with_the_languages_text_keep_their_state`: all 64 missions with ruRU's text step 1000 frames to the same state CRCs as with their own. `the_languages_text_is_valid_and_has_glyphs`: no invalid byte and no missing glyph in any row of the 6 tables or dialog text, past what a menu run reaches. `tools/ci.sh` converts ruRU and walks the product's menu and in-game screens with `--locale ruRU`, failing on a log line of a missing glyph or refused pack. enUS: no golden regenerated. `tools/menus_check.py`, which `tools/ci.sh` does not run and which differs from the original since 2026-10-31 by the remake's own labels (`docs/phase10.md`), prints the same lines on both recorded menu runs (`emu/menus-ui`, `emu/menus-ui2`: 8 and 9 differences) as `kp_oracle` built from the commit before this stage.
- **Checked:** `KOPRULU_FULL=1 tools/ci.sh` with `KOPRULU_SCR` and `KOPRULU_APP`: 435 C tests natively, under LLVM's sanitizers and in wasm (`test_locale` 14, `test_cine` one more), 351 converter tests (`test_locale` 50), the product's checks with `--locale ruRU` beside the others'. Not run in this stage: Apple's sanitizers (LLVM's replace them here), a device, the web page, Windows and Linux products.

## Acceptance across the stages

- enUS does not change: `tools/ci.sh`, the text probes, the oracles and `tools/menus_check.py` give the same results.
- A mission's CRC with a language's text equals enUS's; only speech may differ.
- Every failure in ADR 0016 falls back to the base and logs once; none stops the game.
