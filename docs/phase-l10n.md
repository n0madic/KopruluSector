## L1 as built

- **`kp_text`** decodes on top of `kp_utf8`: a valid sequence is its code point, any other byte its windows-1252 code point. Bytes below `0x80` stay bytes in every scan, so the control codes, the highlight's prefix and its caret byte `0xA6` are found before anything decodes.
- **The engine:** `kp_ui_text.c` steps by character (`char_step`, the span's `next`); a character of a valid sequence with no glyph has width 0 and the text goes on, in the drawing as in the measuring (`text_skips_a_character_with_no_glyph`); a stray byte whose slot is empty still ends a drawn text as the original's does. `kp_ui_glyph` and `kp_ui_char_width` stay byte slots for the probes. The glyph log and `KpUiCanvasGlyph` hold an `int32_t` code point. `kp_vtext` keeps its 256 slots and finds them with `kp_text_byte`, so enUS's atlas is packed as before; `kp_ui_canvas.c` asks the same slot.
- **Input:** `KP_UI_CHAR`'s `key` is the code point (the Basic Multilingual Plane). `& 0xff` is gone from the character handlers, where U+041B would be Escape; `kp_ui_edit.c` steps, deletes and overwrites by character, its cursor and scroll stay bytes at characters' starts, `kp_ui_edit_set_text` moving the old scroll onto the new text's.
- **Hotkeys:** `kp_hud_text_key` turns a non-ASCII character outside an edit box into the physical key's Latin letter, once a text event (an IME's commit or a ligature is one hotkey), and drops it for a key that is no letter or for a soft keyboard. `KpApp.text_vk` comes from every press's scancode at the top of `kp_input_event`: 0 for a key with no virtual key (`;`, `,` and the other punctuation keys) and under Alt, Option, AltGr, Ctrl or Command, whose characters are the layout's symbols. The touch check's `key_letter`, `key_no_letter` and `key_option` steps send these through `kp_input_event`.
- **Limits and buffers:** a name's limit counts characters (24 for an ID, 27 for a save, 78 for the message line); `KP_UI_NAME` is 97 bytes, `KP_UI_SAVE_NAME` 109, `KP_UI_ROSTER_FORCE` 117, `KP_UI_LINE_SIZE` 436; tooltips, formats, status lines and `KP_UI_POPUP_TEXT` are doubled, the credits' texts 4096. The save and load commands' name is limited by the event's text, the dialog's limit being the one that counts. Copies cut on a character's start (`kp_text_copy`, `kp_text_floor`); the score roster keeps the original's cut in characters, 24 for a name and 29 for a force (`kp_text_copy_chars`), so enUS's 30-byte force name loses its last letter as it did.
- **The profile:** schema 7. A profile before it reads its names as windows-1252. `old_save_files` says `KP_SAVE_FILES_BEFORE_IDS` or `KP_SAVE_FILES_BYTES`, and `kp_profile_rename_old_saves` finds the old file names from `kp_text_to_legacy`.
- **File names:** a part past 84 characters of `_xx` (`FILE_PART_MAX`, which no name of the old limits reaches) is `_h` and a 64-bit FNV-1a of its ASCII-lowered bytes.
- **The converter:** `kpd.table_utf8` and `kpd.text_utf8`: on the 1.17 data `GHST` grows 10 bytes (5 × `0x92`), `POOL` 2 (2 × `0xA9`), `DLGS` keeps its size with its offsets moved; nothing else in `generated/data` changes. A table already in UTF-8 stays as it is, and an offset past a table's end stays past it.
- **Checked (2026-11-07):** `tools/ci.sh` with `KOPRULU_ORIGINAL`, `KOPRULU_SCR` and `KOPRULU_APP`: 420 C tests natively, under ASan and UBSan, under LLVM's sanitizers and in wasm, 285 converter tests, the touch check's 8 steps, no golden regenerated. Screenshots of the last commit's build and this one's over their own data are pixel-identical: the main menu and terran01's console, at the original font and the vector font (repeated runs, since the menu's movies differ by phase within either build).
- **Not looked at on screen:** the mission history, the one screen whose text changed bytes, is covered by the width and glyph tests only. No device run, nothing here is phone-specific; a Russian layout's hotkeys are tested through `kp_hud_text_key` and synthetic SDL events, not a real keyboard.

## L2 as built

- **`converter locale --scr DIR --locale LOC --out DIR`** (`converter/emit/locale.py`): after `data` and `missions`, whose packs it measures the language against. Every check runs first and all failures of the language's data go to `reports/locale-<loc>.json`, a map that does not load, strings past STR's offsets and a subtitle file's among them; with any failure nothing else is written. Only what is not the language's data stops it before the report: a base pack not there, a file the install lacks, no `kp_fnt_make`. A pack of the language it did not write is removed. An unknown locale and the base are refused. `converter dump` reads the new sections.
- **The checks of a row:** UTF-8; the same printf conversions in the same order, unless `defs/l10n/locales.json` lists the row (ruRU's `STAT STR_PERCENT`, a bare `%` no format reads); the same NULs; no control byte the base's table does not use; none of Remastered's `{Template}` substitutions; a TBL's button keeps an ASCII hotkey and its mode byte; an escape past a byte is a failure. A row with a NUL has as many `0x07` and NUL marks as the base's, since a stray colour there would move the NUL. A map string goes through UTF-8, the control bytes of its map's strings and the substitutions. **Colours are not compared**, contrary to the plan's "form of the control bytes": the translators dropped the highlight of a button's letter in 254 rows of `stat_txt`, so colours may move or go. A dialog's hotkey must be ASCII; its button form varies (`rОК`, `nОтмена`).
- **What keeps the base's text:** a row the language lacks, a `<<PLACEHOLDER>>`, a row empty in the base, names of files and dialogs, a dialog record's every number (compared field by field against the base's) and the map strings looked up by their text: WAV paths and Set Next Scenario's name. A script may name no file the base's `GFIL` lacks.
- **Reading Remastered's XML:** every value is escaped as `RC3.xml`, decimal `\\N` of up to 3 digits (`\\0041` is byte 4, then `1`); codes past ASCII are windows-1252 characters (`\\169`, ©) and become UTF-8. A span's NUL is written `0x07`, also a colour code; `with_nuls` tells them apart by the base's row. `stat_txt` goes by row number up to Remastered's TBL's count, the others by the manifest's ids.
- **ruRU's result:** `STAT` 1539 of 1547 rows (70,978 bytes, past u16), `NETW` 168, `GLUA` 202, `GHST` 87, `TIPS` 102 of 104, `HELP` 37 of 52; 301 dialog texts, 10 kept; all 64 scripts; 64 missions with 6937 strings translated and 1152 kept (each a WAV path or a scenario name); 20 movies' subtitles; 148 glyphs per font, none dropped. `generated/locale` is 1.3 MB, 376 KB of it `glyphs.kpd` with the two TrueType fonts. It is ignored by git like the rest of `generated/`.
- **The supplement** (`kp_fnt_make`, `native/kp_present/kp_fnt_make.c`) comes from Eurostile and Eurostile Extended, the user's choice at F0, not "first from Exo 2" as the plan had it. Style from the masks of the FNT font's Latin letters: whether it has edges and which shadow (font14's letters have none: its mask 5 is only in the boxes of 0x7f..0xa0, and counted over every glyph it gave U14 a black shadow its letters lack); a font without edges draws over coverage 80; with edges, the body's threshold is searched so the font's own Latin letters, made the same way, have the FNT's share of body pixels (font10 78%, font14 40%), the three edges splitting the coverage under it from 30 in thirds. The first version took 170 for every font: Eurostile's thin strokes at font10's 7-pixel cap fell under it, 79% of U10's ink went to the edge masks, which font10's rows colour magenta in the briefing's palette, and those glyphs cast no shadow, which only the body casts (2026-11-08, the user's report of the briefing's transcript; `test_locale.fnt_supplement_keeps_the_fonts_colours`). Each glyph takes the sharpest of 4 horizontal subpixel positions. Its columns are trimmed to ink, its rows stop at the FNT font's cell with the shadow inside it (`р`, `у`, `ф` lose 1 row in font10 and 2 in font14, ending where the font's own `p` and `y` end), and the horizontal scale is searched so the font's own Latin letters, made the same way, take the FNT Latin's widths: a word laid in cells wider than its letters would show as big word gaps in the vector text, which lays words out on FNT cells. A code either TrueType font lacks leaves all five sections; the same code in a language's text is a failure. A later language keeps the codes of the ones before it.
- **Loading** (`kp_ui_set_locale`, `kp_host_game_text`, `kp_cine_subs_overlay`, `--locale LOC` with the packs under `generated/locale`): a pack of another kind or schema, a damaged one, a table of another row count or section schema, other dialogs, a `POOL` with no final NUL or a malformed section is refused on its own and logged once; the base stays. `kp_host_game_text` goes between the mission's load and its start, and the game owns the overlay. Packaging for the bundles, the web and the phones is stage L4; the dialog is too.
- **The briefing's transcript stayed bitmaps (2026-11-08), in enUS too:** `kp_ui_briefing.c`'s `text_draw` copied the text bitmap's rows into the room's dialog pixel by pixel, without the glyph log, so the vector text never reached it; it now copies them by a keyed blit that carries the glyphs (`kp_ui_glyph_log_blit`, ADR 0011). The text bitmap is never composed, so the prune also dropped its glyphs 120 composes after they were drawn; a glyph a blit carries now counts as seen (`blit_from`), which missed the 4 s before the scroll (L6's `keep_transcript`). `test_flow.briefing_text_is_vector_text`. The glue walk of `--hd-check` takes its briefing screen before the transcript shows, so `tools/ci.sh` does not see it.
- **Fixed on the way:** `stbtt_InitFont` reads out of bounds on bytes that are no font, since `stbtt_GetFontOffsetForIndex` gives -1 and nothing checked it; `kp_vtext_init`, `kp_caption_render` and `kp_fnt_supplement` now open a font through `kp_ttf_open`. A text's time counts characters (`text_duration`), so Cyrillic's two bytes do not double it.
- **The atlas at scale 4 (ADR 0016's open measure):** with Eurostile and the 148 glyphs the vector atlas is 1024 × 725 at scale 2 (725 KB), 2048 × 788 at 3 (1.5 MB), 2048 × 1291 at 4 (2.6 MB), well under `ATLAS_MAX` 4096. Not yet measured on a phone.
- **Acceptance:** `missions_with_the_languages_text_keep_their_state`: all 64 missions with ruRU's text step 1000 frames to the same state CRCs as with their own. `the_languages_text_is_valid_and_has_glyphs`: no invalid byte and no missing glyph in any row of the 6 tables or dialog text, past what a menu run reaches. `tools/ci.sh` converts ruRU and walks the product's menu and in-game screens with `--locale ruRU`, failing on a log line of a missing glyph or refused pack. enUS: no golden regenerated. `tools/menus_check.py`, which `tools/ci.sh` does not run and which differs from the original since 2026-10-31 by the remake's own labels (`docs/phase10.md`), prints the same lines on both recorded menu runs (`emu/menus-ui`, `emu/menus-ui2`: 8 and 9 differences) as `kp_oracle` built from the commit before this stage.
- **Checked:** `KOPRULU_FULL=1 tools/ci.sh` with `KOPRULU_SCR` and `KOPRULU_APP`: 435 C tests natively, under LLVM's sanitizers and in wasm (`test_locale` 14, `test_cine` one more), 362 converter tests (`test_locale` 61), the product's checks with `--locale ruRU` beside the others'. Not run in this stage: Apple's sanitizers (LLVM's replace them here), a device, the web page, Windows and Linux products.

## L3 as built

- **What is measured:** `kp_ui_draw_text` returns where its layout stopped short of a text's end: a word wider than its line, lines past the clip's bottom, a control lower than one line. `KpUiTextCut` (`ui->text_cut`, `kp_ui.h`) is told of it from `control_text` (`kp_ui_draw.c`, every stock control's text) and from the tooltip's `begin_text` (control -1); NULL in the game, the tests listen.
- **`test_locale.the_languages_texts_fit`:** every dialog of `ui.kpd`, in the glue's font set or the game's, painted with all its controls shown; the status panel's text controls with each `stat_txt` row `kp_ui_status.c` sets in them (the 228 unit names, the ranks and status texts, kills with 9999, the supply lines with 200, the labels); every `stat_txt` row as a tooltip. The base's cuts and the language's are compared by dialog, control and row: a cut enUS has too is the original's (30 of them: hidden controls with no room, `koprulu\video.bin`'s labels before its procedure sizes them, "Protoss Robotics Support Bay" at exactly its control's 152 pixels). The new ones go to `generated/reports/widths-ruRU.json` and fail the test; enUS's to `widths-enUS.json`.
- **`test_locale.the_missions_texts_fit`:** every mission's map strings where they show: the objectives (TRIG Set Mission Objectives, MBRF Mission Objectives) in `objctdlg.bin` and in the three ready rooms' objectives control, the briefing's texts and transmissions as the transcript lays them (the control's width, 20 times its height: `text_show`), the units' names of `UNIS`/`UNIx` in the status panel. 147 objectives, 482 transcripts, 16 names; none cut in either language. A transcript of one line's height cuts 27 of the language's, so the measure sees them.
- **What ruRU needed (2026-11-08):** 6 dialog texts and 14 status texts were cut before the fixes. The multiplayer's `allyfltr.bin`, `teamfltr.bin` and `netdlg.bin` (3 cuts) are left out: no engine path opens them. The rest is fixed in `defs/l10n/locales.json`:
  - `layout`: a dialog record's rectangle for a language, applied by `convert_dialogs` after the record is compared with the base's (width and height follow): `gluScore.bin`'s "Общий счет" label 4 pixels left; `statdata.bin`'s unit name over the panel's empty sides (95..268 for 102..253), its four supply lines and its morph label to x 268.
  - `rows`: a language's shorter text for a table row, checked as the language's own: `STAT` 154 "Неисп. строение зергов 5" (184 pixels in font10, past the widened name; an unused building).
  - An entry naming no row or record, an empty rectangle, or a second entry of a language for the same row or record, is a failure of the language.
- **Not needed:** `kp_vtext`'s word squeeze fits a word's vector glyphs into its FNT cells and cannot help a layout that the FNT metrics cut; no engine change was needed, so enUS draws as before. Remastered has no per-language layout (`SD/rez/*.ui.json` is one set).
- **Not measured:** texts a procedure draws itself rather than a control (the score screen's numbers, the credits, the list boxes, which have their own ellipsis), the chat line, and a trigger's text lines, which wrap at 620 pixels; a cut there shows on the product's screens only.

## L5 as built

- **`converter speech --scr DIR --locale LOC --out DIR`** (`converter/emit/speech.py`) writes `generated/speech/<loc>/`: per campaign mission a partial `MISN` (`TRIG` and `MBRF` only) and its `_sounds.kpd` (`MSND`), `units.kpd` (`MSND` by sfx id: the language's unit voices) and `sounds.kpd` (`SFX ` only: each sfx id's RIFF record, the language's where it has the file). ruRU: 64 missions, 1,104 lines (1,103 until Protoss 10's briefing line came back, issue #2), 592 voices, 69 MB (the mission lines 57.6 MB, the voices 9.3 MB, the triggers 4.7 MB).
  - The triggers are the base's records with the language's `TIME` (`time_merged`): an action that differs in more than `TIME` keeps the base's whole, and any difference besides `TIME` is a problem unless `locales.json`'s `speech` lists the mission with its reason (ruRU: `expterran/terran03`, Remastered's own Set Switch and Switch condition in records 20 and 24). A section of another size is a problem; problems go to `reports/speech-<loc>.json` and nothing is written.
  - The lines are keyed by the base's `WAVS` index (a WAV string's position among the mission's in string-id order, whether or not the other files exist: since 2026-11-11, issue #2; before, the position among the existing sounds), so `WAVS` stays the base's: the engine reads no WAV length, only its index, and waits by `TIME`. The index depends on the CHK alone, so every source of the profile gives the base's, a repack that lacks a damaged file too, and the lines do not shift with the install the game reads (`test_chk` compares the installs'). Remastered's lines are Ogg Vorbis at 44.1 kHz, its voices WAV at 44.1 kHz: FFmpeg makes them 16-bit mono 22,050 Hz, the base's form, before the `OggCache` encodes them. A line the install lacks or keeps empty (some `nullsound.ogg` are 0 bytes) keeps the base's sound (`line_sources`).
  - `speech.Encoder` keeps `generated/sounds/speech/sources.json` beside the `OggCache`'s `ogg.json`: each OGG's path and the digest of its source file with the sample rate, the quality and the stream serial. An OGG whose key is the `OggCache`'s and whose source is unchanged is not decoded again, so a second conversion takes 4 s instead of 35 (FFmpeg ran on all 1,695 sources every time).
  - A `locales.json` `speech` entry naming no mission, or a mission whose triggers differ from the base's in `TIME` alone, is a problem: an exception must be needed.
- **The engine:** `kp_host_game_speech` lays the overlay's `TRIG` and `MBRF` over the loaded mission before its start, as `kp_host_game_text` does the text; another kind or schema, a missing section, a size other than the mission's or a record that differs from the mission's in more than the actions' `TIME` (the speech of other data) leaves the mission's (`test_locale.mission_speech_refusals_leave_the_missions_own`). `kp_flow` reads the overlay of a campaign mission (`mission_overlay`, shared with the text's) and the speech's `sounds.kpd` into `KpUiLocale.speech`, which `kp_ui_set_locale` lays over the base's sound records when the counts agree (the voices' durations); a refusal goes to `KpUi.speech_problem`, apart from the text's `locale_problem`, so the text stays, and `kp_flow` logs it once (`test_locale.speech_sound_records_replace_the_bases`). The SDL app plays a mission's lines from the speech's `_sounds.kpd` and a unit's voice from `units.kpd` before its pack (`kp_app_audio.c`'s `speech_pack`, dropped with the decoded sfx when the speech changes); each missing file falls back to the base with one line.
- **The choice:** `--speech LOC`, else the profile's (`LANG`) when installed, else the text's language's when it has speech, else the base's; the checks and `--mission` keep the base's. A speech is installed when `generated/speech/<id>/units.kpd` is there. The language dialog's speech row (button 7) shows with more than one installed and takes the next; OK keeps it in the profile apart from the text's and starts the flow over. `test_flow.the_speech_is_chosen_apart_from_the_text`.
- **Saves:** the format does not change. The `TIME` is in the saved trigger copies, so a save keeps the speech it was made with whatever the game it loads into (`test_speech.a_save_keeps_its_speech`: saved with ruRU and loaded into a base game, and the other way, the saved `TIME`, the same bytes again, the same states 600 steps on).
- **Packaging:** `tools/product.sh`'s `KOPRULU_SPEECH` (`auto`, `none` or a list; `auto` stages every converted speech when languages are staged, except on the web, whose page preloads its data, and none beside `KOPRULU_LOCALES=none`) stages `generated/speech/<id>` with the glyphs' pack, which lists the languages. `tools/ci.sh` converts ruRU's speech beside its text and runs the product's ruRU mission with `--speech ruRU`.
- **Acceptance (`test_speech.campaign_plays_with_the_speech_equal_the_original`):** the original's game played every campaign play again with ruRU's speech: `sc_emulator play FUNC OUT --speech generated/speech/ruRU/missions/<c>/<m>.kpm` (`tools/research/sc_emulator/speech.py`) writes the overlay's `TIME` into the loaded map's trigger lists at the game's first object step, before any trigger runs and before the dump of step 1; each list's node takes the TIME of the next overlay record equal to it apart from TIME, and a node matching none stops the play.
