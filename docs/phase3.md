## Oracle (3.0)

**State dumps.** `python -m sc_emulator campaigns --frames 3 --state 1,2,3 --out-root ~/koprulu-private/emu/states` (from `tools/research`, private venv) runs every campaign mission through the game's own start path and dumps the state at the entry of object steps 1–3.
- Step 1 is the call of `PrimeGameLoop 0x445520`: the state that `StartGame` leaves, before any unit, order or AI step.
- A dump holds the whole writable data section of `StarCraft.exe` (every pool, list head, counter and the RNG live there), the tile flag and megatile heap arrays and the path pool (`[0x69b574]`, 1024 records of 128 bytes). About 160 KB compressed; 20 s per mission.

**Call traces.** `python -m sc_emulator mission NAME WARP --calltrace START,STOP[,WINDOWS]` (or `scenario SPEC --calltrace ...`) records every atlas function entered between two code addresses, nested by stack pointer, for WINDOWS windows in a row. The trace from `StartGame 0x443f40` to the first object step lists the native functions of mission start and their order; it drove the port of 3.1. The block hook is added when a window opens, so the translation cache is flushed then: Unicorn does not apply a new block hook to code it has already translated, and the traces before that fix missed functions such as `StepObjectSprite 0x418b20`.

**State model.** `tools/native_state.py` decodes a dump into lines `<category> <key> <field>=<value> ...`; `tools/lua/state_model.lua` prints Koprulu's state in the same form. Pointers become record numbers (units 1..1700, sprites, images in the `game/images/core.lua` key space, order nodes, guard records `g<k>`); unit references inside the type-dependent union print as `u<n>`. Categories:
- global: RNG, counts, list tails, the cloaked-unit list head;
- list: unit lists in native order, including the per-player lists;
- unit: every CUnit field;
- order, order_free: queues and the free list;
- path, path_free: each unit's path record (header, points, region ids) and the free record chain;
- density: the non-empty cells of the air repulsion grid (`0x67cf60`, dump blob "density"), `cell:count`;
- sprite and image, in row order;
- counter, pstat: per-type counts and the per-player statistics;
- spatial: both bound arrays;
- player, guard: controllers, shared vision, guard AI records;
- tiles: the tile flag DWORDs;
- terrain: MTXM words, the creep engine's backup words and border bytes, the display megatiles.

**Scenarios (level C).** A spec in `tests/scenarios/<name>.json` names a base campaign map, the slot controllers, the units, the frame count and the player's inputs (selection boxes, hotkeys, right clicks at given frames; `tools/research/sc_emulator/scenario.py`). `converter/scenarios.py` rewrites the base CHK (OWNR and UNIT from the spec, THG2 sprites only, empty TRIG and MBRF); `python3 -m converter scenarios --data DIR` writes `generated/scenarios/<name>.kpm`. `python -m sc_emulator scenario <spec>` starts the base mission in the emulator, replaces the map at every `ChkLoadSections 0x4c1200` call with the same CHK, dumps the state before every object step, logs every executed game command at `RecordCommand 0x478830` (`commands.jsonl`, with the frame counter, the turn counter `0x672658` and the issuing player) and every change of the local player's interface selection at `SetLocalSelectionArray 0x49cab0` and every right-click marker at `MovePlacementCursor 0x417ad0` (`ui.jsonl`) for Koprulu to replay. The interface draws the selection circles and moves the marker sprite at once; the command it sends runs a few frames later. In single player the only commands without input are the sync commands 0x37.

**Comparison.** `python3 tools/state_check.py` starts each dumped mission in Koprulu with the dump's initial seed and compares the models; `--write-golden` stores the original's per-category CRCs in `tests/golden/oracle/initial_state/` and the equal missions in its `index.lua`, which `tests/lua/test_initial_state.lua` checks on every Lua backend.

`--step N`, `A-B` or `all` compares object steps: Koprulu runs the same steps (`tools/lua/state_model.lua` `runner`: PrimeGameLoop's two steps, RunGame's first turn, then per loop iteration the interface events, the turn, the frame count and the steps) and replays the run's `commands.jsonl` and `ui.jsonl` on the way; a mission reports its first differing step. With `--root ~/koprulu-private/emu/scenarios --step all --write-golden` the per-step CRCs and the command log of each scenario go to `tests/golden/oracle/scenarios/`, which `tests/lua/test_scenarios.lua` replays step by step on every Lua backend.

Fields the comparison leaves out:
- the image redraw bit (flag 0x01), which only drives the original's dirty rectangles;
- from step 3 on, the image bounds (+0x1c/+0x1e): the original's drawing refreshes them for the rows in view (`0x445de0`), so they depend on the camera; Koprulu's presentation refreshes them itself;
- the resource-area tag (+0xd8) of resources: the AI's `GenerateResourceAreas 0x497a20` (phase 5).

## Initial state (3.1)

`game/simulation/start.lua` follows `StartGame`/`InitGameWorld` for everything that builds simulation state: guard AI pool, fog init with the 12 vision templates, image and sprite pools, the cursor thingy, order pool, counters, acquisition ranges, unit pool, strength tables, the MTXM tile flags and edge strips, THG2 doodads, MASK, the override sections in dispatch order (after THG2, as in the original), and the UNIT section with record admission, creation, properties and the post-load visibility pass.

Unit creation follows the native chain `CreateMapUnit 0x469460 → CreateUnit 0x424900 → AllocateUnit / InitializeUnit / InitializeUnitType → CompleteUnitWithPlacement 0x424db0 → AttachGuardRecord 0x4b2010`, with flingy init, the IScript walking-speed sampling, speed and energy upgrades, the spatial index (`0x4195a0`, `0x419820`, queries `0x4224c0`/`0x422330`), placement (`0x47dc30` direct candidate, footprint `0x42ed50`, contours `0x48b780`), completion accounting, Show with unit vision (`0x46bbb0` and its four callbacks), sprite visibility, overlap flags, initial orders through the native order pool, strength (`0x4a98e0` with its `sqrt`), damage overlays (`0x422dd0`, RNG source 8) and permanent cloak with detection (`0x41d200`, `0x4325a0`, `0x4316b0`).

**Vision templates** equal the original's generators for all 12 sights at strides 64, 128 and 256 (`tests/lua/test_vision.lua`, CRCs from the recorded original-code evidence).

**Requirements.** `EvaluateDatRequirements 0x407570` with the order (`0x407bb0`) and technology-use (`0x407f90`) wrappers, and the unit production table lookup `0x4b3850`. The bytecode tables are built into `StarCraft.exe`; the converter copies them into `dat.kpd` (`RQOR`, `RQRS`, `RQTU`, `RQUP`, `RQUN`, [kpd format](formats/kpd.md)).

**Creep** (`game/terrain/creep.lua`): the creep engine's mutators, border shapes and ranks, initial placement `0x4c0aa0` and spread `0x4c0e60` (game RNG source 26), and the game callbacks (display megatile, tile flags, receding buckets). Creep tile variants come from the CRT `rand()` seeded with the game seed at start; the call trace of a Zerg start shows no other CRT draw before creep. Terrain height (`0x445690`) reads the tile word under the creep (the backup map), which decides line of sight next to creep.

**Status:** all 64 missions equal the original in every compared field (`tests/golden/oracle/initial_state/`). Each step was found by the comparison and fixed in the native code path, for example:
- the dump point (the first object step runs inside `PrimeGameLoop`);
- the carrier and reaver hangar capacity upgrades (43 and 36; the decompiler's branch order was misleading, the disassembly settles it);
- terrain height under creep.

Contracts that the initial states do not reach raise a named error instead of doing nothing: hallucinated map units (`0x430a00`), ownership transfer of addons (`0x426ed0`), additional placement points (`0x4928f0`), building ghosts of fog (`0x417b10`), selection-dependent sprite changes, paths.

## Frame loop (3.2)

`game/simulation/step.lua` follows the frame of the game loop `0x444e30`: the turn's commands, the frame count, `StepGameObjects 0x445070`, then the trigger step `0x4be500`, each with the generator enabled (`0x4781c0`). `PrimeGameLoop 0x445520` runs two object steps before the first frame, without a frame count or a trigger step; the dumps 1 and 2 are those steps. The object step:
- `RecedeCreepTick 0x4b4010` with the receding pool's counters (`game/terrain/creep.lua`);
- `StepAi 0x48dd90` and `StepAiTimers 0x48df50` (`game/ai/step.lua`): the region cursor, the spending and town cursors and the under-attack reset of unit status 0x80 run in every game;
- every 100 steps `RefreshRememberedTerrainOffscreen 0x40af30` and `ResetTileVisibility 0x46c180`, after which the units reveal their sight again;
- `UpdateUnits 0x438ef0`: the order and secondary timer phases, `UpdateDisruptionWebCoverage 0x438cd0`, movement (`PrepareUnitMovement 0x43a5f0`, `ExecuteUnitMovement 0x42ad30` with the states Init, AtRest, Dormant and CheckIllegal, `IsPositionBlocked 0x42eab0`), the revealers' sight, sprite visibility and detection, then per unit `UpdateUnitTimers 0x43a320` (energy, shields, spell timers, acid spores), `DispatchMainOrder 0x439420`, `DispatchSecondaryOrder 0x439310` and the sprite's IScript; then the cloak list, Protoss power and the hit history slot;
- bullets and independent flingies (none yet), then the lone thingies.

The order dispatchers (`game/units/order_dispatch.lua`) carry the native function of every order of their three switches. Ported: Guard `0x41e700` (RandRange on source 29, then PlayerGuard, ComputerAI or GuardPost), PlayerGuard `0x41ee10` with `AcquireBestTarget 0x431c40` (`game/units/targets.lua`: seek ranges and their upgrade table, weapons, `CanAttackTarget 0x41da50`, `IsEnemyUnit 0x4290e0`, the candidate filters of `0x432280`), Nothing, and the original's empty orders. The trigger step (`game/triggers/clock.lua`) keeps its clocks and the elapsed seconds that the AI timers read.

**Turns and commands.** A loop iteration runs the turn (`TurnManagerStep 0x476c00`: its commands, then the turn counter), the frame count, then the object and trigger steps; RunGame runs one turn before the loop. `game/simulation/commands.lua` executes a turn's commands: the sync command 0x37 changes no game state; select 0x09 (`0x472fc0`), Stop 0x1a (`0x473440`) and Hold Position 0x2b (`0x4727c0`) are ported, with `IssueCommand 0x42a8b0` for unqueued orders and `CanIssueOrder` per selected unit; every other command raises with its handler from the executor's switch.

**Selection** (`game/units/selection.lua`): the local interface selection (`SelectUnitsLocally 0x49cf80`, `SetLocalSelectionArray 0x49cab0`, `SelectUnitIntoSlot 0x422eb0`, `AddSelectionCircle 0x423060`, `ShowSelectionHealthBar 0x417110` with the health-bar and circle allocators of phase 2, circle colours of `RefreshAllianceColors 0x41d7b0`); each player's command selection (`0x6a5ef0`), the control groups (`0x527140`) and the recent multi-unit selections stamped with the turn (`0x464360`, `0x4643c0`). The orders Stop (`0x428a10`) and Hold Position (`0x41e9b0`) stop the unit (`StopMovementAndFace 0x43a4e0`, `StopFlingy 0x40ce10`); Hold Position seeks with `AcquireRandomTarget 0x431b70`.

Alliances and shared vision come from `InitAlliancesAndVision 0x477610` (`game/simulation/start.lua`): every player allied with itself and with player 11, computers with each other (value 2), rescuable and neutral players with everyone, then each force's alliance and vision among its human players; a slot's force is its FORC entry plus one, 0 for empty slots. The initial states of all 64 missions also equal the original in these fields and in the step counters (category `step`).

**Status:** `tests/scenarios/idle_marines.json` (five Marines and an SCV of the human player) equals the original at all 61 dumped steps and `marine_commands.json` (the same units; the player box-selects the Marines, orders Stop, then Hold Position) at all 91 steps, in every compared field (`tests/golden/oracle/scenarios/`). The campaign missions stop at step 2 on contracts of later items: 59 at the AI (resource areas `0x497a20`/`0x496c80`, region updates of computer players `0x4b0ce0`), the others at subunits and orders of later items (see Movement and paths).

Contracts the scenarios do not reach raise with their native address, among them: every order other than Guard, PlayerGuard, Nothing, Stop, Hold Position and Move; queued (shift) commands (`0x429650`); dead units in a selection; moving a blocked unit to a legal spot (`0x42ce60`) and the movement states listed under Movement and paths; scoring an attack candidate (`0x41fe60`, `0x48d2e0`, `0x4319d0`) and issuing the attack (`0x4202c0`); dying, hidden and subunit updates; the cloak list upkeep; Protoss power; spell timer expiries; computer players' AI; triggers, countdown timers and leaderboards; all game commands but sync, select, right click, Stop and Hold Position.

## Movement and paths (3.3, 3.4)

The right click on the map runs `ExecuteRightClickCommand 0x47f680` (`game/simulation/commands.lua`): the formation of the selection around the point (`ComputeGroupMoveFormation 0x49c300`, `GetFormationPointForUnit 0x49c5a0`, `game/units/formation.lua`), and for ground units a destination their box fits (one unit: `AdjustUnitMoveDestination 0x42c8c0`; a group: the square of its area, `AdjustGroupMoveDestination 0x42c930` with `IsBoxPlacementLegal 0x42ec70`; both through `0x42c9a0`: the point's region or the reachable region nearest to it, `SnapGoalIntoRegion 0x492a90`, `FindFootprintFitNearPoint 0x492c00`). The right-click handler gives Move (`0x47ef50`); the order (`OrderMove 0x428660`) sets the move target, and the movement states take over (`game/units/movement.lua`): StartPath (17), FollowPath (25), ScoutPath (26), arrival (11), AtRest (9) and the dispatcher's inline states 18, 21, 22 and 27.

Paths (`game/pathing/`):
- `pool.lua`: the 1024 records of 128 bytes (`CreatePathPool 0x48f000`), kept byte for byte because records are reused without clearing; allocation, release, retry timer, stale flag;
- `regions.lua`: the region graph of RGNS as native-shaped arrays and `SearchRegionPath 0x491300` (350-node arena, 125 open nodes, the sentinel heap, reversal for different groups, the 50-region source-side prefix);
- `local_search.lua`: `LocalPathSearch 0x491f50` with its geometry context `0x69d930`: the 64-pixel window, the terrain contours and blocking units' edges copied to local arrays (`0x488600`, `0x488910`, `0x488f00`), the nearest edges (`0x48c5e0`, `0x48c4e0`, `0x48c300`, `0x48c400`), the four quadrant generators (`0x489880`, `0x48a240`, `0x489d50`, `0x489360`; each has its own loop rules) and the swept areas (`0x492de0`, `0x4930b0`);
- `heap.lua`: the heaps of both searches (same code over different priority fields);
- `route.lua`: the search context of `NextPathPoint 0x48ec50`, `InitUnitPathSearch 0x491210`, `BuildLocalPathSegment 0x491c10`, `ContinueLocalPath 0x4919b0`, packing (`0x48e730`, `0x42c840`), `SetDirectPath 0x48ef10`, `CanKeepCurrentWaypoint 0x48ee40`, `AdvancePathWaypoint 0x48eb90`.

The flingy step (`game/units/flingy_move.lua`): `PrepareFlingyMovement 0x40bcd0` (desired direction, velocity turn, speed, walking switches, next position into the step globals `0x543280..0x5432fb`), `CommitFlingyMovement 0x40bdb0` (heading turn, sprite move and facing, walking animations) and `CommitUnitMovement 0x42ab10`. The slope table `0x502eb0` of `SlopeToDirectionOffset 0x40b940` has no closed formula and is kept as data (`game/data/directions.lua`). Collisions (`game/units/collision.lua`): the units a step sweeps (`0x4217f0`), the first that blocks it (`0x42d900`), the unit's safe rectangle (+0x108..+0x10e, `ContractSafeRect 0x48b9e0`) and the contour sweep (`0x48bec0`). Blocked steps go to the collision states (`game/units/movement.lua`): FixCollision (28, `0x42b3b0`: the blocker's touch of the destination or waypoint, its heading, the cardinal side `0x42cc70`, the slide direction `0x42dc70` with `IsPositionBlocked 0x42eab0`), WaitFree (29), FaceTarget (20), the re-path states 19, 23 and 24 (the blocker or every unit as an obstacle of the local search, `0x69b57c`/`0x69b578`), GetFree (30), SlidePrep (31) and SlideFree (32); the path record keeps the blocker, the step speed and the slide direction. ScoutPath compares the forecast positions 30 steps ahead (`ForecastPositions 0x42e6c0`: a unit moved by its IScript runs a copy of its script in the no-op mode) of the unit and its moving neighbours (`0x42e1c0`, `0x421dc0`).

A step that crosses terrain goes to TerrainBlocked (34, `0x42b700`): the step is retried at the path's speed, and while it stays blocked the unit stops walking, turns to its waypoint and stores the slide side in the path record (`GetTerrainSlideDirection 0x42db60`, which shares the side and quadrant table of `0x42dc70`; the sweep `0x42da50` takes an offset). TerrainSlide (35, `0x42c470`) steps in that direction with the facing kept (`PrepareMovementWithDirection 0x40bbc0`) and resumes the path once a step towards the waypoint is clear; anything in the way of a slide ends it in ForceMoveFree (33, `0x42bb00`: a new path unless the unit is at its target).

Flyers move in Fly (7, `0x42b7f0`): the move target and the prepared position stay inside the map by the unit's extents (`0x42aa60`), and the air repulsion (`game/units/repulse.lua`) drifts a flyer that shares its 48-pixel cell with others along its repulse angle (`ApplyAirRepulsion 0x481880`; the angle follows the jittered direction of the target, `0x4814e0` with the table of `0x4816f0`, and turns back near the map edges, which also clears the unit's repulse profile); after the commit the flyer changes cell (`0x481830`, `0x481760`) and a drift close to the target becomes the target (`0x4815d0`). Units that can only turn (status 0x10000) turn in place in state 5 (inline in the dispatcher: `0x40cf50`, `0x40d110`, `0x40bee0`); state 4, for units inside a building, also skips the vision refresh. A ground unit that cannot move settles (state 2) or steps to its move target in Route (14, `0x42be10`). The status bits 0x20000 and 0x10000 mean "can move" and "can turn", not ground and air.

**Subunits.** After its movement a completed unit moves its subunit (`PrepareUnitMovement 0x43a5f0`): the subunit turns by its base's turn of the step or, once both face the same way and it has no target, takes its base's heading (status 0x2000000, `0x43a800`); a Goliath turret stays within 0x20 of its base's heading (`0x40ba90`); the subunit takes its base's exact position (`0x40cc00`) and the special LO point 0 of the base's frame as its image offset, switches its walking animations with its base (status 0x1000000), then runs its own movement with itself as the current unit: state 3 (`0x42c610`) keeps the move target at the sprite and turns unless aligned. `UpdateUnit 0x43a720` runs the subunit's timers, orders and sprite inside its base's, as the current unit; the turret's TurretGuard (`0x41f300`) faces its base's facing waypoint and guards. `tank_goliath.json` (a Siege Tank and a Goliath sent east and back west) equals the original at all 151 steps.

**Map units' orders.** Critter (`0x427ed0`: random points 32 pixels away on RNG source 48, pauses on source 47), Trap (`0x428490`: hidden, cloaked, looking for prey every 15 steps), TowerGuard (`0x41f090`), Neutral (`0x48cfb0`), Burrowed (`0x43c810`) and RescuePassive (`0x48d120`): a human player's unit within 64 pixels rescues the unit (a complete resource depot brings every unit of its player) through `ChangeUnitOwner 0x426ed0` (`game/units/owner.lua`: AI removal, counts, the player lists, the selection circle, targets that are no longer enemies `0x41dd40`, AI admission `0x4b1fe0`, the subunit, speed upgrades), and the rescued unit's circle flashes (`0x446b30`, `FlashSelectionCircle 0x43a580`). A unit the local player loses sight of leaves the local selection (`0x4a7b80`) and drops its circle; a building or map doodad leaves a fog-of-war ghost: a clone of its sprite without health bar and circle (`CreateFogThingy 0x417b10`, `CloneSprite 0x415c00`) in the second thingy pool, removed once the local player sees a tile of its placement box (`0x418c20`, `0x418eb0`). `neutral_idle.json` (a Rhynadon, a floor trap and a Missile Turret) and `rescue_fog.json` (a Marine rescues two Marines and walks away from a neutral Supply Depot) equal the original at all 151 steps.
