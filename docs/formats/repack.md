# The repack (`koprulu*.mpq`)

[ADR 0018](../adr/0018-original-data-at-run-time.md), stage D8. `kp_convert repack` (`native/kp_convert/kp_repack.c`, since ADR 0019's stage C1; before it `python3 -m converter repack`) writes the files the game reads from an install, in their original formats, into MPQ archives; `kp_res` (`native/kp_app/kp_res.c`) reads them before an install in `--data`.

## The archives

MPQ version 1, written by StormLib, with a `(listfile)` and no `(attributes)` (StormLib reads and writes its 64-bit file times at unaligned addresses). Each file is compressed with zlib on its own, except an Ogg Vorbis and a movie (WebM), which are stored as they are.

| File | Holds |
|---|---|
| `koprulu.mpq` | everything but the groups read by ranges (the cinematics, the HD sets, the interface, the portraits) and the languages (`--single`: the computers' bundles) |
| `koprulu-core.mpq` | what the program reads when it starts: the DAT, the scripts, the interface, the fonts, the palettes, the tilesets, every GRP (grpmeta reads their frames), every portrait, the sounds |
| `koprulu-<campaign>-<mission>.mpq` | a mission directory's files, `campaign\<campaign>\<mission>\` (its CHK and speech): 68 |
| `koprulu-music.mpq` | `music\` |
| `koprulu-cinematics.mpq` | `sd/smk/`: the SD set by Remastered's names (`SD/smk/<name>.webm`, ADR 0019, stage C4): StarCraft: Remastered's WebM as they are (status `remastered`), or the 1.17 install's 28 Smacker movies transcoded into WebM (status `converted`, below); apart from `koprulu.mpq` with `--single` too, read by ranges |
| `koprulu-cinematics-hd2.mpq` | `hd2/smk/`: Remastered's HD2 set as it is; apart and read by ranges as the SD set |
| `koprulu-<set>.mpq` | `koprulu/<set>/`: an HD set of StarCraft: Remastered's art (ADR 0019, stage C5), its containers as the converter wrote them: each SD pack's `HDPK` (`packs/<pack>.kpd`), each tileset's `HDTS` (`tilesets/<name>.kpd`), the water's `HDWA` (`water.kpd`), status `converted`; `hd2` and `hd` in BC, `hd2-astc` and `hd2-etc2` transcoded for phones (below); apart from `koprulu.mpq` with `--single` too, read by ranges. The core holds each pack's head (`koprulu/heads/<set>/<pack>.kpd`) |
| `koprulu-ui-<variant>.mpq` | `koprulu/ui/<variant>.kpd`: a variant's HD interface (ADR 0019, stage C6), its `ui.kpd` (`HDUI`) laid out from a Remastered install by the placement table ([HD art](packs.md)), status `converted`; one per variant of the HD sets asked (`hd2-astc` and `hd2-etc2` take `hd2`'s); apart with `--single` too, read by ranges, its names under no prefix. The core holds its head (`koprulu/heads/ui/<variant>.kpd`, its bytes up to `FRMS`'s end) |
| `koprulu-portraits.mpq` | the HD portraits (stage C6): each portrait movie's WebM under Remastered's own name (`hd2/portrait/<unit>/<name>.webm`, else HD's `portrait/…`), with any HD set; apart with `--single` too, read by ranges, its names under no prefix. From any Remastered install with HD2 the core holds the consoles' art, `koprulu/console.kpd` (`CONW`, compressed) |
| `koprulu-locale-<loc>.mpq` | `locales/<loc>/`: a language from StarCraft: Remastered (ADR 0019, stages C2 and C3), by its CASC names: the files its text is built from (the XML strings, the glue's `rez/*.txt`, the subtitles' `.srt`: exactly the names `kp_locale_names` records the runtime reading), each campaign mission's map (`Assets/campaign/<c>/<m>/staredit/scenario.chk`: its strings, and its triggers' TIME the mission takes), its spoken lines (the mission's WAV strings' paths, `.ogg`) and the unit voices (sfxdata's paths, `.wav`); apart from `koprulu.mpq` with `--single` too; one per language the install holds, or those `--locales` names (`none`: no language). From Remastered the core holds its TrueType fonts (`font/EUROSTILE-REG.TTF`, `font/EUROSTILEEXT-REG.TTF`), which the languages' glyphs are drawn from |

A group with no file is not written. `--out` defaults to `generated/repack`, with `--single` to `generated/repack-single`: the folders a bundle stages (`tools/product.sh`, under its data's `generated/`) and the app looks in when no `--data` names a source. A bundle carries the cinematics' groups `KOPRULU_CINEMATICS` picks (`auto`: HD2 where the repack has it, else SD), and the HD sets of its platform the repack holds (the web `hd2`, a phone `hd2-astc` or, with `KOPRULU_PHONE_BLOCKS=etc2`, `hd2-etc2`, a computer `hd2` and `hd`) with their variants' interface groups and the portraits' group. The files are the input manifest's (`defs/scr/inputs-<profile>.json`) but its absent names, in its sorted order, then the 1.17 cinematics, then the names a `--res-log` of a run read unlisted, then Remastered's movies (both sets) and the base's subtitles the install holds (`locales/enus/assets/smk/<name>.srt`, in the core), then each language's texts and speech; a file the source lacks, or holds a damaged copy of (one StormLib cannot read whole), is left out and reported. A language's file the install lacks or holds empty (Remastered's silent stand-ins) is left out and counted: the game plays the base's there. The report gives a line for each group, `<file>: N files, A MB (B MB of files)`: the archive's size on the disk, then its files' before the archive's compression. The web lays every group but the core beside its page: a mission's, the music's and a language's are fetched whole when wanted (a language's when it is the start's or chosen in the main menu), the ranged ones by their ranges.

## The listing `(koprulu)`

Each archive holds one, in UTF-8, a line each:

```
koprulu repack 4
profile <profile id>
source <1.17|remastered>
group <file> <prefix>
in <file> <offset> <sha256> <size> <status> <name>
<sha256> <size> <status> <name>
<sha256> <size> <status> ogg <wav sha256> <wav size> <wav header> <name>
```

Version 3 (stage C2) added the `remastered` status and the language groups; version 4 (stage C4) the `in` lines, the
`converted` status and the movies' sets; stage C5 the HD sets' groups and stage C6 the interface's and portraits' groups, in the same version. `kp_res` refuses an older version, and the app then reads the install
(`make repack` writes the repack again).
A language group of stage C2 holds no texts: the language's text then stays the base's, with one line in the log
(`make repack` writes it again).

- `group` lines are the core's only: a group's file and the normalized prefix of its names (lower case, `/`). `kp_res` adds a group lying beside the core when it opens it; `kp_res_group_wanted` names the group of a name while it is not open (the web fetches it, then `kp_res_add_repack`).
- `in` lines are the core's only: a file of a group read by ranges (the movies' groups, the HD sets', the interface's and the portraits'), the group's file and the offset of its bytes there (stored as they are, so that the bytes are the file), then the file's line. `kp_res_raw_range` names a file's group and range while that group is not open: the web fetches a movie alone, an HD page's layers, an interface frame or a portrait's clip alone, by an HTTP Range request on the group beside the page (`kp_app_cine.c`, `kp_app_hd.c`, `kp_app_hd_ui.c`). A computer or a phone opens every group it carries at start, and reads the movie and the portraits through StormLib, the HD pages and interface frames through a reader of their own (`kp_res_raw_place`, `kp_res_reader_read`). A group whose names have no prefix (the interface's, the portraits') is not fetched whole: `kp_res_group_wanted` names none of them.
- `<sha256>` and `<size>` are the stored bytes'. `<status>` is the source's: `exact`, `derived`, `differs`, `equivalent`, `colour-equal`, `approximation` (Remastered's statuses, `tools/research/scdata/casc/source.py`), `unlisted` (a name the manifest does not hold), or `remastered`: a file of StarCraft: Remastered's own by its CASC name, which no manifest lists (a language's texts and speech, the TrueType fonts, the movies), or `converted`: the converter's own of an install's file, stored by a Remastered name (a 1.17 movie as WebM). `<name>` is the source's spelling, `\` separated; a `remastered` file's is its CASC name normalized (lower case, `/`). `kp_res_raw_read`, `kp_res_raw_head` and `kp_res_raw_files` read the `remastered` files by their CASC names, a repack's copy before the install's (its size checked, a CHK's SHA-256 too), and `kp_res_raw_held` tells whether either has one.
- `ogg`: a WAV stored as Ogg Vorbis (libvorbisenc at `-q 3`, the CRC-32 of the normalized name as the stream's serial; the bytes can differ from build to build, what they decode to cannot beyond the encoder's rounding: macOS's clang and Linux's or Windows's GCC write different bytes for most files, GCC on Linux arm64 and on Windows x86-64 for a few, and `-ffp-contract=off` on macOS does not remove it; the decoded sound is as good on each), done only when the Ogg is smaller and the WAV's header, up to its data chunk, fits in 4,096 bytes. The WAV's digest, size and header (hexadecimal) follow: `kp_res_head` answers them for the WAV (the game computes the sounds' durations from the header), `kp_res_read` gives the Ogg (SDL3_mixer tells the formats apart by their bytes).
- A language's speech is encoded by `kp_ogg_speech`: mono (the channels averaged), a 44,100 Hz sound halved to 22,050 Hz (a 65-tap Blackman-windowed sinc), the same quality and serial; a line (Remastered's Ogg Vorbis, decoded by libvorbis) is replaced by its Ogg when that is smaller, a voice (a WAV: 16- or 24-bit, Remastered's deDE keeps a few at 24) kept as `ogg` with its WAV's header, so that the interface's talking durations stay the original's. The encoded files are kept in the cache as `<sha256>-q3-s<serial>-speech.ogg`.

- An HD set (`--hd LIST`; from a Remastered install the default is the BC variants it holds, `hd2` and `hd`; `none`: no set) is built by the runtime's own code (`kp_hd_pack_build`, `kp_hd_scr_tileset`, `kp_hd_scr_water`): equal to what `python3 -m converter hd` wrote before stage C5, byte for byte (`test_hd.repack_equals_the_converters`). A phone's set transcodes them (`kp_hd_transcode.c`): a pack's pages into ETC2 and EAC (`hd2-etc2`) or ASTC (`hd2-astc`, built with `KP_ASTC`), the tiles and the water's normal maps into ETC2 for both; each container kept in the cache as `<BC sha256>-<etc2|astc>-t2.kpd` (`KP_HD_TRANSCODE_SETTINGS`; `t2` since the ASTC encoder is built invariant, `kp_astcenc.cmake`: with a patch filling its angle tables in double precision, so that macOS, Linux and Windows write the same `hd2-astc` set byte for byte, as the BC and ETC2 sets). Each pack's head (its bytes up to its frames' end, `kp_hd_pack_head_size`) goes into the core too: the runtime opens a pack from it, the web before it fetches any page. HD2 in BC is 648.8 MB, HD 2,449.4 MB, `hd2-etc2` 606.9 MB, `hd2-astc` 545.4 MB.
- The HD interface (stage C6, from a Remastered install): for each variant of the HD sets asked its `ui.kpd` (`kp_hd_ui_scr_build`, `kp_hd_ui_pack`: equal to what `python3 -m converter hd` wrote before stage C6, byte for byte, `test_hd.repack_ui_equals_the_converters`), HD2's 35.9 MB and HD's 144.0 MB, and its head in the core; with any HD set the 621 portraits' WebM (72.8 MB); from any Remastered install with HD2 the consoles' art (`kp_hd_ui_scr_console`, 892 KB). The report's line: `the HD interface: N variants' ui.kpd, M portraits, the consoles' art`.
- A 1.17 movie (`smk\<name>.smk`, checked against `defs/campaign/cinematics.json`'s size and SHA-256) is stored as `sd/smk/<name>.webm` (`kp_movie.c`): the frames kp_cine's player decodes as VP9 profile 1, 4:4:4 sRGB (the palette's colours as G, B, R planes, without loss before the encoder) at the movie's own size and exact frame rate, constant quality 32 at `--cpu-used 2`, a key frame at least every 128 frames, one thread; the first sound track as Vorbis at `-q 3` (libvorbisenc); written by `kp_webm_write.c` and read back by the player's reader (nestegg) before it is kept: its packets and its sound's length as written. Each is kept in the cache as `<smk sha256>-<KP_MOVIE_SETTINGS>.webm`; the 28 take a few minutes on a laptop's cores, the cache makes a second run quick. The movies are 1.17's own frames: no subtitles (the 1.17 install has none).

## Android: the groups read in place

An Android bundle carries its groups in the APK's assets, `generated/repack/` (`tools/product.sh`), stored uncompressed (`tools/native/android_app.sh`'s `noCompress`). The app reads them in place (`kp_app_files.c` `apk_repack_file`, `KpResConfig.repack_file`): `AAsset_openFileDescriptor64` gives a group as the APK's descriptor, the group's offset and its length, and StormLib opens the archive by the name `fd:N:OFFSET:LENGTH` (`kp_mpq_slice_name`; its POSIX file streams patched for that, `tools/toolchain/patches/StormLib-9.40/`), through a descriptor of its own (`dup`) read with `pread`. The core is asked for first, then each group its listing names; a group the APK does not hold (a cinematics' set the bundle left out) is not open. A group stored compressed is refused with its name: the core then leaves no repack. Until 2026-11-11 the app copied the groups out of the APK into its preference path (`repack.txt`, its SHA-256 checked on the copy): 140 MB more on the phone.

## Checks

`kp_res` refuses another magic, another profile or no profile line (the install is read instead), before any line of the listing applies: a listing refused adds neither its files nor the groups it names. A blank line is skipped. A file listed `exact` or `derived` whose digest (an Ogg's: its WAV's) and size are not the manifest's is dropped from the table and logged, and the install's copy is read; a file's size is checked against its listing when read, and a file the simulation is built from (`simulation_input`: the DAT tables, the scripts and dialog BINs, CHK, CV5, VF4, GRP, LO, TBL) its SHA-256 too; a copy that differs is read from the install. A file that only shows or plays (sounds, music, pictures, movies) is taken by its size: the converter wrote the repack from files it checked, Android's groups are read from its signed APK (above), the web fetches a group whole. The listing is all that vouches for a file of another status (Remastered's rebuilds): nothing else holds its digest. A line that is not a file's is counted and logged.
