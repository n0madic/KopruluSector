# Phase 5 progress

Plan: `IMPLEMENTATION_PLAN.md` §7 phase 5 (CHK triggers). Started 2026-10-17, after the user approved the design (inline design document, 2026-10-17):
- the state of the trigger engine lives in the native game (`KpTriggers` in `KpGame`, `native/kp_core/src/core/kp_triggers.c`): each copy of a TRIG record that the owner expansion makes keeps its whole 2400-byte record, as the original's node does (its execution flags, continuation byte and action flags change in place), with the eight player lists, the waits, switches, countdown, pending results, objectives, locations, the leaderboard and the unit-count cache of Command and Bring; the copies are allocated at the start, the save format stays version 1 and grows with them;
- the frame stays strictly sequential in the original's order: the object step, then the trigger scheduler with the game RNG on; a paused game runs its turn, the selection flashes and the scheduler only (`RunPendingFrames 0x444e30`, `kp_paused_tick`);
- what the interface decides comes in as commands of the presentation: the end of a transmission's portrait or of a camera pan (`kp_trigger_release_wait`, `0x4be3a0`), the Escape skip (`kp_trigger_skip`, `0x4bda80`) and the briefing's objectives before the game (`kp_briefing_objectives`, MBRF action 4 `0x44fdc0`);
- the actions' texts, sounds, portraits, pings, camera pans and pauses go to the presentation as events (`KP_EVENT_TRIGGER_TEXT` … `KP_EVENT_TRIGGER_SKIP`), with string ids the presentation resolves in the mission's STR;
- conditions and actions that are not ported yet fail with their handler's address; those outside the V1 profile, which no campaign map reaches (Opponents, Modify Unit Resource Amount, Modify Unit Hangar Count), the converter rejects as well (`converter/analyze/triggers.py UNSUPPORTED_CONDITIONS`, `UNSUPPORTED_ACTIONS`; a TODO until a map that needs them comes into scope).

**Design corrections (2026-10-17).**
- Run AI Script (actions 15, 16) fails with its address (`0x493970`) instead of making the script's thread record: launching a script (`0x494d90`) belongs to the AIScript VM of plan phase 7, and the AI step after it would fail at once.
- A building a trigger makes (`CreateUnitWithPlacementCheck 0x4261f0`) or moves (`MoveGroundedBuilding 0x4b7810`) needs the grounded placement validator `0x412e20` (`0x412560`, `0x412360`) that construction shares: it comes with plan phase 6; until then such an action fails with the address. So do the creep of a Zerg building made by a trigger (`0x4c0790`, `0x43c220`) and a given building that trains, researches or upgrades, or a hangar unit with queued fighters (their refunds, `0x41b5c0`, `0x43ab80`, `0x43abe0`). TriggerGiveUnit `0x4b81a0` (`kp_give_unit_checked`, shared with Mind Control) gives what belongs to a unit with it: the worker inside a gas building, the cargo (`0x437da0`), the hangar's children (`0x41ca90`), the add-on, the add-on under construction and a Nydus Canal's exit.

## Oracle

**The trigger state in the dumps.** The emulator dumps the nodes of the eight player lists (`0x50e0d8`, a player byte and the 2400-byte record per node). The category `trigger` gives each copy by its place in its player's list (`p.k`): the execution flags, the continuation byte and the CRC-32 of the whole record (its action flags included). `triggers` holds the current player `0x6ca754`, the trigger pause `0x6ca740`, the game's pause `0x67517c`, the game speed `0x6d3130`, the waits, pending and committed results, participants, objectives, switches, the countdown and its pause, quiet mode `0x667280`, the next scenario `0x526526` and the leaderboard; `trigger_counts` the unit-count cache (key, location and the CRC-32s of its three tables); `location` the MRGN records that are not zero; `resources` the players' current and cumulative minerals and gas.

**The trigger trace.** `triggers.jsonl` logs each action the runner dispatches (`0x4bdf72`, the result at `0x4bdf74`): the frame, the current player, the trigger's place in that player's list, the action index and type and the handler's result. Koprulu emits the same as `KP_EVENT_TRIGGER` in a game started with the option `trace` (`oracle.start_mission(…, { trace = true })`; the place of each copy is fixed at the owner expansion), never in play; `tools/state_check.py` compares the two up to the last compared step, and the scenario goldens keep the trace for `tests/lua/test_scenarios.lua`.

**The interface's part.** A transmission's portrait timer and a camera pan end on the interface's clock: the emulator logs each call of `0x4be3a0` (`release`) and Koprulu replays it at the same place. So are the frames of a paused game (`paused`: `0x444de0`, where `RunPendingFrames` runs the turn, the flashes and the triggers without the frame count), the Escape skip and the briefing's objectives, which the ready room sets before the game (the emulator presses Start at once, so the briefing's first Set Mission Objectives is the one that counts). The oracle's runner takes the log's leading `objectives` before step 1 (once: a run continued after a load does not take them again) and any later one at its frame; the mission manager takes them as `opts.objectives` before its prime, and without them the ones the briefing's first tick sets (`kp_briefing_lead`: the first record of the local player's briefing list with Mission Briefing as its first condition, up to its first Wait or Transmission; equal to the original's for all 64 missions in `tests/lua/test_initial_state.lua`), as when the player presses Start at once.

**Game speed.** The waits count down by the milliseconds of a frame at the game speed (`0x503360[0x6d3130]`). The emulator runs at speed 4 (Fast, 56 ms), the original's speed without a saved setting; a game starts with it (`KP_DEFAULT_SPEED`) unless its start input (`speed`, the option of `kp_core.game.new`) names another; the mission manager starts the game at the player's speed, sets it again when the player changes it (`g.speed`) and keeps it over a load (the save carries the speed byte with the other scalars).

**The mission index.** The Escape skip works in the original campaigns only (`0x526524` < 32); a game starts with the index of its start input (`mission_index`, the option of `kp_core.game.new`; 0, a custom map, without it): `tools/lua/oracle.lua mission_index` from `generated/missions/index.txt` and, for a scenario, its base in `generated/scenarios/index.txt`, the replays' `index` line, the viewer's mission list through the mission manager's `mission_index`.

**A result over a paused game.** The result dialog pauses a single-player game; the emulator's run then makes no further object step and so no further dump, and its scenario stops at its wall-clock limit (the runner was stopped by hand for `trigger_outcome`). The goldens keep the interface events before the last compared step only.

**The resources and the triggers' categories.** The players' minerals and gas have a category of their own (`resources`), like the trigger categories, so the goldens of the scenarios before phase 5 stay valid; the initial-state goldens were rewritten with them (all 64 missions equal, their trigger copies and locations included) and carry the briefing's objectives.

**Campaign runs.** `python -m sc_emulator mission NAME WARP --frames 2000 --state 1-2001 --out-root …/emu/campaign` dumps every step of an idle mission with the logs Koprulu replays; `tools/state_check.py --kind runs --step 1-2001/20 --write-golden` (the dumps of `…/emu/campaign`) writes `tests/golden/oracle/runs/<run>.lua`, which `tests/lua/test_scenarios.lua` checks like the scenarios.
