# StarCraft / Brood War: simulation algorithms for Defold

Research date: 9 October 2026. The target is a faithful remake of all six StarCraft and Brood War campaigns. Multiplayer and runtime replay playback are outside V1. The local reference executable is Windows PE StarCraft 1.17, file version **1.17.0.1**, SHA-256 `94dea44898a3934cdfae2a8149c0044db8ad1af4b4bc54306cdca3b1612d6ed0`.

## Findings

- OpenBW provides a detailed executable model of most simulation mechanisms. The source reference is pinned to commit `4b046d5f65302b10cb0a745f0fecd37ec85b20a8`.
- GPTP contains reconstructed algorithms and original **1.16.1** function anchors for orders, combat, damage, harvesting, construction, abilities, and unit state updates. Its pinned commit is `ce321f0fa83174aee741b91f1b2eaec30300773e`.
- BWAPI, pinned to commit `d727fed68558c506163048ea889131d8cbb33915`, provides original engine structures, a game API, and a basis for frame-by-frame observation of its supported original version, 1.16.1.
- **The local 1.17 PRNG is statically confirmed** in [Native PRNG](native-prng.md). A limited set of native 1.17 AIScript dispatcher and wait-handler witnesses is documented in [Native AI](native-ai.md). These are static findings from the exact local PE, without executing the original. The remaining algorithms below are reference implementations or reconstructed 1.16.1 behavior; they are not verified native 1.17 behavior.
- OpenBW has substantial gaps that affect campaigns. `ComputerAI`, `AtkMoveEP`, `HarassMove`, `AIPatrol`, `GuardPost`, `RescuePassive`, `ComputerReturn`, and some door/trap orders call `error()`. Powerup, carrying, trigger, and score paths contain `fixme` or `todo`. OpenBW therefore does not provide a complete engine for all campaigns.
- OpenBW and GPTP disagree on several rules, particularly target priorities, AI-specific seek range, and Scourge target selection. Existing code reduces the amount of reverse engineering needed, but cannot replace original-game validation.

## Evidence boundaries

In the tables, “established” means **established by reading the named source**, unless explicitly marked `native-static 1.17`. These findings support a candidate specification and a discriminating probe: a test that distinguishes competing explanations. They do not establish complete parity with the original.

GPTP is a modifiable plugin template, rather than published Blizzard source. Its files contain alternate functions under `EVENTS_SYSTEM`, added callbacks, comments claiming “identical” or “equivalent” behavior, and calls to native helpers whose implementations have not been reconstructed. A branch containing callbacks cannot automatically be treated as original semantics. BWAPI provides access to the original and an environment for external bots; bot algorithms must not be attributed to the built-in AI. OpenBW is a separate implementation. Agreement between two projects strengthens a hypothesis, but both may have used the same reverse-engineering source.

**GPTP/BWAPI 1.16.1 addresses must not be transferred to 1.17 without validation.** Matching version strings, DAT files, or function names do not establish compatible addresses or layouts. Validation requires byte and disassembly anchors, callers, calling conventions, argument layouts, and state deltas for the exact local PE. No retail execution or DLL injection was performed for these findings.

**Lua numerical trap:** direct `state * 22695477 + 1` in IEEE double precision exceeds the 53-bit significand's exact integer range. For `state=0xffffffff`, the exact next state is `4272271820`, while floating-point arithmetic gives `4272271824`. This is a derived arithmetic vector from the confirmed recurrence, rather than output from an executed original. Use 16-bit limbs or native uint32 multiplication with wraparound. `math.randomseed` and checks using only small initial seeds are insufficient. Range multiplication must also reproduce native low-32-bit and logical-shift behavior if broad ranges are possible. See [static JSON evidence](evidence/prng-static.json) and [Native PRNG](native-prng.md).

## 3. Pathfinding, collision, and movement

This independently supports the broad structure; exact path, node, and timer rules still require source analysis and original-game probes. ## 6. Campaign-specific gaps in OpenBW

The pinned OpenBW dispatcher contains hard errors for computer AI, attack/harass/guardpost/computerreturn/rescue, and several door/trap orders. `drop_carried_items` contains a `fixme`; trigger predicates and kill/remove paths for powerups contain `fixme`; `on_unit_damage` and death paths contain score-related `todo` entries. These gaps directly affect rescue units, interior doors/traps, powerup/artifact delivery, and mission score conditions. Each requires separate reconstruction. See the [dispatcher](https://github.com/OpenBW/openbw/blob/4b046d5f65302b10cb0a745f0fecd37ec85b20a8/bwgame.h#L8079), [powerup paths](https://github.com/OpenBW/openbw/blob/4b046d5f65302b10cb0a745f0fecd37ec85b20a8/bwgame.h#L2212), and [trigger predicate](https://github.com/OpenBW/openbw/blob/4b046d5f65302b10cb0a745f0fecd37ec85b20a8/bwgame.h#L19014).

Candidate probes:

1. Proximity-based rescue ownership: same-frame death, detection, and order queue; hero restrictions; all units of the rescuable owner versus only the touched unit.
2. Interior doors/traps: Disable/Enable doodad-state commands; original `HiddenGun`, OpenDoor, CloseDoor, HideTrap, and RevealTrap order transitions; the frame of visibility and walk-map updates.
3. Powerups: attach, carry, drop, worker death, transport, load, and delivery; whether exact CHK `Bring` conditions count attached and ground powerups differently.
4. Kill/loss/razing/custom scores: simultaneous kills with a dead source, projectile parent, Hallucination, Spawn Broodlings, Consume, or Mind Control; same-frame trigger evaluation.
5. Mission state without cheats: campaign availability/restrictions and mapped hero statistics in CHK; mission scripts launching AI versus ordinary player orders.

The campaign trigger scheduler, AI script VM, and strategic military/town AI require separate specifications. They connect to simulation through observable orders, units, and regions; a successful external-bot game does not establish their behavior. [Native AI](native-ai.md) records the available native-static 1.17 AIScript witnesses, with their narrow limits.

## 7. Minimum trace contract and validation order

Every probe needs the exact target SHA-256/version, MPQ/CHK/data hashes, map setup, seed/PRNG enabled state/source counters, and all initial units with slot/index/generation, owner/type, raw HP/shields/energy/status, position, and order. Each command must include its frame and payload. Record:

- Frame/phase and stable entity visit order.
- Raw exact position, velocity, and directions; sprite pixel position; movement/order targets; collision/path flags.
- Main/secondary orders, states, timers, queue contents, interruptibility, and `order_signal`.
- Raw HP/shields/energy/matrix/status timers; weapon cooldown/jitter; supply/resources/depot queue.
- Bullet parent/source/owner/target/position/state/lifetime/hit flags, plus emitted impact/damage events.
- Fog visible/explored and detected flags; region/path/waypoints; relevant creep/psi tiles.
- PRNG pre/post state and source identifier for **every** call, including iscript, construction, creep, larvae, and random sounds.

BWAPI integer `getHitPoints/getShields/getEnergy` observations lose fractional bits. HP and shields, in particular, are formed using `ceil(raw/256.0)` in [UnitUpdate.cpp](https://github.com/bwapi/bwapi/blob/d727fed68558c506163048ea889131d8cbb33915/bwapi/BWAPI/Source/BWAPI/UnitUpdate.cpp#L165). Proving raw arithmetic requires read-only access to correctly identified structures for the **target version**. The 1.16.1 CUnit layout is a comparison reference, rather than a ready 1.17 memory layout. Injecting BWAPI/GPTP 1.16.1 into 1.17 without compatibility validation would use unverified layouts and offsets.

The cheapest initial discriminating set is: one Marine attacking a Zergling with raw damage/cooldown/iscript traces; two Marines killing each other in the same frame with reversed creation order; one SCV and a mineral patch for the 75 service timer and deposit; a 1-pixel range/box sweep; a 12-worker choke with Stop-reset; human versus computer Scourge; and two overlapping Storms. After the first mismatch, vary one hypothesis and retain the first divergent frame. Video and playthroughs are needed later to verify player-visible campaigns, but cannot replace state traces.

## 8. Implications for Defold: design inferences

Use authoritative simulation in ordinary Lua modules/state tables with stable entity IDs and explicit phases. Rendering, input, UI, and audio should deliver commands and consume events/snapshots. Gameplay must not depend on the order of per-unit game-object, collision, or physics callbacks. Acceptance depends on matching traces rather than resembling the C++ architecture.

Implement fixed-point arithmetic, PRNG, and command/order semantics first. Rendering can interpolate position; the gameplay iscript VM must remain authoritative and produce attack/damage/order events in the required phases. Audio muting and offscreen culling must preserve the RNG schedule where native traces establish that dependency. Maintain a resource/system completeness matrix by campaign usage: prioritize mechanisms reached by the first playable mission slice while explicitly recording unimplemented or unknown orders.

Pathfinding must match observable behavior. Flow fields, modern navmeshes, and friendly collision avoidance can improve visual movement while changing AI arrival, mining throughput, attack-wave timing, and mission balance. Establish original probes, implement the smallest behavior they verify, then profile performance. A native extension for expensive pathfinding or arithmetic may be justified by measurements later; it is not a prerequisite for all Lua algorithms.

This report provides a concrete source/function map, known contradictions, native-static 1.17 PRNG findings, links to limited native-static AIScript witnesses, and discriminating probes. The full algorithms of local 1.17 and all campaign edge cases **have not been established by executing the original**.
