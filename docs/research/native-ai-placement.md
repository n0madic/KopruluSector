## Grid coordinates and initialization

The grid is **64 by 64 bytes**. A nonzero byte denotes a candidate; the covered filters preserve its value when retaining it. It is not a continuously weighted score map. Given the packed signed-16-bit pixel seed, base generation uses `trunc(seed_x/32)-32+column` and the corresponding y tile. Several later filters use pixel points `seed-1024+32*index` directly. Preserve these conversions at their native callers.

Base generator `0x495d40` receives `ECX=requested_ID`, `EDX=grid`, stack `[player, packed_seed, window_size]`. Its square window starts at unsigned `32-(window_size>>1)` and ends at start+size, with u32 arithmetic. It scans row first, column second within the 64-cell bounds. Ordinary size3 includes indexes31..33; size1 includes only32; size0 visits no candidate. Sizes64/65/66 and `ffffffff` are independently covered, including unsigned window behavior.

For each selected cell it calls actual shared validator `0x412f10` with null builder, output entry0, vision1, include-unseen0 and ignore-visibility0. Requested IDs **106,113,114,116** first require placement of Turret124 at `(tile_x+4,tile_y+1)`. A failed extra check skips the requested-building check. This reserves addon room with a specific surrogate footprint; replacing it with an arbitrary spacing radius changes the rule.

Success writes1. Failure and positions outside the window **do not clear an existing byte**. The pipeline `0x495bb0` first clears all4096 bytes with original `memset`. Stand-alone base probes deliberately prefill bytes to distinguish these responsibilities. All11 IDs106..116 are tested against a blocked addon-surrogate tile. The stock batch separately tests all96 IDs106..201 against plain, creep and blocked flags, with and without a supplied power source. Gas types reject with empty live/fog lists; this is a lookup result, not a hardcoded no-build classification.

## Mandatory filters and optional rollback

Connectivity filter `0x497630(ECX=grid, stack=[seed])` resolves the seed and each nonzero candidate through actual `0x481b10`, then reads connectivity group through `0x481c90`. A different group clears the byte. Equal groups preserve the byte, even when region IDs differ. The covered cases execute ordinary map-cell lookup; region generation and arbitrary connected-region route construction remain separate.

Neighbor filter `0x497910(ECX=requested_ID, EDX=grid, stack=[player,seed])` bypasses IDs106/131/154. Other types resolve each candidate's region and call `0x4ae700`. That helper reads the ground-neighbor pointer at `path+region*64+0x44a08` and count `u8(+0x44a03)-s8(+0x44a1d)`. It rejects when any listed neighboring AI region has state3, nonzero dword+0x1c, nonzero dword+0x20, or flag bit0x20. Empty neighbors pass. This predicate does not test the current region itself unless it appears in the supplied neighbor list. State, target fields and flag cases are exercised with the actual helper.

Radius filter `0x4976d0(ECX=grid, EDX=limit, stack=[seed])` clears a candidate when native path distance in tiles exceeds the **unsigned** limit. Same-region paths use approximate pixel distance divided toward zero by32. Different connectivity groups yield9999. Connected, different-region paths call long-path helper `0x491300`; [region paths](native-region-paths.md) subsequently recover that function and64 complete connected/unreachable/sub-tile radius calls. This filter retains the original seed's sub-tile offset when forming candidate pixel positions. [Worker probes](native-workers.md) separately cover same/disconnected distance branches.

Several later filters snapshot all4096 bytes, attempt exclusions, and **restore their entire input snapshot if no candidate remains**. They implement preferences that may be abandoned. Applying all such exclusions as permanent constraints changes the search. Each snapshot belongs to that filter's entry, after previous filters have already run.

- `0x498430`: keep only candidate points at the seed's terrain elevation through actual `0x445690`; restore if this erases every candidate. The original helper resolves current overlay/base tile, CV5 megatile and VF4 minitile elevation. A same-height alternative and an all-mismatching rollback are covered with actual terrain reads.
- `0x498820`: visit all in-map grid coordinates, including zero bytes. When tile predicate `0x413270(x,y,[0x10000,0])` fails, mask a1-by-1 object neighborhood with margin1 through actual `0x4960b0`. Restore on exhaustion. This recovers the literal bit consumer; terrain-flag generation is still required before assigning broader walkability semantics.
- `0x498230`: exclude resource/depot neighborhoods, described below; requested DAT Addon bit2 bypasses this filter.
- `0x497d90`: reserve room around existing addon-capable buildings, described below.
- Type-specific building, defense and Pylon filters have their own rollback rules below.

## Rectangle masking and existing-unit eligibility

Mask helper `0x4960b0` receives `ECX=object_width_tiles`, `EDX=object_height_tiles`, stack `[object_tile_x,object_tile_y,requested_ID,grid,seed,margin]`. Requested dimensions come from signed DAT placement pixels divided toward zero by32. In valid positive-size fixtures, its rectangle is:

```text
left = object_tile_x - floor(object_width/2) - requested_width - margin + 1
       - trunc(seed_x/32) + 32
top  = object_tile_y - floor(object_height/2) - requested_height - margin + 1
       - trunc(seed_y/32) + 32
width  = object_width  + requested_width  + 2*margin - 1
height = object_height + requested_height + 2*margin - 1
```

Clear in-grid positions of that rectangle. Unsigned comparisons exclude negative indexes after wrap. Twenty-seven calls distinguish object/request dimensions and margins0/1/2. Wrapper `0x4961a0` obtains the existing unit's sprite tile and dimensions, then invokes this original helper. Object dimensions, requested dimensions and collision borders must not be conflated.

Resource spacing `0x498230` walks the player's units through `0x4256f0` and next+0x6c. Inactive predicate `0x41fe40` rejects null sprites or primary Death0. A DAT ResourceContainer is eligible independently of completion/grounded status. A ResourceDepot additionally needs Grounded bit2 and either Completed bit1, type132/133, or type131 with native morph predicate `0x43c040` true. That morph predicate examines the real construction queue.

Eligible units are masked with margin2. Unless requested type is Bunker125, a second pass scans player11 and masks eligible ResourceContainers. No owner/visibility filter is added to this neutral pass beyond the supplied list and inactive predicate. Native cases distinguish completion, grounding, Hatchery morph queue, container/depot properties, the player11 pass, requested Bunker and full-exhaustion rollback.

Addon-space filter `0x497d90` walks active own units of types106/113/114/116. If the existing sprite is at tile delta `(dx,dy)` from the seed tile, it clears columns `dx+34` and `dx+35`, starting at row `dy+33` and proceeding upward for **requested_height_tiles+1** rows. It uses the requested building's height, not a generic existing-building bounding box. Out-of-grid positions skip. Restore the original grid if every candidate is removed.

## Building spacing and defense patterns

`0x497f00` combines list exclusions and an optional eight-neighbor erosion. Its complete existing/requested switch mappings are recorded as data in the static evidence.

- Existing types113/124/155/160/162 mask with margin2.
- Existing types111/125/143 use the unit wrapper with margin1.
- Other reviewed types111..162 add no exclusion through this switch.
- Requested types111/113/124/125/155/160/162 require each retained candidate to have all eight neighbors in bounds and nonzero in **the function-entry snapshot**. Neighbor tests do not read the progressively edited output grid. Other requested types skip erosion.

Restore the whole entry snapshot on exhaustion. All52 IDs111..162 are independently exercised in both switches. Eight missing-neighbor cases distinguish the erosion/rollback behavior. The pipeline has dedicated dispatch for Turret124, Bunker125 and ShieldBattery162, so those requested types do not necessarily invoke this general spacing filter even though its stand-alone switch supports them.

Defense filter `0x498600` walks active own units. Existing Turret124/Bunker125/ShieldBattery162 contribute only when matching the requested type; existing CreepColony143/Spore144/Sunken146 contribute through the colony branch without that equality test. Four EXE ASCII masks have sides **17,13,9,5**, respectively at `0x509120/0x509248/0x5092f8/0x50934c`. The static report preserves every character. Only `x` cells clear candidates.

The pattern origin uses `trunc((existing_pixel-seed_pixel)/32) + 31 - floor(side/2)`. Consequently a same-center object uses pattern center index **31**, not32. This shift is preserved in the probes. If a mask level erases all candidates, restore that invocation's snapshot and recursively try the next smaller level. Level3 restores without further recursion. Eight existing/requested combinations at all four levels and recursive-exhaustion fixtures execute these original branches.

Pylon coverage filter `0x498520` removes candidate pixel points for which actual power predicate `0x430000` succeeds using ShieldBattery162 as the requested DAT type. Restore on exhaustion. Its purpose in the Pylon search is to prefer extending uncovered territory. A powered point can therefore remain available when every candidate is already powered. Supplied list/mask tests distinguish no source, partial coverage and all-covered rollback; power-list maintenance is still independent.

## Pipeline order and final selection

`0x495bb0(ECX=requested_ID, EDX=grid, stack=[player,seed,size])` executes:

1. Clear grid; generate the base window.
2. Connectivity filter.
3. Neighbor-threat filter, except requested Pylon156.
4. Radius filter using size.
5. Return early if empty.
6. Elevation and tile-bit filters.
7. Resource spacing except IDs106/131/154.
8. Existing addon-space reservations.
9. Requested-type dispatch: Pylon156 coverage; Turret124/ShieldBattery162 defense masks; Bunker125 defense-anchor gate then masks when no anchor; CreepColony143 campaign gate and anchor before defense masks; other non-base types use general building spacing.

All51 IDs106..156 plus157/162 execute the connected pipeline with actual callees on a declared ordinary synthetic profile. Additional window cases cover sizes0/1/2/4/7. An absent runtime source list is still handled by the real native helper, rather than a substituted return.

Placement search `0x494fc0(ECX=builder, EDX=requested_ID, stack=[seed,out_position,size])` first attempts the fixed addon geometry for DAT Addon bit2. It uses parent placement half-size and requested addon offsets, validates the proposed addon tile with the real shared validator, then converts back to the proposed parent center. Failed validation falls through to ordinary search. Six stock addon/parent pairs cover success and blocked failure:107/106,108/106,115/114,117/116,118/116,120/113. Conversion preserves the actual integer rounding of parent half-size, including a96-pixel height.

Ordinary search normalizes requested107/108 to106,115 to114,117/118 to116,120 to113. It temporarily sets builder override `0x6a2e80` during grid construction and clears it afterward. Requested106/131/154 bypass the subsequent directional filter. Other selected branches retain their own switch behavior, including a Pylon recenter operation and optional defense-region anchor.

Directional filter `0x498930` clears13 fixed lines from the EXE table: column32,row32,column31,row31,column33,row33,column30,column29,row30,column28,row29,column27,row28. After each line it checks for any candidate; exhaustion restores **the entire pre-filter grid** and returns. These are not cumulative per-line rollback snapshots. The helper's seed argument is unused in the recovered body. Sparse, empty and seven-by-seven grid cases exercise the exact order and rollback.

The final search scans rows then columns. It computes native path distance from the selected anchor. It prefers candidates with distance<=size over candidates outside that threshold, then smaller distance within a category. Equality does not replace the previous candidate: the first in row-major traversal wins a tie. A failed defense-anchor search can make a second pass using the original seed anchor. The output is selected tile*32 plus the signed half placement size of the **normalized requested ID**. Search returns0 without writing an output on failure. Same-region complete searches, failures and zero/one-anchor cases execute the real distance helper; arbitrary connected routes and complete anchor production remain separate.

Defense-anchor selector `0x495480(ECX=player, EDX=out_region)` reads count `0x6a2e84` and region words at `0x6a5d70`. Count0 returns0 without writing; count1 writes the first region and returns1. For larger counts, obtain each original region center through `0x481a60`. Walk active own units of IDs **125 Bunker,143 CreepColony,146 SunkenColony**; Turret124, Spore144 and ShieldBattery162 do not contribute. For each anchor compute the **minimum** native distance from eligible existing defenses. Select the anchor with the **maximum** of those minima, keeping the first anchor on equality. With no eligible defense, all minima remain99999999 and the first anchor wins. Eighteen calls distinguish counts0/1/2/3/24, unit eligibility, opposite-end defenses and the minimum-then-maximum rule. The fixtures keep pixel-region lookup in one region while explicitly supplying several region-center records; they test this selection arithmetic without certifying generated terrain consistency. The producer's valid-count/capacity invariant remains separate; this selector has no local count clamp.

Wrapper `0x496240` takes `ECX=unit`, `EDX=requested_ID`, stack `[out_position,throttle]`. It uses the unit sprite seed and ordinary size3, or size40 for Turret124. With throttle enabled, nonzero player byte `0x67d279+player*0x4e8` rejects immediately. Otherwise run the actual search; failed throttled search sets that byte1. Successful search does not clear a previously set byte. Fixtures cover enabled/disabled throttle, prior flag values, actual search success and fully blocked terrain. [Spending dispatch](native-spending-dispatch.md) is the addon caller; issuing/advancing the addon construction order remains separate.

## Pylon recenter and nearest search

The Pylon branch calls `0x433220`, whose callback `0x433f20` accepts **status bit0x400 and the matching owner**. It does not independently require Pylon type, RequiresPsi, Completed or a specific primary order. The bit's Disabled label agrees with the [pinned Teippi status declaration](https://github.com/neivv/teippi/blob/05c006c2f74ad11285c39d37135aed03d1fb8806/src/unit.h#L32); the original comparison and callback are local evidence. Broader disabled-state generation remains separate.

The wrapper calls actual nearest search `0x442d40`/`0x442d90`, using border indexes, current search rectangle `0x543228`, original unit pool base and approximate distance. Its sweep visits previous-X, next-X, previous-Y, next-Y entries, evaluates the callback, and keeps only a **strictly** closer candidate. Equal distance retains the candidate encountered first by that sweep, not lowest unit ID. After finding candidates it tightens the rectangle to the current best distance. Half-open center bounds and index order remain part of the algorithm.

The selected unit is stored at `0x6a5da0`. When nonnull, its sprite replaces the grid seed and the direction filter is bypassed for this branch. Complete empty/found Pylon searches and nearest-predicate/list-order fixtures run all these actual callees. The supplied indexes are explicit; building/reordering those indexes remains a different contract.
