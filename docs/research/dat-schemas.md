# DAT record schemas (1.17.0.1)

The executable loads every `arr\*.dat` file through one generic loader, `0x4442b0` (atlas [P14](atlas/p14.md)). Each call passes the file name in ECX and a column descriptor in EDX: `{destination, element size, element count}` triples ending with a zero destination. Columns are stored back to back in descriptor order, each as `count` little-endian elements of `size` bytes. The loader rejects a file whose length differs from the descriptor total with fatal error 24.

The tables below are generated by [inspect_dat_descriptors_117.py](../../tools/research/inspect_dat_descriptors_117.py) from the exact executable, without running original code. All 11 effective archive files match their descriptors byte for byte in total size. Column names come from the pinned PyMS DAT definitions, which have the same column count and widths for every file. Names are labels only; the descriptor order, widths, counts and destinations are the authoritative layout. Machine-readable data: [dat-schemas.json](evidence/dat-schemas.json).

A column whose count is smaller than the file's record count covers a contiguous ID subrange. In `units.dat`, `infestation` (96) starts at unit 106, the sound columns (106) cover units 0–105, `addon_position` (192 shorts = 96 units) starts at unit 106, and `staredit_placement_size` (456 shorts) and `unit_extents` (912 shorts) hold 2 and 4 shorts per unit. In `sprites.dat`, the health bar and selection-circle columns (387) start at sprite 130. These subrange starts follow PyMS and the consuming code cited in the atlas.
