# P18: Multiplayer lobby, campaign selection menu, connection screen and the Create Game / Play Custom screen

This package covers `0x451140`–`0x45554f`: `gluchat.cpp`, the object between `gluchat.cpp` and `gluchatslot.cpp`, `gluchatslot.cpp`, the objects between `gluchatslot.cpp` and `gluconn.cpp` (the lobby slot menus and the campaign menu `rez\gluCmpgn.bin`), `gluconn.cpp`, and the head of `glucreat.cpp` (the functions before its first assertion string). Its 87 functions form four groups.

1. **Multiplayer lobby** (`0x451140`–`0x453cc0`, 57 functions). These run the chat room `rez\gluChat.bin` (glue state 3, `0x451470`): the chat output list and edit line, the twelve slot rows with their type and race drop-downs, latency bars, map-download percentages, ladder `/stats` queries and the force headers of team games. Glue state 3 is entered only from network screens: Create Game when the multiplayer byte `0x672664` ≠ 0 (`0x455550`), the join screen (`0x459130`), the Battle.net game selection after `SNetSelectGame` succeeds (`0x449990`) and the modem screen's result 5 (`0x45e300`); see [P17](p17.md). The network chat-command handlers that call into it (`0x46f3c0`, `0x470930`, `0x471340`, `0x477c20`, …) also exist only in network games. The two Battle.net ladder `/stats` functions (`0x451830`, `0x452ab0`) stay `excluded`; the other 55 are `specified` since the second pass (2026-11-14) for the network design.
2. **Campaign menu** (`0x453d90`–`0x454130`, 5 functions plus the embedded dialog procedure `0x453e80`). Glue state 6 shows `rez\gluCmpgn.bin`, the original-campaign menu: Terran, Zerg and Protoss episode buttons, Load Saved, Load Replay, Play Custom and Cancel. It reads the player profile (`characters\<name>.spc`) to decide whether the Zerg or Protoss episode shows an "incomplete" hint and asks for confirmation. All of it is `specified`.
3. **Connection screen** (`0x4541f0`–`0x454c40`, 15 functions). Glue state 2 shows `rez\gluConn.bin`: Storm network-provider enumeration (Battle.net, modem, IPX, UDP LAN, direct cable) and the Battle.net gateway list. The main menu enters it only for Multiplayer. The three Battle.net gateway functions (`0x4542e0`, `0x454a80`, `0x454c40`) stay `excluded`; the other twelve are `specified` since the second pass (2026-11-14) for the network design.
4. **Create Game / Play Custom** (`0x454ca0`–`0x4554a0`, 10 functions). `0x455550` (P19) runs `rez\gluCustm.bin` in single player (glue states 11 "Play Custom" and 12 "Load Replay") and `rez\gluCreat.bin` in multiplayer, with the dialog procedure `0x4550e0` in both. This package holds the dialog procedure, its post-load initialization, the OK handler, the single-player start step, the registry-persisted game speed and game type, the fixed-settings lock for replay entries and the transfer of the race drop-downs into the game setup. These are `specified`. Their branches that run only when `0x672664` ≠ 0 are stated explicitly.

## Shared conventions

**Dialog fields and helpers** follow [P17](p17.md) and [P36](p36.md): `+0x14` text, `+0x18` flags, `+0x20` s16 control ID, `+0x22` type, `+0x26` `lUser`, `+0x2a` interact callback, `+0x2e` draw callback, `+0x32` parent, `+0x42` first child, `+0` next sibling. `0x4c2200`(ECX = dialog or control, DX = ID) finds a control, `0x4c2890` shows, `0x4c22f0` hides, `0x4c2280`/`0x4c2910` disable/enable, `0x4c2840` marks dirty, `0x4c5960`(ECX = owner, EDX = timer ID, stack `[period ms, callback]`) creates or replaces a repeating UI timer and `0x4c58f0`(ECX, EDX = ID) deletes it. Dialog event: `+0` u32 user code, `+4` u32 parameter, `+8` u16 key, `+0xc` u16 type (4 left down, 6 left double, 14 user event, 15 character, 17/18 wheel). User codes seen here: 0 dialog started, 1 destroy, 2 control activated (the activated control's ID is in the dialog result `0x6ce6dc`), 4 hit test, 10 post-load initialization, 11 selection changed, `0x405` custom refresh.

**Glue states** (`0x66a274`, dispatched by `0x457510`): 0 main menu, 2 connection screen (`0x454250`), 3 lobby (`0x451470`), 4 Battle.net, 5 character selection (`0x459f10`), 6 campaign menu (`0x453f00`), 7/8/9 the Terran/Zerg/Protoss mission screens (`0x461420`/`0x461660`/`0x4611e0`), 10 and 21 join list (`0x459130`), 20 modem (`0x45e300`), 11 and 12 Create Game (`0x455550`, ECX = 0 and 1), 13 load game (`0x459970`), 22 expansion campaign menu (`0x458b00`).

**Player profile record** (`0x70` bytes, read by `LoadCharacterFile` `0x40d680`, see [P03](p03.md)): campaign progress u32 per race at `+0x28 + 4·race` (race 0 Zerg, 1 Terran, 2 Protoss), the Brood War values 12 bytes later at `+0x34`. A progress value is the progress number of the furthest mission reached. The Terran mission list `0x4f0680` ends with its closing cinematic at progress 12 and the Zerg list `0x4f0700` at progress 22, so a Terran value ≤ 11 or a Zerg value ≤ 21 means that campaign is not finished. (List records are `{u16 mission, u16 progress, u16 cinematic, u16 race}`; the Protoss list is `0x4f0778`.)

## Entries

### 0x00451140 `AppendLobbyChatLine` — add text to the chat list, word-wrapped
- Module: gluchat.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, ECX = text, EDX = kind, one unused stack argument; `ret 4`; no return value.
- Behavior:
  1. While the chat list `0x667c14` holds 64 items or more, item 0 is deleted (count − 63 deletions), so at most 63 old lines remain before the new one.
  2. Colour from jump table `0x451300`: kind 0 (own message) → 2, kind 1 (another player) → 6, kinds 2 and 3 (system text) → 4, any other → 2. The list's font is selected (`SelectControlFont` `0x4c3660`).
  3. If `GetTextWidth` `0x4ce3e0`(text) < `GetListTextWidth` `0x4c6860`(list) − byte `0x6d3036` (the font's widest glyph), the text is appended with flags colour | `0x10` (copied), selected and the list is marked dirty.
  4. Otherwise it wraps a heap copy (`SMemAlloc` strlen + 1, "gluChat.cpp" line `0xc1`): `n` = `GetTextFitLength` `0x4cdd30`(rest, maximum width). If `rest[n]` ≠ 0 and `n` > 3, it searches backwards from `n` while the index is > 3 for a space and, when one is found, breaks there. It saves `c = rest[n]`, writes 0, appends the piece (colour | `0x10`) and selects it. A full list (`0xff`) returns at once without freeing the copy (a leak). When the piece reached the end of the text, it frees the copy (line `0xe5`) and marks the list dirty. Otherwise it restores `c`, skips all spaces when `c` is a space, overwrites the three bytes before the new start with spaces (a three-space indent) and continues from there.
- Callers/callees: `AddLobbyChatMessage` `0x451560`.
- Second pass (2026-11-14): excluded while the remake had no network play; specified for the network design.
