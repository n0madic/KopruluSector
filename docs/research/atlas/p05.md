# P05: Save compression, order pool, unit counters, credits screens, sprites and thingies

This package spans `compress.cpp`, the objects between it and `credits.cpp`, `credits.cpp`, the objects up to `csprite.cpp`, `csprite.cpp` itself and the objects up to `cthingy.cpp`. It falls into six groups.

1. **Save-file block compression** (`0x4137d0`–`0x413ae0`). Every large save section (bullets, flingies, orders, sprites, thingies, units, AI, …) goes through one chunked PKWARE DCL wrapper. A block is stored as `DWORD crc, DWORD chunkCount, {DWORD len, bytes}*`. Chunks are 8 KiB of input, imploded with type 0 (binary) and a 1 KiB dictionary; a chunk is stored raw when implode fails or does not shrink it, and the reader detects that by `len == expected chunk size`. The checksum is a table CRC-32 (`0x50eb28`) seeded with `0xffffffff` and **not** finally inverted.
2. **Order node pool** (`0x413c80`–`0x414010`). 2000 queue nodes of `0x14` bytes at `0x5a52c0`, free list `0x5aef00/0x5aef04`, allocated count `0x5aef08`. Node: `+0` prev, `+4` next, `+8` order ID, `+0xa` FoW unit type, `+0xc` target position, `+0x10` target unit. Allocation/free are covered by [primary orders](../native-primary-orders.md); this package adds reset, save/load and index conversion.
3. **Unit counters, supply and score statistics** (`0x414060`–`0x414760`). Per-type `[228][12]` DWORD tables (`0x529604` all, `0x52c0c4` completed, `0x52eb84` kills, `0x531644` deaths) and per-player DWORD arrays from `0x5290c4` (group totals, scores, supply). Live accounting `0x414760` and completed accounting `0x4145a0` produce the count and supply arrays (the supply maxima are also set to 400 by `0x414400`); death statistics `0x414080` produce the loss/kill arrays. Other writers outside the package: the trigger actions Add/Set/Subtract Score (`0x4b6cf0`/`0x4b8440`/`0x4b8950`) write the four score arrays and the custom score, Add/Set/Subtract Deaths (`0x4b6a90`/`0x4b7e80`/`0x4b8640`) write the men/buildings/factories lost arrays, and cancelling an unfinished Zerg building (`0x43b380`) subtracts from units score and decrements men produced.
4. **Credits and campaign text screens** (`0x4148b0`–`0x4150d0`). A small markup interpreter over `rez\<name>.txt`, shown in dialog `rez\credits.bin`. It is used for the main-menu credits, the campaign epilog, the per-mission `Est*` establishing texts before missions and the one `Fin*` finale. Text runs are assigned to one of six positioned text controls; tags select the control, the background, the font colors, the fade speed, the page time and the page break.
5. **Sprites** (`0x415190`–`0x417860`). The 2500-record sprite pool, its tile-row lists, sprite/image creation helpers, selection circles and health bars, damage overlays, cloak draw-method switching, dirty-rectangle invalidation, drawing and save/load.
6. **Thingies** (`0x4178d0`–`0x4185c0`). Shared order-field setters for Bullets and units, two 500-record thingy pools (lone effect sprites and fog-of-war building ghosts), visibility updates from the map tile flags, the building-placement cursor sprite and fog-ghost lookups used by placement and the minimap.

Three short pieces of code inside the address range are not separate functions in the Ghidra list. They are described in the entry that precedes them: the credits draw callback `0x414c20` (in `0x4148b0`), the credits dialog event handler `0x4149f0` (in `0x415010`) and the unit placement-box predicate `0x417f00` (in `0x417ef0`).

## Shared data and tables

**List helpers** (outside the package) used everywhere here: `0x4119a0`(ECX = node, &head, &tail) unlinks; `0x411930`(ECX = node, &head, &tail) inserts the node directly **after the current head** (or makes it head and tail of an empty list); `0x411900`(ECX = existing, new, &tail) inserts after `existing`, updating the tail; `0x411970`(ECX = existing, new, &head) inserts before `existing`, updating the head. Pools initialized by inserting records 1..n−1 after record 0 therefore hand out record 0 first, then n−1, n−2, …, 1. After a save is loaded, the free lists are rebuilt in ascending record order, so allocation order after loading differs from a new game.

## Entries

### 0x004137d0 `WriteCompressedBlock` — compress a memory block in 8 KiB chunks and write it to a save file
- Module: compress.cpp · Relevance: data
- Status: specified
- Signature: `__fastcall`-like: ECX = source buffer, EDX = byte size, stack = [FILE*]; `ret 4`. Returns the total number of payload bytes written (sum of chunk lengths), or 0 on failure or when size is 0.
- Behavior: 1. Size 0 returns 0 immediately and writes nothing.
  2. Computes the checksum with `0x402160` (table CRC-32, table `0x50eb28`, initial value `0xffffffff`, **no final inversion**) over the whole block and writes it as a DWORD (`0x4cc4a0`, one `fwrite` element).
  3. `chunks = size >> 13`, plus 1 when `size` is not a multiple of `0x2000`; writes `chunks` as a DWORD.
  4. Allocates the parameter block (0x18 bytes), the implode work buffer (`0x8dd8`) and the chunk buffer (`0x2000`) with Storm `SMemAlloc` (`compress.cpp`, lines `0x30/0x32/0x35`).
  5. For chunk `i = 0..chunks-1`: `len = min(size - i*0x2000, 0x2000)`; `0x413940` produces (pointer, length) — either the imploded bytes or the raw chunk; writes the length as a DWORD and then that many bytes. A failed checksum write returns 0 at once; any later write failure (including the chunk-count write, which happens before the buffers are allocated) calls `0x4139e0` and returns 0. The allocations are not checked.
  6. Frees the buffers and returns the sum of chunk lengths.
  - File layout: `DWORD crc, DWORD chunkCount, { DWORD len, BYTE data[len] } * chunkCount`. A chunk whose stored length equals its uncompressed length is stored raw.
- Globals/fields: `0x5a52b0/0x5a52b4/0x5a52b8` (PKWARE buffers).
- Callers/callees: Called by `0x40a720`, `0x40c9f0`, `0x40d830`, `0x411300`, `0x413ee0`, `0x416ed0`, `0x418a10`, `0x431400`, `0x46b710`, `0x478980`, … (21 total). Calls `0x402160`, `0x413940`, `0x4139e0`, `0x4cc4a0`, `0x4d001c`.
- Prior evidence: none

### 0x00413940 `CompressChunk` — implode one chunk, falling back to the raw bytes
- Module: compress.cpp · Relevance: data
- Status: specified
- Signature: ECX = chunk source, EDX = chunk length, stack = [out pointer*]; `ret 4`. Returns the output length.
- Behavior: Fills the parameter block: `+0` source, `+4` read position 0, `+8` destination = chunk buffer `0x5a52b8`, `+0xc` written 0, `+0x10` source size, `+0x14` destination capacity = chunk length. Calls PKWARE `implode` (`0x401000`) with read callback `0x413750`, write callback `0x413790`, work buffer `0x5a52b4`, type 0 (binary) and dictionary size `0x400`. If implode returns 0 **and** the written count `+0xc` is strictly less than the chunk length, the output is the chunk buffer with that length. Otherwise the output pointer is the original source and the length is the chunk length (stored uncompressed).
  - Read callback `0x413750` (unlisted helper): copies `min(requested, size - pos)` bytes from `source + pos`, advances `pos`, returns the count. Write callback `0x413790`: if `written + n` exceeds the capacity it copies nothing but still adds `n` to `written`; otherwise it copies and adds `n`. An overflowing implode therefore always fails the `< length` test.
- Globals/fields: `0x5a52b0..0x5a52b8`.
- Callers/callees: Called by `0x4137d0`. Calls `0x401000`.
- Prior evidence: none

### 0x00413ae0 `ReadCompressedBlock` — read and decompress a block written by `0x4137d0`
- Module: compress.cpp · Relevance: data
- Status: specified
- Signature: ECX = destination buffer, EDX = expected size, stack = [FILE*]; `ret 4`. Returns 1 on success, 0 on failure.
- Behavior: 1. Expected size 0 returns 0.
  2. Reads DWORD stored checksum and DWORD chunk count (`0x4cc460`, `fread` of one element); failure returns 0 before allocating.
  3. Allocates the parameter block, the explode work buffer (`0x3134`, line `0x34`) and the chunk buffer.
  4. Loops `i` from 0 while `i < chunkCount` (signed; the count comes from the file and is not compared with the size): reads DWORD `len`; fails if `len > size - consumed`; reads `len` bytes directly at the destination cursor. `expected = min(size - i*0x2000, 0x2000)`. If `len != expected`, the bytes just read are exploded (`0x413a40`) and the result (which must be nonzero and `<= size - consumed`) is copied over the destination cursor. The cursor and `consumed` advance by the produced length.
  5. Frees the buffers. Success requires `consumed == size` and `0x402160(destination, size, 0xffffffff) == stored checksum`.
  - Any failure after allocation frees the buffers and returns 0. The destination may already be partly overwritten.
- Globals/fields: `0x5a52b0..0x5a52b8`.
- Callers/callees: Called by `0x40a210`, `0x40a2f0`, `0x40c580`, `0x40d680`, `0x410090`, `0x413e10`, `0x416790`, `0x418600`, `0x425de0`, `0x426000`, … (26 total). Calls `0x402160`, `0x4139e0`, `0x413a40`, `0x4cc460`, `0x4d001c`, `0x4d16a0`.
- Prior evidence: none

### 0x00413e10 `LoadOrderPool` — read the order pool from a save
- Module: compress.cpp..credits.cpp · Relevance: simulation
- Status: specified
- Signature: ECX = FILE*; returns 1/0.
- Behavior: Reads the whole pool (`0x9c40` bytes) with `0x413ae0`. ### 0x00417610 `RequestSpriteVisibilityChecksum` — ask the next draw-list build for a checksum
- Module: csprite.cpp..cthingy.cpp · Relevance: network

- Where it is set and served (one turn boundary of a network game, from `GameLoop` `0x4451f0`, [P15](p15.md)):

  3. `RunPendingFrames` runs the first frame of the new turn (the object step `0x445070`, or `0x444de0` while paused, then the trigger pass `0x4be500`) and leaves its loop, because `*out` ≠ 0 ends it after that frame at the latest (exit reason 5, 6 or 7).
