# P29: AI towns, worker and building AI, spending consumers and local-path geometry

This package covers `0x483ca0`–`0x488600` (92 functions), the rest of the object between `sai_banker.cpp` and `sai_contourscreate.cpp`. Most of it is the computer player's **town** layer: fixed pools of Town, WorkerAI and BuildingAI records, their save/load encoding, assignment of units to towns, the persistent town requests and their conversion into spending requests ([P28](p28.md) owns the spending heap), worker resource assignment and reassignment, construction and repair service, the nine spending consumers called by the building AI entry `0x487110`, and the AIScript helpers for towns. The last three functions belong to the local path search: they collect the terrain contours around the current search node and emit candidate neighbor points.

The functions form seven groups.

1. **Pools and save/load** (`0x483ca0`–`0x484670`, `0x486160`/`0x486180`, `0x487510`, `0x4877d0`, `0x487950`/`0x487970`, `0x486a20`). Three shared pools serve all eight players. Save converts every pointer into a 1-based index, writes the block and converts back. Load reads and converts.
2. **Assignment and removal** (`0x484cd0`, `0x486200`, `0x486340`, `0x486af0`, `0x486ba0`, `0x487900`, `0x487990`, `0x485840`, `0x4856a0`, `0x485770`, `0x486e80`, `0x487030`). `0x484cd0` is the one allocator that turns a unit into a WorkerAI or BuildingAI member of a town.
3. **Town requests** (`0x485fa0`, `0x487550`, `0x487890`, `0x4878b0`, `0x4865b0`, `0x485970`, `0x485ab0`, counters `0x4872f0`/`0x487ba0`/`0x4863b0`). AIScript opcodes write persistent desired counts; every spending pass converts the missing amount into spending requests.
4. **Worker economy** (`0x485020`, `0x486480`, `0x487580`, `0x485f20`, `0x4852b0`, `0x485400`, `0x485de0`/`0x485e80`, `0x486c80`, `0x487730`).
5. **Building AI and spending consumers** (`0x487110`, `0x4849c0`, `0x485390`, `0x485b70`, `0x485ca0`, `0x485d30`, `0x487d30`, `0x487de0`, `0x488030`, `0x488100`, `0x485dc0`, `0x486bf0`).
6. **AIScript helpers** (`0x486410`, `0x486c50`, `0x4872a0`, `0x4872d0`, `0x4877f0`, `0x487ac0`, `0x487b70`).
7. **Local path geometry** (`0x488220`, `0x488320`, `0x488600`).

## Data model

**Pools.** All three are fixed arrays with an intrusive doubly linked free list (`+0` next, `+4` previous). A record taken from the free list is prepended to a list; a released record is prepended to the free list without clearing its payload.

| Pool | Base | Stride | Slots | Free head | Block size | Initializer |
|---|---|---:|---:|---|---|---|
| WorkerAI | `0x67f7b0` | 24 | 1000 | `+0x5dc0` | `0x5dc4` | `0x483da0` |
| BuildingAI | `0x685578` | 44 | 1000 | `+0xabe0` | `0xabe4` | `0x483bd0` ([P28](p28.md)) |
| Town | `0x690160` | `0x1cc` | 100 | `+0xb3b0` | `0xb3b4` | `0x483ca0` |

`0x69b518 + 8·player` holds 8 pairs `{town pool pointer (always 0x690160), active town list head}` (64 bytes). `0x685574` is the round-robin player cursor of `0x486c80`. `0x69b558` is the town-migration lock of `0x485840`.

**Town record** (`0x1cc` bytes):

| Offset | Meaning |
|---|---|
| `+0x00/+0x04` | next / previous town of the same player |
| `+0x08/+0x0c` | WorkerAI pool pointer (fixed `0x67f7b0`) / worker list head |
| `+0x10/+0x14` | BuildingAI pool pointer (fixed `0x685578`) / building list head |
| `+0x18` | owner player |
| `+0x19` | initialized (set when the first building joins) |
| `+0x1a` | worker count (u8, wraps) |
| `+0x1b` | worker limit (from the resource area) |
| `+0x1c` | resource area index (0 = none) |
| `+0x1d` | gas-reference refresh request |
| `+0x1e` | "under attack" countdown (set to 1 by `0x487b80`, decremented by `0x486c80`) |
| `+0x20/+0x22` | center x / y (s16) |
| `+0x24` | main building (resource depot) |
| `+0x28` | designated repair SCV |
| `+0x2c` | mineral field reference |
| `+0x30/+0x34/+0x38` | three gas references (geyser or racial gas building) |
| `+0x3c` | 100 persistent requests of 4 bytes: byte `count<<3 \| kind<<1 \| special`, byte priority, WORD ID ([economy](../native-economy.md#town-request-layout-and-insertion)) |

**WorkerAI** (24 bytes): `+8` type 2, `+9` assignment code (1 minerals; 2/3/4 first/second/third gas), `+0xa` reassign count, `+0xb` wait timer, `+0xc` last-update time (`0x5349d8`), `+0x10` unit, `+0x14` town.

**BuildingAI** (44 bytes): `+8` type 3, `+9..+0xd` five training tags, `+0x10` unit, `+0x14` town, `+0x18..+0x28` five training contexts. Tag meaning (`0x484010`/`0x484380`): 0 none, 1 region AI record (`*(0x6b1a74 + 4·player) + 0x34·region`), 2 GuardAI record (32 bytes at `0x6b6908`), 3 town; any other tag is cleared to context 0 on load.

**Gas classification** (`0x485e80`): 1 raw Vespene Geyser (188); 2 the player's racial gas building with resource WORD `+0xd0` = 0 (depleted); 3 the same with resources left; 0 other or inactive. Racial IDs come from `0x6726d1 + 36·player`: race 1 → Terran (SCV 7, Command Center 106, Refinery 110, Supply Depot 109), race 0 → Zerg (Drone 41, Hatchery 131, Extractor 149, Overlord 42), other → Protoss (Probe 64, Nexus 154, Assimilator 157, Pylon 156).

**Resource areas** (`0x6a2e88 + 48·area`, areas 1..249): `+0/+2` center, `+4` mineral field count, `+5` geyser count, `+7` flags, `+8` total minerals. Used through `0x496bf0` (nearest area), `0x496510` (gas references), `0x4964b0` (first mineral field), `0x496690`/`0x4966f0` (worker capacity), `0x496f20`/`0x496f40` (field/geyser count).

Other globals: `0x5349d8` elapsed-time counter; `0x6726d0 + 36·p` controller type (1 = computer); `0x5263d0`/`0x526400` current minerals/gas (signed DWORDs); units.dat `0x521660` property flags (`0x1` building, `0x2` add-on, `0x8` worker, `0x1000` resource depot, `0x2000` resource container), `0x523c40` group flags, `0x523d28` supply provided, `0x520708` max HP; `0x529604`/`0x52c0c4` all/completed unit counts `[(type·12 + player)·4]`.

**Retriable error set.** Several consumers read the last requirement error (`0x4b38a0`, global `0x6be654`) after a failed race/requirement check. Errors **2, 23, 21, 8, 7, 13** drop the top request (`0x482c70`) and immediately re-run the building AI `0x487110` on the producer; any other error keeps the request.

**Local path search context** (used by `0x488220`/`0x488320`/`0x488600`; see [local paths](../native-local-paths.md)):

| Offset | Meaning |
|---|---|
| `+0x00..+0x0c` | four contour array pointers (map arrays on entry, local arrays on exit) |
| `+0x10..+0x16` | four contour counts (WORD) |
| `+0x20..+0x26` | per-direction extent offsets ("inner", s16), `+0x28..+0x2e` outer offsets |
| `+0x38/+0x3a` | current node x / y |
| `+0x40/+0x42` | target point |
| `+0x44` | target unit; `+0x48/+0x4a/+0x4c/+0x4e` its box left/top/right/bottom |
| `+0x50..+0x5c` | nearest contour in directions up/right/down/left |
| `+0x60/+0x62/+0x64/+0x66` | search box min x / min y / max x / max y |
| `+0x70` | neighbor count (WORD); `+0x72` goal found; `+0x73` resulting direction mask |
| `+0x74` | 32 neighbors of 8 bytes: x, y (WORD), flags byte, goal byte |
| `+0x174..+0x18a` | saved map contour array pointers and counts |
| `+0x18c` | visited-area count |
| `+0x2d0..+0x2d6` | local contour counts; arrays at `+0x2d8`, `+0x6d8`, `+0xad8`, `+0xed8` (128 entries of 8 bytes each) |

A contour entry is 8 bytes: `+0` position on its axis (s16), `+2`/`+4` start/end on the other axis, `+6` direction, `+7` flags (bits 0–1 choose the extent offset added to `+2`, bits 2–3 the one added to `+4`). Direction mask bits: `0x10` up, `0x20` right, `0x40` down, `0x80` left, `0x01` up-right, `0x02` down-right, `0x04` down-left, `0x08` up-left.
