# P08: Unit spatial queries, unit helpers, harvesting orders and the CUnit pool lifecycle

This package covers `0x422150`–`0x425de0`, the tail of the object that sorts between `ctxthelp.cpp` and `cunitinit.cpp`. Its 107 functions fall into seven groups.

1. **Spatial unit queries** (`0x422150`–`0x4224c0`). The unit finder keeps two sorted arrays of 8-byte entries `{DWORD unit index, DWORD coordinate}`: X bounds at `0x5c99b8` and Y bounds at `0x5d03f8`, with one shared entry count `0x5c99b0` (two entries per indexed unit; 3400 slots each). Each unit stores the array positions of its left/right/top/bottom bounds at `+0x13c/+0x140/+0x144/+0x148`. Every query pushes a frame on a small result stack: results are appended to the buffer `0x5d88f8` starting at DWORD offset `0x5d6e5c`, terminated by a null, and the previous offset is saved in `0x5d6e4c[depth]` with depth `0x5d6e48`. The caller must release each query with `0x4222b0`. The maximum unit width/height used to widen point queries are `0x5d6e40/0x5d6e44`.
2. **Unit geometry, visibility and image helpers** (`0x422760`–`0x423120`). Box-to-box and box-to-point distances, visibility predicates, damage overlays, selection circles, show/hide, button-set changes.
3. **Unit vision and image replacement** (`0x423150`–`0x423330`).
4. **Harvesting orders and resource queues** (`0x423400`–`0x424810`). The primary-order handlers for Harvest/MoveToGas, WaitForGas, HarvestGas, ReturnGas/ReturnMinerals, MoveToMinerals, WaitForMinerals, MiningMinerals, Harvest3 and Harvest4, plus cargo extraction and the per-resource waiting list.
5. **Unit allocation, type change and completion** (`0x424860`–`0x425020`).
6. **Unit removal and recycling** (`0x425050`–`0x425700`, `0x425cd0`–`0x425dd0`).
7. **Pool initialization, DAT normalization and save loading** (`0x425610`, `0x425690`, `0x425960`, `0x425de0`).

## Shared data and tables

**CUnit pool.** 1700 records of `0x150` bytes. Index *i* (1-based) lives at `0x5da250 + i*0x150`, so index 1 is at `0x5da3a0` (returned by `0x4255f0`). Index→pointer conversion is `0x428ba0` (`base - 0x150 + (index & 0x7ff)*0x150`, 0 → null). The pool's lists all use CUnit `+0x00/+0x04` (prev/next) and the generic list helpers `0x411930` (insert after head; an empty list gets the node as head and tail) and `0x4119a0` (unlink):

| Head / tail | List |
|---|---|
| `0x665ae0 / 0x665ae4` | active (visible) units; read by `0x425600`/`0x425db0` |
| `0x665ae8 / 0x665aec` | pending-destruction units (released body, sprite still animating); `0x4255b0`/`0x425d80` |
| `0x665af0 / 0x665af4` | free CUnits |
| `0x665af8 / 0x665afc` | hidden units; `0x4255e0`/`0x425da0` |
| `0x665b00 / 0x665b04` | Scanner Sweep (33) and Map Revealer (101) units; `0x4255d0`/`0x425d90` |
| `0x665b08[12]` | per-player unit list heads, linked through `+0x68` (prev) / `+0x6c` (next); `0x4255c0`/`0x4256f0` |
| `0x665b38` | allocated unit count (cap 1700 = `0x6a4`) |

`0x5da398` (WORD, just before the first record) holds the last unit-creation error string ID: 61 = too many units, 62 = no free CUnit, 0 = out of map bounds. `0x5da390` and `0x5da394` are two countdown timers consumed by the pending-unit pass `0x438ef0` (initial 10 and 150; that function reloads them to 150 and 300).

**units.dat columns used here** (indexed by unit type): `0x51faa8` flingy (BYTE), `0x51fb90` subunit 1 (WORD, 228 = none; only types ≤ 105 are consulted), `0x51ffe0` construction image (DWORD), `0x520370` initial direction (BYTE, 32 = random), `0x520458` shield-enabled (BYTE), `0x520540` max shields (WORD), `0x520708` max HP (DWORD, ×256), `0x520a98` elevation (BYTE), `0x520d50` computer idle order, `0x520e38` human idle order, `0x520f20` return-to-idle order (all BYTE), `0x5211d8`/`0x5213a8` ground/air weapon (BYTE), `0x5219f0` target acquisition range (BYTE), `0x521660` special-ability flags (DWORD), `0x521ad8` sight range (BYTE), `0x521e78` right-click action (BYTE), `0x522c38` unit dimensions `{left, up, right, down}` signed WORDs, `0x5238b0` build time (WORD). Weapons.dat max range is `0x5254b8` (DWORD). Special-ability bits referenced: `0x1` building, `0x8` worker, `0x10` subunit, `0x400` two-units-in-one-egg, `0x800` single-entity (powerup), `0x1000` resource depot, `0x2000` resource container, `0x400000` permanently cloaked, `0x08000000`, `0x10000000`, `0x20000000` invincible.

**CUnit status bits** (`+0xdc`) used here: `0x1` completed, `0x2` grounded building, `0x4` in air, `0x10` burrowed, `0x40` in transport, `0x100/0x200` cloak (requires detection / cloaked), `0x400` disabled (doodad state), `0x1000` (cleared by `0x429d00`), `0x4000`, `0x10000`, `0x20000`, `0x80000` (movement target unreachable/blocked), `0x100000`, `0x200000` no-collide, `0x800000` gathering, `0x4000000` invincible, `0x40000000` hallucination. "Disabled" below means status `0x400` or lockdown `+0x117`, stasis `+0x119` or maelstrom `+0x124` nonzero.

**Worker/resource fields.** Worker: `+0xc4` saved resource position (DWORD x|y<<16), `+0xc8` saved resource unit, `+0xce` active-service byte, `+0xd0` resource being served or waited on, `+0xd4/+0xd8` prev/next in the resource's waiting list, `+0xe0` carried type (bit 1 gas, bit 2 minerals). Resource: `+0xd0` amount (WORD), `+0xd2` animation cache byte, `+0xd3` busy byte, `+0xd4` waiting-list head.

**Order IDs** used by the harvest handlers: 23 Nothing (secondary), 79 Harvest1, 81 MoveToGas, 82 WaitForGas, 83 HarvestGas, 84 ReturnGas, 85 MoveToMinerals, 86 WaitForMinerals, 87 MiningMinerals, 88 Harvest3, 89 Harvest4, 90 ReturnMinerals, 151 ResetHarvest, 156 ComputerAI.

**Primary-order dispatch into this package** (resolved from the throttled third table of `0x439420`, bytes `0x439d5c` → pointers `0x439bcc`, entered only when the order timer `+0x85` expires and is reloaded to 8): orders 79 and 81 → `0x423480`; 82 → `0x4237a0`; 83 → `0x4235c0`; 84 and 90 → `0x423ce0`; 85 → `0x4239a0`; 86 → `0x423c30`; 87 → `0x423810`. The unthrottled second table (bytes `0x439b18`, pointers `0x439a84`, order−4) sends 88 → `0x423c70` and 89 → `0x423cc0`. The hidden-unit dispatcher `0x439e20` also tail-calls `0x4235c0` for order 83.

**Jump tables inside the package.**

- `0x423150` sight range: index byte table `0x423200` (type−1, 84 entries) → pointer table `0x4231ec`: type 1 Ghost → upgrade 20 (Ocular Implants); 42 Overlord → 25 (Antennae); 70 Scout → 41 (Apial Sensors); 84 Observer → 38 (Sensor Array); every other entry → default.
- `0x423fd0` cargo image: byte table `0x424088` (type−110, 69 entries) → `0x424074`: 110 Refinery → image 403, 149 Extractor → 401, 157 Assimilator → 399, 176–178 mineral fields → 397 (mineral flag set); all others return without extraction.
- `0x4253a0` type teardown: byte table `0x425518` (type−14, 143 entries) → `0x425500`: 14 Nuclear Missile → `0x42545b`; 73 Interceptor and 85 Scarab → `0x42542f`; 108 Nuclear Silo → `0x425440`; 134 Nydus Canal → `0x4254ae`; 156 Pylon → `0x425488`; others → return.

## Entries

### 0x00422150 `GetUnitsClickableAtPoint` — units whose clickable images contain a point
- Module: ctxthelp.cpp..cunitinit.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, ECX = x, EDX = y (signed 16-bit used); returns pointer to a null-terminated unit list (query frame pushed; release with `0x4222b0`).
- Behavior: Builds the rectangle `left = x−32, top = y−32, right = x+32+maxW (0x5d6e40), bottom = y+32+maxH (0x5d6e44)` (WORD arithmetic) and runs `0x422330`. It then compacts the result in place, keeping a unit when `0x416980`(ECX = unit sprite, stack x, y) is true. That predicate unions the screen rectangles (`0x411530`: `left = image +0x1c`, `right = left + frame width − 1`, same for Y, so right/bottom are inclusive edges) of the sprite's images that have image flag `0x20` (clickable) and tests `left ≤ x < right`, `top ≤ y < bottom`; the last pixel column and row of the union are therefore not clickable. If a sprite has no clickable image, the union rectangle is left uninitialized on the stack and the result is undefined. Order of survivors is the order returned by `0x422330`.
- Callers/callees: `0x4bcd00` (mouse picking); `0x422330`, `0x416980`.

### 0x004221f0 `GetUnitsContainingPoint` — units whose spatial bounds contain a point
- Module: ctxthelp.cpp..cunitinit.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = x, EDX = y; returns null-terminated list (release with `0x4222b0`).
- Behavior: Queries `0x422330` with `[x, y, x+maxW, y+maxH]`, then keeps a unit when `Xcoord[+0x13c] ≤ x < Xcoord[+0x140]` and `Ycoord[+0x144] ≤ y < Ycoord[+0x148]` (signed DWORD compares against the stored entry coordinates `0x5c99bc + i*8` / `0x5d03fc + i*8`). Stored bounds are `sprite.x − left` and `sprite.x + right` (no `+1`), and `0x5d6e40` is the maximum of `left + right + 1` over all types (computed by `0x421be0`), so a containing unit's right bound is always below `x+maxW`: every unit whose bounds contain the point is reached through its left or right X entry (and the Y filter of `0x422330` does not lose it either). The containment test itself is half-open, so the point `sprite.x + right` is outside.
- Callers/callees: `0x4132b0` (placement point lookup).
- Prior evidence: [placement](../native-placement.md) (point query, half-open containment).

### 0x00422330 `QueryUnitsInRect` — border query over the sorted spatial arrays
- Module: ctxthelp.cpp..cunitinit.cpp · Relevance: simulation
- Status: covered
- Signature: `__fastcall`, ECX = pointer to rectangle of signed WORDs `{left, top, right, bottom}`; returns pointer into `0x5d88f8`.
- Behavior: Pushes the frame (save `0x5d6e5c` at `0x5d6e4c[depth++]`). Increments generation `0x5da38c` (0 wraps to 1). `ys = 0x419500(Y, top, ≥)`; `ye` = first Y index ≥ ys whose coordinate ≥ bottom (linear scan). `xs = 0x419500(X, left, ≥)`. If `ys < ye` and `xs < count`, walk X entries from xs while `coord < right`; for each entry's unit index u whose tag `0x5d6e60[u]` ≠ generation, set the tag and append the unit if `unit+0x148 ≥ ys` and `unit+0x144 < ye`. Null-terminate, set `0x5d6e5c` to the index after the terminator, return the start.
- Prior evidence: [placement](../native-placement.md) (full contract incl. generation wrap edge), [combat AI](../native-combat-ai.md).

### 0x004224c0 `QueryUnitsOverlappingRect` — overlap query (selection boxes, triggers)
- Module: ctxthelp.cpp..cunitinit.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = rectangle `{left, top, right, bottom}`; returns list (frame pushed; release with `0x4222b0`).
- Behavior:
  1. Push the frame. `xEnd = right`, `yEnd = bottom` (unsigned WORDs). If the rectangle is narrower than the widest unit (`right − left + 1 < 0x5d6e40`, signed span against the unsigned maximum), set `shortX` and widen `xEnd = left + maxW − 1`, so units whose left bound lies before the rectangle are still reached through their right bound. The same applies to Y with `0x5d6e44` (`shortY`).
  2. `xs = bsearch(X, left)`, `xe = bsearch(X, xEnd zero-extended)`, `ys = bsearch(Y, top)`, `ye = bsearch(Y, yEnd zero-extended)` (all `0x419500` with flag 1: first coordinate ≥ target; the end values are zero-extended, so a negative right/bottom behaves as a large positive value). If `xe ≤ xs` or `ye ≤ ys`, return an empty list.
  3. Pass 1 over X entries `[xs, xe)`, unit u: tag `0x5d6e60[u] = 1`, except when `shortX` and `sprite.x − dim.left > right`, which stores 0 (the unit starts right of the rectangle).
  4. Pass 2 over Y entries `[ys, ye)`: unless `shortY` and `sprite.y − dim.up > bottom`, promote a tag of 1 to 3.
  5. Pass 3 over X entries `[xs, xe)`: append u when its tag is 3, then set the tag to 0. A unit with both X bounds in range is therefore appended once, at its first X entry. Output order is X-array order.
  The tags are left 0; this never matches a `0x422330` generation (which skips 0).
- Callers/callees: `0x42eab0`, `0x443110`, `0x4bc2d0` (drag selection); `0x419500`, `0x4255f0`.
- Prior evidence: [trigger unit counts](../native-trigger-unit-counts.md), [trigger ownership](../native-trigger-ownership.md), [spell casting](../native-spell-casting.md).

### 0x00422760 `GetUnitDistanceToPoint` — box-to-point approximate distance

### 0x00422dd0 `UpdateBuildingDamageOverlays` — fire/blood overlays from HP
