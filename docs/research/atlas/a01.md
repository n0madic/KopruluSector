# A01: Late-discovered functions

This addendum covers 62 addresses: 59 that an extra Ghidra pass turned into functions after their surrounding packages were written, two functions that package agents reported as missing from the atlas (`0x41cfe0` and `0x468a20`), and the unreferenced timing stub `0x405c70`, which [P01](p01.md) lists in its addendum and delegates here. Each address was checked against its disassembly and neighbors, against raw-image references (calls, jumps and little-endian pointers) and against the package that owns its range.

Status counts: 16 specified, 7 covered, 14 excluded, 25 library.

## What the addresses turned out to be

1. **Game static constructors** (`0x4021a0`–`0x4025b0`, 28 here; `0x402460`, `0x402480` and `0x4024e0` have their entries in [E01](e01.md)). These are compiler-generated C++ dynamic initializers for globals in many game objects. The linker gathered them at the start of `.text`, between the PKWARE library and the crash reporter of [P01](p01.md). None has a direct caller. `_cinit` (`0x4d59eb`) runs them through `_initterm` over the table `__xc_a`..`__xc_z` = `0x4eb6c8`–`0x4eb748`, in this order: `0x4021b0`, `0x4021d0`, … `0x402440`, `0x402480`, `0x402460`, `0x4024a0`, `0x4024c0`, `0x4024e0`, `0x402550`, `0x402570`, `0x402590`, `0x4025b0`, and last `0x4021a0`. They do three kinds of work:
   - Most build an empty Storm `TSList` and register its static destructor (listed in [C01](c01.md)) with `atexit`. A list object is `{+0 link offset, +4 terminator prev-link, +8 head}`; "empty" means head = bitwise NOT of the terminator address (object + 4), a non-positive value that ends every walk.
   - Three initialize a `CRITICAL_SECTION`.
   - One creates a named Win32 event, and one records the main thread id.
   A remake only needs the resulting state: every list starts empty and every lock exists before `WinMain`. The destructors run only at process exit, so the order is irrelevant to gameplay.

2. **Jump-table case labels and shared exits in game code** (`0x432735`, `0x433ef6`, `0x433f07`, `0x4a6442`, `0x4a6449`, `0x4a77ed`). Ghidra created functions at jump-table targets inside embedded callbacks. Each is `covered` by the entry that documents the containing code.

3. **Two real game functions missing from the atlas**: the hangar-child unlink `0x41cfe0` (now fully specified) and the trivial `TYPE` chunk callback `0x468a20`.

4. **An unreferenced timing stub** in the [P01](p01.md) range: `0x405c70` (`rdtsc`), with two unlisted variants behind it. Nothing in the image reaches it.

5. **CRT** (25 addresses at `0x4d0000`+). These are table-driven initializers and terminators (`__xi`, `__xp`), SEH `__except`/`__finally` blocks that Ghidra split at scope-table handler addresses, a signature-prefixed `_except_handler3`, x87 math helpers and unreferenced dispatch stubs. All are `library`. Several funclet entries sit a few instructions before the `$fin` labels in [C01](c01.md). They only restore registers from the frame and then fall into those labels.

## Corrections to earlier packages

- [P26](p26.md) said nothing creates the event handle `0x672968`. The static constructor `0x4023d0` creates it at startup in every process (`CreateEventA(NULL, TRUE, FALSE, "Battle.net League Connected")`). P26's single-player conclusion is unchanged: its uses are gated by the flag `0x67296c`, which only the `'BNET'` path sets. P26 (`0x474bf0`) now records this.

- [C01](c01.md) labeled `0x4d3a22` as `raise$fin`. It is the `__finally` tail of the console-control handler `ctrlevent_capture` at `0x4d3999`, which Ghidra merged into `_initp_misc_signal` `0x4d397d` (see `0x4d3a1a`). C01 now uses the label `ctrlevent_capture$fin`.

- [P36](p36.md) `0x4a63e0`: the event-3 (hover) case calls `0x4a6480` and then also runs the common default tail (see `0x4a6442`). P36 now states this.

- [P06](p06.md)/[P08](p08.md) `0x41cfe0`: the unlink does not clear the removed child's own parent and sibling fields when it has a parent (see the entry).
