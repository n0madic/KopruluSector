# P06: Thingy pools, tooltip box, unit spatial index, construction/repair/training orders and hangar units

This package covers the tail of `cthingy.cpp`, `ctxthelp.cpp`, and the first part of the objects that sort between `ctxthelp.cpp` and `cunitinit.cpp` (0x418600–0x41d2fa). It falls into six groups.

1. **Thingy pools** (`0x418600`–`0x418eb0`). A *thingy* is a 16-byte record `{+0 prev, +4 next, +8 param (DWORD), +0xc sprite}`. There are two pools of 500 records each. Pool A at `0x5c5ae0` holds lone sprites (explosions, remnants, doodad overlays): free list head/tail `0x5c7a20/0x5c7a24`, active list `0x5c7a28/0x5c7a2c`. Pool B at `0x5c7a30` holds fog sprites, the remembered building images the local player keeps seeing under fog: free list `0x5c9970/0x5c9974`, active list `0x5c9978/0x5c997c`. For a pool-B record, `+8` is the unit type whose placement box is used. The pool-A record `0x5c9984` is the command-target marker; byte `0x5c9988` says whether it is showing. The group covers save/load, list rebuilding after a load, the per-frame step, and rectangle tests over the per-tile flag DWORDs at `0x666454` (map width in tiles `0x5264b4`, height `0x5264b6`). Byte 0 of a tile flag word has one bit per player set while the tile is **not visible**. Byte 1 has one bit per player set while the tile is **unexplored**.
2. **Context-help tooltip box** (`0x418f60`–`0x4193e0`). The tooltip is drawn into a private 160×92 bitmap at `0x5c9994`. A bitmap descriptor is `{u16 width, u16 height, u8* pixels}`. A second 160×92 bitmap at `0x5c998c` saves the background the box covers. The box is shown through screen layer 1 (the 20-byte layer records start at `0x6d0b90`). Layer 1 is at `0x6d0ba4`: `+0` enabled byte, `+1` flags byte (bit 0 = redraw), `+2/+4` x/y, `+6/+8` width/height (signed WORDs), `+0xc` bitmap pointer, `+0x10` draw callback. The visible flag is `0x5c999c`. A save/restore rectangle at `0x5c99a0` is `{s16 left, top, right, bottom, width, height}`. The current drawing target is `0x6d0c40`; the main screen bitmap is `0x6d0b88`. The dirty-cell grid at `0x6d06d0` (16×16-pixel cells, 40 per row) is marked by `0x4cac50(ECX=left, EDX=top, stack right, bottom)`. Blits use `0x4ce720(ECX=dest x, EDX=dest y, stack [source bitmap, source rect])`, which copies a source-bitmap-sized block, starting at the rect's left/top, into the current target with Storm `SBltROP3` (SRCCOPY). Ghidra did not mark the release routine `0x419170`, which is referenced by pointer from `0x465b5f`. It clears the layer-1 enabled byte and frees both pixel buffers through `0x4cb230` when their data pointers (`0x5c9990`, `0x5c9998`) are nonzero.
3. **Unit spatial index** (`0x419460`–`0x41a210`). Two sorted arrays of 8-byte entries `{unit index (1-based), signed coordinate}` hold unit bounding-box borders. The X array is `0x5c99b8` (left and right borders) and the Y array is `0x5d03f8` (top and bottom borders). Each array is `0x6a40` bytes (3400 entries). The shared entry count is `0x5c99b0`, which is twice the number of indexed units. A unit stores the index of its own entries at `+0x13c` left, `+0x140` right, `+0x144` top, `+0x148` bottom; −1 means not indexed. Unit index `i` maps to `0x5da3a0 + (i−1)*0x150` (base returned by `0x4255f0`). Bounds come from `units.dat` unit dimensions at `0x522c38 + type*8` (`left, up, right, down` signed WORDs): left = x − left, top = y − up, right = x + right, bottom = y + down. The same group adds and removes the building occupancy bit `0x08000000` in the tile flags; it is touched only for grounded buildings (status `0x2`) and by building landing `0x435bf0`.
4. **Unit order and production helpers** (`0x41a250`–`0x41bfb0`). This group holds the movement-arrival test, construction progress and cancellation, map clamping, the Terran PlaceBuilding (30), IncompleteBuilding (44), ConstructingBuilding (33) and Repair (34) orders, and ResetCollision (150). It also contains the Train secondary order (38), repair cost arithmetic and the HP setter. The build queue is five WORDs at `+0x98..+0xa0`, a circular queue with head byte `+0xa4` and empty sentinel 228 (`0xe4`). The group further holds the queue add/cancel helpers, refinery conversion, rally points and small unit-type predicates.
5. **Hangar units** (`0x41bfe0`–`0x41d1c0`). These are Carrier (72), Gantrithor (82), Reaver (83) and Warbringer (81) with their Interceptors (73) and Scarabs (85). A parent's `+0xc0` is the inside (hangar) list head, `+0xc4` the outside list head, and bytes `+0xc8/+0xc9` the inside/outside counts. A child's `+0xc0` is its parent, `+0xc4/+0xc8` are next/previous sibling links, and byte `+0xcc` is 1 while outside. Ghidra did not mark the fragment `0x41cfe0`–`0x41d05b`, which is called from `0x42543b` (unit removal). It unlinks a child from its parent's inside or outside list according to `+0xcc` and decrements the matching count. If the child has no parent it only clears its sibling links.
6. **Begin cloaking** (`0x41d200`).

## Entries

### 0x00418600 `LoadThingyPool` — read one thingy pool from a save
- Module: cthingy.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = `FILE*`, EDX = pool base, stack = [record count (low WORD used)]; `ret 4`; returns 1 on success, 0 on failure.
- Behavior: Reads a WORD `n` through `0x4cc460`(ECX=&n, EDX=2, stack FILE); a read failure returns 0. It zeroes `count*16` bytes of the pool. If `n` is 0 it returns 1. Otherwise it allocates `n*18` bytes (Storm `SMemAlloc`, `"CThingy.cpp"`, line `0x3df`), zeroes them, and reads them through the compressed-chunk reader `0x413ae0`(ECX=buffer, EDX=`n*18`, stack FILE). On failure it frees (line `0x3e5`) and returns 0. For each 18-byte record in order, the leading WORD is a pool index `i` (not range-checked); the next 16 bytes are copied over pool record `i`, followed by the no-op hook `0x4be950`. It frees the buffer (line `0x3f7`) and returns 1. Links and sprite stay in index form; the caller converts them.
- Callers/callees: called twice by `0x4185c0` (pool A `0x5c5ae0`, then pool B `0x5c7a30`, count 500). That caller then runs `0x418240` (index→pointer) and `0x418910` (list rebuild).
- Prior evidence: none.

### 0x00418700 `ThingyIndicesToPointers` — load-time conversion for one record
- Module: cthingy.cpp · Relevance: simulation
- Status: specified
- Signature: `__thiscall`, ECX = record, stack = [convert-links flag, pool selector]; `ret 8`.
- Behavior: Converts the sprite field `+0xc` from a 1-based sprite index to a pointer through `0x416070` (0 → null, else `0x5af214 + i*0x24`). Zero indices become null. Any other selector leaves the links unchanged.
- Callers/callees: Flingy conversions `0x40c050`, `0x40c580`, `0x40c720`, `0x40c9f0` (always flag 0, sprite only). The thingy pools themselves are converted inline by `0x418240`.
- Prior evidence: [P03](p03.md) `0x40c050`.

### 0x00418840 `RebuildThingyList` — rebuild one list from pool contents
- Module: cthingy.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = &head, EDX = &tail, stack = [pool base, count (low WORD), predicate]; `ret 0xc`. The predicate is called with ECX = record's sprite field.
- Behavior: Finds the first record (ascending index) whose predicate is true. If none, head = tail = 0. Otherwise that record becomes head and tail and its prev/next are zeroed. Every later record, in ascending order, that satisfies the predicate gets prev/next zeroed and is inserted after the previously inserted record with `0x411900`(ECX=previous, stack [record, &tail]), which updates the tail. Lists are therefore in ascending index order after a load.
- Callers/callees: `0x418910`. Predicates: `0x418820` returns 1 when the sprite is null (free list); `0x418830` returns 1 when it is nonnull (active list).
- Prior evidence: none.
