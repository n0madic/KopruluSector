# L01: Local.dll resource module

This package covers `Local.dll` from the StarCraft 1.17.0.1 repack: SHA-256 `597e78f855a2853602e3dde0876a92849c3a5b6679e4003a46eba4f1d1dada43`, 52,224 bytes, image base `0x2000000`, linker 5.10, time stamp 1998-03-11. It is the localized resource module. Every resource is language 1033 (English, United States). The DLL has no export directory. Its 44 functions are the statically linked Visual C++ 5 runtime with an empty `DllMain`. StarCraft.exe uses the module only as a resource container, through the handle `0x6d0c54`.

Machine-readable index: [l01.json](../evidence/atlas/l01.json). The function entries are there; the resources are listed only in this document.

## How StarCraft.exe uses the module

| Exe address | Role | Local.dll resources |
|---|---|---|
| `0x465a20` ([P22](p22.md)) | `LoadLocalDll`: loads `<install dir>\local.dll` through `0x4cb840` into `0x6d0c54`, then calls `SFileSetLocale(0x4cb750())`. It registers `0x465880` (FreeLibrary at exit, `0x4cb6f0`). | string 3 |
| `0x4cb710` ([P44](p44.md)) | `ShowResourceDialog`: `DialogBoxParamA(0x6d0c54, id, main window 0x66fd28, proc, text)`. A result of −1 is fatal (`"GdsDialogBoxParam: %d"`). It has no fallback to the executable. | dialogs 101–103, 106–112 |
| `0x4cb750` ([P44](p44.md)) | Language ID: `LoadStringA(string 3, 16 bytes)` from Local.dll, then from the executable, else `0x409`. The text is parsed with `strtoul(..., 16)`. | string 3 |
| `0x4cb7b0` ([P44](p44.md)) | `FindResourceA`/`LoadResource`/`LockResource` by name and type. It does not fall back to the executable. | types 7004, 7005 |
| `0x4cb810` ([P44](p44.md)) | `LoadAcceleratorsA` from Local.dll, falling back to the executable. | accelerators 101–103 |

No other StarCraft.exe code references `0x6d0c54`. A raw image scan finds only the nine references inside `0x4cb6f0`–`0x4cb84a`, and the only `LoadStringA`, `FindResourceA` and `DialogBoxParamA` call sites are those listed above. When Local.dll fails to load, `0x465a20` calls `DialogBoxParamA` with the **executable's** instance and dialog `0x6a`. The executable's own dialog 106 says the file `local.dll` failed to load. That path therefore never uses Local.dll's dialog 106.

Offline single player needs Local.dll. Without it the game shows the error and exits. The accelerators, the language ID, the glue message boxes, and every start-up warning and fatal error dialog come from it.

## Functions

Status for all 44 functions: `library`, relevance `crt`, module "local.dll CRT (MSVC 5.10 static runtime)". StarCraft.exe never calls any of them directly, because the DLL exports nothing. They run only as side effects:

- `LoadLibraryA` (`0x4cb840`) runs `_DllMainCRTStartup` with `DLL_PROCESS_ATTACH`. The CRT then creates its private heap and copies the command line, the program path and the environment. It also sets up multibyte tables for the ANSI code page and the low-I/O handle table.
- `FreeLibrary` (`0x4cb6f0`, registered exit callback) runs the detach path, which frees all of this.

The initializer and terminator tables (`0x2005000`–`0x200501c`) are empty, and `DllMain` returns TRUE. No game-visible state is produced, so a remake needs none of this code. The CRT start-up fails in two ways. If `HeapCreate` or the first small-block region fails, or the command line or environment copy is null, `_CRT_INIT` returns FALSE and the load fails like a missing DLL. An allocation failure inside `_ioinit`, `_setargv` or `_setenvp` instead calls `_amsg_exit`: a "Microsoft Visual C++ Runtime Library" R6027/R6008/R6009 message box, then `ExitProcess(255)` of the whole StarCraft process.

### 0x2001000 `DllMain` — user DLL entry
- Module: local.dll CRT (MSVC 5.10 static runtime) · Relevance: crt
- Status: library
- Signature: `__stdcall(hinstDLL, reason, reserved)`, `ret 0xc`; returns 1
- Behavior: returns TRUE for every reason; the DLL has no user code.

### 0x2001010 `_CRT_INIT` — CRT attach/detach
- Module: local.dll CRT (MSVC 5.10 static runtime) · Relevance: crt
- Status: library
- Signature: `__stdcall(hinstDLL, reason, reserved)`, `ret 0xc`; returns BOOL
- Behavior: reason 1 (attach): `GetVersion` into `_osver` 0x2007210 (high word), `_winver` 0x2007214 (major·256+minor), `_winmajor` 0x2007218, `_winminor` 0x200721c; `_heap_init` (fails → return 0); `GetCommandLineA` → 0x20076f0; `__crtGetEnvironmentStringsA` → 0x20071f4; if either is null, `_heap_term` and return 0. Then `_ioinit`, `__initmbctable`, `_setargv`, `_setenvp`, `_cinit`, increment the attach count 0x20071f0, return 1. Reason 0 (detach): return 0 if the count is ≤ 0; otherwise decrement it, call `_cexit` unless `_C_Termination_Done` 0x2007248 is set, then `_ioterm`, `_heap_term`, return 1. Thread attach/detach return 1.

### 0x2001100 `_DllMainCRTStartup` — PE entry point
- Module: local.dll CRT (MSVC 5.10 static runtime) · Relevance: crt
- Status: library
- Signature: `__stdcall(hinstDLL, reason, reserved)`, `ret 0xc`; returns BOOL
- Behavior: detach with a zero attach count returns 0 immediately. For process attach/thread attach (reasons 1, 2) it calls the raw hook `_pRawDllMain` 0x20076f4 (null in this image) and `_CRT_INIT`; a failure returns 0. It then calls `DllMain`. If an attach's `DllMain` returned 0, it runs `_CRT_INIT` with reason 0 to undo. For detach reasons 0 and 3 it calls `_CRT_INIT` after `DllMain` (a failure forces 0) and then the raw hook. Runs when StarCraft.exe calls `LoadLibraryA` (0x4cb840) and `FreeLibrary` (0x4cb6f0).

### 0x20011b0 `_amsg_exit` — fatal runtime error
- Module: local.dll CRT (MSVC 5.10 static runtime) · Relevance: crt
- Status: library
- Signature: `__cdecl(int code)`; does not return
- Behavior: calls `_FF_MSGBANNER` when `__app_type` 0x20071fc is 1 (console) or it is 0 and `__error_mode` 0x2007200 is 1; then `_NMSG_WRITE(code)` and `_aexit_rtn(255)` through pointer 0x2005020, which holds `_exit`. Both globals are 0 in this DLL, so the banner is skipped and `_NMSG_WRITE` shows a "Microsoft Visual C++ Runtime Library" message box. `_exit(255)` then ends the whole StarCraft process with `ExitProcess(255)`. ### 0x2001320 `_ioinit` — low-I/O init
- Module: local.dll CRT (MSVC 5.10 static runtime) · Relevance: crt
- Status: library
- Signature: `__cdecl()`
- Behavior: allocates the first handle block (0x100 bytes, 32 entries of 8 bytes: handle −1, flags 0, pipe char 10) into 0x20075e0 and sets the handle count 0x20076e0 = 32; on failure `_amsg_exit(27)`. ### 0x2001760 `parse_cmdline` — argument splitter
- Module: local.dll CRT (MSVC 5.10 static runtime) · Relevance: crt

- Signature: `__cdecl(char *cmd, char **argv, char *args, int *numargs, int *numchars)`

### 0x2001970 `_setmbcp` — select multibyte code page
- Module: local.dll CRT (MSVC 5.10 static runtime) · Relevance: crt
- Status: library

It records the code page, `__mblcid` 0x2007564 (`CPtoLCID`), `__ismbcodepage` 0x20075c8 and the upper-range words 0x2007568–0x2007570, then calls `setSBUpLow`. If `GetCPInfo` fails, it falls back to single-byte tables for a system pseudo code page and returns −1 otherwise.

## Resources

### String table (type 6, blocks 1–4, IDs 0–63)

**Only string 3 is consumed by the game.** `0x4cb750` loads it, and its callers use the value as follows:

- `0x465a20` passes it to `SFileSetLocale`, so MPQ lookups prefer locale `0x409` files.
- `0x46f330` stores it in the Storm program record at `+0x38`.
- `0x465590` maps it to `'enUS'` for System Survey and the crash reporter.

`strtoul` with base 16 accepts the `0x` prefix, so the value is `0x409`. The executable has no string 3, so without the Local.dll string the default `0x409` is used anyway.

No StarCraft.exe code loads the other strings. The only `LoadStringA` calls in the executable are the two in `0x4cb750`, both with ID 3. Storm's `SErrGetErrorStr` uses storm.dll's message table instead ([S01](s01.md)). The other strings look like leftovers of an older Storm/GDS error-string scheme: strings 16–36 match Storm error codes, and string 49 matches the CD prompt.

### Dialogs (type 5, IDs 101–112)

All twelve are classic `DIALOG` templates:

- Style `0x80c800c0`: popup, caption, system menu, modal frame, `DS_SETFONT`.
- Font "MS Sans Serif", 8 pt. Dimensions are in dialog units.
- Buttons are ID 1 (OK or Continue, default) and ID 2 (Exit). Static text has ID −1.
- ID 1000 is the static text that the dialog procedure replaces with the caller's text.

Every caller passes `MessageDialogProc` `0x4cea00` ([P45](p45.md)). That procedure handles three things:

- `WM_INITDIALOG`: arrow cursor, `ShowCursor(TRUE)`, centre on the screen, and item 1000 = lParam when non-null.
- ID 1 → result 1.
- ID 2 → result 0.

The "fatal" wrappers first shut down the network, video and sound (`0x4cc340`). After the dialog they exit through `0x4cc320` with `ExitProcess(1)`. The "warning" wrappers exit through `0x4cf730` when the result is 0.

### Custom type 7004 (`0x1b5c`): glue dialog binaries

The two named resources `GLUEOK_BIN` (271 bytes) and `GLUEOKCANCEL_BIN` (373 bytes) are in the [dialog bin](../native-dialog-bin.md) format. Each is a chain of 86-byte (`0x56`) control records with relative offsets: `+0` next, `+4..+0xa` rect, `+0xc/+0xe` size, `+0x14` text offset, `+0x18` flags, `+0x20` ID, `+0x22` type, `+0x42` first child. The control text strings follow the records.

The consumer is `LoadResourceBinary` `0x456f50` ([P19](p19.md)): find by name with type `0x1b5c`, then copy into an allocated buffer. The bitmap loader `0x4c33a0` loads the binary through it and then relocates the records.

| Resource | Record | Rect (l,t,r,b) | ID | Type | Flags | Text |
|---|---|---|---|---|---|---|
| `GLUEOK_BIN` | dialog | 0,0,359,199 (360×200) | 0 | 0 (dialog) | `0x8` | `gluEOk`; first child at `0x56` |
| | button | 103,159,260,187 (158×29) | −2 | 1 (default button) | `0x218` | hotkey `o`, label `\x04O\x01k` ("Ok" with the O in highlight colour 4) |
| | text | 10,10,349,149 (340×140) | 2 | 9 (left-aligned label) | `0x8` | empty; filled with the message |
| `GLUEOKCANCEL_BIN` | dialog | 0,0,359,199 | 0 | 0 | `0x8` | `gluEOkCancel` |
| | button | 17,159,174,187 | −2 | 1 | `0x218` | hotkey `o`, "Ok" |
| | button | 186,159,343,187 | −3 | 2 (button) | `0x218` | hotkey `c`, label `\x04C\x01ancel` |
| | text | 10,10,349,149 | 2 | 9 | `0x808` | empty; filled with the message |

All bitmap fields are 0. The image comes from type 7005: `InitMessageBox` `0x456da0` draws it.

`InitMessageBox` treats the controls as follows:

- Control 2 receives the message text, a draw procedure `0x4605c0` and font fitting.
- Control 5 would receive a second text, but neither binary has a control 5. The two-text box `0x456fb0` therefore shows only the first text when it falls back to `GLUEOK_BIN`.
- Controls −2 and −3 get flag `0x20000`.

Consumers:

- `ShowGlueOkBox` `0x4570d0` and `ShowGlueMessageBox2` `0x456fb0` use `GLUEOK_BIN`.
- `ShowGlueOkCancelBox` `0x4571b0` uses `GLUEOKCANCEL_BIN`.

These boxes are used only when no glue dialog is active. While a glue screen is up, the MPQ popups `rez\gluPOk.bin`, `gluPOkSplit.bin` and `gluPOkCancel.bin` are used instead. The resource boxes are reachable offline, for example from error paths outside a glue screen (callers `0x474a70`, `0x453d90`, `0x458be0`), but rarely.

### Custom type 7005 (`0x1b5d`): PCX images

All four are ZSoft PCX images: version 5, RLE encoding, 8 bits per pixel, 1 plane, with a 256-colour palette after the `0x0c` marker at the end.

| Resource | Size | Bytes | Consumer |
|---|---|---|---|
| `GLUEOK_PCX` | 288×153 | 4225 | `InitMessageBox` `0x456da0` for the OK boxes. It is decoded with `SBmpDecodeImage(2, …)` (size pass, then pixels) and remapped to the current game palette by nearest colour (`0x456b50`). `LoadResourcePcx` `0x456ee0` is the equivalent loader used by `0x4c33a0`. |
| `GLUEOKCANCEL_PCX` | 288×153 | 4341 | Same path for the OK/Cancel box. |
| `GLUECURSOR_PCX` | 32×31 | 1172 | **None.** The name occurs in no game module (StarCraft.exe, storm.dll, the SNP providers and Smackw32.dll, case-insensitive). |
| `GLUECURHOT_PCX` | 32×32 | 965 | **None** (same check). |

`InitMessageBox` overwrites the dialog's size fields `+0xc/+0xe` with the image size (288×153). The rect `+4..+0xa` stays 360×200. The buttons at y 159–187 therefore lie below the image height. A remake should reproduce the layout from these numbers rather than assume the controls fit inside the bitmap.

## Notes and open points

- Two dialog texts disagree with the code that shows them. The 108 text says Pentium while the test is "below 486". The 109 text says 16 MB while the test is 13 MiB. The atlas records the code's thresholds as authoritative.
- Dialogs 104 and 105, strings other than 3, and the two cursor PCX images ship unused.
- The repack's Local.dll was compared only with this StarCraft.exe. Other language builds are out of scope.
