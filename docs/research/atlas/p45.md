# P45: Bitmap-font text engine, application exit list, registry options, cursor clipping and DirectDraw start-up

This package covers `0x4cd670`–`0x4cffd7` (60 functions), the last objects of the engine library run before the C runtime. Its pieces are:

1. **Text engine** (`0x4cd670`–`0x4ce520`, `vidblit.cpp..font.cpp`, `font.cpp`, `font.cpp..appaddex.cpp`). It lays out and draws byte strings with the FNT bitmap fonts: the bounded line consumer that plots glyphs, the multi-line engine, vertical alignment, the main text entry `DrawText` `0x4cdf20`, width measurement, the fit-to-width cutter, font load/free/select and the colour-row selector. Most of the pure arithmetic was executed in [native text](../native-text.md); this package adds the visible drawing path, the highlight glyph, the in-line alignment controls `0x12`/`0x13`, the outer layout wrapper and the string-width helpers.
2. **Registry options** (`0x4ce530`–`0x4ce6a0`): a 16-entry table of Storm registry values (game speed, scroll speeds, volumes, sound/intro/tip flags).
3. **Surface helpers** (`0x4ce6f0`–`0x4ce7d0`, `0x4ce9c0`, `0x4cf4f0`–`0x4cf5e0`, `0x4cfda0`, `0x4cfe60`–`0x4cffd7`): clear, opaque and colour-key blits with source/destination clipping, rectangle outline and fill, GRP frame descriptors.
4. **Cursor** (`0x4ce820`–`0x4ce8e0`): cursor clipping to the 640×480 client area, cursor position get/set.
5. **Application exit list** (`0x4ce940`, `0x4cf6b0`, `0x4cf730`, `appaddex.cpp`/`appexi.cpp`): 32 exit callbacks run in reverse slot order before the CRT `exit`.
6. **Win32 message dialogs and error text** (`0x4cea00`–`0x4cf350`): the shared dialog procedure, start-up warnings, the two fatal-error dialogs, and HRESULT-to-name tables for DirectDraw and DirectSound.
7. **Video start-up/shutdown and palette upload** (`0x4cf760`–`0x4cfd60`, `vidinimo.cpp`, `vidinimo_pc.cpp`): brightness, the 640×480 main bitmap, DirectDraw creation in 640×480×32 exclusive full screen, Storm `SDraw` hand-off, palette submission.

## Text engine state

All text routines share one global state block. Byte widths are unsigned unless stated; coordinates are signed.

| Global | Meaning |
|---|---|
| `0x6d0c40` | Current drawing surface: pointer to `{s16 width (= stride), s16 height, u8* pixels}`. |
| `0x6d3008` | Korean double-byte width (0 = off). Set only by `0x4ce160` when `GetUserDefaultLangID()` is `0x412`. |
| `0x6d300c` | Korean lead-byte state (u8). |
| `0x6d300d` | Measuring flag (u8): 1 = lay out without plotting. |
| `0x6d300e` | Layout flags (u8). `0x02` centre each line, `0x04` right-align each line, `0x08` "centre if one line" (see `0x4cdf20`), `0x10` no vertical alignment, `0x20` vertical centre (otherwise bottom). Any of `0x08/0x20/0x40` requests a measuring pass. `0x01` is only toggled. Default `0x11`. Some atlas entries ([P19](p19.md), [P21](p21.md)) call this byte a colour byte; it is the layout flag byte. |
| `0x6d300f` | Tab width (u8) = 2 × font maximum width. |
| `0x6d3010` | Current colour row: pointer to 8 palette indices, one per glyph mask value 0–7. |
| `0x6d3014`, `0x6d3018`, `0x6d301c` | Glyph width, glyph height, and `surface stride − glyph width`, inputs of the packet blitter `0x4cfdf0`. |
| `0x6d3020` | Current font (FNT image with relocated offsets). |
| `0x6d3024`…`0x6d3030` | The four loaded fonts of the current font set (see `0x465c40`/`0x465ce0` in [P22](p22.md)). |
| `0x6d3034` | Line gap (u8, default 3). |
| `0x6d3035` | Letter spacing (u8, default 1). |
| `0x6d3036`, `0x6d3037` | Font maximum width and height (u8). |
| `0x6d3038`, `0x6d303a`, `0x6d303c`, `0x6d303e` | Clip rectangle left, top, right, bottom (s16, inclusive). |
| `0x6d3040`, `0x6d3042`, `0x6d3044`, `0x6d3046` | Output extent left, top, right, bottom (s16). |
| `0x6d3048`, `0x6d304c` | Current pen X and Y (s32). |
| `0x6d3050`–`0x6d3108` | Colour rows, 8 bytes each (selected by `0x4ce250`); `0x6d3068` (code 5) is the grey row that locks colour changes during drawing. |
| `0x6d3110` | Previous colour row (restored by control code 1). |
| `0x6d3114` | Highlight glyph code (u8, 0 at load). The edit control sets it to `0xa6` (`0x4c7d60`), the caret glyph. |

**FNT image.** `+0` `"FONT"`, `+4` low code, `+5` high code, `+6` maximum width, `+7` maximum height, `+8` one u32 per code from low to high: after loading, an absolute pointer to a glyph `{u8 width, u8 height, u8 xOffset, u8 yOffset, packets…}`; a zero file offset becomes the font base pointer. See [native text](../native-text.md#fnt-schema-and-complete-native-packet-decoding).

**Glyph advance** (`0x4cdc30` and the inline copies): space `0x20` = max width / 2 (floor); tab 9 = tab width (in measuring helpers) or next tab stop (in layout); control codes 1–8, 10, 12–31 = 0; any other byte = `xOffset + width + spacing` when it is inside `[low, high]` and its glyph pointer is nonzero, else 0. Byte 11 reaches the glyph lookup. In Korean mode, bytes ≥ `0xa0` follow the lead-byte rule in [native text](../native-text.md#byte-widths-bearings-and-scalar-dbcs-state).

**Control-byte jump tables** (resolved): `0x4cd670` uses index table `0x4cd9d0` (codes 1–31) into targets `0x4cd9c8` = {`0x4cd6da` colour change, `0x4cd703` other}; codes 1–8, 14–17, 21–25, 27–31 are colour changes, codes 9–13, 18–20, 26 go to the general path. `0x4cdd30` (`0x4cde64` → `0x4cde54`) and `0x4ce3e0` (`0x4ce4f8` → `0x4ce4e8`) share one layout for codes 1–32: code 9 → tab width, code 11 → glyph lookup, code 32 → space, every other code → 0. `0x4cdc30` uses `0x4cdce4` → `0x4cdcd4` with the same classes.

**Video**: main screen bitmap `0x6d0b88` `{640, 480, pixels}`, `0x6d3180` video initialized, `0x6d3184` `ddemulate` command-line flag ([P22](p22.md)), `0x6d318c` `ddraw.dll` module, `0x6d3190` `IDirectDraw`, `0x6d3188` primary surface, `0x6d3194` system-memory back surface, brightness `0x50f2ec` (initial 100).

**Clip records** used by `0x4cfe60`: a 12-byte array of s16 `{x0, y0, x1, y1, w, h}`. For the source, `x0..y1` is the inclusive source rectangle and `w, h` the source bitmap size; on success `w, h` are overwritten with the copy size. For the destination, `x0, y0` is the target position, `w, h` the target surface size and `x1, y1` are scratch.

## Functions

### 0x004cd670 `DrawTextSpan` — lay out or plot one line segment
- Module: vidblit.cpp..font.cpp · Relevance: render
- Status: specified
- Signature: custom; ECX = start pointer, EDX = exclusive end pointer; returns EAX = pointer where it stopped.
- Behavior: Sets the destination pointer `d = pixels + width·Y + X` (surface `0x6d0c40`, X/Y = `0x6d3048`/`0x6d304c`) and processes bytes while `p < end`:
  - NUL or `0x0c`: stop (pointer stays on it).
  - Colour codes (1–8, 14–17, 21–25, 27–31): when not measuring and the current row is not the grey row `0x6d3068`, `SelectTextColor` `0x4ce250`(code); otherwise ignored.
  - `0x0a`, `0x0d`, `0x1a`: ignored.
  - Tab 9: `X += tab − (X − clipLeft) mod tab`, using signed `idiv` (remainder takes the dividend's sign); `d` moves by the same amount.
  - Space: X and `d` advance by max width / 2.
  - `0x12` (right-align rest): `ParseTextLine` `0x4cd100`(p) measures the rest of the line from the current X, leaving X at the measured end `Xe`; `d += clipRight − Xe`. X is left at `Xe`.
  - `0x13` (centre rest): same, but `d += (clipRight − Xe) >> 1` (arithmetic shift, i.e. floor).
  - Any other byte: if it is outside the font range or its glyph pointer is 0, stop. Otherwise, with glyph g:
    - Highlight case: the byte equals `0x6d3114`, it is not the first byte, and the previous byte is 4. Save `d` and X, no plot, advance 0.
    - Else when measuring: no plot, advance `g.xOffset + g.width + spacing`.
    - Else (drawing): set `0x6d3018 = g.height`, `0x6d3014 = g.width`, `0x6d301c = stride − g.width`, then query `GetUserDefaultLangID()`. If it is `0x412` (Korean), the byte is a DBCS lead byte (`IsDBCSLeadByte`) and it is not `0xa9` or `0x99`, the pair is rendered by the GDI path `0x4cd310` (ECX = `d`, EDX = p), which returns the advance; the pointer skips the trail byte and the bottom extent uses `Y − 1 + advance`. Otherwise the glyph packets are plotted with `0x4cfdf0` at `d + g.yOffset·stride + g.xOffset`, advance `g.xOffset + g.width + spacing`.
    - Bottom extent (s16 `0x6d3046`) = `Y + g.yOffset + g.height − 1` when that is ≥ the current value (all paths except Korean).
    - X and `d` advance by the advance.
  - No horizontal clipping is done; line breaking by the caller keeps glyphs inside.
- After the loop, if a highlight position was saved and the call is not measuring: X = saved X, and glyph `0x6d3114` is plotted at the saved `d` (so it overlays the following glyph). X stays at that saved value.
- Globals/fields: `0x6d0c40`, `0x6d300d`, `0x6d3010`, `0x6d3014`–`0x6d3020`, `0x6d3035`, `0x6d3038`, `0x6d303c`, `0x6d3046`–`0x6d304c`, `0x6d3114`.
- Callers/callees: `0x4cd9f0`; `0x4cd100`, `0x4cd310`, `0x4ce250`, `0x4cfdf0`.
- Prior evidence: [native text](../native-text.md#complete-line-wrapping-measurement-and-control-consumers) executed the measuring path (all bytes except 18/19) and the highlight advance rule; the drawing path, `0x12`/`0x13` and the deferred highlight plot are static here.

### 0x004cd9f0 `LayoutTextLines` — multi-line engine
- Module: vidblit.cpp..font.cpp · Relevance: render
- Status: covered
- Signature: custom; ECX = text, EDX = pointer to s32 line count; returns the stop pointer.
- Behavior: [Native text](../native-text.md#complete-line-wrapping-measurement-and-control-consumers). Exact control flow: extents start as left `0x7fff`, right 0, top = bottom = Y; count = 1. Empty text → jump to the exit adjustment. Per line: `start = X`; `e = 0x4cd100(p)` (X becomes the line end, `w = X − start`). Flag `0x02`: `X = start + (clipRight − start)/2 − w/2` (both halves truncated toward zero); right = `X + w` if that is ≥ right. Else flag `0x04`: right = clipRight, `X = clipLeft + clipRight − w − start`. Else X = start, right = max(right, line end X). Left = X when X ≤ left. Then `p = 0x4cd670(lineStart, e)`; X = clipLeft; `Y += gap + maxHeight`; bottom += gap − 1 (16-bit); count++. If `*p == 0x0c` return `p + 1` with no further adjustment. Continue while `Y + maxHeight ≤ clipBottom` and `*p ≠ 0`. Exit adjustment: bottom += 1 − gap, Y −= gap, count−−, return p (the unconsumed text).
- Callers/callees: `0x4cdf20`; `0x4cd100`, `0x4cd670`.

### 0x004cdd30 `GetTextFitLength` — bytes of a string that fit a width
- Module: font.cpp · Relevance: ui
- Status: specified
- Signature: custom; ECX = text, EDX = maximum width (s32); returns the byte count.

### 0x004cdf20 `DrawText` — main text entry
- Module: font.cpp..appaddex.cpp · Relevance: render
- Status: specified
- Signature: custom; ECX = x, EDX = y, stack `[text]`, `ret 4`; returns the unconsumed text pointer, or 0 when the text was consumed up to its NUL.
- Behavior:
  1. Normalises the clip rectangle: left < 0 → 0, top < 0 → 0, right ≥ surface width → width − 1, bottom ≥ surface height → height − 1 (signed 16-bit compares).
  2. Extents = `{x, y, x, y}`.
  3. If `x ≥ clipLeft`, `y ≥ clipTop`, `x ≤ clipRight` and `y + maxHeight ≤ clipBottom`:
     - X = x, Y = y, count = 0.
     - If flags & `0x68`: measuring pass (`0x6d300d` = 1, `0x4cd9f0`(text, &count), `0x6d300d` = 0); then unless flags & `0x10`, `0x4cdbf0`(&y) moves y for vertical alignment.
     - If flags & `0x08`: flags ^= 9 when count > 1, else flags ^= `0x0a` (so one line is centred by toggling `0x02`).
     - Drawing pass: X = x, Y = y, `text = 0x4cd9f0(text, &count)`; read the extents it produced.
     - Restore the original flags byte.
  4. Otherwise nothing is drawn and the extents stay `{x, y, x, y}`.
  5. Final extents get a 2-pixel margin clamped to the clip: left = max(L − 2, clipLeft), top = max(T − 2, clipTop), right = min(R + 2, clipRight), bottom = min(B + 2, clipBottom) (16-bit). These are stored at `0x6d3040`–`0x6d3046`; callers use them as the dirty rectangle and `0x6d3044` as the text end.
  6. Returns 0 if `*text == 0`, else `text`.
- Callers/callees: 19 UI callers (dialog controls, tooltips, briefing, score screens, chat). `0x4cd9f0`, `0x4cdbf0`.
- Prior evidence: [native text](../native-text.md#visible-wrapper-boundary-and-converter-consequences) records this wrapper as unexecuted.

### 0x004ce7d0 `DrawRectOutline`
