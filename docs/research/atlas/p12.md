# P12: Unit order handlers, per-frame unit step, transports, status-effect appliers, research/upgrade and Zerg morphs

This package spans the middle of the object that sorts between `cunitsave.cpp` and `cur.cpp` (0x435bf0–0x43bc4b). It contains the per-frame unit update and most of the order handlers that the dispatchers reach. The pieces connect as follows.

1. **Per-frame unit step** `0x438ef0`, called by the object step `0x445070`. It redistributes order throttles, clears and re-marks Disruption Web coverage (`0x438cd0`), processes the pending (dying) list, prepares movement for every active unit (`0x43a5f0`), updates visibility and detection, and then runs each active unit through timers `0x43a320`, the main-order dispatcher `0x439420`, the secondary-order dispatcher `0x439310`, subunit processing `0x43a720` and the image update `0x418b20`. Hidden units go through `0x43a770` and its own dispatcher `0x439e20`. The special list (Scanner Sweep and Map Revealer) gets a second main pass.
2. **Order handlers** for building lift-off and landing, Siege mode, Medic healing, nuclear launch, Spider Mines, Scanner Sweep, transports and Bunkers, Defensive Matrix casting, Zerg morphing and construction, and research/upgrade progress. Each takes `ECX = CUnit` and works on the order state byte `+0x4e`, the order signal byte `+0x4f` (set by IScript `sigorder`), the order timer `+0x54` and the order target `+0x58/+0x5a/+0x5c`.
3. **Movement-request helpers** `0x43a070`/`0x43a0a0`/`0x43a0d0`/`0x43a180`/`0x43a270`/`0x43a490`/`0x43a4e0`, used by most order handlers in the game. For AI-owned ground units they first ask `0x437540` whether a transport should carry the unit.
4. **Transport cargo**. A transport stores passengers in eight WORD slots at `+0xb0`. Each slot encodes `pool index (low 11 bits) | generation << 11` (`0x428bd0` encodes, `0x428b50` decodes). Passengers point to their transport with `+0x80` and carry status `0x40` (in transport) or `0x20` (in a Bunker).
5. **Status-effect appliers and expiry** for Defensive Matrix, Irradiate, Lockdown, Maelstrom, Optical Flare, Stim Packs and Restoration. The per-unit eight-frame service `0x4351e0` (P11) and the damage/spell code (P01/P11) call them.
6. **Research and upgrade** start, progress, refund and completion, and the movement-speed upgrade appliers.
7. **Zerg morphing**: Larva/Hydralisk/Mutalisk morph, building self-construction, Drone build, cancellation, and the twin-unit spawn of Zerglings and Scourge.

### 0x00435bf0 `OrderBuildingLand` — order 71: fly to the landing site, check the footprint, land
- Module: cunitsave.cpp..cur.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = CUnit (a lifted Terran building); no return value.
- Behavior:
  - If the unit is already a grounded building (status `0x2`), it reissues the sequence: `0x42a2c0(72 BuildingLiftOff)`, then `0x42a0c0(71, packed +0x58, +0x5c, clearOthers 0)` appends BuildingLand at the same target, then `0x429eb0(ReturnToIdle[type], 0)`. It then returns.
  - Otherwise it switches on state `+0x4e` (table `0x435eec`; values above 3 return):
  - State 0: let `s` = the signed vertical offset byte `+0xf` of the sprite's last (shadow) image (`0x416060`). It requests movement to `(x, y − s)`, where (x, y) is the order point, through `0x43a070`. State becomes 1.
  - State 1: returns until `0x41a250` reports arrival (nonzero). It then converts the order point into the footprint's top-left tile: `tx = trunc((x − trunc(w/2)) / 32)` and `ty` likewise, using the placement box `0x522728[type]` and signed truncating division. It calls placement check `0x412f10`(ECX = unit, DL = owner, stack [tx, ty, type, 0, 0, 1, 0]).
    - Nonzero (blocked): `0x4465e0` plays the race's "can't land here" error for the local player. If the queue head is PlaceAddon 36, that node is removed (`0x42a140`). It ends with `0x42a5a0`.
    - Zero: `0x419fd0` marks the footprint tiles with reservation flag `0x08000000` (through `0x412c40`). It sets landing timer `+0xcb = 1`, requests movement to the exact order point (`0x43a070`), sets flag `0x4` on the shadow image when that image uses palette type 10 (`0x416970`) and sets status `0x1000`. It sets top speed `+0x34 = 256` and current speed 256 (`0x40c220`). State becomes 2.
  - State 2: it computes `d = 0x40ba10`(sprite x, y → next target waypoint `+0x1c/+0x1e`). Unless velocity direction `+0x23 == d` or the waypoint equals the position (`0x40ba70`), it returns. Otherwise it plays animation 17 (Landing), sets state 3 and falls through.
  - State 3: requires arrival (`0x41a250` nonzero) and signal bit `0x10`, which it clears. Landing:
    1. `0x41a190` clears the footprint reservation and `0x41a210` removes the unit from the air spatial structures.
    2. `0x436fc0` changes status to grounded. The sprite elevation byte `+0xd` becomes 4. `0x436fe0(0)` clears the in-air bit.
    3. `0x43a270` relocates the unit to the order point and `0x41a050` reinserts it as a ground building.
    4. If the sprite is selected (flag `0x8`) and more than one unit is selected (`0x6ab4c0 > 1`), `0x4a7b80` removes the unit from the selection.
    5. Sprite cleanup: shadow offset 0 (`0x417260(0)`), clear shadow flag `0x4` (`0x417840`), landing dust (`0x415ce0`: when images.dat column `0x518c78` is nonzero for the primary image, two image-323 overlays are added from LO overlay 3), then the UI refresh `0x4a7ed0`. Landing timer `+0xcb = 0`.
    6. `0x435ae0` kills friendly units under the building (see its callback below).
    7. Queue cleanup. If the head order is Move 6 or Follow 49, BuildingLiftOff 72 is inserted before it (`0x429de0`). Otherwise `keep` = the head when its order is PlaceAddon 36, else null. Tail nodes are removed (`0x429d20`) until the tail equals `keep`. If the queue is then empty, ReturnToIdle is issued (`0x42a2c0`).
    8. `0x4370e0` lifts the building off again if an immobile armed unit remains underneath. Then `0x429d00`.
    9. `a = 0x431ae0(unit)` searches for an unattached neutral addon of the right type; if found, `0x4359c0(a)` connects it.
    10. If building placement mode is active (`0x47d070`), `0x47d530` refreshes the placement preview. If `0x47db60` then returns 0, `0x47d300(0, 0, 1)` cancels placement.
