# U01: `standard.snp`'s UDP provider

Package U01 specifies the "Local Area Network (UDP/IP)" provider of the 1.17 install's `standard.snp` (SHA-256 `429b480869bfe8722f9742f016ef84902f44c868ba4a8d5fccaa718a6c14b4c3`, preferred base `0x1d000000`): the two exports `SnpQuery` and `SnpBind`, the UDP provider's code (`Udp.cpp`, `0x1d0077c0`–`0x1d0096bf`), the shared code it reaches in the other providers' objects, the four table stubs Ghidra made no function of, and the 20 library functions the code calls directly. With [S02](s02.md) (Storm's network layer above the provider) it is stage N0 of the [network phase](../../phase-network.md); the wire format is collected in [storm-udp.md](../../formats/storm-udp.md). [S01](s01.md) holds the Storm exports the provider imports.

**Method.** Static analysis, as for S01 and S02: a Ghidra 12.2 export of the exact file and capstone disassembly, which is authoritative for calling conventions, widths, signedness and order. The binary, the decompiler output and the analysis database stay in the private workspace; no decompiled code is reproduced here. Storm's side of each slot was read in `storm.dll`'s disassembly (base `0x15000000`). `caps.dat`, the provider list inside the file's MPQ that Storm actually reads (S02 `ScanProviders` `0x15022a30`), was extracted and compared with `SnpQuery`'s records. Material from outside the binaries was not used as evidence.

**Review (2026-11-17).** An independent reviewer re-derived every entry from the disassembly (the 20 library entries from the import table and the linked runtime code), re-read the five provider tables, `SnpQuery`'s records and `caps.dat`, and checked the wire behavior against the network recordings of the full-game emulator (two- and four-player LAN games: packet captures of the virtual LAN). 62 entries are confirmed and 1 corrected (`AdvertReceiveThread` `0x1d0089d0`: the paths of a failed `recvfrom` and of the stop flag; no wire change). In the recordings every game-list datagram has a valid checksum and the documented layout, and all Storm traffic runs between ports 6112; the stop advertisement, the wake datagrams of `UdpDestroy` and oversized datagrams do not occur in them. Counts are in [storm-udp.md](../../formats/storm-udp.md#runtime-confirmation-2026-11-17).

**Addresses.** `standard.snp` addresses at base `0x1d000000`; Storm addresses at `0x15000000`; "game" addresses are `StarCraft.exe`'s at `0x400000`.

**Modules.** The objects were linked in name order, `Ipx.cpp`, `Modem.cpp`, `Serial.cpp`, `Udp.cpp` (the four `.cpp` names in the image); a function between two anchors gets a bracket as in the [README](README.md). The shared helpers lie in the IPX object; the code between `Modem.cpp` and `Serial.cpp` holds the single-player provider and the stubs all providers share; `SnpQuery`/`SnpBind` sit between `Serial.cpp` and `Udp.cpp`.

**Scope notes.**
- `excluded` here means that no path from StarCraft over the UDP provider reaches the code: Storm never calls the slot, or calls it only from exports StarCraft does not use with this provider (S01, S02). Each excluded entry still states its behavior.
- JSON `ordinal`: `standard.snp`'s own export ordinal for `SnpBind` (1) and `SnpQuery` (2), the imported Storm ordinal for the import thunks, otherwise null.
- Code outside the package that the summary refers to: the static initializer `0x1d0010c0` (not a Ghidra function) creates the provider lock `0x1d01c7ac` with `InitializeCriticalSection` when the DLL loads and registers `0x1d014f30`, which deletes it at unload; the DLL entry `0x1d0075f0` stores the module handle in `0x1d01c620` on process attach.

## Provider summary

### The providers in `standard.snp`

`SnpBind`(index) gives the function table, `SnpQuery`(index) the id, name, description and caps. Storm builds its provider records from `caps.dat`, not from `SnpQuery` (S02), and uses `SnpQuery` only to stop the scan (result 0, NULL or short caps, flag `0x10000000`).

| Index | Id | Name | Table | `SnpQuery` caps |
|---:|---|---|---|---|
| 0 | `'IPXN'` `0x4950584e` | Local Area Network (IPX) | `0x1d01b030` | `0x1d01b00c`, the same values as UDP |
| 1 | `'SCBL'` `0x5343424c` | Direct Cable Connection | `0x1d01b240` | `0x1d01b21c` |
| 2 | 0 | empty name and description | `0x1d01b1a0` | `0x1d01b178` |
| 3 | `'MODM'` `0x4d4f444d` | Modem | `0x1d01b0f0` | `0x1d01b0cc` |
| 4 | `'UDPN'` `0x5544504e` | Local Area Network (UDP/IP) | `0x1d01b2e8` | `0x1d01b2c4` |

Index 2 is the single-player provider, the "provider 0" StarCraft initialises for every offline game: id 0 (a zero dword at `0x1d01c584` that nothing writes), empty strings (so Storm never lists it, S01), 1 player, latency 0, 30 turns a second, and receive slots that never return data.

`SnpQuery`'s record at `0x1d01b2c4` and `caps.dat`'s UDP entry carry the same fields except the flags: `SnpQuery` reports `0x20000003`, `caps.dat` `0x00000003`. Storm's provider record, and so `SNetGetProviderCaps`, has `caps.dat`'s value; Storm itself tests only bit 0 (and its enumeration filter).

### Sockets

- **Winsock.** `wsock32.dll` is loaded with `LoadLibraryA` and ten functions are taken from it by ordinal into a 0x28-byte table `0x1d01c79c`: bind (2), closesocket (3), htons (9), recvfrom (17), sendto (20), setsockopt (21), socket (23), WSAGetLastError (111), WSAStartup (115), WSACleanup (116). `ws2_32.dll` is loaded as well, only for `WSAIoctl`; without it that step is skipped. There is no fallback from `wsock32.dll`: without it, or with any of the ten missing, Initialize fails.
- `WSAStartup`(version 0x101).
- **Two sockets**, both `socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP)`, blocking, read by threads:

  | Global | Port | Bound to | Carries |
  |---|---:|---|---|
  | `0x1d01c754` (socket A) | 6111 (`0x17df`) | `0.0.0.0` | the provider's own game-list datagrams: requests, advertisements, stops |
  | `0x1d01c780` (socket B) | 6112 (`0x17e0`) | `0.0.0.0` | Storm's datagrams, both directions |

- **Options**, in order: on A then B, when `WSAIoctl` is available, `SIO_UDP_CONNRESET` (`0x9800000c`) with FALSE, so an ICMP "port unreachable" does not fail the next `recvfrom` (a failure only calls `WSAGetLastError`); B is bound to port 6112, then A to 6111; then `SO_BROADCAST` = 1 on A and on B (results ignored). No receive or send buffer sizes, no `SO_REUSEADDR`, no non-blocking mode. A second instance on the same machine fails at the bind of 6112.
- **Local address.** The provider never learns its own address: no `getsockname`, no host name, no interface list (`WSAIoctl` is used for nothing else). Peers learn each other's addresses from the sources of received datagrams.
- **Broadcast address.** `0x1d01c758` holds `sockaddr_in` {AF_INET, port 6111, `255.255.255.255`}: every broadcast goes to the limited broadcast address on port 6111 through socket A. Which interfaces carry it is the operating system's choice.

### Addresses

Storm's 16-byte provider address (player record +0x108, game record +0xC, command 6's address field, S02) is, for UDP, the Winsock `sockaddr_in`:

| Offset | Size | Field |
|---|---|---|
| 0 | u16 little-endian | family, 2 |
| 2 | u16 big-endian | port |
| 4 | 4 | IPv4 address in network order |
| 8 | 8 | zero |

The receive threads zero bytes 8–15 of every source address (and any bytes beyond the length `recvfrom` reports), so Storm's 16-byte comparisons see one canonical form. A game-list entry's address is the advertiser's source address with the port replaced by 6112: a host's game socket must answer at the advertising IP on port 6112. Datagrams to a peer go to the address exactly as Storm holds it, so a peer's own source port is what the others reply to.

### Datagrams on port 6111

Every game-list datagram starts with an 8-byte header; integers are little-endian.

| Offset | Size | Field |
|---|---|---|
| 0 | u16 | checksum: Storm's packet checksum (S02 `FletcherSum`/`ComputePacketChecksum`) over bytes 2 to the end |
| 2 | u16 | length of the whole datagram |
| 4 | u16 | type: 0 advertisement, 1 stop, 2 request |
| 6 | u16 | 0 when sent; not checked |
| 8 | u32 | program id (StarCraft `'STAR'` `0x53544152`, Brood War `'SEXP'` `0x53455850`: the program data +0xC) |
| 12 | u32 | program version (program data +0x10; StarCraft 1.17: 0xD5) |
| 16 | u32 | type 0 and 1: the game's mode bits (S02: 1 password, 2 full, 4 advertised, 8 closed); type 2: 0 |

- **Advertisement (type 0)**, built by `UdpStartAdvertisingGame` in the zero-filled 0x214-byte buffer `0x1d01c750`: the header, then at +20 the game name and the stat string, each NUL-terminated (copied with `SStrCopy` limit 0x80), then Storm's 12-byte player record {u32 12, u32 players, u32 max players} (S02 `BuildPlayerCountInfo`). Length = 22 + strlen(name) + strlen(stat string) + 12. Password, uptime, game type, program data +0x28 and ladder type, which Storm also passes, are not sent. Sent by broadcast every time Storm advertises (game created, a join, a removal, a mode change: S02), and unicast in answer to each request while the buffer exists.
- **Stop (type 1)**: the current advertisement with type 1 and a new checksum, broadcast once by `UdpStopAdvertisingGame`; then the buffer is freed. Receivers drop the sender's entry.
- **Request (type 2)**: exactly 20 bytes, mode field 0. Broadcast when the advertisement thread starts (once per Initialize) and from `UdpUnlockGameList` when more than 400 ms have passed since the last one sent from there. StarCraft's join screen re-reads the list once a second ([P19](p19.md) `0x4596e0`), so a joiner broadcasts about one request a second. Any host holding an advertisement answers every request with it, unicast to the request's source address and port; the request's program id and version are not checked.
- **Acceptance** (`AdvertReceiveThread` `0x1d0089d0`): at least 20 bytes, the length field equal to the datagram's size, the checksum summing to 0; then types 0 and 1 go to `OnGameAdvertisement`, type 2 is answered, other types are ignored. A datagram above 532 bytes fails `recvfrom` and is ignored.
- **The wake datagram.** `UdpDestroy` sends the 8 bytes `08 EF 08 00 00 00 00 00` (u16 `0xEF08`, u16 length 8, then zeros) to `255.255.255.255:6111` from socket A and twice to `255.255.255.255:6112` from socket B, in each of up to five rounds, to wake its own blocked threads. Every machine on the segment receives them: port 6111 ignores them (shorter than 20 bytes); on port 6112 they are queued to Storm, which drops them (shorter than 12 bytes, S02).

### The game list

A receiver keeps one list `0x1d01c768` of 0x13C-byte records, the layout Storm copies (S02):

| Offset | Field |
|---|---|
| +0x000 | id: kept from the entry this one replaces, else the next value of the counter `0x1d01c77c` (first 1; 0 is skipped on wrap). Ids are local to the receiver |
| +0x004 | flags: the advertised mode |
| +0x008 | 0 |
| +0x00C | the sender's address with port 6112 |
| +0x01C | 50 (no reader in Storm 1.17) |
| +0x020 | `GetTickCount` at receipt |
| +0x024 | game type: 0 (not transmitted) |
| +0x028 | game name (0x80) |
| +0x0A8 | stat string (0x80) |
| +0x128 | next |
| +0x12C / +0x130 | copy of the bytes after the two strings (the player record) and their count |
| +0x134 / +0x138 | the advertised program id and version |

- **Filing** (types 0 and 1): every entry whose 16-byte address equals the sender's (port 6112) is removed, whatever the packet's program; a type-0 packet carrying the receiver's own program id then adds a new entry at the head, so the list runs from the most recently heard game. There is no limit on the number of entries.
- **Ageing**: `UdpLockGameList` first removes entries more than 10,000 ms old (unsigned `now − +0x20 > 10000`). A host keeps its entry alive only by answering requests.
- **Visibility**: Storm hides entries with any of mode bits `0xB` (S02 `CopyGameList`); the provider keeps them. StarCraft's list shows players and maximum players from the record's u32s at +4 and +8 (S01 `SNetEnumGamesEx`).
- **Joining**: `UdpGetGameInfo` zeroes Storm's record and copies the matching entry, so `SNetJoinGame` compares the joiner's program id and version with the advertiser's (a version mismatch is `0x85100079`), takes the host's address from +0xC, and sets the game type to 0. No entry → `0x85100068`.

### Storm's datagrams on port 6112

- **Receive.** One thread on Windows 9x and two on NT (`GetVersion` bit 31) run `GameReceiveThread` `0x1d008b80`: each allocates a 0x210-byte node {+0x000 source `sockaddr_in`, +0x010 up to 504 data bytes, +0x208 length, +0x20C next}, blocks in `recvfrom`(B, 504 bytes), appends the node to the tail of the queue `0x1d01c784` under the lock and signals Storm's pump event (S02 Threads). Nothing is checked: every datagram, from any source and of any content, goes to Storm, which validates it (S02 `ReceivePackets`).
- **Errors end a thread.** When `recvfrom` fails, the node is freed and that thread exits for good. A datagram above 504 bytes fails with `WSAEMSGSIZE`; without `SIO_UDP_CONNRESET`, an ICMP "port unreachable" would fail with `WSAECONNRESET`. After two such failures on NT (one on 9x) the provider receives nothing until it is destroyed and initialised again.
- **Storm's slots.** Receive pops the oldest node and returns its address, data and length; FreePacket frees the node. Send transmits one `sendto` from socket B per address, last address first, with no size check and the result ignored. The queue has no limit.

### Threads and locks

| Thread | Start | Priority | Loop |
|---|---|---|---|
| advertisement | `0x1d0089d0`, created first | `THREAD_PRIORITY_ABOVE_NORMAL` | broadcasts one request, then `recvfrom` on A until the stop flag `0x1d01c790` or socket A = 0 |
| game receive ×2 (×1 on 9x) | `0x1d008b80`, argument 0/1 | `THREAD_PRIORITY_HIGHEST` | `recvfrom` on B until the stop flag, socket B = 0 or an error |

Threads are created with the CRT's `_beginthreadex` and kept in the list `0x1d01c794` of 12-byte nodes {thread id, handle, next}. One critical section, `0x1d01c7ac`, guards the advertisement buffer, the game list and the receive queue; `UdpLockGameList` returns holding it and `UdpUnlockGameList` releases it, so the threads wait while Storm copies the list.

### Timers and constants

| Value | Use |
|---|---|
| 400 ms | minimum gap (strictly more) between requests from `UdpUnlockGameList`; the clock `0x1d01c7d0` starts at 0 |
| 500 | written to `UdpUnlockGameList`'s second argument, which `SNetEnumGamesEx` returns to StarCraft as its `*out` |
| 10,000 ms | game-list entry lifetime, checked at each `UdpLockGameList` |
| 500 ms × 5 | `UdpDestroy`: each round sends the wake datagrams and waits up to 500 ms in all for the threads; up to five rounds |
| 500 ms | the provider's own game dialog: refresh timer (not used by StarCraft) |

Storm's timers above the provider are S02's.

### Errors

- Initialize: `wsock32.dll` missing or incomplete → returns 0 without an error code; `WSAStartup`, `socket` (a zero handle) or either `bind` failing → `UdpDestroy`, error `0x4C6` (`ERROR_NETWORK_UNREACHABLE`), returns 0. Storm keeps the error and unloads the provider (S02); StarCraft's `InitNetworkProvider` `0x4757e0` reports it with `ReportStormError` `0x474b80` (network.tbl `0x53` and the system text of the error, [P26](p26.md)).
- Slots with NULL arguments set 0x57 (`ERROR_INVALID_PARAMETER`); Receive with an empty queue and ReceiveExternalMessage set `0x8510006B` (no messages waiting); GetGameInfo without a match sets `0x85100068` (game not found); StartAdvertisingGame without memory sets 8.
- "Unable to connect." appears only in the provider's own game-selection dialog, when `SNetJoinGame` fails from it. StarCraft opens that dialog only through `SNetSelectGame` on Battle.net's screens ([P16](p16.md) `0x449990`), so a UDP game never shows it.

### Interoperability

- **Byte order**: the provider's headers are little-endian; the address's port and IP are in network order (above).
- **Uninitialised bytes**: none. The advertisement is built in a zero-filled buffer, the request is built field by field, and the wake datagram is constant. Receive nodes are not zeroed, but only the received bytes are passed on.
- **Product and version**: entries of another program id are never filed (StarCraft and Brood War do not see each other's games); the version is compared only when joining.
- **Fixed ports**: game-list traffic is on 6111 and the game address of an advertised game is the advertiser's IP on 6112, so a host must be reachable there. Replies to requests go to the requester's actual source.
- **Limits a sender must respect**: Storm datagrams of at most 504 bytes (larger ones stop the receiver's threads, above); advertisement strings NUL-terminated within the datagram's length. When the strings run past the length, the receiver computes a negative size and `SMemAlloc` treats it as fatal (S01); a name of 128 characters or more makes the receiver's string walk land inside it.
- **Destroy without a stop**: `UdpDestroy` closes socket A before it stops advertising, so the stop it sends fails and a destroyed host's entry ages out after 10 s. Storm's `SNetLeaveGame` stops advertising before that for a host, so the normal leave does send the stop.

### Relation to S01 and S02

- Confirmed: the UDP provider's device list is empty (S01 `SNetEnumDevices`), so `SNetInitializeDevice` (116) is never called with UDP, and the slot would return 0 if it were. ReceiveExternalMessage never succeeds, so UDP raises no event 4 (S02 `PollExternalMessages`). The latency of 50 ms (S02 Timers). The provider signals the pump event once per datagram queued on port 6112, never for game-list traffic (S02 Threads).
- Refined: S01 and S02 note that the program id and version checked by `SNetJoinGame` fail only when the provider reports other values; the UDP provider always reports the advertiser's, so a joiner with another version gets `0x85100079`. The game type `SNetJoinGame` stores from record +0x24, and the one `SNetEnumGamesEx` passes to StarCraft, is always 0 with UDP.

## Entries

### 0x1d001990 `LockDeviceList` — the empty device list (shared)

- Module: standard.snp Ipx.cpp · Relevance: network · Status: specified

- Signature: cdecl, [esp+4] = block.
- Behavior: a non-NULL block is freed with `SMemFree`(block, `"delete"`, −1, 0); NULL does nothing.
- Callers/callees: `GameReceiveThread` (the node of an interrupted receive), IPX `0x1d0024d0`.

### 0x1d001f90 `FletcherSum` — the packet sum (shared)
- Module: standard.snp Ipx.cpp · Relevance: network · Status: specified
- Signature: register call, ECX = bytes, EDX = count; returns a u16 in EAX.
- Behavior: walks the bytes from the last to the first: a += byte, minus 255 when a reaches 255 or more; b += a (32-bit). Returns `(a & 0xFF) << 8 | (u8)(b + b/255)` (unsigned division), whose low byte equals b mod 255. The same function as Storm's `FletcherSum` `0x15021c50` ([S02](s02.md)): a datagram is valid when the sum over all of its bytes is 0.
- Callers/callees: `AdvertReceiveThread`, `ComputeAdvertChecksum`, `UdpStopAdvertisingGame`, `BroadcastGameListRequest`; the IPX, cable and modem code.
