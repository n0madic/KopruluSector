# P34: Save-game files and dialogs, map-scroll and parallax stars, per-player selections, SHA/RSA helpers and DirectSound setup

This package covers `0x499c50`–`0x49d900` (89 functions). It holds the tail of `saveload.cpp` and the objects between it and `scroll.cpp`, then `scroll.cpp` and the objects up to `snd.cpp`. The functions form eight groups.

1. **Save-file header and paths** (`0x499c50`–`0x49a130`, `0x49a4d0`, `0x49a8e0`). The text banner at the start of a save, the binary header that follows it, and the reader that restores the header and the core game block when a save is resumed. Also the directory and file-name builders and map-path normalization.
2. **Load-time restoration and DAT-backed tables** (`0x49a230`–`0x49a4a0`). The pending local selection that is reselected after a load. The getters and setters for per-player technology and upgrade tables, which are split between original-game and expansion arrays.
3. **File enumeration and the save list** (`0x49aa20`–`0x49ace0`). A recursive `FindFirstFile` walker, and the list of save records that the save and load dialogs show.
4. **Save and load dialogs** (`0x49add0`–`0x49b710`). `rez\savegame.bin` and `rez\loadgame.bin`, their control procedures, the overwrite and delete confirmations, and the multiplayer save cooldown.
5. **Scrolling and parallax stars** (`0x49b7c0`–`0x49bf10`). The `parallax\star.spk` loader, the full and dirty-rectangle star renderers, keyboard and mouse scroll input, the scroll speed table, and the scripted camera pan used by the Center View trigger.
6. **Selections** (`0x49c0f0`–`0x49cf80`). The eight per-player selection rows used by commands and the local selection array. Also the group-move formation used by right-click and targeted orders, and the targeted-order executor itself.
7. **Hash and signature helpers** (`0x49cff0`–`0x49d460`). Three SHA-1-like contexts used by the font decoder, and the `NGIS` RSA signature check.
8. **Sound support** (`0x49d520`–`0x49d900`). The streamed-sound list, DirectSound creation and primary-buffer setup, the RIFF/WAVE parser, and the loader for one sound effect by ID.

## Data model

**Save file** (written by `0x498d20`, read by `0x499c50`/`0x499890`):

1. The banner from `0x49a4d0`. It is ASCII text ending with byte `0x1a`, and readers skip it by reading bytes until `0x1a`.
2. A raw DWORD tag `0x00690003`. Readers check only its high WORD, `0x0069`.
3. A compressed `0xb5`-byte header (`0x4137d0`/`0x413ae0`) with this layout:

   | Offset | Contents |
   |---|---|
   | `+0` | WORD format version `0x69` |
   | `+2` | WORD sub-version `3` |
   | `+4` | DWORD RNG state (`0x4781d0`) |
   | `+8` | DWORD 0 |
   | `+0xc` | the `0x8d`-byte game header `0x6728d0` (its `+0x1c` is the save ID, so it lands at header `+0x28`) |
   | `+0x99` | the 28-byte save name |

4. The compressed player table `0x6726c8` (`0x1b0` bytes).
5. The compressed core game block `0x5263d0` (96,000 = `0x17700` bytes).
6. A raw DWORD holding the saving machine's local slot `0x508d54`.
7. The remaining pools, which `0x498d20`/`0x499890` write and read (not in this package).

**Save list** (TSList header `0x509374`: `+0` link offset, sentinel at `0x509378`, whose `+4` (`0x50937c`) is the first node). Each node is `0x28` bytes: `+0/+4` link (prev, encoded next; a next ≤ 0 marks the end), `+8` save ID, `+0xc` NUL-terminated name. The count is WORD `0x6a5e9c` (maximum 128).

**Dialog state**: `0x6a5e7c` record ID of the pending overwrite or delete; `0x6a5e80` pending name (28 bytes); BYTE `0x6a5e9e` remembered list index; `0x6a5ea0` `GetTickCount` of the last save command; BYTE `0x671a81` menu depth.

**Selections**: `0x6a5ef0 + 0x30·p` (p = 0…7) are the per-player rows of 12 unit pointers. Each row is filled from index 0 and ends at the first null. `0x6a6070[12]` is the local selection, and BYTE `0x6a60a0` is the iteration cursor of `0x49cb10`/`0x49cb20`. `0x6a5e48[12]` holds the selection to restore after loading a save.

**Formation record** F (on the caller's stack):

| Offset | Contents |
|---|---|
| `+0` | target x, y (s16) |
| `+4` | per-unit point output |
| `+8` | copy of the target |
| `+0xc` | adjusted target |
| `+0x10` | offset dx, dy |
| `+0x14` | DWORD total footprint area |
| `+0x18` | WORD side |
| `+0x1a` | BYTE flags: 1 = x offset valid, 2 = y offset valid, 4 = target inside the group box, 8 = group contains a pathing (ground) unit |

**Parallax** (`parallax\star.spk`, buffer `0x6a5ed0`):

- File layout: WORD layer count n, then n WORD star counts, then star records of 8 bytes: WORD x, WORD y, DWORD file offset of an image. On load the offset is replaced by a pointer. Each image is WORD w, WORD h, then w·h palette bytes, where 0 means transparent at the destination.
- Star counts are stored at `0x6a5ea4 + 4i`. Layer record pointers are `0x6a5eb8`, `0x6a5ebc`, `0x6a5ec0`, `0x6a5ec4` and `0x6a5ec8`.
- Wrap sizes are `0x543250 = 0x28800` and `0x543254 = 0x1e800` (648 × 488 pixels in 8.8 fixed point).
- Per-layer offsets: X[k] at `0x543268 − 4k`, Y[k] at `0x54327c − 4k`. They are maintained by the scroll routines in [P03](p03.md) with factors 16, 21, 26, 31 and 36.

## Tables

- `0x509380` (4 entries, installed by `0x4c25b0` with byte size 16) maps control ID n to entry n−1: 1 → `0x49b500` (save list), 2 → `0x49b4d0` (name edit), 3 → `0x46c7a0` (button forwarder, [P23](p23.md)), 4 → none.
- `0x49ced4`/`0x49cedc` jump table of `0x49cc40`: an index byte per order 0…155 selects target 0 (`0x49ceca`, return at once) or 1 (`0x49cc85`, process). Orders above 155 are processed. Index 0 (ignored) is used by orders 0, 15, 20, 25, 29–33, 36, 46, 71–73, 80–83, 85–89 and 155.
- `0x509390` scroll speeds and `0x5093ba` pan thresholds, listed above.

### 0x00499c50 `ReadSaveHeaderAndGameBlock` — restore header, player table and core block of the save being loaded
- Module: saveload.cpp..scroll.cpp · Relevance: data
- Status: specified
- Signature: no arguments (file `0x6a5e34`); returns 1/0.
- Behavior:
  1. Remember the expansion byte `0x536720`. Read bytes (`fgetc` via `0x4cc3b0`) until `0x1a`.
  2. Read the tag and header with `0x49a0c0`(header buffer, file). Then WORD `0x6a5e78` = header sub-version `+2`, and the `0x8d` bytes at header `+0xc` are copied to `0x6728d0`.
  3. Zero `0x5263d0` (96,000 bytes).
  4. Read compressed `0x1b0` bytes. The destination is `0x6726c8` in single player. In multiplayer (`0x672664`) it is `0x6726c8` only when `IsGlueGameActive` `0x475360` is nonzero, otherwise a discarded stack buffer.
  5. Read compressed `0x17700` bytes into `0x5263d0`, then 4 raw bytes into `0x6a5e44`.
  6. If the restored `0x536720` is nonzero, `GetExpansionDataFlag` `0x4635b0` must be nonzero. The restored `0x536720` must equal the remembered value.
  7. Older sub-versions are migrated by raw byte copies; there is no per-player restriding:
     - Sub-version < 2: `0x534f20` = DWORD `0x5349dc`, and the `0x500` bytes at `0x534a20` are copied to `0x534f40` (switches and locations).
     - Sub-version < 3: the 36 bytes at `0x534344` are copied to `0x536510`, and the 72 bytes at `0x5347b8` to `0x5366c0` (tech and upgrade in-progress bits).
  8. If the campaign key WORD `0x526524` = 0, the map path `0x52701c` is resolved again with `ResolveGameFile` `0x45cb90`(copy, `0x52701c`, 0x104).
  9. `0x6a5e3c` = header `+0x28` (the save ID). Return 1.
  10. Any failure, including end of file before `0x1a`, closes the file (`fclose` `0x4cc370`) if it is open, sets `0x6a5e34` = 0 and returns 0.
- Callers/callees: `CreateGameFromSave` `0x443d20` ([P14](p14.md)), `InitJoinedLobby` `0x474c60` ([P26](p26.md)).

### 0x00499e80 `BuildSaveDirectory` — user directory plus `save\<player>\`
- Module: saveload.cpp..scroll.cpp · Relevance: data
- Status: specified
- Signature: ECX = player name, EDX = output, stack [size, replay flag]; `ret 8`; returns 1/0.
- Behavior: The name must be shorter than 25 characters, or the result is 0. Get the Storm user directory with a trailing `\` (ordinal 296, [S01](s01.md)); its length plus 36 must be below size, or the result is 0. The output starts with the user directory, then one of:
  - flag ≠ 0: `maps\replays\`;
  - multiplayer `0x672664`: `maps\` and `save\`;
  - otherwise: `save\`, the name and `\`.

  All appends use `SStrNCat` with the full size. Returns 1. Every caller (`0x498a70`, `0x498b30`, `0x4991b0`, `0x499f70`) passes flag 0, so the replay branch is unused.

### 0x0049a130 `StripKnownDirectoryFromMapPath` — make the map path relative

- Status: specified

### 0x0049a240 `RestoreSavedLocalSelection` — reselect the units remembered at load
- Module: saveload.cpp..scroll.cpp · Relevance: ui
- Status: specified
- Signature: no arguments.
- Behavior:
  1. Scan `0x6a5e48[0…11]` and stop at the first null. Keep each unit that is not dead or dying (`0x41fe20`) and whose sprite visibility byte `+0xc` has a bit of the local vision mask `0x672668`.
  2. If any were kept, call `0x4bce70`(ECX = count, EDX = list, stack [0, 1]): a local select without sound that is sent as commands (`0x4bce70` forwards to `0x49cf80`(n, list, [0, 1]); only for a single unit with Alt `0x665e6a` held does it first try `0x464030`(packed ref) and skip the select when that returns nonzero).
  3. Then `0x4a7ed0` (console refresh).
- Callers/callees: `RunGame` `0x445310`, unconditionally. In a new game the list is empty because `0x49a340` copied a just-cleared row.

### 0x0049a4d0 `WriteSaveBanner` — human-readable text before the binary data
- Module: saveload.cpp..scroll.cpp · Relevance: data
- Status: specified
- Signature: ECX = file, EDX = file path; returns 1/0.
- Behavior: Writes these lines, each without its terminating NUL (`fwrite` of `strlen` bytes through `0x4cc4a0`); every write must succeed:

  8. ` SCM Title:  ` + `0x67291d`.

- Callers/callees: `0x498d20`.

### 0x0049a8e0 `WriteSaveTagAndHeader`
- Module: saveload.cpp..scroll.cpp · Relevance: data
- Status: specified
- Signature: ECX = save ID, stack [file]; `ret 4`; returns 1/0.
- Behavior:

### 0x0049aa20 `EnumerateFiles` — find files, optionally recursing

- Callers/callees: `0x440420`, `0x498a70`, `0x498bd0`, `0x4991b0`, `0x499450`, `0x4995e0` (save/replay listing).

### 0x0049ace0 `AddSaveListRecord` — enumeration callback for one save header
