# P26: Network error reporting, Storm session glue, the turn and command pipeline, network player records, the game RNG and the replay command recorder

This package covers `0x4748d0`–`0x4788b0`: `net_error.cpp`, `net_glue.cpp`, `net_mgr.cpp`, `net_misc.cpp`, `net_player.cpp` and the start of `net_record.cpp`, with the objects between them. Single player runs through most of it. Storm's local provider (ID 0) creates a one-player "network" game, and every player action travels through the same turn pipeline as in multiplayer. The functions form six groups.

1. **Error reporting** (`0x4748d0`–`0x474b80`). A report has a `rez\network.tbl` index (`0x43f0c0`), an optional detail string and an optional source file and line. A fatal report leaves the Storm game, latches `0x6728b8`, shows the message and requests a glue exit. While the latch is set, every later report is ignored. Reports raised while no dialog can show them are deferred in `0x6728bc..0x6728c8` and shown by the next glue screen (`0x458790` → `0x474980`).
2. **Session glue** (`0x474bf0`–`0x475a20`). This group contains provider initialization `0x4757e0` (single player passes provider 0), single-player game creation `0x475220` and the multiplayer create/join/list code. It also holds the current game header `0x6728d0` (`0x8d` bytes; layout in [P20](p20.md) and [P15](p15.md)), the flag `0x672970` (this seat created the game: `0x475040` and `0x475220` set it and `JoinNetworkGame` `0x475610` clears it, so in a lobby it marks the host) and the provider ID `0x672974`.
3. **Turn pipeline** (`0x475a60`–`0x476e20`). Commands are queued into the outgoing turn buffer `0x6729d8` by `0x476c80`. `0x476500` sends turns until the provider's turns-in-transit target is met, padding empty turns with a keep-alive byte `5`. In game it also queues a 7-byte sync command `0x37` after every sent turn (`0x47a300`). `0x475ac0` receives one turn per Storm player (`SNetReceiveTurns`). `0x4768a0` then executes each player's commands through the dispatcher `0x475d30`, with the game RNG enabled. Before the game loop starts (`0x67298c` = 0) the lobby dispatcher `0x476650` runs instead; the offline briefing room uses it for the Start command `0x54`. `0x476c00` is the per-frame entry ([PollTurn](p15.md)).
4. **Network player helpers** (`0x476ef0`–`0x4781a0`). They cover the game-result vector, alliance initialization, leave and drop handling, the Battle.net test and the 8-record network player table `0x673818`.
5. **Game RNG** (`0x4781c0`–`0x478270`), covered by [native-prng.md](../native-prng.md) and [native-frame.md](../native-frame.md).
6. **Replay command recorder** (`0x4782d0`–`0x4788b0`). The recorder object `*0x673d40` keeps a growable buffer of frame blocks. Every executed command except twelve housekeeping IDs is appended under the Storm ID of its sender. In replay playback `0x4769b0` reads the blocks back and feeds them to the dispatcher.

The unlisted thunk `0x474ef0` (`jmp 0x4716d0`, called from `0x4baea0`) lies inside this range but is not an atlas function.

## Data model

**Turn state (net_mgr)**

| Address | Meaning |
|---|---|
| `0x672670[8]` | Per-Storm-ID turn status DWORDs written by `SNetReceiveTurns`. Bit `0x10000` = player present, `0x20000` = turn data present this turn, `0x40000` is counted by `0x47a630`. `0x4768a0`/`0x475d30` overwrite an entry with `0x10000` to mark a desynchronized player. |
| `0x672994[8]`, `0x6729b4[8]` | Received turn data pointer and size per Storm ID. |
| `0x6729d8` (bytes), `0x6729d4` (DWORD size) | Outgoing turn buffer; capacity `0x67265c`. |
| `0x67265c` | Maximum message size from provider caps, clamped to ≤ `0x200` (init requires ≥ `0x80`). |
| `0x672660` | Turns-in-transit target: 1 for provider 0, else `max(2, min(8, caps.defaultTurnsInTransit))`. |
| `0x672990` | Extra latency turns 0–2 (command `0x55`), added to the target in game. |
| `0x67298c` | Game-loop flag (set by `0x476e00`): selects the game dispatcher and enables sync and latency. |
| `0x672658` | Turn counter (incremented per executed turn). |
| `0x672665` | Byte: turns were received this poll. |
| `0x6737e8` | Tick of the last received turn; `0x475ac0` reports "still alive" for 2500 ms (`0x9c4`) after it. |
| `0x672984` | Byte: commands are executing. `0x672985`: a pause/resume handler asks for `0x448c20(0)` after the turn. |
| `0x672988` | Count of keep-alive (`5`) and sync (`0x37`) commands seen in the player's turn. |
| `0x672bd8` | Some player was marked desynchronized this turn → `0x47a630`. |
| `0x672986` | Briefing ready state: 0 idle, 1 armed, 2 Start sent. `0x672bdc[8]` ready bytes per Storm ID (set by command `0x54`). |
| `0x508d4c` | Storm ID whose commands are executing (8 or `0x508d58` otherwise). `0x508d44`/`0x508d48` = that player's game player ID and player-record index; restored to the local `0x508d50`/`0x508d54` afterwards. `0x508d58` = local Storm ID. |
| `0x672878[8]`, `0x672898[8]` | Storm ID → game player ID and → player-record index (8 = none); rebuilt by `0x4793b0`. |

**Network player table** `0x673818 + 0x22*id` (8 records, `0x110` bytes): `+0` byte state (0 none, 1 active, 2 left), `+2`, `+4`, `+6` WORDs from the join handshake, `+8` name (25 bytes). Only multiplayer join handlers (`0x470af0`, `0x470ee0`) fill it. In single player every record is zero, so `0x4780a0` returns 0 for all IDs.

**Replay recorder** (`0x20` bytes at `*0x673d40`): `+0` recording enabled (1 when created), `+4` playback flag (not written by the constructor `0x4788b0`; `0x4789f0`, called by `StartGame` `0x443f40` for a replay, sets `+4` = 1, `+0` = 0 and the cursor `+0x1c` = buffer start; `0x478a10` at `EndGame` `0x443db0` clears it), `+8` buffer, `+0xc` used bytes, `+0x10` capacity (50 000 initially, grows by 10 000), `+0x14` pointer to the payload start of the open block (0 = none), `+0x18` frame of the open block (−1 initially), `+0x1c` read cursor. Block format: DWORD frame (`0x52651c`), BYTE payload length, then entries `{BYTE Storm ID, command bytes}`. The length byte of the open block is written only when the block is closed (`0x4787e0`, `0x478340`) or when the buffer is saved (`0x478980`). Commands **not** recorded (table `0x4ef2fc`): `0x37, 0x05, 0x06, 0x07, 0x08, 0x10, 0x11, 0x38, 0x39, 0x3a, 0x3b, 0x55`.

**Playback scratch** (used by `0x4769b0`): `0x672980` command count, `0x672be8[]` Storm ID bytes, `0x672de8` command bytes (`0x200`), `0x672fe8[]` command lengths, `0x508d68` frame of the buffered commands (−1 = none, reset by `0x476d80`).

**Command length table** `0x4ef048` (signed DWORD per command ID, read by `0x4720c0`; IDs 9–`0xb` instead use `2 + 2·count`, their table value 26 is unused). All IDs in hex: 5→1, 6→33, 7→33, 8→1, `0xc`→8, `0xd`→3, `0xe`→5, `0xf`→2, `0x10`→1, `0x11`→1, `0x12`→5, `0x13`→3, `0x14`→10, `0x15`→11, `0x18`→1, `0x19`→1, `0x1a`→2, `0x1b`–`0x1d`→1, `0x1e`→2, `0x1f`→3, `0x20`→3, `0x21`→2, `0x22`→2, `0x23`→3, `0x24`→1, `0x25`→2, `0x26`→2, `0x27`→1, `0x28`→2, `0x29`→3, `0x2a`→1, `0x2b`–`0x2d`→2, `0x2e`→1, `0x2f`→5, `0x30`→2, `0x31`→1, `0x32`→2, `0x33`→1, `0x34`→1, `0x35`→3, `0x36`→1, `0x37`→**1**, `0x38`→1, `0x39`→1, `0x3a`→2, `0x3b`→2, `0x55`→2, `0x56`→10, `0x57`→2, `0x58`→5, `0x5a`→1, `0x5c`→82; all other IDs (0–4, `0x16`, `0x17`, `0x3c`–`0x54`, `0x59`, `0x5b`, `0x5d`–`0x5f`) → −1. `0x4720c0` does not bound the ID. The table differs from the dispatcher `0x475d30` for the sync command `0x37` (table 1, dispatcher 7) and for `0x24` (table 1, dispatcher stops); neither difference matters in practice, because `0x37` passes the replay filter and is never recorded, and `0x24` is never generated.

## Functions

### 0x004748d0 `StoreDeferredNetError` — keep a report for later
- Module: net_error.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, ECX = network.tbl index, EDX = detail string or 0, stack `[file, line]`, `ret 8`.
- Behavior: `0x6728bc` = index. For the detail and the file separately: a null or empty string stores 0; otherwise `SStrLen + 1` bytes are allocated (`SMemAlloc`, "net_error.cpp" line `0x24`) and the string with its terminator is copied. The detail copy goes to `0x6728c0`, the file copy to `0x6728c4`; `0x6728c8` = line. Earlier copies are not freed.
- Callers/callees: `0x474a70` only.

### 0x00474980 `FlushDeferredNetError` — show the stored report

- Status: specified

### 0x00474a00 `ReportNetError` — show a network.tbl message, optionally fatal
- Module: net_error.cpp..net_glue.cpp · Relevance: ui
- Status: specified
- Signature: ECX = network.tbl index, EDX = detail string, stack `[file, line, fatal]`, `ret 0xc`.
- Behavior: Nothing while the latch byte `0x6728b8` ≠ 0. With fatal = 0 it calls `0x474a70`(ECX = index, EDX = 0, 0, 0): message only; the detail, file and line are dropped. With fatal ≠ 0 it calls `0x477e50`(3) (leave the Storm game) and sets `0x6728b8` = 1. It then calls `0x474a70`(index, detail, file, line). If the mode word `0x6662b8` = 3 (in game) it ends the game with `0x444e00`(4), and finally it calls `RequestGlueExit` `0x457cf0`.
- Callers/callees: 24 sites, including game start (`0x443790`, `0x443850`, `0x443900`, `0x443970`, `0x443c70`, `0x443d20`, `0x443f40`) and save/load.

### 0x00474a70 `ShowNetErrorMessage` — display or defer
