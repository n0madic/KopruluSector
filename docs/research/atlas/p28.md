# P28: Right-click orders, cinematics, replay files and controls, flyer repulsion, region accessors and the AI banker

This package covers `0x47eb00`–`0x483bd0` (224 functions): the end of the object between `placebox.cpp` and `replay.cpp`, `replay.cpp`, `repulse.cpp`, `sai_banker.cpp` and the objects next to them. The functions form eight groups.

1. **Team start units, cinematics and the draw heap** (`0x47eb00`–`0x47ef20`). Team-game start units (multiplayer only), Smacker cinematic playback with skip handling, and the max-heap that orders sprites for drawing ([P05](p05.md) calls it).
2. **Right-click resolution** (`0x47ef40`–`0x47fc60`). Mouse and minimap handlers queue command `0x14`; its executor `0x47f680` asks a per-class selector for each selected unit which order a right-click means, then issues it. `0x47f530` repeats the resolution for a fogged right-click once the point becomes visible.
3. **Replay files** (`0x47fd60`–`0x4808d0`). The in-memory replay header `0x67cca0`, `.rep` writing/reading, `LastReplay` copies, and the `/replay show|hide` chat commands that set a leaderboard.
4. **Save-replay dialog** (`0x480900`–`0x481450`). `rez\savegame.bin` with a list of saved replays, a name edit box and a Delete button. Its only entry is the score-screen Save Replay button (`0x4620c0`), which is disabled for replays, loaded saved games, campaign missions (`0x526524` ≠ 0) and when the spawn flag is set (it is 0 on this install, [V01](v01.md)); the dialog is therefore reachable after a non-campaign game, not in the offline campaigns.
5. **Replay speed controls** (`0x480d70`–`0x481040`). Command-card buttons (pause, slower, faster), the speed/multiplier/pause state and the elapsed-time display.
6. **Flyer repulsion** (`0x4814e0`–`0x481880`). Air units register in a 171 × 171 grid of 48-pixel cells; where two or more share a cell, each pushes its prepared movement position sideways every frame.
7. **Region accessors and pathing lifecycle** (`0x481a00`–`0x481d80`). Thin readers of the SAI pathing structure `*0x69b584` (layout of BWAPI `SAI_Paths`), plus creation/free wrappers.
8. **AI banker** (`0x481d90`–`0x483bd0`). The eight PlayerAi records at `0x67d068` (stride `0x4e8`): budget and demand, the spending-request heap, script flags, defense and attack rosters, save/load, and the building/worker AI record pools.

## Data model

**Right-click selector table** `0x508e18[7]`, indexed by the units.dat right-click class (`0x422d90`; hallucinations of class 4/5 use class 1). Every selector takes ECX = unit, EDX = x, stack [y, &target, fog-ghost type] and returns an order ID; 23 (Nothing) means "do nothing", 8 is replaced by the unit's units.dat attack-unit order `0x521008[type]`.

| Class | Selector | Meaning |
|---|---|---|
| 0, 6 | `0x47ef40` | none (always 23) |
| 1 | `0x47ef50` | move / attack / follow / board |
| 2 | `0x47f070` | move only (rally for producer buildings, Queen infest, Medic heal-move) |
| 3 | `0x47f010` | attack only (else return-to-idle order) |
| 4 | `0x47f2c0` | harvest (workers) |
| 5 | `0x47f180` | harvest and repair (SCV) |

`0x67cc68` is a secondary order byte that every resolution resets to 23; `0x47f680` issues it as a second command when a selector changed it (no selector in this package does).

**Replay header** `0x67cca0` (633 bytes, BWAPI `ReplayHeader`): `+0` Brood War flag, `+1` frame count (`0x67cca1`), `+5` campaign mission ID (`0x67cca5`), `+7` 13-byte seed record (`+8` RNG seed `0x67cca8`), `+0x14` 141-byte network game header (`0x67ccb4`; speed `+0x3a` = `0x67ccda`, slots `+0x39`), `+0x46` saved flag (`0x67cce6`), `+0xa1` 12 player records of 36 bytes (`0x67cd41`), `+0x251` 8 colour DWORDs (`0x67cef1`), `+0x271` 8 force bytes (`0x67cf11`). File layout: compressed blocks (`0x4137d0`/`0x413ae0`) holding the magic `0x53526572`, the header, the command buffer ([P26](p26.md) recorder), the CHK size and the CHK data. Other replay globals: `0x67cc74`/`0x67cc78` CHK size/data, `0x67cc7c` paused, `0x67cc80` pause-blink, `0x67cc8c` blink tick, `0x508e34` speed multiplier (static 1), `0x508e38` last shown second (static −1), `0x67cf40[7]` replay frame times, `0x67cf19` dialog list selection, `0x67cf1c` dialog name buffer, `0x67cc98` dialog background path, `0x67cc70` list being filled.

**Repulse fields** (CUnit): `+0x14c` low 3 bits re-aim countdown, high nibble jitter index (0 = re-roll on next registration); `+0x14d` push angle (256 = full turn, 0 = north); `+0x14e/+0x14f` registered cell (x/48, y/48). Grid `0x67cf60` (`0x7239` bytes, row stride 171). Eligibility everywhere: status `0x20000`, not a units.dat building (`0x1`), not an Interceptor (73).

**Region record** (`*0x69b584 + 0x449fc + 64·id`): `+0` accessibility WORD (`0x1ffd` = inaccessible), `+2` connectivity group, `+6` ground-neighbor count, `+7` neighbor count, `+0xc` neighbor ID array, `+0x10/+0x14` center (8.8 fixed), `+0x18` box (4 WORDs), `+0x20` rank byte, `+0x21` signed byte subtracted from `+7`. Tile map `+0xc` (256 × 256 WORDs); split tiles at `+0x2000c` (6 bytes: mask, region for clear bits, region for set bits).

**PlayerAi** (`0x67d068 + 0x4e8·player`; field names follow [AI opcodes](../native-ai-opcodes.md)):

| Offset | Meaning |
|---|---|

| `+0x210` | heap count |

### 0x0047eb00 `CreateTeamStartingUnits` — start units for team-game leaders
- Module: placebox.cpp..replay.cpp · Relevance: simulation
- Status: specified
- Signature: no arguments; no return value.
- Behavior: Reached only from `CreateStartingUnitsAndView` `0x469e90` in team mode (`0x4b2d90`: multiplayer byte `0x672664` and team mode `0x67294d` both nonzero), so single-player games never run it. For team `t` = 1 up to the team count (`0x4b2bc0`: 2 for Top vs Bottom, else `0x67294d`; re-read on every iteration, unsigned byte):
  1. Skip the team unless a slot of force `t` (`0x6726d2 + 0x24·p`) has controller 2 (`0x4b2d20`) or controller 1 or 5 (`0x4b2cf0`).
  2. `leader = 0x5264ab[t]`; `size` = team size from `0x4b2b10` (team mode 2 → 4, 3 → 3, 4 → 2; other values raise the `Teams.cpp` line `0x71` fatal report); `base = byte(size · (t − 1))`.
  3. If starting units `0x672949` = 2: `0x47df00`(CL = race `0x5264a0[base]`, DL = leader) creates the leader's town hall. If that race byte is 0 (Zerg), `0x47e080`(CL = leader) also creates the Overlord.
  4. For `i` = 0..3: `k = base + i % size` (signed); the race is `0x5264a0[k]` when `k < 8`, else `0x5264a1[base]`. When `0x672949` is 1 or 2, the worker type is race 0 → 41 Drone, 1 → 7 SCV, 2 → 64 Probe, anything else → 228; `CreateUnit` `0x424900`(type, x = `0x534a00[leader]`, y = `0x534a02[leader]` (signed WORDs), owner = leader), and a non-null result goes to `CompleteUnitWithPlacement` `0x424db0`.
  So each team leader receives four workers whose races cycle through the team members' race bytes.
- Globals/fields: `0x5264a0` per-team-position race bytes, `0x5264ab[1..4]` team leaders, `0x534a00` start locations (x, y WORD pairs), `0x672949`, `0x67294d`.
- Callers/callees: `0x469e90` only. Calls `0x4b2bc0`, `0x4b2d20`, `0x4b2cf0`, `0x4b2be0`, `0x4b2b10`, `0x47df00`, `0x47e080`, `0x424900`, `0x424db0`.

### 0x0047ec60 `PlayCinematic` — play one `smk\*.smk` movie with skip handling
- Module: placebox.cpp..replay.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, ECX = cinematic index 0..27; returns `0x675270` (1 = skipped or quit requested, 0 = played to the end).
- Behavior:
  1. `HideCursorLayer` `0x43e590`, `ResetInputHandlers` `0x43f330`, then installs `0x47ec30` for input event types 5, 8 and 15 and clears `0x675270`.
  2. `SVidPlayBegin`(name `0x508da8[index]`, 0, 0, 0, 0, flags, &handle). Flags are `0x10280808` for index < 25 and `0x10a80808` for 25..27 (the Brood War mission cinematics).

- Data: `0x508da8[28]` movie names: 0 `blizzard`, 1 `starintr`, 2–5 `PreTerran_1..4`, 6–9 `Terran1..4`, 10–12 `PreZerg_2..4`, 13–16 `Zerg1..4`, 17–19 `PreProtoss_1..3`, 20–23 `Protoss1..4`, 24 `starXintr`, 25 `xProtoss`, 26 `xTerran`, 27 `xZerg` (all `smk\<name>.smk`).

### 0x0047edd0 `HeapSortDrawList` — sort the heap and return the first sprite
- Module: placebox.cpp..replay.cpp · Relevance: render
- Status: specified
- Signature: no arguments; returns a sprite pointer or 0.
- Behavior: Empty heap → 0. Otherwise `0x67c7b4` = count − 1 and an in-place heap sort runs: repeatedly the root sprite is appended to the output array `0x67a0a0` (ascending output index), the last heap entry is sifted down from the root (children `2i`, `2i+1`; the larger key wins, the right child only when its key is strictly greater; stops when the moving key is ≥ the child key), and the count drops by one, until the count is 0. The output therefore holds sprites in descending key order; the function returns `0x67a0a0[0x67c7b4]` (the smallest key), and `0x47ef20` walks the array downward towards larger keys.
- Callers/callees: `DrawSortedSprites` `0x415b30` ([P05](p05.md)).

### 0x0047f680 `ExecuteRightClickCommand` — command `0x14` for the issuing player's selection
