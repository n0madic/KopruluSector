# P21: Map-list tail, modem screens, glue popups, campaign ready rooms (briefings) and the score screen

This package covers `0x45de70`–`0x4634df`: the tail of the object between `glumap.cpp` and `glumodem.cpp`, `glumodem.cpp`, the object between `glumodem.cpp` and `glupopup.cpp`, `glupopup.cpp`, the object between `glupopup.cpp` and `glurdy.cpp`, `glurdy.cpp`, the objects between `glurdy.cpp` and `glurdyp.cpp`, `glurdyp.cpp`, `glurdyt.cpp`, `glurdyz.cpp` and `gluscore.cpp`. Its 118 functions fall into six groups.

1. **Map-list tail** (`0x45de70`–`0x45dfc0`, 3 functions; the rest of `glumap.cpp` is in [P20](p20.md)). Two Storm container helpers used by the map-list hash table of `glumap.cpp` (`TSHashTable<HASHENTRY,HASHKEY_CONSTSTRI>`, constructor `0x45ade0`), and `0x45dfc0`, which publishes the selected map/save/replay entry to the map-information callbacks of the Create Game / Play Custom screen ([P19](p19.md)). All in scope.
2. **Modem and AppleTalk screens** (`0x45e1c0`–`0x45f990`, 33 functions). Glue state 20 (`rez\gluModem.bin`, phone book, dialing status) and the device/zone pickers that the network-provider hook `0x4757e0` opens for the `'MODM'` and `'ATLK'` providers. Glue state 20 is set only when the multiplayer provider is `'MODM'`/`'MDMX'` (login `0x459f10` with `0x672664` ≠ 0, chat `0x451470`, create `0x455550`, and the provider-to-state helper `0x457e50` used by the multiplayer branches of the ready rooms and score screen), so the group is `excluded`, except `SetupModemProvider` `0x45e380`: `0x4757e0` calls it for every provider, including provider 0 on each offline game creation, where it finds no devices and returns 1, so it is `specified`.
3. **Glue popups** (`0x45fa70`–`0x460740`, 24 functions). `glupopup.cpp`: the text-entry popup (`rez\gluPEdit.bin`, used for "Enter new character name"), the OK, split OK and OK/Cancel popups (`gluPOk.bin`, `gluPOkSplit.bin`, `gluPOkCancel.bin`) that the glue message boxes delegate to, the Original/Expansion game-mode popup (`gluGameMode.bin`) and the campaign mission-history popup (`gluHist.bin`, "Select starting mission"). All in scope except three helpers whose only callers are modem code.
4. **Briefing owner expansion** (`0x4607e0`, `0x4609c0`). The MBRF section loader's per-record owner filter and a generic list-free helper.
5. **Campaign ready rooms** (`0x460a20`–`0x461840`, 29 functions). `glurdy.cpp` runs the briefing of every campaign mission: the MBRF list runner (100 ms timer), the scrolling text box, objectives, portrait slots, Start / Cancel / Replay / Skip Tutorial, and the ready handshake that starts the game. `glurdyp/t/z.cpp` are the three race screens (glue states 9, 7, 8). All in scope; multiplayer-only branches are stated.
6. **Score screen** (`0x4618a0`–`0x463350`, 27 functions plus the unlisted Units-tab callback `0x462c10`). `gluscore.cpp`: the roster captured at game start, the victory/defeat score screen (glue states 14–19, `rez\gluScore.bin`) with its four tabs, sorting, count-up animation and Save Replay button. The XML game report for Battle.net ladder and its time formatter are `excluded`.

## Shared conventions

**Dialog machinery** is as in [P17](p17.md), [P18](p18.md) and [P19](p19.md): `0x4c2200`(ECX = dialog or any control, DX = ID) finds a control (from a control it searches that control's dialog); `0x4c2890` shows (it first sends user code 13 to the control's interact procedure; the control becomes visible only if the default handler runs); `0x4c22f0` hides; `0x4c2280` disables; `0x4c2910` enables; `0x4c2600`(EDX ≠ 0 ? disable : enable); `0x4c2840` marks dirty; `0x4c2820`(EDX = text) sets text and marks dirty; `0x4c2540`(ECX = control, DX = code, stack param) sends a type-14 user event; `0x4c5960`(ECX = owner, DX = timer ID, stack `[period ms, callback]`) creates or replaces a repeating UI timer (GetTickCount clock, see [briefing loader](../native-briefing-loader.md#briefing-waits-and-the-ui-clock)) and `0x4c58f0`(ECX, DX) deletes it; `0x4c33a0`(ECX = BIN name, EDX = file loader `0x444890`, stack `[bitmap loader 0x444930, file, line]`) loads a dialog; `0x4c35c0`(ECX = dialog, EDX = 0, stack procedure) runs it modally and returns the result `0x6ce6dc`. The modal loop calls the dialog field `+0x4a` (an "idle" callback, ECX = dialog) once per iteration for every active dialog. Event types: 0 key down, 1 key repeat, 15 character, 14 user event. User codes: 0 activate, 1 destroy, 2 button activated (ID in `0x6ce6dc`), 7 re-centre, 10 post-load initialization, 11 value changed, 13 show request, `0x405` slide-in finished.

Glue framework helpers ([P19](p19.md)): `0x457f00`(ECX = dialog, EDX = procedure array, stack `[array bytes, effect]`) InitGlueDialog; `0x458380` ReleaseGlueDialog; `0x458100`(ECX = dialog, EDX = slide table, stack `[count, unused, delay ms]`) slide-in; `0x457a40` slide-out; `0x4579b0` ActivateGlueScreen; `0x457b50` EndGlueScreen; `0x457c70`(ECX = buffer, EDX = size) theme directory of the current glue state; `0x457ca0`(ECX = id) `rez\gluAll.tbl` string (1-based); `0x43f0c0`(ECX = id) `rez\network.tbl` string; `0x457ed0`(ECX = dialog, DX = ID, stack text) sets a child's text; `0x457e40` invalidates the glue palette; `0x457e50` glue state from the network provider. `0x46c8a0`(ECX = dialog) centres the dialog on 640 × 480 when game mode `0x6662b8` = 4 (glue mode); it is the user-code-7 handler of every popup. Text drawing `0x4c3e70`(ECX = control, EDX = x offset, stack `[y offset, clip rect or 0]`) draws the control text with the font chosen by `flags & 0x4c00` and the layout-flags byte `0x6d300e` ([P45](p45.md)); its colour table is 5 when disabled, 4 when flag `0x80` (hover) is set, 3 for control types 1, 2, 3, 13, and for static types 9/10/11: 4 if bit 31, 6 if `0x40000000`, 3 if `0x20000000`, else 2.

**Storm lists** (`TSList`): a list object is `{+0 link offset, +4 terminator prev-link, +8 terminator next}`. A `next` value ≤ 0 (bit-inverted pointer) marks the terminator, so "for node = head; node > 0; node = node.next" walks it. Nodes put their link `{prev-link, next}` at `+0`/`+4`.

## Functions

### 0x0045de70 `SetListArrayCount` — resize a growable array of Storm lists
- Module: glumap.cpp..glumodem.cpp · Relevance: ui
- Status: specified
- Signature: `__thiscall`, ECX = array `{+0 capacity, +4 count, +8 data, +0xc chunk}`, stack new count `n`; `ret 4`.
- Behavior: Growing (`n` > count): if `n` > capacity, the chunk is `+0xc`, or when that is 0 `0x45b6c0(n)` (the highest power of two ≤ `n` for `n` ≤ 20; for `n` > 20 it stores 21 in `+0xc` and uses 21). `n` is rounded up to a multiple of the chunk and passed to the reallocator `0x45db90`. Each new 12-byte element becomes an empty list `{0xdddddddd, self-link, ~self-link}` and count = `n`. Shrinking: for each removed element in ascending order it unlinks every node (`0x45df70`) and detaches the element's own terminator, then count = `n`.
- Callers/callees: `0x45ade0` (map-list hash table constructor, 4 buckets), `0x45cc80`.

### 0x0045df70 `UnlinkAllListNodes` — empty a Storm list without freeing
- Module: glumap.cpp..glumodem.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, ECX = list object.
- Behavior: While the head `+8` is a node (> 0), it unlinks the link at node + link offset `+0` (prev-link and next patched, both fields of the link zeroed). Nodes are not freed.
- Callers/callees: the map-list hash table code `0x45ade0`, `0x45aea0`, `0x45afa0`, `0x45ba40`, `0x45cc80`, `0x45ceb0`, `0x45db90`, `0x45de70`.

### 0x0045dfc0 `PublishMapInfo` — feed the selected entry to the map-information callbacks
- Module: glumap.cpp..glumodem.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, ECX = map-list entry (list `0x508208`); tail-jumps to `0x455710`.
- Behavior:
  Entry layout: [P20](p20.md#data-structures).
  1. Game-type text `+0x169` (32 bytes): if the load status `+0x25c` = 1 (invalid) it is emptied. Else if flags `+0x268 & 0x81` = 0 (a map) it is copied from the Battle.net create-screen combo text `0x6677d0` (empty offline). Else (saved game or replay) it is emptied and, when byte `+0x4f9` ≠ 0, set to the template name `0x447a40`(CL = `+0x4f9`, DL = `+0x4fa`).
  2. Show flag = 1 when the entry is a replay (`+0x268 & 0x80`) or `0x447de0`(CL = `0x667350`, DL = `0x667354`, stack `0x667358`) (UMS template; offline this asks for template (0, 0, 0), see [P17](p17.md)), else 0. The show callbacks of fields 6 and 9 receive it.
  3. Sanitizes the description `+0x69` in place (`0x4a8350`, limit 256): keeps bytes ≥ `0x20` and tab, LF, CR.
  4. Text callbacks, in this order: field 0 ← `+0x49` (name), 1 ← `+0x69` (description), 3 ← `+0x169` (game type), 4 ← `+0x1a5` (players), 6 ← `+0x1c8` (computer slots), 7 ← `+0x1eb` (human slots), 5 ← `+0x20e` (map size), 2 ← `+0x189`, 8 ← `+0x231` (tileset). Each callback record is `0x66adc8 + 4·k` with k from `0x45c6a0`'s switch (field 0 `0x66adc8`, 1 `0x66adcc`, 2 `0x66ade8`, 3 `0x66add0`, 4 `0x66add4`, 5 `0x66ade4`, 6 `0x66add8`, 7 `0x66ade0`, 8 `0x66adec`, 9 `0x66addc`); a null record is skipped. Calls are `cb(field, control, text)`.
  5. `0x479cc0`(ECX = `+0x535`): copies the entry's 8 user-select slot flags to `0x673f08` (1 for a slot whose map race was User Select, set by `0x478a20` from `LoadMapHeader` `0x46b5c0`, [P27](p27.md)) and, outside replay mode `0x67cc90`, to `0x67cf11` ([mission units](../native-mission-units.md)).
  6. If the Battle.net create screen is open (`0x44d7d0`), `0x44d5d0`(ECX = `+0x479`).
  7. Slot count = replay-header byte `0x67ccd9` (`0x4805e0`) in replay mode, else byte `+0x479`; tail call `0x455710`(ECX = count) ([P19](p19.md)).
- Callers/callees: `0x45b970`, `0x45d1e0`.

### 0x0045e380 `SetupModemProvider` — choose and initialize a provider device (single player: no devices, success)
- Module: glumodem.cpp · Relevance: network
- Status: specified (it executes on every offline game creation and its result gates `InitNetworkProvider` `0x4757e0`)
- Signature: `__fastcall`-like with stack arguments: ECX = provider ID, EDX = program record; stack = [user record, interface record]; `ret 8`; returns 1 to continue provider set-up, 0 to abort it.
