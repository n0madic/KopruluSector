# P09: Unit pool persistence, ownership, reference cleanup, doodad/critter/powerup orders and the order-queue API

This package covers the end of `cunitinit.cpp` and the objects that sort between it and `cunitprotoss.cpp` (0x426000–0x42ac20). The code works on the CUnit pool and on unit orders. Its groups are:

1. **Unit pool save/load and list maintenance** (`0x426000`–`0x426700`, `0x4275e0`–`0x427970`, `0x428b50`–`0x428bd0`). Two loaders read CUnit records from a save. Two converters turn pointer fields into packed indices before a save and back after a load. Helpers rebuild the unused list and recount the pool.
2. **Unit creation, morph, placement and ownership** (`0x4261f0`, `0x426600`, `0x426750`, `0x426e80`, `0x426ed0`, `0x428db0`, `0x428df0`). These cover map/trigger unit creation with placement checks, building morph re-initialization, owner transfer and the "give to neutral" path.
3. **Reference cleanup** (`0x4268d0`–`0x426d30`, `0x429d20`). When a unit dies, hides or is lost to a player, these clear every pointer to it in other units, their subunits and their order queues, and remove it from the local selection.
4. **Worker cargo and powerups** (`0x427090`–`0x427480`). These carry minerals, gas or a powerup (flag, crystal) as images on the worker. They also handle pick-up, drop, delivery and the powerup return timer.
5. **Order handlers** dispatched by the primary order dispatcher `0x439420`: Critter, doodad/trap/door orders, Follow, Move, JunkYardDog, StayInRange, Stop, WatchTarget, the obscured-target family and the powerup orders.
6. **Small unit predicates and DAT getters**: race, overlay size, enemy tests, speed/acceleration/turn modifiers, type sets, names and command-target validation.
7. **The order-queue API** (`0x4295d0`–`0x42a8b0`). It has append/insert/prepend wrappers, issue wrappers, queue removal, secondary-order setters, queued (shift) command dispatch and activation. Executed probes cover most of it in [primary orders](../native-primary-orders.md).
8. **Movement commit helpers** used by the movement state machine (`0x42aa60`–`0x42ac20`).

## Shared data

**CUnit pool.** 1,700 (`0x6a4`) records of `0x150` bytes at `0x5da3a0`; `0x4255f0` returns that base. The doubly linked global lists use `+0x00/+0x04` and are:

| Head / tail | List |
|---|---|
| `0x665ae0 / 0x665ae4` | active (visible) units |
| `0x665ae8 / 0x665aec` | units pending recycling (dead this frame) |
| `0x665af0 / 0x665af4` | unused records |
| `0x665af8 / 0x665afc` | hidden units (sprite flag `0x20`) |
| `0x665b00 / 0x665b04` | Scanner Sweep (33) and Map Revealer (101) |

Per-player lists start at `0x665b08 + 4*player` (12 players) and link through `+0x68` (previous) / `+0x6c` (next). New members are **prepended**. `0x665b38` is the allocated-unit count.

**Packed unit reference** (save files and some network/AI fields): `index | generation << 11`. Here `index` is the 1-based pool index (1..1700, 11 bits) and `generation` is the unit's byte `+0xa5`. Zero encodes null.

**DAT columns used** (units.dat descriptor at `0x501520`, 228 entries): `0x51ffe0` construction animation, `0x520458` shields enabled, `0x520540` shields (u16), `0x520708` HP (fixed ×256, s32), `0x520a98` elevation, `0x520d50` computer idle order, `0x520e38` human idle order, `0x520f20` return-to-idle order, `0x521008` attack-unit order, `0x5210f0` attack-move order, `0x521660` special-ability flags (u32), `0x522038` "what" sound start, `0x522200` "what" sound end, `0x522728` placement box (w,h u16), `0x522c38` unit dimensions (left, up, right, down; s16; stride 8), `0x5238b0` build time, `0x523c40` group flags, `0x523ef8` space required, `0x523fe0` space provided, `0x524458` map-string override (u16), `0x524708` StarEdit availability (u16). `0x51faa8` is the units.dat flingy column; flingy.dat columns are listed in [P03](p03.md).

Special-ability flag bits named below: `0x1` building, `0x2` addon, `0x4` flyer, `0x8` worker, `0x10` subunit, `0x800` single entity (powerup), `0x2000` resource container, `0x10000` organic, `0x20000` requires creep, `0x2000000` medium overlays, `0x4000000` large overlays, `0x40000000` mechanical. Group flags: `0x1` Zerg, `0x2` Terran, `0x4` Protoss.

**orders.dat columns** (descriptor `0x501278`, 189 entries; see [primary orders](../native-primary-orders.md)): `0x51ae40` use weapon targeting, `0x51b080` subunit inheritance, `0x51b200` interruptible, `0x51b380` queueable, `0x51b740` targeting, `0x51b800` energy/tech, `0x51b980` highlight (u16, `0xffff` = none), `0x51bc80` obscured-order replacement.

**Other globals.** Alliance matrix `0x534914 + a*12 + b`: byte 0 means "enemy". Player records `0x6726d0 + player*0x24`: byte `+0` is the controller type (1 computer, 3 rescuable, 4 unused/neutral-like, 7 neutral) and `+3` is the name. Tile visibility map pointer `0x666454`: one DWORD per tile; bit `player` set means not visible. Order pool counters are at `0x5aef00/04/08`. Pending placement-error string id is `0x5da398` (WORD). Local selection is 12 slots at `0x6a6070`.

**Status bits** (CUnit `+0xdc`; OpenBW names): `0x1` completed, `0x2` grounded building, `0x4` flying, `0x10` burrowed, `0x40` loaded, `0x400` disabled, `0x1000` order not interruptible, `0x2000` iscript nobrk, `0x8000` cannot attack, `0x20000` can move, `0x40000` collision, `0x80000` "immovable" (see note), `0x100000` ground unit, `0x200000` no-collide, `0x4000000` invincible, `0x8000000` ready-to-attack/holding, `0x10000000` speed upgrade, `0x20000000` cooldown upgrade, `0x40000000` hallucination.

**"Disabled" test.** Many handlers use the same four-part test: status `0x400`, lockdown timer `+0x117`, stasis timer `+0x119` or maelstrom timer `+0x124` nonzero.

**Ineffective `0x80000` test.** Several functions here (`0x427ed0`, `0x428660`, `0x4286f0`, `0x42ac20`) check "move target equals sprite position" and then evaluate status bit `0x80000` as `((flag != 0) != -1)`. That expression is always true. The bit therefore never changes the result. A remake must not add a dependence on it.

## Function entries

### 0x00426000 `LoadUnitsLegacy` — read CUnit records from a pre-Brood War save (version < 3)
- Module: cunitinit.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = `FILE*`, EDX = record count; returns 1 on success (also when count is 0), 0 on read failure.
- Behavior:
  1. If the count is 0, return 1.
  2. Allocate `count*0x144` bytes (`SMemAlloc`, line `0x7b5`) and zero them. Read them with the compressed reader `0x413ae0`(ECX=buffer, EDX=size, stack FILE). On failure, free the buffer (line `0x7bb`) and return 0.
  3. For each record in file order: DWORD 0-based pool index `i`, then `0x140` payload bytes. Copy payload bytes `0..0x123` to unit `+0x000..+0x123`, the next 16 to `+0x134..+0x143`, the next 8 to `+0x144..+0x14b` and the last DWORD to `+0x14c`. **Unit bytes `+0x124..+0x133`** (maelstrom timer, acid spores and the other Brood War additions) are not in this format. They keep the zero from the caller's memset of the whole pool.
  4. Call `0x41bf70`(ECX=unit, 1). That is a no-op chain (`0x4178d0 → 0x40bbb0 → 0x417c00 → 0x4be950`) plus the side-effect-free predicate `0x429250`.
  5. For buildings (special flag `0x1`), convert the old "none" sentinels: tech byte `+0xc8` 24 → 44 and upgrade byte `+0xc9` 46 → 61.
  6. Free the buffer (line `0x7e1`) and return 1.
- Callers/callees: `0x425de0` (unit-pool load) picks this loader when the save format version is ≤ 2.

### 0x00426130 `LoadUnits` — read CUnit records from a save (version ≥ 3)
- Module: cunitinit.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = `FILE*`, EDX = record count; returns 1/0 as `0x426000`.
- Behavior: Same frame as `0x426000` with `0x154`-byte records: a DWORD 0-based index, then the whole `0x150`-byte CUnit, copied as 84 DWORDs. After each record it calls the no-op hook `0x41bf70`(1). No sentinel conversion. Allocation/free lines `0x7ee`, `0x7f4`, `0x807`.
- Callers/callees: `0x425de0`. After loading, `0x425de0` runs `0x431340`, `0x434b20`, reads eight packed list heads/tails into `0x665ae0/af8/ae8/b00/ae4/afc/aec/b04` through `0x428ba0`, rebuilds the unused list with `0x426700`, then reads the 12 player-list heads.

### 0x004261f0 `CreateUnitWithPlacementCheck` — create a fully initialized unit at a map position (trigger/map creation)
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: custom; ECX = unit type (low 16 bits), EDX = x, stack [y, player]; `ret 8`; returns CUnit* or 0.
- Behavior:
  1. Fail (return 0) if `type ≥ 228` or StarEdit availability bit `0x2` (`0x524708[type]`) is clear.
  2. Clamp the center to the map. All x arithmetic is 16-bit with signed tests. If `x - left` (left = `0x522c38[type*8]`) is negative, `x = left`. Otherwise, if the sign-extended `x + right` (`0x522c3c`) is ≥ map width (`0x543230`, u16), then `x = mapWidth - (x+right) - 1 + x`, which is `mapWidth - right - 1`. Y is clamped the same way with up (`+0x522c3a`), down (`+0x522c3e`) and map height (`0x543234`).
  3. Buildings (special flag `0x1`) snap to the 32-pixel grid and check placement. With `hw = trunc(width/2)`, `hh = trunc(height/2)` from the placement box `0x522728/0x52272a` (signed halving): `x0 = clamp(x - hw, 0, mapWidth-1)`, then `x = (x0 & ~31) + hw`. Y is snapped the same way with `hh`. The tile corner is `tx = x/32 - hw/32`, `ty = y/32 - hh/32`, both signed divisions truncating toward zero. If `0x412e20`(ECX=player, EDX=tx, stack [ty, type, 0]) returns nonzero (blocked), it formats string `0x12` of the table at `0x665de0` with (unit name `0x428ce0(type)`, x, y) into a 256-byte buffer (`0x4cb860`). It shows the text for 7 s with UI sound 2 (`0x46b070`, DL=3) and returns 0.
  4. Create the unit through `0x424900`(ECX=type, EDX=x, stack [y, player]). On failure, show the pending error string through `0x425020`(CL=player) and return 0.
  5. Creep: if the creep-provider query `0x4c0790`(ECX=type, EDX=1) is nonzero, stamp creep `0x43c220`(ECX=type, EDX=sprite x, stack sprite y) and cancel receding creep `0x4b4dd0`(unit). Otherwise, if the type has RequiresCreep `0x20000`, call `0x4c0aa0`(type, sprite x, y) and then `0x4b4dd0`.
  6. Run prefinish `0x424f40`, then placement `0x426600`. If placement fails, show the same string-`0x12` message with the sprite position, issue Death through `0x42a4d0` and return 0.
  7. Run postfinish `0x424de0`. If `0x4c0790(type,1)` is nonzero, call `0x4b4dd0` again.
  8. Addons (flag `0x2`) are transferred to player 11 through `0x426ed0`(11, 0).
  9. A grounded building (status `0x2`) whose race (`0x428d60`) is Terran gets `0x437180` (search for an addon or parent to attach).
  10. Call AI guard attachment `0x4b1fe0`(unit) and the dirty marker `0x42ffc0`.
  11. Resource amount `+0xd0` (u16): 5000 for type 188 (Vespene Geyser) or a completed refinery type (`0x424300`). Mineral fields 176–178 (`0x424380`) get 1500, followed by the animation threshold update `0x4247b0`. Return the unit.
- Callers/callees: `0x493a60`, `0x4b7020` (map/trigger unit creation).
- Prior evidence: [trigger unit actions](../native-trigger-unit-actions.md) (Create action path).

### 0x00426530 `MoveUnitToRecycleList` — unlink a dead unit from all live lists
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = CUnit.
- Behavior: Unlinks the unit from its player list (`+0x68/+0x6c`). If it was that player's head, the head becomes its next. Clears both links. Then it removes the unit (`0x4119a0`) from one global list: the special list `0x665b00` for types 33 and 101; the hidden list `0x665af8` when sprite flag `0x20` is set; otherwise the active list `0x665ae0`. It inserts the unit after the head of the pending-recycle list `0x665ae8` (`0x411930`).
- Note: Ghidra swaps the hidden/active branches; the assembly is authoritative. The 4 bytes at `0x4265d0` (`xor eax,eax; ret 0xc`) are a stub that the atlas does not list as a function. It is not unreferenced: `RemoveSpecialUnitBody` `0x425270` ([P08](p08.md)) pushes it at `0x42530f` as the callback argument of `0x4c0960` (a callback that always returns 0).
- Callers/callees: `0x425050` (unit removal).

### 0x00426600 `PlaceCompletedUnit` — find a free spot for a hidden newborn unit and its subunit
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = CUnit; returns 1 (placed or not hidden) or 0.
- Behavior: If sprite flag `0x20` (hidden) is clear, return 1. Otherwise call `0x47dc30`(ECX=unit, EDX=&{sprite x, sprite y}, stack [&out, 0, 0, 0]). On failure: if the pending error string `0x5da398` (WORD) is nonzero, show it to the owner (`0x43f0c0` → `0x46ae50`) and clear it; return 0. On success, relocate to `out` (`0x43a270`). If the unit has a subunit `+0x70` and is not itself a subunit type, the subunit receives:
  - completed accounting `0x414060` (EDX=0). This changes nothing, because `0x4145a0` skips subunit types;
  - status bit `0x1`;
  - HP = DAT HP (raw);
  - relocation to the same point.

  Returns 1.
- Callers/callees: `0x424db0` (training completion), `0x4261f0`.
- Prior evidence: [unit creation](../native-unit-creation.md), [training lifecycle](../native-training-lifecycle.md).

### 0x00426700 `RebuildUnusedUnitList` — rebuild the unused list from an in-use flag array

### 0x00426750 `ReinitializeMorphedUnit` — change a unit's type in place (building morphs, Drone → building)
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__thiscall`, ECX = CUnit, stack [new type (low 16 bits)]; `ret 4`.
- Behavior:
  1. Save the order `+0x4d`, order state `+0x4e`, order target position `+0x58` and unit `+0x5c`, and the raw HP `+0x8`.
  2. Previous type `+0x88` = current type. `+0xae` (u16) = `HP >> 8` (arithmetic), replaced by 1 when that is 0.
  3. Save the sprite owner byte `+0xa` and the sprite x/y (sign-extended). If the sprite has a first image (`+0x1c`), release the sprite (`0x416720`) and clear `+0xc`. If a path `+0x100` exists, release it (`0x48e880`).
  4. Re-run type initialization `0x425a70`(ECX=unit, stack [new type, x, y, owner]). Clear status `0x400`.
  5. New HP = `(DAT_HP[new]>>8) * (oldHP>>8)` (signed). Divide it signed by `DAT_HP[previous]>>8` when that divisor is nonzero; otherwise the quotient is 1. Shift left 8, store, and store 1 if the result is 0.
  6. Refresh the cached AI strengths `0x4a8f30`.
  7. Status: clear `0x1000|0x2000`, then set `0x1000` iff interruptible[saved order] (`0x51b200`) is 0.
  8. Restore the sprite owner (`0x417160`, saved byte). Grounded buildings get `buildQueue[+0xa4]` = 228.
  9. Restore the saved order fields. Set the button set (`0x422f00`) to the new type when completed (status `0x1`), else 228. Refresh the UI (`0x4a7ed0`).
- Callers/callees: `0x424a00`, `0x424bd0`.
- Prior evidence: [Zerg construction](../native-zerg-construction.md).

### 0x004268d0 `RemoveUnitFromSelection` — drop a unit from the local selection
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, ECX = CUnit.
- Behavior: Only if sprite flag `0x8` (selected) is set. It counts the leading non-null entries `n` of the 12-slot array `0x6a6070` (at most 12) and copies them to a local array. It removes slot `k` = sprite byte `+0xb` (selection index) by shifting entries `k+1..n-1` down (`memmove`) and nulls slot `n-1`. It installs the result with `0x49cf80`(ECX=n-1, EDX=array, stack [0, 0]). If the selection became empty, it calls `0x423120`.
- Callers/callees: `0x422ba0`, `0x424ad0`, `0x425050`, `0x428df0`.

### 0x004269b0 `ClearReferencesToUnit` — erase every pointer to a unit that is hidden, dying or moved
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__thiscall`, ECX = unit `U` being removed, stack [full flag]; `ret 4`.
- Behavior: For every unit `V` in the active list `0x665ae0` (forward through `+4`), apply the per-holder clear of `0x426d30` inline:
  - `+0xec`, `+0x5c`, `+0x14`, `+0x7c`, `+0x80`, `+0x11c` equal to U → 0.
  - Workers (flag `0x8`): `+0xc8` = U → 0; if `+0xce` ≠ 0 and `+0xd0` = U → clear both.
  - Non-workers: if status `0x2` and addon `+0xc0` = U → 0.
  - Rally producers (`0x429250`) with rally unit `+0xfc` = U: clear it and copy U's sprite position into `+0xf8/+0xfa`.
  - If V has a subunit (flag `0x10` type), call `0x426d30`(ECX=subunit, U).
  - Walk V's order queue (saving `next` first) and remove every node whose target `+0x10` = U through `0x429d20`.

  Then:
  - If the flag is 0 and U's sprite is hidden (`0x20`), call `0x4a6e60`(U), which drops U from the status-panel object reference.
  - If the flag is nonzero, call `0x4a6e60`(U). Then call `0x426d30`(ECX=each hidden unit, U) over `0x665af8`. If U is a worker with harvest target `+0xd0`, call `0x424170`(ECX=resource, U) to unlink U from that resource's gatherer list.
- Callers/callees: `0x422ba0` (Hide), `0x425050` (removal), `0x430390`, `0x4304d0` (trigger Move).
- Prior evidence: [trigger Move](../native-trigger-move.md), [trigger Move links](../native-trigger-move-links.md).

### 0x00426ed0 `ChangeUnitOwner` — core ownership transfer
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__thiscall`, ECX = CUnit, stack [new owner (byte), completed-score flag]; `ret 8`.
- Behavior: Returns at once if the owner byte `+0x4c` already equals the new owner. Otherwise:
  1. Remove the unit from AI structures (`0x48dbc0`, EDX=0).
  2. If `0x43c040` (morphing building) is true, temporarily set status `0x1` and remember to clear it.
  3. Live accounting −1 (`0x414590`). If completed, completed accounting −1 (`0x414580`, extra argument 0).
  4. If sprite flag `0x8` (selected) is set, save the selection index `+0xb` and remove the selection circle (`0x423000`).
  5. Unlink from the old player list (head fix-up) and write the new owner. If it was selected, re-add the selection (`0x423060`, saved index).

### Order-queue API conventions (0x429520–0x42a8b0)

All entries take ECX = CUnit. Packed positions are `u16(x) | u16(y) << 16`. "FoW" is the remembered target type word, 228 = none. Node allocation is `0x413c80`(CL=order, DX=FoW, stack [packed, target]). The highlight count `+0x84` is incremented when `0x51b980[order]` ≠ `0xffff` and decremented on removal, followed by the `0xff → 0` fix-up. On allocation failure every inserter shows stat_txt `0x368` to the owner (`0x4a7d70` → `0x46ae50`) and changes nothing else. The core entries (`0x4295d0`, `0x429e10`, `0x429f60`, `0x42a2c0`…`0x42a3e0`, `0x42a5a0`, `0x42a610`, `0x429ac0`) are verified by executed probes in [primary orders](../native-primary-orders.md).
