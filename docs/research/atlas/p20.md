# P20: Character selection, main menu, CD checks and the glumap map/replay file list with game creation

This package covers `0x459f10`–`0x45dcf0`: the tail of `glulogin.cpp`, the object between `glulogin.cpp` and `glumain.cpp`, `glumain.cpp`, the object between `glumain.cpp` and `glumap.cpp`, and most of `glumap.cpp`. Its 63 functions form four groups.

1. **Character selection** (`0x459f10`–`0x45a620`, 11 functions). Glue state 5 runs `rez\gluLogin.bin`. It lists the player profiles (`characters\*.spc` offline, `*.mpc` in multiplayer) sorted by creation time, creates and deletes profiles, and on OK copies the chosen name into the player name `0x672690`. Single player then goes to the campaign menu (state 6, or 22 with Brood War). In scope, `specified`.
2. **Main menu and CD checks** (`0x45a690`–`0x45ac60`, 10 functions). Glue state 0 runs `rez\gluMain.bin`: Single Player, Multiplayer, Campaign Editor, Exit, View Intro and Show Credits, the version label, the title music, the Original/Expansion choice (`rez\gluGameMode.bin`) and the CD-archive checks that gate the campaigns. In scope, `specified`.
3. **Map list engine** (`0x45b080`–`0x45dcf0` except group 4, 30 functions). `glumap.cpp` builds the file list of the Play Custom and Load Replay screens ([P19](p19.md) `0x455550`) from the user and installation directories, deduplicated through a Storm hash table of file names. It sorts it (folders first), remembers the five most recent maps in the registry, loads the per-entry information (map header, saved-game header or replay header) on a 100 ms deferred timer, and creates the game for the chosen entry. It also creates the game for a campaign's "next scenario" (`0x45c510`). In scope, `specified`, except two helpers that only Battle.net code reaches (`excluded`).
4. **Storm hash-table template code** (`0x45ade0`, `0x45aea0`, `0x45af30`, `0x45afa0`, `0x45b6c0`, `0x45c790`, `0x45cc80`, `0x45ceb0`, `0x45cf40`, `0x45cf70`, `0x45d040`, `0x45d0d0`, `0x45d160`, `0x45db90`, 14 functions). These are the methods of `TSHashTable<HASHENTRY,HASHKEY_CONSTSTRI>` that the list engine instantiates. They are specified briefly as a case-insensitive string set. A remake can use any hash set with the same lookup semantics.

## Shared conventions

Dialog fields, list-box fields, glue helpers, glue states and string tables are as in [P18](p18.md#shared-conventions) and [P19](p19.md#shared-data-and-tables). Additional facts used here:

- `0x457ca0`(ECX = n) returns `rez\gluAll.tbl` string n; `0x43f0c0`(ECX = n) returns `rez\network.tbl` string n (table `0x665de0`, loaded from `rez\network.tbl` by `0x43f0d0`). Quoted texts below are from the shipped `Patch_rt.mpq` tables. They are data, and a remake should read them from the tables.
- Storm path getters: ordinal 296 (thunk `0x4d006a`, mislabeled `SFileGetFileCompressedSize`) `(buffer, 260, 1)` writes the **user data base directory** (the one that holds `characters\`, see [P03](p03.md) `0x40d4f0`). Ordinal 295 (thunk `0x4d01ba`, mislabeled `SFileRegisterLoadNotifyProc`) `(buffer, 260, flag)` writes the **installation directory**. Every "file exists" test in this package tries the user directory first and then the installation directory. A path "exists" when `GetFileAttributesA` does not report the directory bit `0x10`. A missing file returns `0xffffffff`, which has that bit, so it counts as absent.
- Storm lists (`TSList`): a list object is `{s32 link offset, terminator link {prev, next}}`. The head pointer is the terminator's `next` (`+8` of the object). A `next` ≤ 0 ends the iteration. `0x440c10`(ECX = list, stack `[node, where, anchor]`) links a node: `where` = 1 with anchor 0 puts it at the head, and `where` = 2 puts it before the anchor (at the tail when the anchor is 0).
- UI timers on the main window `0x66fd28`: `KillTimer`/`SetTimer` with ID 12 (`0xc`) drive the deferred entry-information load.
- `0x4635c0()` returns the **spawn flag** DWORD `0x5085c8` and `0x4635b0()` returns the **expansion data flag** `0x66cac0` (1 when `rez\epilogX.txt` exists, set by `0x463880`). The spawn flag is computed at start-up by `0x4638a0` (grid.cpp) as `0x463710() == 0`. `0x463710` loads `font\font.ccd`, decodes it (`0x4119f0`) with the key data from `font\font.gid` and returns 1 when the result equals `"sgubon"` (`SStrCmp`, thunk `0x4d019c`). The retail `StarDat.mpq` contains all three `font\font.*` files (72 bytes each), so a full installation has spawn flag 0 (confirmed by a host decode of `StarDat.mpq` `font\font.ccd` to `"sgubon"`; see [P22](p22.md) `0x4638a0` and [P19](p19.md)). A spawned (limited) copy has flag 1: single player is refused, the PalCs theme is skipped and Brood War data is not opened.
- `0x4658b0()` returns the CD archive handle `0x66cccc` (0 when none is open). `0x465470`(ECX = file, EDX = archive) returns 1 when `SFileOpenFileEx(archive, file, 0)` succeeds, closing the file again.

## Data structures

**Login profile list** (`0x5081a0`: link offset at `+0`, terminator `0x5081a4`, head `0x5081a8`). Nodes are `0x78` bytes: `+0/+4` links, then the `0x70`-byte profile record at `+8` (layout in [P03](p03.md) `0x40d680`). Node `+0x10` is the record's creation time (`+8`, `time(NULL)` when created) and node `+0x14` is the name (record `+0x0c`). The SMem source tag is `0x510850 + 8`. The list holds at most 250 nodes (`0x66adc0` counts the enumerated ones).

**Map list** (`0x508200`: link offset at `+0`, terminator `0x508204`, head `0x508208`). Each entry is a `0x544`-byte block (SMem tag `0x510864 + 8`, zero-filled by flag 8):

| Offset | Field |
|---|---|
| `+0x00/+0x04` | list links |
| `+0x08` | display name (65 bytes): file name; `"[" folder "]"` for folders; the "[Up One Level]" text for `..` |
| `+0x49` | title (32): gluAll 61 "Invalid Scenario" / 64 "Invalid Saved Game" until loaded; map title, file name, gluAll 47 "Saved Game" or 178 "Replay" |
| `+0x69` | description or error text (256) |
| `+0x169` | game-type label (32, written by `0x45dfc0`, [P17](p17.md)) |
| `+0x1a5`, `+0x1c8`, `+0x1eb`, `+0x20e` | formatted "players", "computer slots", "human slots" and "W×H" lines (35 bytes each) |
| `+0x231` | tileset name (35) |
| `+0x254` | list-box item index returned by the fill callback |
| `+0x258` | u32 information loaded (1 once a loader ran) |
| `+0x25c` | u32 load status: 0 valid, 1 invalid, 2 needs the expansion |
| `+0x260` | u32 map class (see `0x45d870`) |
| `+0x264` | u32 copied from the game header `+0x1c` (saves and replays) |
| `+0x268` | u8 kind: 1 saved game, 4 map, 8 folder, `0x80` replay; plus flags `0x10` recent map, `0x20` sorted insertion (and `0x40`, passed through from the caller's flags) |
| `+0x269` | path relative to the base directories (260) |
| `+0x36d` | file name (260) |
| `+0x472/+0x474/+0x476` | u16 width, height, tileset |
| `+0x478` | u8 (1 for maps and replays; header `+0x24` for saves) |
| `+0x479` | u8 player count (maps: slots of owner type 3–7; replays: 8; saves: header `+0x25`) |
| `+0x47a`, `+0x47b` | u8 computer slots, human slots |
| `+0x480` | `0xb5` bytes of the saved-game file header (saves); the 141-byte (`0x8d`) game header is at `+0x48c` for saves and replays |
| `+0x535` | 8 user-select slot flags copied from `0x673f08` (maps) |
| `+0x540` | u32 replay campaign-map index (replays) |

**Game header** (`0x8d` bytes, the layout of `0x6728d0`, see [P15](p15.md)): fields written here are `+0x04` game name, `+0x20/+0x22` u16 map width/height, `+0x24` u8 = 1, `+0x25` u8 maximum players, `+0x26` u8 speed, `+0x27` u8 map class, `+0x28` u8 template type, `+0x29` u8 template sub-byte, `+0x2a` u16 template subtype, `+0x30` u16 tileset, `+0x4d` map title (32), `+0x6d` the 32-byte template record.

**Information-field callbacks**: ten 12-byte records `{text callback, show callback, control}` registered by `0x45c6a0`. Field → global: 0 `0x66adc8`, 1 `0x66adcc`, 2 `0x66ade8`, 3 `0x66add0`, 4 `0x66add4`, 5 `0x66ade4`, 6 `0x66add8`, 7 `0x66ade0`, 8 `0x66adec`, 9 `0x66addc`. The text callback is stdcall `(field, control, text)`.

**"[Up One Level]" label** `0x66adf0`: built once (first byte 0) as `"[" + gluAll 28 "Up One Level" + "]"`.

**Name table** (`TSHashTable<HASHENTRY,HASHKEY_CONSTSTRI>`, `0x28` bytes, vftable `0x4edbe0` = {`0x45cf40` delete node, `0x45cf70` new node, `0x45afa0` deleting destructor, `0x45c790` reset}). `+0x04` link offset of the all-nodes list (`0xc`), `+0x08` all-nodes terminator, `+0x10` chain-length counter, `+0x14` bucket array `{+0x14 capacity, +0x18 count, +0x1c data, +0x20 chunk}`, `+0x24` mask (bucket count − 1). Buckets are 12-byte lists `{link offset 4, terminator}`. Nodes: `+0x00` hash (`SStrHash`), `+0x04` bucket link, `+0x0c` all-nodes link, `+0x14` key (a `char*`, not copied), `+0x18` value (the map entry).

**Dialog-procedure jump tables** (resolved): login `0x45a040` byte map `0x45a174` over user codes 0–10 = {0, 1, 2, 5, 5, 5, 5, 5, 3, 5, 4} into `0x45a15c` = {code 0 `0x45a0c1`, code 1 `0x45a140`, code 2 `0x45a0d8`, code 8 `0x45a11d`, code 10 `0x45a096`, default `0x45a14f`}. Main menu `0x45ac60` byte map `0x45adcc` over codes 0–10 = {0, 1, 2, 4×7, 3} into `0x45adb8` = {code 0 `0x45acaf`, code 1 `0x45ace3`, code 2 `0x45ad0c`, code 10 `0x45ac96`, default `0x45aca4`}. **Save-file extensions** (`0x4995a0`, saveload.cpp): `"*.sng"` (original, single player), `"*.snx"` (Brood War, single player), `"*.mlt"` (original, multiplayer), `"*.mlx"` (Brood War, multiplayer); callers skip the `*.`.

**Map class marker files** (`0x4f1038`, records `{name[20], u32 class}`, scanned by `0x4c1350` from class 6 down to 1): `Ladder_2.cnd` 1, `PGL_2.cnd` 3, `Ladder_3.cnd` 1, `Ladder_4.cnd` 2, `KBK_2.cnd` 4, `CompUSA_1.cnd` 3, `WGT_1.cnd` 6, `Tourn_1.cnd` 5; class 5 also needs `League_<n>.cnd`. The class is kept only when the map archive's signature verifies (`0x46b0d0`); ordinary maps have class 0.

## Error codes returned by the game-creation functions

`0x80000001` needs the expansion; `0x80000002` map only allows Use Map Settings; `0x80000003` tournament template on a map of class ≠ 2; `0x80000004` SErr `0xb7`; `0x80000005` SErr `0x44` (too many games); `0x80000006` generic failure; `0x80000007` invalid scenario; `0x80000008` no template record or the template's team count does not fit the map; `0x80000009`/`0x8000000a` empty password for a saved game/replay; `0x8000000b` the entry is a folder; `0x8000000c` no human slot; `0x8000000d` no computer slot / fewer than 2 players; `0x8000000e` server template on a map of class ≠ 5; `0x8000000f` SErr `0x85100085`; `0x80000011` server template without Brood War; `0x80000012` previous game type in `[0x11, 0x16]` and map class ≠ 6. [P18](p18.md) `0x455240` maps them to messages.

### 0x00459f10 `RunLoginScreen` — glue state 5, character selection
- Module: glulogin.cpp · Relevance: ui
- Status: specified
- Signature: no arguments, no result (tail-calls `0x457b50`).
- Behavior: Loads `rez\gluLogin.bin` with `0x4c33a0` (ECX = path `0x4edb58`, EDX = file loader `0x444890`, stack `[0x444930, "gluLogin.cpp", 0x1c0]`). It stores the root in `0x66adb8` and runs it modally with `0x45a040` (`0x4c35c0`, EDX = 0). Result:
  - 4 (Ok): single player (`0x672664` = 0) → glue state `0x66a274` = 6, or 22 when the Brood War byte `0x536720` ≠ 0. Multiplayer → by provider `0x475a10()` (`0x672974`): `0x4d444d58` ('MDMX') or `0x4d4f444d` ('MODM') → 20; `0x5343424c` ('SCBL', direct cable) → 21; any other → 10.
  - 5 (Cancel): `0x477f60`(CL = 0) tears down the network layer (`0x4765a0`, `SNetLeaveGame(3)`, `SNetDestroy`, then `0x474bf0`, `0x46fd30`, `0x474580`; the two 1 s sleeps happen only in multiplayer). State = 0, or 2 in multiplayer.
  - anything else: state 0.
  
  All paths end in `0x457b50`.
- Globals/fields: `0x66adb8` login dialog, `0x66a274`, `0x672664`, `0x536720`, `0x672974`.
- Callers/callees: glue loop `0x457510` (state 5).

### 0x0045a040 `LoginDialogProc` — gluLogin dialog procedure
- Module: glulogin.cpp..glumain.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, ECX = dialog, EDX = event; returns the handled flag.
- Behavior:
  - Event types 17 and 18 (wheel): `0x4c2540`(ECX = list `0x66adbc` `+0x36` (its scroll bar), DX = 15 for 17 or 16 for 18, param 0); returns 1.

### 0x0045a180 `InsertProfileNodeByTime` — link a profile node in creation order
- Module: glulogin.cpp..glumain.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, ECX = node; returns the node's index.
- Behavior: Walks the list from the head. While the new node's u32 time `+0x10` ≥ the visited node's time (unsigned), it advances and counts. It links the node before the first visited node with a greater time, or at the tail when none (`0x440c10`, ECX = `0x5081a0`, where 2). Equal times keep insertion order. Returns the count of skipped nodes, which is the list-box index.
- Callers/callees: `0x45a1d0`, `0x45a320`.

### 0x0045a1d0 `OnProfileEnumerated` — enumeration callback
- Module: glulogin.cpp..glumain.cpp · Relevance: ui
- Status: specified
- Signature: `__stdcall`, stack `[record]` (`0x70` bytes), `ret 4`.
- Behavior: Only when `0x66adc0` < 250 (unsigned) and record byte `+4` (multiplayer flag) equals (`0x672664` ≠ 0): allocates a `0x78`-byte node (SMemAlloc flags 8), clears its links, copies the 28 DWORDs of the record to node `+8`, inserts it with `0x45a180` and increments `0x66adc0`. A null allocation is not checked.
- Callers/callees: `0x40d570`.

### 0x0045a320 `CreateNewProfile` — New ID
- Module: glulogin.cpp..glumain.cpp · Relevance: ui
- Status: specified
- Signature: no stack arguments; ECX = list (from `0x66adbc`).
- Behavior:
  1. If the list count (`0x4c6830`) ≥ 250: OK popup (`0x460230`) gluAll 26 "Please delete a character before adding a new one."; return.
  2. Clears the first byte of a 28-byte stack name buffer. `0x45fd50`(ECX = gluAll 23 "Enter new character name:", EDX = buffer, stack `[25 max length, network.tbl 17 = forbidden characters *\/:><|&+^?"]`) runs `rez\gluPEdit.bin`. Cancel returns.

  5. `CreateCharacterFile` `0x40d7c0`(name, local record) = 0 → popup gluAll 27 (file error); return.

- Callers/callees: `0x45a040` (button 6 and the empty-list timer).
