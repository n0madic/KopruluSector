# S01: Storm library functions used by StarCraft 1.17

StarCraft 1.17.0.1 imports 145 functions from the repack `storm.dll` (SHA-256 `2c48536982309f7f03ee72908e7d2fff22aa40838c03f71b98c43775dd6313ae`, preferred base `0x15000000`). The game imports 143 of them by ordinal and two C++ functions by mangled name. This package specifies every import as the game sees it: arguments, return values, error codes, edge cases and the effect of Storm's internal helpers. Internal helpers have no entries of their own; their effect is described inside the public function that reaches them. Each entry also lists the StarCraft call sites and the argument values those sites pass.

All results come from static analysis of the exact DLL (Ghidra decompilation plus capstone disassembly) and of the StarCraft 1.17 decompilation. No Storm or game code was executed. Addresses are Storm virtual addresses at base `0x15000000`, except "game" addresses, which belong to `StarCraft.exe` at base `0x400000`.

**Runtime cross-check (added in [F03](f03-final-fixes.md)).** The static results above were written without execution. The later [full-game emulation oracle](../full-game-emulation.md) runs this exact `storm.dll` and `standard.snp` as x86 code through boot and all 64 campaign missions. Across its 65 runs (boot and 64 missions; `storm_exports_executed` in each coverage record) it executed 94 of the 145 imports, among them the internal helpers that this package had only spot-checked: the SBmp decoders (321 `SBmpDecodeImage`, 323, 325) for every PCX load, the SNet provider and turn pipeline of the single-player provider 0 (101, 102, 103, 109, 114 `SNetGetProviderCaps`, 115, 117, 119, 121, 122, 123, 128, 138, and the pump thread `0x15022780`), and the SDraw surface path. All 64 missions reached their target frames, so these helpers behave as specified on the offline path. The SDraw PNG encoder inside ordinal 342 was not executed: it runs only when the player presses PrintScreen and writes a file, with no effect on play or presentation.

## Conventions and global caveats

- **Calling convention.** Every export is `__stdcall` with these exceptions: ordinal 578 is `__cdecl` varargs, and the two mangled imports (ordinals 132 and 148) are `__fastcall`. Ghidra argument names were corrected against the disassembly.
- **Error reporting.**
  - "Error X" means `SErrSetLastError(X)` (ordinal 465). That call stores X in Storm's own last-error global `0x15069360` and also calls Win32 `SetLastError`.
  - `0x57` is `ERROR_INVALID_PARAMETER`.
  - `SErrGetLastError` (ordinal 463) returns only Storm's copy. Paths that call Win32 `SetLastError` directly do not update it: the registry-API failures of all SReg functions (their argument checks do use ordinal 465), `SFileOpenArchive` when `CreateFile` fails, and a short loose-file read.

## How the pieces connect

- **SFile.** It keeps a priority-sorted list of open MPQ archives plus a list of open file objects, both under one critical section (`0x15069564`).
  - Reads go either synchronously through a one-sector cache or through a background I/O thread. The thread also streams DirectSound "DDA" buffers.
  - Decompression supports PKWARE implode, Huffman and IMA ADPCM; there is no zlib or bzip2.
- **SDraw.** It owns a 640×480 8-bit software back buffer. On unlock it converts dirty rectangles to the 32-bit DirectDraw primary surface through a 256-entry palette (`0x15068b48`).
- **SBlt, SGdi and SVid.** They all draw with SCode, a tiny blitter compiler that turns strings such as `"4 W=0 1 A=S B=D W1=A1 W2=B1 D=TW"` into x86 loops.
- **STrans.** It encodes 8-bit transparency masks as run-length word streams. The game uses them for its UI-overlay mask and dirty-cell tracking.
- **SRgn.** It keeps float rectangle regions; the game uses one for dirty-screen rectangles.
- **SNet.** It is a reliable-ordered turn and message transport over a pluggable `.snp` provider. Single player uses the hidden provider id 0 from `standard.snp`. That provider is a null transport, so every turn and message loops back inside Storm's own queues. Details are under [SNet](#snet-turnmessage-transport).

## SFile: archives, files and streamed sound

### Shared SFile state

**Archive object** (`0x144` bytes):

| Offset | Content |
|---|---|
| +0/+4 | list link |
| +8 | resolved path [0x104] |
| +0x10C | Win32 handle |
| +0x110 | async mode (0 = synchronous; 1 or 2 = reads go through the I/O thread) |
| +0x114 | priority |
| +0x118..+0x128 | one-sector cache (owner file, owner offset, sector size, buffer, valid bytes) |
| +0x12C | MPQ header offset |
| +0x130 | header copy |
| +0x134 | block table (decrypted, offsets made absolute) |
| +0x138 | hash table |
| +0x140 | reference count |

**File object** (`0x144` bytes, open-file list `0x150665ac`):

| Offset | Content |
|---|---|
| +8 | name as passed |
| +0x10C | loose Win32 handle, or −1 for an archived file |
| +0x110 | archive (0 = loose file) |
| +0x114 | block entry |
| +0x118 | key |
| +0x11C | position |
| +0x124 | sector count |
| +0x128 | sector offset table |
| +0x12C | offset table loaded |
| +0x130 | DDA active |
| +0x134 | 0x1000-byte read-ahead buffer |
| +0x138/+0x13C | read-ahead cursor / fill |
| +0x140 | reference count |

An open archived file holds one reference on its archive. Each queued asynchronous request or DDA stream holds one reference on its file.

**Globals:**

| Address | Meaning |
|---|---|
| `0x15069560` | locale (u16, default 0) |
| `0x15069562` | platform (u8, 0) |
| `0x15069698` | direct-access mode (0; the game never changes it) |
| `0x15069580` | base path: exe directory with a trailing `\`, built lazily from `GetModuleFileName` |
| `0x150696b0` | user-data path (ordinal 297) |
| `0x1506658c` | async chunk size (`0x20000`) |
| `0x15066590`/`0x150696a8` | I/O error mode (default 2) / callback |
| `0x150696a4` | crypt table |

**MPQ crypto.**
- The crypt table is the standard MPQ table: seed `0x00100001`, step `seed = (seed*125+3) % 0x2AAAAB`, `0x500` dwords.
- Name hash for type t: `s1=0x7FED7FED`, `s2=0xEEEEEEEE`. For each byte: `c=toupper(c)` (ASCII only), `s1 = T[t*256+c] ^ (s1+s2)`, `s2 = c + s1 + 33*s2 + 3`.
  - Bytes are **sign-extended**, so bytes ≥ 0x80 index before the row. A remake must reproduce this.
  - `/` is not converted.
- Table and sector decryption is the standard MPQ algorithm (`T[0x400 + (key & 0xFF)]`).

**Hash lookup** (FUN_15019110):
1. Start at `Hash(name,0) & (count−1)` and match `Hash(name,1)` and `Hash(name,2)`.
2. Probe linearly with wraparound. Stop at block index `0xFFFFFFFF` (empty) or after a full lap; skip `0xFFFFFFFE` (deleted).
3. An entry whose locale and platform both equal the current values returns at once.
4. Otherwise the last entry whose locale is 0 or current *and* whose platform is 0 or current is the fallback.

**Sector reading.**
- Sector size is `0x200 << header[+0x0E]`.
- Compressed files (`flags & 0xFF00`) load a (count+1)-entry offset table on first use. The table is decrypted with key−1 when encrypted (`0x10000`). If the entries are not monotonic, the read yields 0 bytes.
- Sector i is decrypted with key+i, over whole dwords only.
- A sector whose stored size is smaller than expected is decompressed:
  - block flag `0x100` → PKWARE DCL explode;
  - block flag `0x200` → SCompDecompress (its first byte is the method mask). The mask is applied in the order `0x08` implode, `0x01` Huffman, `0x80` ADPCM stereo, `0x40` ADPCM mono. Any of `0x02` zlib, `0x04`, `0x10` bzip2 or `0x20` sparse is unsupported and returns failure.
  - A failed SCompDecompress raises fatal error `0x85100083` ("file data is corrupt") through SErrDisplayError, which terminates the process.
  - Other `0xFF00` values produce no output.
- The expected size of the last sector is `fileSize & (sectorSize−1)` when that is non-zero.

**I/O error handling.** The read helper FUN_15019010 applies the I/O error mode only when Win32 `ReadFile` *fails*; a short read is not retried. See ordinal 274.

### 0x150196a0 `SFileCloseArchive` (ord 252) — close an archive handle
- Module: SFile.cpp · Relevance: data · Status: specified
- Signature: `BOOL SFileCloseArchive(HANDLE archive)`
- Behavior:
  - Unlinks the archive from the search list, so it is no longer searched, and decrements its reference count.
  - At zero it closes the Win32 handle and frees the sector cache, header, block table and hash table.
  - NULL is **not** a no-op: the unlink step then operates on the archive list's own terminator link `0x15066598`, detaching it and emptying the search list (a later SFileOpenArchive would dereference the zeroed terminator). The game call sites inspected pass only handles from successful opens. Always returns 1.
  - Files still open on the archive keep it alive.
- Callers: game map and league loaders (0x4654a0, 0x4657d0, 0x465fc0, 0x466070, 0x466490, 0x469440..0x469b80).

### 0x15019730 `SFileCloseFile` (ord 253) — close a file handle
- Module: SFile.cpp · Relevance: data · Status: specified
- Signature: `BOOL SFileCloseFile(HANDLE file)`
- Behavior:
  - Unlinks the file and decrements its reference count. At zero it:
    - closes the loose handle;
    - clears the archive's sector-cache owner;
    - frees the offset table and read-ahead buffer;
    - releases the archive reference.
  - The handle is not validated. As with ordinal 252, NULL unlinks the open-file list terminator `0x150665b0` instead of doing nothing. Always returns 1.
- Callers: game file wrappers 0x4442b0..0x444bd0 and others.

### 0x150197f0 `SFileDdaBeginEx` (ord 255) — start streaming a WAV file to DirectSound
- Module: SFile.cpp · Relevance: audio · Status: specified
- Signature: `BOOL SFileDdaBeginEx(HANDLE file, DWORD bufSize, DWORD flags, DWORD startOffset, LONG volume, LONG pan, DWORD unused)` (`ret 0x1C`).
- Behavior:
  1. Argument checks:
     - `bufSize==0` → error 0x57.
     - No DirectSound object set (ordinal 260) → error `0x85100071`.
     - A stream already active on this file is ended first (ordinal 257).
     - A loose file (no archive) → error `0x8510006F`. DDA works only on archived files.
  2. Setup:
     - Allocates the global `0x4000`-byte scratch buffer once.
     - Forces the archive's async mode to 1 if it was 0, so all later reads from that archive become threaded.
     - Rounds `bufSize` up to a multiple of `0x4000`, minimum `0x8000`.
     - Rewinds the file.
  3. WAV parsing:
     - Reads 12 bytes and requires `RIFF` and `WAVE`.
     - Scans 8-byte chunk headers and skips `size` bytes with no odd padding, until `fmt ` (size ≥ 16).
     - Reads 16 bytes as WAVEFORMATEX (cbSize 0). The format tag passes through unchanged; DDA does no decoding.
     - Finds `data`.
     - Any parse failure → error `0xD`. A failed fmt read returns 0 with no code set.
  4. DirectSound buffer:
     - DSBUFFERDESC: size `0x14`, flags `0x80` (CTRLVOLUME), plus `0x20` (CTRLFREQUENCY) if `flags&0x20`, plus `0x40` (CTRLPAN) if `flags&0x40`; buffer bytes = the rounded size. Created with `IDirectSound::CreateSoundBuffer`.
     - Volume and pan are applied unless the value is 0 or `0x7FFFFFFF`.
     - A non-zero `startOffset` seeks forward.
  5. The stream record stores:
     - loop = `flags & 0x40000`;
     - start = dataStart + min(startOffset, dataSize − dataStart);
     - end = dataSize;
     - silence byte = `0x80` for 8-bit audio, otherwise 0.
     - Quirk: `end` is compared with the absolute file position, so playback stops dataStart bytes (usually 44) before the true end.
  6. Marks the file DDA-active, adds a file reference, wakes the I/O thread, returns 1.
- Pump (on the I/O thread):
  - State 0: prefill the buffer in `0x4000` reads.
  - Then: `Play(0,0,DSBPLAY_LOOPING)`.
  - While playing: refill whenever at least `0x4000` bytes are free.
  - At end of data:
    - looping streams rewind to start;
    - non-looping streams write one block of silence and keep playing silence until ordinal 257 is called.
  - A short read is padded with the silence byte.
- Callers:
  - Music (0x46ef10, 0x46f1b0, 0x49ebf0): `(h, 0x40000, loop?0x40000:0, 0, musicVolume, 0, 0)`.
  - Sound streams (0x49e810): `(h, 0x40000, 0, 0, volumeTable[v*99/100], 0, 0)`.

### 0x15019ca0 `SFileDdaDestroy` (ord 256) — stop all DDA streaming
- Module: SFile.cpp · Relevance: audio · Status: specified
- Signature: `BOOL SFileDdaDestroy(void)`
- Behavior:
  1. Sets the pause flag `0x15069694`.
  2. Waits in 10 ms steps until the I/O thread has no current or pending request.
  3. Releases every stream (the file reference and `IDirectSoundBuffer::Release`).
  4. Clears the DirectSound pointer and the pause flag. Returns 1.
- Callers: sound shutdown 0x49eae0.

### 0x15019d90 `SFileDdaEnd` (ord 257) — stop a file's stream
- Module: SFile.cpp · Relevance: audio · Status: specified
- Signature: `BOOL SFileDdaEnd(HANDLE file)`
- Behavior:
  - Removes every stream bound to `file`. When a stream's reference count reaches zero, it releases the file reference and the DirectSound buffer; there is no explicit Stop.
  - Clears the DDA flag. Always returns 1.
- Callers: track switches (0x46ef10, 0x46f040, 0x46f1b0, 0x46f290, 0x49ebf0) and sound reaping (0x49d520, 0x49d590).

### 0x15019e30 `SFileDdaGetPos` (ord 258) — playback position of a stream
- Module: SFile.cpp · Relevance: audio · Status: specified
- Signature: `BOOL SFileDdaGetPos(HANDLE file, DWORD *pos, DWORD *size)`
- Behavior:
  - Both outputs are zeroed first. No stream on the file → error `0x85100072`, returns 0.
  - `*size` = end − start.
  - `*pos`:
    - In the playing and draining states it estimates the bytes already played from the bytes written (file position + silence written − start) and the DirectSound play cursor (wrapped by the buffer size), clamped to `size`.
    - Before playback starts it is 0.
- Callers: 0x46ee70 advances to the next music track when `pos >= size`; 0x49ea10 reaps finished sound streams the same way.

### 0x1501a6f0 `SFileOpenArchive` (ord 266) — open an MPQ and add it to the search list
- Module: SFile.cpp · Relevance: data · Status: specified
- Signature: `BOOL SFileOpenArchive(const char *name, int priority, DWORD flags, HANDLE *out)`
- Behavior:
  1. Arguments: `out==NULL` or an empty name → error 0x57. Otherwise `*out=0`. Also initialises the crypt table and I/O thread if needed.
  2. Path resolution:
     - If the name exists as a non-directory file, it is used as given (a path relative to the current working directory works).
     - Otherwise it is kept as an absolute path when it starts with `\` or contains `:\` or `\\`.
     - Otherwise it is resolved with `GetFullPathName(exeDir + name)`.
  3. CD test:
     - The drive root's volume info (FS flags & 4, the first dword of the FS name, free clusters, bytes per sector, drive type) is XOR-folded to 16 bits.
     - The test passes for the folded values `0x1F00` or `0x805`. That is a genuine CDFS CD-ROM; an empty FS name also passes.
     - `flags&1` (must be on CD) with a failed test → error `0xF`, returns 0.
  4. Opens the file read-only, share-read. On failure returns 0 with only the Win32 error set.
  5. Async mode: 2 on CD, otherwise 1 if `flags&2`, otherwise 0. Modes 1 and 2 both route reads through the I/O thread.
  6. Header search:
     - Reads 0x20 bytes at offsets 0, 0x200, 0x400, …
     - Accepts the first block with signature `0x1A51504D` (`MPQ\x1A`) and header size ≥ 0x20.
     - EOF without a match → error `0x8510006C`.
     - Fields used: sector shift (+0x0E), hash table offset/count (+0x10/+0x18), block table offset/count (+0x14/+0x1C). The format version is ignored.
  7. Tables:
     - Hash and block tables (16-byte entries) are decrypted with the keys `Hash("(hash table)",3)` and `Hash("(block table)",3)`. Table read failures are ignored.
     - Non-zero block offsets get the header offset added.
  8. Priority insertion:
     - Inserted **before the first archive whose priority ≤ the new one**.
     - The search order is therefore descending priority, and the newest archive wins ties.
     - Opening the same file twice is not detected.
  9. Returns 1.
- Callers and archive set (0x465de0). All paths are the exe directory plus the name:

  | Archive | Priority | Flags | Condition |
  |---|---|---|---|
  | `\Stardat.mpq` | 2000 | 2 | Failure is fatal |
  | `\patch_rt.mpq` | 7000 | 2 | Optional |
  | `\Broodat.mpq` | 2500 | 2 | Attempted when the spawn flag (0x4635c0) is 0, which it is on this install; failure is tolerated (handle 0 when the file is absent) |
  | CD/campaign archive (0x4660f0, also only when 0x4635c0 returns 0) | 1000 | — | Tried in this order: `BroodWar.mpq`, `StarCraft.mpq` (flags 2); then registry `StarCD` + `\Install.exe` opened *as an MPQ* (flags 3); then a scan of every CD-ROM drive's `Install.exe` (flags 3) |

  - The resulting search order is patch_rt → BrooDat → StarDat → CD archive → maps (priority 0, flags 0, 0x469560/0x469de0). This matches [campaigns.md](../campaigns.md).
  - League archives `leagues\%s\%s.mpq` (0x466490) are Battle.net only.
- Prior evidence: [campaigns.md](../campaigns.md) documented the order empirically and left the resolver open. This entry closes it.

### 0x1501abe0 `SFileOpenFileEx` (ord 268) — open a file from disk or archives
- Module: SFile.cpp · Relevance: data · Status: specified
- Signature: `BOOL SFileOpenFileEx(HANDLE archive /*0 = all*/, const char *name, DWORD flags, HANDLE *out)`
- Behavior:
  1. Arguments: `out==NULL` or an empty name → error 0x57. Otherwise `*out=0`.
  2. Disk search (only when `flags & 3`):
     - `flags&2`: try exeDir + the part of `name` after its last `\`.
     - Then `flags&1`: try `name` verbatim if absolute (same rule as ordinal 266), else `GetFullPathName(exeDir+name)`.
     - The working directory and the user-data path are never consulted.
     - An existing non-directory file is opened with GENERIC_READ, share-read and SEQUENTIAL_SCAN.
     - With `flags&4`, `*out` is the raw Win32 handle. Otherwise it is a loose file object.
     - A failed CreateFile falls through to the archive search.
  3. Archive search:
     - The given archive only, or every archive in priority order; the first hash hit wins.
     - No hit or no archives → error 2.
     - Block flag `0x80000000` (exists) clear → error `0x3EE`.
  4. `flags&4` with an archived file:
     - Allowed only when `(blockFlags & 0x1FF00)==0` (stored raw).
     - Opens a fresh Win32 handle on the archive file, seeks to the block offset, and returns that raw handle.
     - Otherwise error `0x3EE`. A failed CreateFile gives error 2.
  5. Normal archived file:
     - Key = `Hash(basename,3)`. The basename is what follows the last `:` and then the last `\`.
     - If block flag `0x20000` is set: `key = (key + blockOffset − headerOffset) ^ fileSize`.
     - Sector count = ceil(size / sectorSize).
     - An offset table is allocated only when compressed (`0xFF00`); the read-ahead buffer is always allocated.
     - Archive reference +1. Returns 1.
- Callers:
  - Game wrappers 0x4442b0, 0x444890, 0x444990, 0x4445f0. 0x4442b0 and 0x444890 always fatal-error on failure; 0x444990 and 0x4445f0 fatal-error unless their "allow missing" argument is set and the error is 2 or `0x3EE`.
  - Flag 1 (a loose file in the exe directory overrides the archives) is used by the snd.cpp loaders (0x49d950) and fd_user.cpp (0x440e70, 0x440fb0). Everything else uses 0.

### 0x1501b090 `SFileReadFile` (ord 269) — read bytes
- Module: SFile.cpp · Relevance: data · Status: specified
- Signature: `BOOL SFileReadFile(HANDLE file, void *buf, DWORD toRead, DWORD *read, OVERLAPPED *ov)`. Only `ov->Offset` (+8) and `ov->hEvent` (+0x10) are used.
- Behavior:
  1. `*read=0`. `buf==NULL` → error 0x57.
  2. `toRead==0` → signal `ov->hEvent` if given, return 1.
  3. Loose file without `ov`: one synchronous read at the current OS position. Returns `got==toRead`. A short read sets **no** error code.
  4. Archived file without `ov`:
     - First serve bytes from the 0x1000 read-ahead buffer.
     - If the remaining request is smaller than chunk = min(sectorSize − pos%sectorSize, 0x1000), read `chunk` bytes into the read-ahead buffer instead of the caller's buffer.
  5. Reading:
     - Synchronous-mode archives decode in place: partial head and tail sectors through the archive's one-sector cache, whole sectors directly. Reading at or past EOF yields 0 bytes; reads are clamped to the file size.
     - Async-mode archives, and loose files with `ov`, are split into chunks (`0x20000` by default) and queued to the I/O thread (urgent when there is no `ov`).
     - With `ov` the call returns 1 at once; `*read` stays 0 and the position is not advanced. The caller waits on the event.
     - Without `ov` it waits internally.
  6. Finish:
     - n = min(got, toRead), copied out of the read-ahead buffer when that was used.
     - The position advances by n when there is no `ov`. `*read += n`.
     - Returns 1 if n == toRead; otherwise error `0x26` (EOF) and returns 0.
- Callers: 0x444640 (read wrapper; tolerates `0x3E5` IO_PENDING with an OVERLAPPED), 0x4c08c0, SBmp, SNet upgrade.

### 0x1501b600 `SFileSetIoErrorMode` (ord 274) — I/O failure policy

## SMem: memory

SMem is initialised in the DLL entry point (0x1501f560), which:
- reads the registry values `Internal\Debug Memory`, `Internal\Protect Memory` and `Internal\Debug Error Output`;
- creates 256 heap critical sections.

The debug-fill flag `0x1506b49c` is enabled only through ordinal 496, which the game does not import. It is therefore off in normal runs.

### 0x1501e620 `SMemAlloc` (ord 401) — allocate
- Module: SMem.cpp · Relevance: platform · Status: specified
- Signature: `void *SMemAlloc(DWORD size, const char *srcName, int line, DWORD flags)`
- Behavior:
  - Not initialised → fatal SErrDisplayError(`0x8510007D`, "SMemAlloc()"), then `ExitProcess(1)`.
  - Heap selection:
    - The heap is chosen by `SStrHash(srcName, 1, line) & 0x7FFFFFFF`; a result of 0 becomes 1.
    - The hash is case-sensitive and uses `line` as the seed.
    - Each heap is created on demand and cached.
  - `size ≥ 0x80000000` or exhaustion → fatal error 8, so the function never returns NULL in practice.
  - Flags:
    - flag 8 zero-fills the block;
    - otherwise the block is filled with `0xEE` only in debug mode, and its contents are otherwise unspecified (leftover heap bytes);
    - flags `0x4000000` and `0x8000000` become internal block flags.
- Callers: 221 game call sites. Each passes its source file name and line; about 170 use flags 0 and about 10 use flag 8.
- Prior evidence: [native-local-heaps.md](../native-local-heaps.md) concerns game pathing heaps, not this allocator.

### 0x1501ec70 `SMemFree` (ord 403) — free
- Module: SMem.cpp · Relevance: platform · Status: specified
- Signature: `BOOL SMemFree(void *p, const char *srcName, int line, DWORD flags)`
- Behavior: each failure case reports its error and returns 0 without freeing; a valid block is freed and the call returns 1.

  | Condition | Error | Result |
  |---|---|---|
  | Not initialised | `0x8510007D` | Returns 0 |
  | `p == NULL` | `0x85100081` | Returns 0; dialog only if Debug Error Output is set |
  | Bad block signature (word `0x6F6D`) | `0x8510007C` | Returns 0; dialog only if Debug Error Output is set |
  | Block already freed | `0x8510007A` | Returns 0; dialog only if Debug Error Output is set |
  | Trailing sentinel `0x12B1` damaged | `0x8510007B` reported | — |
  | Valid block | — | Freed; returns 1 |

- Callers: 297 game call sites.

### 0x1501f5e0 `SMemReAlloc` (ord 405) — resize

## SBmp: image decoding

**Type detection** is shared by ordinals 321, 323 and 325. It runs when the requested type is 0 and at least 2 bytes are available:

| First 16-bit word | Type |
|---|---|
| `0x050A` | 2, PCX (manufacturer 0x0A, version 5) |
| `0x4D42` (`BM`) | 1, BMP |
| anything else | 3, TGA |

Other types return 0 without an error code.

Palettes are written as 256 `PALETTEENTRY` values `{R,G,B,flags}`. Pixels are written packed with no row padding, top-down.

**BMP decoder** (memory 0x15008cf0, file 0x15008b60):
- Fields: width `+0x12`, height `+0x16`, bpp `+0x1C`.
- Not validated: biSize (40 assumed), compression, ClrUsed.
- Palette (when bpp ≤ 8): the 256 RGBQUADs at offset `0x36`, mapped `{B,G,R,x}` → `{R,G,B,0}`.
- Rows:
  - Source stride is `(bpp*w>>3)` rounded up to 4.
  - Rows are copied last-to-first (bottom-up to top-down).
  - Output is clipped to the destination size.
  - Pixels are not converted, so 1/4-bit images stay packed.
  - A negative height is not handled.
- File variant: reads `biSizeImage` bytes from `bfOffBits` and returns 0 on a short read.
- Memory variant: it computes the pixel pointer as a relative seek, so it reads from the wrong offset. No game path decodes BMP from memory.

**PCX decoder** (memory 0x15008f70, file 0x15008dd0):
- Size: `w = Xmax−Xmin+1`, `h = Ymax−Ymin+1`, `bpp = BitsPerPixel × NPlanes`. BytesPerLine is at +0x42.
- RLE data starts at `0x80`:
  - a byte `< 0xC0` is a literal;
  - a byte `≥ 0xC0` is a run of `(b & 0x3F)` copies of the next byte (0 allowed), clamped to the space left in the row;
  - x runs to BytesPerLine; bytes at `x ≥ width` (padding) are consumed but dropped;
  - runs may cross scanlines.
- Planes: the first plane is written to component `planes−1`, so 24-bit PCX comes out BGR.
- Only 8×1 and 8×3 layouts are meaningful.
- Palette (bpp 8): the trailing 768 bytes of RGB triples. The `0x0C` marker is not checked.
- Data length (memory variant): `srcSize − 0x80 − (bpp==8 ? 0x301 : 0)`. Output is clipped to `min(Bpp·w·h, dstSize)`.
- Returns 1 once the header has been read.

**TGA decoder** (memory 0x150094f0, file 0x15009070):
- Accepted: image types 1, 2, 9 or 10 with no interleave. Valid combinations:

  | Colour map | Image bpp | Extra requirement |
  |---|---|---|
  | none | 24 | 0 alpha bits |
  | none | 32 | 8 alpha bits |
  | present | 8 | `first + len ≤ 256`, entries of 24 or 32 bits |

- Required size: `18 + idLen + cmapBytes + (uncompressed ? w·h·Bpp : 1)`.
- Palette: entries before `first` and after the map are zeroed. Alpha goes into peFlags.
- Pixels:
  - written raw (BGR/BGRA order);
  - flipped to top-down unless descriptor bit 5 is set; mirrored if bit 4 is set;
  - RLE packets: high bit set = run of `(n&0x7F)+1` copies, otherwise `n+1` literal pixels; packets may cross rows;
  - a packet that overruns the source returns 0.
- File variant quirk: a colour map larger than 1024 bytes overflows a stack buffer.

### 0x15030d60 `SVidInitialize` (ord 453) — load Smacker and compile the scalers
- Module: SVid.cpp · Relevance: render · Status: specified
- Signature: `BOOL SVidInitialize(IDirectSound *ds)`
- Behavior:
  1. Loads the function table.
  2. Once, compiles three SCode blitters with `maxIter=0x140`:
     - [0] prolog `"1 W2=S W1=W2 2 D=W"`, loop `"1 W1=W2 W2=S W1=TW 2 D=W"`, flags 0. This is a 2× horizontal stretch: the first pixel is doubled, then each source pixel emits the pair `(T[prev | cur<<8], cur)`.
     - [1] loop `"1 W1=S W2=SC D=TW"`. This interpolates rows vertically: `T[S[x] | S[x+C]<<8]` with `C` = pitch.
     - [2] loop `"1 W1=S W2=W1 2 D=W"` with flags `0x4000000`. This doubles pixels using alternating row adders.
  3. Calls `SmackSoundUseDirectSound(ds)`. Returns 1, or 0 on failure.
- Callers: 0x49de30 passes the game's DirectSound object.

### 0x15030e20 `SVidPlayBegin` (ord 454) — open and start a video
- Module: SVid.cpp · Relevance: render · Status: specified
- Signature: `BOOL SVidPlayBegin(const char *file, BYTE *dstBuf, const RECT *dstRect, const SIZE *dstSize, const SVIDPALETTEUSE *pal /*{cb=12, first, count}*/, DWORD flags, HSVIDEO *out)`
- Behavior: validates the arguments, derives the effective flags, opens the Smacker file and sets up zoom, blend table and palette as listed below; returns 1 with `*out` set, or 0 on failure (an open or buffer failure ends the partially built video through ordinal 458).
- Validation: error 0x57 when any of these holds:
  - `file` or `out` is NULL;
  - `dstBuf` is NULL while `0x20000000` is set;
  - `dstBuf` is given without `dstSize`;
  - `pal` is given with `cb != 12`.
- Steps:
  1. Sets a "video active" global, which is written but never read.
  2. When `flags & 0x808`, reads the registry value `Video Player\Mode`. If bit `0x100` of the stored value is clear, the value 0x203 is used instead. Flag `0x800` copies its bits `0x300`; flag `8` copies its bits `0x7`.
  3. Loads Smacker if needed (ordinal 453).
  4. Forces `0x10000000` to the inverse of `0x20000000`:
     - `0x10000000` = render into SDraw surface 0;
     - `0x20000000` = render into `dstBuf`; this also clears `0x80000`.
  5. Palette range: `pal` if given, otherwise first 1, count `0xFE`.
  6. SmackOpen flags start at `0x1000` (file-handle open):

     | Storm flag | SmackOpen flag added |
     |---|---|
     | `0x20000` | `0x200` (preload all) |
     | `0x400000` | `0x400` (no skip) |
     | `0x1000000` **clear** | `0xFE000` (all audio tracks) |
     | `0x2000000` | `0x20` (need pan) |
     | `0x4000000` | `0x40` (need volume) |

     So `0x1000000` means "no audio".
  7. Opening:
     - With `0x10000`, `file` is already a Win32 handle.
     - Otherwise SFileOpenFileEx(0, file, 5) is used: disk first, raw handle. The handle is closed by ordinal 458.
     - SmackOpen gets extra buffer −1.
  8. Zoom:
     - `0x200` (2× zoom) is cleared when the screen is smaller than twice the video.
     - `0x80000` centres vertically.
     - When zoomed, a Smacker buffer of width `W·(1+vInterp)` is opened. vInterp requires zoom plus bits 1 and 2.
     - `0x100` is set to "not zoomed"; when set it clears bits 0–2.
  9. If `(flags & 0x100002) == 0x100002` and a frame window exists, a 64 KB blend table is built from the system palette. Each entry is the nearest palette index to the average of a palette-index pair, using squared RGB distance. With `0x800000` the table is built as two halves, 0–0x7F and 0x80–0xFF.
  10. `0x200000` clears surface 0 to colour 0 (Storm ordinal 344).
  11. Without `pal` and without `0x100000`, sets palette entry 0 to black and entry 255 to white (forced).
  12. Returns 1 with `*out` set.

- Other bits:

  | Bit | Meaning |
  |---|---|
  | 1 | Full lines when zoomed. Otherwise scanline mode, where the palette is brightened by gamma `pow(c/256,0.8)·256`, capped at 255. |
  | 2 | Horizontal blend |
  | 4 | Interlace |
  | `0x40000` | Loop |
  | `0x100000` | Ignore the video palette |
  | `0x800000` | Split-half palette |

- Callers:

  | Game site | Use | Arguments / flags |
  |---|---|---|
  | 0x4503d0, 0x4504c0 | Unit portraits | `(name, buf, {0,0,w−1,h−1}, {w,h}, 0, 0x21100200, &h)`: buffer, no audio, ignore palette, zoom |
  | 0x4a6b40, 0x4a6c50 | Portraits | `0x21100000` |
  | 0x47ec60 | Cinematics | `0x10280808` for ids below `0x19`, else `0x10a80808` |
  | 0x4c8860 | Open only, then play | open-only with all-zero arguments; then `0x21520100`, or `0x21560100` with loop |

- Prior evidence: [native-audiovisual.md](../native-audiovisual.md) covers the portrait gate.

### 0x15031430 `SVidPlayContinueSingle` (ord 457) — advance one frame
- Module: SVid.cpp · Relevance: render · Status: specified
- Signature: `BOOL SVidPlayContinueSingle(HSVIDEO v, BOOL force, BOOL *frameShown)`
- Behavior:
  1. Zeroes `*frameShown`. `v==NULL` → error 0x57. An unknown handle → 0.
  2. Without `force`: if `SmackWait()` is non-zero the frame is not due yet, and the call returns 1.
  3. **Video palette change** (and `0x100000` clear):
     - SmackBufferNewPalette, then copy the RGB triples.
     - If entries 2..0x7E all equal entry 1, the update starts at 0x80. If entries 0x82..0xFE all equal entry 0x81, it ends at 0x80.
     - Clear the screen if `0x200000` is set without `0x800000`.
     - Apply the 0.8 gamma if `(flags & 0x201) == 0x200`.
     - With bit 2, force entry 0 black and entry 255 white and rebuild the blend table.
  4. **Rendering without zoom:**
     - SDrawUpdatePalette(start, count, …, 1), then wait for vertical blank.
     - Lock the target: SDraw surface 0 at the centring offset, or `dstBuf + top·cx + left` with pitch `cx`.
     - SmackToBuffer, SmackDoFrame, then unlock surface 0 in SDraw mode.
  5. **Rendering with zoom:**
     - SmackDoFrame first, then the palette.
     - Dirty rects come from SmackToBufferRect into an SRgn and are drawn with the SCode scalers.

## SCode: the blitter compiler

SCode compiles short strings into self-patching x86 row loops. A remake can implement the same semantics with an interpreter, or with a specialised loop for each string the game uses. The language is described below.

**Characters**
- Allowed characters: `W S D T A B C 0 1`, space, `= & | ^ + -`, and digits used as size or byte selectors.
- Any other character is an error at that position. A string shorter than 3 characters is an error at its start.
- The compiler upper-cases the source before parsing.

**Statements and operand size**
- Statements are separated by spaces.
- A token that consists only of `1`, `2` or `4` sets the operand size in bytes for the statements that follow. The default size is 4.

**Registers**

| Name | Class | x86 register | Meaning as an operand |
|---|---|---|---|
| `W` | general | eax | value |
| `A` | general | ecx | value |
| `B` | general | edx | value |
| `C` | general | ebx | value |
| `D` | pointer | edi | memory at the pointer |
| `S` | pointer | esi | memory at the pointer |
| `T` | pointer | ebp | memory at the pointer |

- A pointer letter always means memory: `size` bytes at that pointer.
- A pointer letter followed by an index register means memory at pointer + the full 32-bit register value. For example, `TW` is `[ebp+eax]` and `SC` is `[esi+ebx]`.
- A general register followed by a byte digit selects one byte: `1` = bits 0–7, `2` = 8–15, `3` = 16–23, `4` = 24–31. Selectors 3 and 4 are implemented with `ror 16`.
- Any byte selector makes the whole statement a 1-byte operation.

**Constants**
- `0` is zero. `1` is all ones at the current size.
- Constants take no suffixes, and neither constant may be a destination.

**Statement form: `DEST=SRC op SRC …`**
- Operators are `& | ^ + -`, evaluated left to right.
- Peephole rules:
  - `x=0` and `x&0` become a zero move;
  - `|0`, `^0`, `+0`, `-0` are dropped;
  - `|1` becomes a move of −1;
  - `^1` becomes a NOT.
- Quirk: `x=1` is deleted entirely, so `x` keeps its old value. No string in the game triggers this.

**Pointer advance.** At the end of each body, `D`, `S` and `T` each advance by the largest size of any non-indexed memory access made through that pointer. Indexed accesses (such as `TW` or `SC`) do not advance anything.

**Row boundaries**
- `W` is clobbered at every row end, which is why strings start with `W=0` (the upper bits of a `TW` index must be zero).
- `A`, `B` and `C` persist across rows.

### 0x1500cd60 `SCodeCompile` (ord 331) — compile a prolog/loop pair
- Module: SCode.cpp · Relevance: render · Status: specified
- Signature: `BOOL SCodeCompile(const char *prolog, const char *loop, char **errPos, DWORD maxIter, DWORD flags, HSCODE *out)`
- Behavior: compiles the prolog and loop strings into code buffers and links a new handle; after the argument checks it returns 1 whether or not compilation succeeded, as detailed below.
- Validation: `out` NULL, an empty `loop`, or `maxIter==0` → error 0x57, returns 0. `*errPos` is zeroed first; `*out` is not cleared.
- Prolog text:
  - Without flag `0x40000`: `"W=0 "` + `prolog`, truncated to 256 bytes.
  - With flag `0x40000` and a non-NULL `prolog`: the prolog alone. A leading `#` in the prolog becomes `1`, and a leading `#` in the loop becomes `4`.
- Output code:
  - The prolog is compiled once. With `0x40000` it is compiled as 3 copies, with entries that execute 0–3 copies, plus an identical second buffer for the trailing pixels.
  - The loop is compiled as `maxIter` copies, with an entry for each count `j` that executes exactly `j` bodies.
- On a syntax error, `*errPos` is set to the offending character in the caller's string and the function **still returns 1** without writing `*out`. Callers can detect the failure only through `errPos` or a NULL handle.
- On success the handle is linked into a global list, `*out` is set, and the function returns 1.
- Callers: 0x4ca420 (effects.cpp) compiles two handles. Both use flags `0x40000` and `maxIter 0xA0`:

  | Handle | Prolog | Loop |
  |---|---|---|
  | `0x6cfbd4` | `"4 W=0 1 A=S B=D W1=A1 W2=B1 D=TW"` | `"4 W=0 A=S B=D W1=A1 W2=B1 C1=TW W1=A2 W2=B2 C2=TW W1=A3 W2=B3 C3=TW W1=A4 W2=B4 C4=TW D=C"` |
  | `0x6cfbd8` | same with `A=D B=S` | same with `A=D B=S` |

  - Per pixel, handle `0x6cfbd4` computes `dst = T[src | dst<<8]` and handle `0x6cfbd8` computes `dst = T[dst | src<<8]`. `T` is a 64 KB blend table.
  - The loop processes 4 pixels per dword; the prolog and trailing copies handle unaligned edges.
  - The game's failure check calls FUN_4cc190 ("effects"). Because of the always-1 return above, it can never fire.

### 0x1500d330 `SCodeExecute` (ord 334) — run a blitter
- Module: SCode.cpp · Relevance: render · Status: specified
- Signature: `BOOL SCodeExecute(HSCODE h, SCODEEXECUTEDATA *d)`. No validation; always returns 1. It is not thread-safe, because it patches code.
- `SCODEEXECUTEDATA` layout:

  | Offset | Field |
  |---|---|
  | +0 | size (0x40, not checked) |
  | +8 | width |
  | +0xC | rows (must be ≥ 1) |
  | +0x10 | D row adder = dstPitch − width |
  | +0x14 | S row adder = srcPitch − width |
  | +0x18 | D pointer |
  | +0x1C | S pointer |
  | +0x20 | T pointer |
  | +0x24/+0x28/+0x2C | initial A/B/C; written back on exit |
  | +0x30/+0x34 | alternate D/S adders |

- Behavior:
  - Without `0x40000`:
    - Each row runs the prolog once and then the body `width` times.
    - `width` must be ≤ `maxIter`; this is not checked.
  - With `0x40000`:
    - Each row runs the 1-byte prolog `lead = min((4 − (D&3)) & 3, width)` times.
    - It then runs the loop body `(width−lead)>>2` times, then the trailing 1-byte copy `(width−lead)&3` times.
    - The split is computed from the first row's D.
    - Net semantics: exactly `width` pixels per row.
  - After each row: decrement `rows`, add the adders, and repeat.
  - Flag `0x4000000`: rows alternate between the primary adders and the alternate adders at `+0x30`/`+0x34` (line doubling in SVid).
- Callers:
  - The game fills the block at `0x6cfbe0` with: width, height, both row adders, dst, src and table.
  - 0x4ca950: colour-0-keyed copy. Handle `bd8`, table `0x6cfbd0`: row 0 is identity, rows j ≥ 1 are filled with j.
  - 0x4ca8a0: percentage alpha. level = pct·7/100; level 0 draws nothing, level 7 is the keyed copy, and levels 1–6 use palette blend tables built by 0x4c9c70.
  - 0x4ca9b0: keyed copy with one colour blended.
  - These are UI/glue effects, distinct from the GRP blitters in [native-pixel-blitters.md](../native-pixel-blitters.md).

## SBlt: raster operations

### 0x150083e0 `SBltROP3` (ord 313) — ROP3 block transfer
- Module: SBlt.cpp · Relevance: render · Status: specified
- Signature: `BOOL SBltROP3(BYTE *dst, const BYTE *src, int w, int h, int dstPitch, int srcPitch, DWORD pattern, DWORD rop)`
- Behavior:
  1. `w<1` or `h<1` → returns 1 and does nothing.
  2. Fast path for SRCCOPY `0xCC0020` or PATCOPY `0xF00021`:
     - Requires `(dst|w) & 3 == 0` and `w ≤ 0x280`. Source alignment is not checked.
     - Runs the precompiled dword loops `"4 D=S"` / `"4 D=A"`.
  3. Other ROPs are normalised first:
     - BLACKNESS `0x42` → PATCOPY with pattern 0;
     - `0x000F0001` → PATCOPY with pattern `(pattern==0)`; this is a logical, not bitwise, inverse;
     - WHITENESS `0xFF0062` → PATCOPY with pattern `0xFFFFFFFF`.
  4. Compiled-ROP cache:
     - The cache key is `(rop>>16)&0xFF`.
     - A ROP is compiled on first use, or recompiled when `w` exceeds the compiled width, as `SCodeCompile(s, s, 0, max(640,w)/4, 0x40000)`.
     - The string `s` comes from the standard GDI ROP3 encoding (ordinal 312). For example: SRCCOPY → `# D=S`, PATCOPY → `# D=C`, `0xB8074A` → `# D=C^D&S^C`.
  5. Executes with `D=dst`, `S=src`, `C=pattern` and returns 1. `T`, `A` and `B` are left uninitialised.
  6. `src` is not NULL-checked for ROPs that read it.
- Semantics: per byte, apply the GDI ternary ROP to `(P=pattern, S, D)`.
- Callers (all SRCCOPY, pattern 0):
  - 0x4cb390: presents a dirty rect from the 640-pitch back buffer to the locked surface.
  - 0x4ca110: mode 0 of the UI draw.
  - 0x4b5300: save-under copies.
  - 0x4ce720: image copy.

### 0x15008540 `SBltROP3Clipped` (ord 314) — clipped ROP3
- Module: SBlt.cpp · Relevance: render · Status: specified
- Signature: `BOOL SBltROP3Clipped(BYTE *dst, const RECT *dRect, const SIZE *dSize, int dPitch, const BYTE *src, const RECT *sRect, const SIZE *sSize, int sPitch, DWORD pattern, DWORD rop)`

## STrans: transparency masks

**Mask object**

| Offset | Field |
|---|---|
| +8 | data |
| +0xC / +0x10 | allocated / used size |
| +0x14 | offset of the run stream = size of the pixel section (0 when the mask has no pixels) |
| +0x18 / +0x1C | width / height |
| +0x20..+0x2C | bounding box of opaque pixels |

- **Pixel section.** The opaque pixel values in raster order, padded to a multiple of 4 (the pad bytes are not written).
- **Run stream.**
  - Per row: 16-bit words whose low byte is the opaque (copy) count and high byte the transparent (skip) count. A row ends with the word 0.
  - Each count is at most `0xFC`.
  - A row that starts transparent begins with `(0, n)`. A zero-width row is just the terminator word.

### 0x1502bb50 `SRgnGetRectsi` (ord 529, BWAPI name `SRgn529i`) — get rects as integers

## SReg: registry

**Key path.** Every function builds the key as prefix + subkey, at most `0x104` characters:
- `flags & 0x10`: no prefix.
- else `flags & 2`: prefix `Software\Battle.net\`.
- otherwise: prefix `Software\Blizzard Entertainment\`.

**Errors.** Registry-API failures are reported only through Win32 `SetLastError`; Storm's own last-error value is not updated for them. Argument-validation errors (0x57) go through SErrSetLastError and do update it.

**Load behaviour** (helper FUN_150282d0):
1. Unless `flags & 4`, read from HKCU: `RegOpenKeyEx` with `KEY_READ`, then `RegQueryValueEx`.
2. If that failed and `flags & 1` is clear, read from HKLM.
3. If both hives were skipped, the error is `0x3F3`.

**Save behaviour** (FUN_15028410):
- Hive: HKLM if `flags & 4`, otherwise HKCU.
- Writes with `RegCreateKeyEx(KEY_WRITE)` + `RegSetValueEx`.
- `flags & 8` also flushes the key.

## SNet: turn/message transport

### Model

**Providers.**
- Storm scans `*.snp` files in the exe directory. Each must be an MPQ that passes authentication.
- Provider identity (id, name, description, CAPS) comes from `caps.dat` in each `.snp`. Storm subtracts 16 from maxmsg.
- `standard.snp` contains these providers:

  | Id | Name | maxmsg | maxplayers | Bytes/s | Latency | Turns/s | In transit |
  |---|---|---|---|---|---|---|---|
  | `IPXN` | IPX | — | — | — | — | — | — |
  | `SCBL` | Direct Cable | — | — | — | — | — | — |
  | **`0`** | **"" (hidden)** | 512 | 1 | 3145728 | 0 | 30 | 0 |
  | `MODM` | Modem | — | — | — | — | — | — |
  | `UDPN` | UDP | — | — | — | — | — | — |

- `battle.snp` contains `BNET`.

**Single player** initialises provider **id 0**:
- Game 0x475220 calls 0x4757e0 with ECX=0, which calls `SNetInitializeProvider(0, …)`.
- The provider is a null transport:
  - Send drops packets.
  - Receive fails.
  - The game list is empty.
  - Advertising succeeds.
- Effective values: maxmsg 496, latency 0.
- With latency `L = 0`, the timing globals are:

  | Global | Formula | Single-player value (ms) | Use |
  |---|---|---|---|
  | `0x15066708` | max(5L, 250) | 250 | turn ack delay |
  | `0x1506670c` | max(12L, 5000) | 5000 | join timeout |
  | `0x15066710` | max(4L, 1000) | 1000 | responsive window |
  | `0x15066714` | max(L/2, 25) | 25 | message ack delay |
  | `0x15066718` | max(L, 50) | 50 | resend and leave sleep |

**Player records.**
- The local player is a separate record; remote players are list `0x15066728`.
- Ids are slot numbers 0..7, because base `0x1506b8d8` stays 0 (the game never calls SNetSetBasePlayer).
- The "none" id is −1.
- Local id byte `0x15066600` is `0xFF` when not in a game (error `0x85100070`).
- Record fields per class (0 control, 1 message, 2 turn, 3 unreliable):
  - u16 send sequence at `+0x1CC+2c`;
  - u16 next deliverable sequence at `+0x1D4+2c`; `+0x1D8` is the current turn;
  - a receive list kept sorted by sequence.
- Record flags at `+0x118`: 4 = joining (not yet at the current turn), 8 = being dropped.

**Packets.** 12-byte little-endian header:

| Offset | Field |
|---|---|
| +0 | u16 checksum |
| +2 | u16 length |
| +4 | u16 sequence |
| +6 | u16 ack |
| +8 | u8 class |
| +9 | u8 command |
| +10 | u8 sender id |
| +11 | u8 flags: 1 = ack only, 2 = resend request, 4 = relayed |

- **Checksum.** Fletcher-style sum mod 255 over bytes +2..end, processed backwards:
  - Walk the bytes from last to first: `a = (a + byte)`, subtracting 255 when the sum exceeds 254; then `b += a`.
  - Let `lo = (u8)(b + b/255)` and `hi = a`.
  - Store `c1 = 0xFF − (lo+hi)%255` at +1 and `c0 = 0xFF − (c1+hi)%255` at +0.
  - The receiver recomputes over the whole packet and requires 0. It also requires length ≥ 0xC, class ≤ 3, and a known sender.

**Loopback.** A packet addressed to the local record is appended directly to the local receive list. In single player every turn and message travels this path, in order.

**Pump thread** (event `0x1506b8f8`):
- Receives from the provider, then runs timers: pings every 20 s, acknowledgements, resend requests and retransmits.
- With no remote players the wait is INFINITE, so nothing happens in single player.

**Events.**
- User handlers are SEvt `'SNET'` type 1. They receive `{id, player, data, size}`.
- They are dispatched synchronously on the caller's thread inside SNetReceiveTurns, SNetReceiveMessage and SNetJoinGame.
- No events fire in single player.

### 0x15025f00 `SNetInitializeProvider` (ord 117) — load a provider
- Module: SNet.cpp · Relevance: network · Status: specified
- Signature: `BOOL SNetInitializeProvider(DWORD providerId, PROGRAMDATA*, PLAYERDATA*, INTERFACEDATA*, VERSIONDATA*)`
- Behavior:
  1. Copies the four structs, normalised to sizes 0x3C, 0x10, 0x5C and 0x14. Missing strings default to `""`. Interface data defaults: window = SDrawGetFrameWindow, message box = MessageBoxA. A normalisation failure → error 0x57.

### 0x15027110 `SNetReceiveTurns` (ord 122) — collect the next turn from every player
- Module: SNet.cpp · Relevance: simulation · Status: specified
- Signature: `BOOL SNetReceiveTurns(int firstId, int count, void **data, DWORD *sizes, DWORD *status)`
- Behavior: processes drops and joins, dispatches queued events, writes a status word per slot and, when every present slot has its turn-T packet, returns those packets and advances the turn; details below.
- Validation:
  - When `count` is non-zero, each array is zeroed first.
  - NULL arrays or `count==0` → error 0x57. No provider → `0x4B4`. Not in a game → `0x85100070`.
- Steps (T = the local current turn):
  1. Players marked for dropping whose turn has reached their drop turn are removed and event 3 is queued (data = the 4-byte reason). Host migration and re-advertising happen here.
  2. Joining players whose turn equals T lose the joining flag, and event 2 is queued.
  3. Leaves the lock, dispatches the queued events on this thread, and re-enters. If the game ended meanwhile → error `0x85100069`.
  4. Frees the turn buffers delivered by the **previous** call. Pointers from that call become invalid.
  5. Writes a status word for each slot:

     | Bit | Set when |
     |---|---|
     | `0x10000` | The player is present (not joining) |
     | `0x20000` | The head of that player's turn queue has sequence T |
     | `0x40000` | The local player (always); or a remote player heard from within `max(4L,1000)` ms; or a remote player being dropped whose data is present |

     A slot with no record is 0.
  6. For any present slot without data: send resend requests at most every `max(L,50)` ms, and pings to idle players.
  7. If every present slot has its turn:
     - each slot gets `data[i]` = packet+12 and `sizes[i]` = length−12, and that player advances to T+1;
     - empty slots get NULL/0;
     - the local turn becomes T+1 (also mirrored at `0x15066618`);
     - returns 1.
  8. Otherwise → error `0x8510006B`. Nothing is consumed.

## SBig: big-number arithmetic (league and map signature checks)

The game uses SBig only in 0x49d3e0 and 0x49d460. 0x49d460 is the interface-data callback `+0x54`, and the game also calls it directly from `VerifyMapSignature` 0x46b0d0 ([P23](p23.md), call at 0x46b170). It verifies a Blizzard "strong" signature:
- The file must end with the tag `NGIS` (`0x5349474E`) followed by a modLen-byte signature.
- Expected block: modLen bytes of `0xBB`, last byte `0x0B`, with SHA-1(file data before the tag + upper-cased file name) at its start.
- The check computes `sig^E mod N` (little-endian numbers) and compares it with the expected block using SMemCmp.

`battle.snp` calls the callback for league files with a 2048-bit modulus, exponent bytes `01 00 01 00` and exponent length 0. Exponent length 0 loads E = 0, so that check can never succeed in this repack. The game's own call in `VerifyMapSignature` 0x46b0d0 passes the 256-byte modulus 0x4eec90, exponent 0x4eed90 (`01 00 01 00`) and exponent length 4, so E = 65537 and a correctly signed map verifies. That path runs only when a map archive contains a ladder/tournament condition file (`*.cnd`, [P20](p20.md), [P23](p23.md) `0x469650`). Campaign missions never reach it: `OpenMapArchive` `0x469de0` returns at `0x469de6`–`0x469e09` without opening an archive or running the condition probe whenever the campaign mission key `0x526524` is nonzero, and the other caller `0x469560` serves only the Battle.net ladder check `0x477e90`. A file check agrees: none of the nine condition names exists at the archive root or in any of the 64 campaign directories of the five game archives (each directory's `staredit\scenario.chk` was found) (F03). All five SBig imports are excluded: they are reached only from Battle.net league loading and from signature checks of ladder/tournament condition maps.
