# P33: AI placement filters, resource areas, expansion choice and saved games

This package covers `0x495d40`–`0x499890` (64 functions). The first 50 functions lie in the object between `sai_scripts.cpp` and `saveload.cpp`; the last 14 are in `saveload.cpp`. The functions form five groups.

1. **AI building-placement grid** (`0x495d40`, `0x4960b0`–`0x4962c0`, `0x497630`–`0x497910`, `0x497d90`–`0x498930`). `BuildPlacementGrid` `0x495bb0` and `FindAiBuildingPlacement` `0x494fc0` (both [P32](p32.md)) fill a 64 × 64 byte candidate grid centred on a seed point and narrow it with these filters. All of them are covered by [AI placement](../native-ai-placement.md); the entries below add signatures and the exact table contents.
2. **Region-path distances** (`0x495e70`, `0x496780`, `0x496930`, `0x496ac0`, `0x4976d0`). Each runs the long region search `SearchRegionPath` `0x491300` ([region paths](../native-region-paths.md)) on a 0x170-byte stack context and sums distances or enemy strength along the retained route.
3. **Resource areas** (`0x4964b0`–`0x496740`, `0x496bf0`–`0x497480`, `0x4979b0`, `0x497a20`). This is the 250-record script-area table, its generator, its periodic refresh, its lookups, the expansion chooser `0x4970e0` and the attack-route chooser `0x496320`.
4. **Saved-game files** (`0x4989f0`–`0x499890`). The save writer `0x498d20`, the loader `0x499890`, the saved-game list for the load screen, file lookup, deletion and validation.
5. **Accessors** for the save state (`0x499850`–`0x499880`).

## Data model

**Placement grid.** 64 × 64 bytes, row-major (`grid[row*64 + col]`), nonzero = candidate. Cell (col, row) stands for tile `trunc(seed_x/32) − 32 + col`, `trunc(seed_y/32) − 32 + row`; pixel-based filters use the point `(seed_x − 1024 + 32·col, seed_y − 1024 + 32·row)`, keeping the seed's sub-tile offset. The seed is a packed DWORD (low WORD x, high WORD y, both signed). Filters that "restore on exhaustion" copy all 4096 bytes on entry (`memcpy` `0x4d16a0`) and copy them back when no nonzero byte remains.

**units.dat placement box** `0x522728 + 4·type`: signed WORD width (`+0`) and height (`+2`) in pixels. Tile sizes in this package are these values divided by 32 with truncation toward zero. **units.dat flags** `0x521660 + 4·type`: `0x1` building, `0x2` add-on, `0x1000` resource depot, `0x2000` resource container.

**Resource-area table** `0x6a2e88`: 250 records of 48 bytes, index 0 unused. `0x6a5d68` used count, `0x6a5d6c` refresh countdown (the clear in `0x497a20` covers `0x2ee8` bytes = the records plus both DWORDs).

| Offset | Meaning |
|---|---|
| `+0x00/+0x02` | x, y (signed WORDs, pixels) |
| `+0x04` | mineral-field count (BYTE) |
| `+0x05` | gas-object count (BYTE) |
| `+0x06` | start-location marker (BYTE, 1 for areas created from start positions) |
| `+0x07` | flags: `0x01` occupied by a building, `0x02` reserved (chosen as an expansion or by script) |
| `+0x08` | remaining minerals (DWORD, unsigned sum) |
| `+0x0c` | remaining gas (DWORD) |

A resource unit's area index is the CUnit byte `+0xd8` (0 = none); its amount is the WORD `+0xd0`.

**Region-search context** (0x170 bytes, see [P32](p32.md)): `+0x04/+0x06` source x, y, `+0x08/+0x0a` destination x, y, `+0x18` copy of the destination DWORD, `+0x1c` 0, `+0x20` route of up to 50 region WORDs, `+0x86` route length (signed WORD), `+0x140/+0x142` source and destination region IDs. Callers here build it with the region centres from `0x481a30` (pixels, DWORDs from the 8.8 fixed fields `+0x10/+0x14` of the 64-byte region record) or `0x481a60` (WORD pair).

**Pathing region record** (64 bytes at `*0x69b584 + 0x449fc + 64·id`): `+0x02` connectivity group, `+0x04` tile count. Different groups mean no ground connection.

**AI region record** (52 bytes at `0x6b1a74[player] + 52·id`): `+0x02` target region WORD, `+0x05` state, `+0x18/+0x1a` enemy air/ground strength.

**Expansion scratch arrays** (indexed by category 0..8): `0x6a5da4` best ground distance, `0x6a5dc8` best air distance, `0x6a5dec` area with the best ground distance, `0x6a5e10` area with the best air distance.

**Category order table** `0x508fc8`: three rows of ten DWORDs, each a list of categories terminated by 9.

| Row | Address | Order |
|---|---|---|
| 0 | `0x508fc8` | 8, 0, 1, 3, 2, 5, 4, 6 |
| 1 | `0x508ff0` | 0, 3, 5, 1, 2, 4, 7, 6 |
| 2 | `0x509018` | 0, 1, 2, 3, 4, 5, 6, 7 |

**Directional line table** `0x509040`: 16-byte records {x0, y0, dx, dy} (signed DWORDs), terminated by x0 = −1. Each record clears 64 cells starting at (x0, y0) and stepping (dx, dy): columns 32, row 32, column 31, row 31, column 33, row 33, column 30, column 29, row 30, column 28, row 29, column 27, row 28.

**Defense masks** (ASCII, row-major, only `x` clears): side 17 at `0x509120`, 13 at `0x509248`, 9 at `0x5092f8`, 5 at `0x50934c`. Each is a filled disc: for side 17 the row widths are 5, 9, 11, 13, 15, 15, 17 ×5, 15, 15, 13, 11, 9, 5; side 13: 5, 7, 9, 11, 13 ×5, 11, 9, 7, 5; side 9: 3, 7, 7, 9 ×3, 7, 7, 3; side 5: 3, 5, 5, 5, 3 (all centred).

**Save-file extensions** (`0x4995a0`): `.sng` single player and `.mlt` multiplayer for the original game; `.snx` and `.mlx` when the Brood War byte `0x536720` is set. The strings at `0x4efa8c/94/9c/a4` are `*.sng`, `*.mlt`, `*.snx`, `*.mlx`; callers skip the `*` for the extension.

**Saved-game list** `0x509368`: a Storm `TSList` (head object; `+4` terminator link, `+8` first node, nonpositive = end). Node (200 bytes, `SMemAlloc` with flag 8): `+0/+4` links, `+8` the 0xb5-byte save header with the display name at header `+0x99`, `+0xc0` the file's last-write `FILETIME`.

**Save globals.** `0x6a5e34` open save `FILE*` while loading; `0x6a5e38` "game was loaded from a save" byte; `0x6a5e3c`, `0x6a5e44`, `0x6a5e78` written by the header reader `0x499c50` (P34): `0x6a5e44` is the saved local-player DWORD, `0x6a5e78` the header's second WORD (format sub-version 3), passed to the pool loaders; `0x6a5e40` is header DWORD `+4` (the RNG state written by `0x49a8e0`), stored by `0x49a0c0`. `0x672690` is the current profile name, `0x672664` the multiplayer byte.

## Saved-game file layout

`0x498d20` writes, in order (raw = `fwrite` of one element via `0x4cc4a0`; block = `WriteCompressedBlock` `0x4137d0`):

1. Text banner `0x49a4d0`: lines of ASCII ending with byte `0x1a`.
2. `0x49a8e0`: raw DWORD `0x00690003`, then a block of the 0xb5-byte header (WORD 105, WORD 3, RNG state, then a copy of the game description `0x6728d0`).
3. Block `0x6726c8` (`0x1b0` bytes: 12 player records of 36 bytes).
4. Block `0x5263d0` (`0x17700` bytes: the per-player game-state area, which includes the elapsed seconds `0x526520` and the map path `0x52701c`).
5. Raw DWORD `0x508d54` (local player).
6. Images, sprites, both thingy pools, the independent flingy, units, bullets, orders (`0x411300`, `0x416ed0`, `0x4189d0`, `0x40c9f0`, `0x431400`, `0x40a720`, `0x413ee0`).
7. Raw DWORD size and block of the creep map `0x6ca7a4` (w·h·2 bytes), then raw size and block of the creep-edge map `0x6ca7a8` (w·h bytes).
8. Creep record pool `0x4b4b80`.
9. Blocks `0x666458` (`0x20000`), `0x54323c` (`0x20000`), `0x666454` (`0x40000`): raw tiles, remembered megatiles, tile flags.
10. Triggers `0x4bd920`.
11. Raw DWORD `0x666444` and block of the map string table `0x666440` of that size.
12. Block of the 96 packed unit references of `0x6a5ef0` (`0x180` bytes).
13. Raw DWORD size and block of the pathing buffer (`0x48cb90`/`0x48ca50`).
14. AI data `0x48ddb0`; DAT overrides `0x46b710`.
15. Raw DWORDs `0x543218`, `0x54321c` (screen x, y).

The loader `0x499890` reads items 6–15 in the same order; items 1–5 are read before it by `0x499c50` (P34).

### 0x00495e70 `PickClusterReferenceMineral` — closest unassigned mineral by route distance
- Module: sai_scripts.cpp..saveload.cpp · Relevance: ai
- Status: specified
- Signature: `__fastcall`, ECX = default unit (returned when nothing qualifies), EDX = point x, stack [point y, classification array]; `ret 8`; returns a CUnit*.
- Behavior: Walks the active unit list (`0x425600`, next `+4`) in step with the byte array (one byte per list position, as built by `0x497a20`). Only units whose byte is 1 (unassigned mineral) are scored. With (sx, sy) the unit's sprite position, r1 = region at (x, y) and r2 = region at (sx, sy) (`0x481b10`):
  - r1 = r2: score = `ApproxDistance`(x, y, sx, sy) / 32, signed truncation.
  - Different connectivity groups: 9999.
  - Otherwise `SearchRegionPath` `0x491300` from (x, y) to (sx, sy). Failure: 9999. Route length ≤ 2: the direct score above. Longer: distance from (x, y) to the centre of route[1], plus centre-to-centre distances for route[2] .. route[length − 2], plus the last of those centres to (sx, sy); the DWORD sum shifted right 5 (unsigned).
  The unit is taken when score ≤ best (unsigned, best starts at 99,999,999) and score ≤ 20; equal scores therefore replace the earlier unit. Returns the last taken unit, or ECX when none.
- Callers/callees: `ClusterUnassignedResources` `0x495890`. Prior evidence: [resource generation](../native-resource-generation.md#unassigned-cluster-order-weight-and-reference), [reference ties](../native-resource-reference-ties.md).

### 0x00496320 `ChooseEnemyBaseRoute` — pick the enemy base region to attack and a staging region
- Module: sai_scripts.cpp..saveload.cpp · Relevance: ai
- Status: specified
- Signature: `__fastcall`, ECX = player, EDX = source region, stack [pointer to DWORD staging region]; `ret 4`; returns the target region or 2500.
- Behavior:
  1. (cx, cy) = centre of the source region (`0x481a30`). best cost = 99,999,999, best distance = 99,999,999, best owner = −1, best area = 0, count = 0, result = 2500, staging = 2500.
  2. For each unit of the active list (`0x425600`, next `+4`) that is a resource depot (`0x521660` flag `0x1000`), hostile to the player (`IsPlayerEnemyOfUnit` `0x429110`) and inside a start area (`FindStartAreaForResource` `0x4955b0` ≠ 0, giving area a):
     - count += 1; d = `ApproxDistance`(cx, cy, area x, area y); t = region at the area point.
     - cost = `0x496780`(player, source, [t, &target, &stage]).
     - cost = 100,000,000 (no route) → skip.
     - If cost = 99,999,999 (other group) or the depot's owner (`+0x4c`) differs from the best owner: accept when d < best distance (strict).
     - Otherwise (same owner as the best, finite cost): accept when cost ≤ best cost.
     - Accept: best owner = owner, result = target, staging = stage, best cost = cost, best distance = d, best area = a.
  3. Writes staging to the output. Returns 2500 when count < 2, best cost > 1000 (unsigned), elapsed seconds `0x5349d8` < 1500, best area ≠ 0 and that area's start marker `+0x06` ≠ 0 (a lone, strongly defended enemy start location early in the game). Otherwise returns result.
- Callers/callees: `0x4aa8f0`, which then sets the staging AI region's target to the result and its state to 8.

### 0x00496780 `SumRouteEnemyStrength` — enemy strength along a region route
- Module: sai_scripts.cpp..saveload.cpp · Relevance: ai
- Status: specified
- Signature: `__fastcall`, ECX = player, EDX = source region, stack [target region, out target, out staging]; `ret 0xc`; returns the summed strength or a sentinel.
- Behavior: S(r) = enemy air + enemy ground strength of AI region r (`0x4aeaf0`(player, r, [0]) reads WORDs `+0x18` + `+0x1a`).
  1. out staging = source, out target = target.
  2. Equal regions: return S(source).
  3. Different connectivity groups: return 99,999,999.
  4. `SearchRegionPath` `0x491300` between the two region centres; failure → 100,000,000.
  5. Route length ≤ 2: return S(source) + S(target).
  6. Otherwise, for i = 0 .. length − 1: s = S(route[i]); if out target still equals the requested target (no strength region found yet): if i ≥ 3 and route[i − 3] has a tile count (`+0x04`) ≥ 60, out staging = route[i − 3]; then, if s ≠ 0, out target = route[i]. The total of all s is returned. So the target becomes the first region on the route with enemy strength, and the staging region is the last large region three steps before it.
- Callers/callees: `0x496320`.
