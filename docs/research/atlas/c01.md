# C01: C runtime and library code

This package covers the 712 functions Ghidra identifies between 0x4d001c and 0x4ea930, plus 27 addendum entries added in [F03](f03-final-fixes.md): `__ftol3` 0x4d3fc0 and the 26 static destructors 0x4ea150–0x4eaad0, and two added in the F04 tail-jump scan: the x87 dispatchers `_trandisp1` 0x4e3940 and `_trandisp2` 0x4e39a7 (741 in all). The range is the tail of `.text` after the game and engine objects. It holds three kinds of code. First come 145 six-byte import thunks for Storm.dll at 0x4d001c–0x4d037c, plus 7 Windows thunks at 0x4e890a–0x4e892e (KERNEL32, WINTRUST and PSAPI). Next is the statically linked Visual C++ 12 runtime at 0x4d0382–0x4ea0e9: string, memory, stdio and lowio, heap, time, locale and MBCS, startup and exit, SEH and C++ EH, libm `sqrt` and `pow`, printf/scanf engines and compiler helpers. Last is a small block of compiler-generated game teardown code (0x4ea120, 0x4ea930 and the static destructors between them).

All CRT routines were identified from Ghidra function-ID matches (Visual Studio 2012/2013 signatures), import references, string constants and their call structure. Each is recorded with status `library` and a one-line behavior statement. The two game-code functions have full `specified` entries.

## Global facts that shape CRT behavior

- **Locale is always "C".** No `setlocale` exists in the image, so `__locale_changed` (0x6d3220) stays 0. Every `is*`, `tolower`/`toupper`, `_stricmp`/`_strnicmp`, `strtol`/`strtoul` and `printf`/`scanf` call uses the static C tables. Case folding is ASCII-only (`A`–`Z` ↔ `a`–`z`). The decimal point is `.`. The MBCS code page is the system ANSI code page (`_setmbcp(_MB_CP_ANSI)` at startup), and only the `_mbs*` routines consult it.
- **No user hooks are installed.** The game never sets an invalid-parameter handler, new-handler, SE translator or matherr replacement; the matherr slot holds stub 0x4b8e80. A failing secure call such as an overflowing `sprintf_s` or `strncpy_s` without `_TRUNCATE` therefore terminates the process through Watson (`STATUS_INVALID_CRUNTIME_PARAMETER`).
- **There is no `_ftol`, `_ftol2` or `_ftol2_sse`.** The build targets SSE2. Game float-to-int conversions are inline `cvttsd2si`: three in the palette gamma path 0x4cf760 and one in 0x49c300. 64-bit conversions use `__dtol3` (0x4d41a1). Both truncate toward zero, and none depends on the x87 rounding mode. A per-function scan of game code found no `fistp`/`fisttp`/`frndint`.
- **SSE2 math has an x87 fallback.** `sqrt` and `pow` take their SSE2 path only while MXCSR is 0x1F80 and the x87 exception masks are all set (the process defaults). Otherwise they fall back to x87 code.
- **CRT `rand` is not the game LCG.** The game RNG (seed 0x673934, state 0x67393c; see native-frame.md) is separate. CRT `rand` keeps per-thread state in the thread data block. `srand` is called with the game's initial seed (getter 0x4781e0) twice during game start (0x443f40, at 0x44403b and 0x4440ad), and also by 0x441ae0 and 0x47a8d0 (seed 0x4781e0), 0x40dee0 (seed 0x75, then `time(NULL)`), 0x448f40 (0x150b, then `time(NULL)`) and font-key preparation 0x411c40.

## Game code in this package

### 0x004ea120 `GameLockUnwindFunclet_6d44f8` — C++ EH unwind action that releases critical section 0x6d44f8
- Module: compiler-generated EH tail of the game objects (placed after the CRT) · Relevance: platform · Status: specified
- Signature: unwind funclet called by `__FrameUnwindToState` through `_CallSettingFrame@12` with EBP = parent frame; no arguments, no return value. The body is the single instruction `jmp 0x404110`.
- Behavior: tail-jumps to 0x404110, which performs `LeaveCriticalSection(&0x6d44f8)`. Ghidra's decompiled body is that callee. The funclet is the only action of the unwind map at 0x4fe144 (state 0 → -1) of FuncInfo 0x4fe14c (magic 0x19930522, one state). The matching `__ehhandler` stub at 0x4ea125 (`mov eax, 0x4fe14c; jmp __CxxFrameHandler3`) is installed by the SEH prologues of game functions 0x404420, 0x404530, 0x4046b0 and 0x404790, which all lock 0x6d44f8. The funclet runs only when a C++ exception unwinds through one of them while the lock is held, so the lock is never left held. Normal execution never reaches it.
- Globals/fields: 0x6d44f8 (CRITICAL_SECTION shared by 0x404110–0x4049e0).
- Callers/callees: reached only via `__CxxFrameHandler3` (0x4e910d); calls 0x404110.
- Code that follows (0x4ea125–0x4eaadb). Ghidra knows the 26 static destructors with their own starts; since [F03](f03-final-fixes.md) each has a `library` row in the table "0x4ea150–0x4eaad0 Static destructors" below. The rest is not split into atlas functions:
  - Two `__ehhandler` stubs: 0x4ea125, and 0x4ea12f, which checks the cookie and then loads FuncInfo 0x4fe8e0 (installed by the CRT's `CallUnexpected` 0x4e9438, not by game code).
  - The game's static destructors, each registered with `atexit` by a dynamic initializer. Their run order at `exit` is the reverse of registration.
    - The list destructors at 0x4ea150, 0x4ea1b0, 0x4ea210, 0x4ea270, 0x4ea2e0, 0x4ea340, 0x4ea3a0, 0x4ea400, 0x4ea460, 0x4ea4c0, 0x4ea520, 0x4ea580, 0x4ea5e0, 0x4ea640, 0x4ea6a0, 0x4ea700, 0x4ea780, 0x4ea7e0, 0x4ea840, 0x4ea8d0, 0x4ea9b0, 0x4eaa10 and 0x4eaa70 each call TSList unlink-all 0x4c4760 on one list object. Each destructor then self-unlinks the list's terminator link at object+4/+8.
    - `DeleteCriticalSection` on 0x6662c8 (0x4ea2d0), 0x6aa970 (0x4ea8c0) and 0x6d168c (0x4eaad0).
    - `CloseHandle([0x672968])` when nonzero (0x4ea760).
    - Storm `SBigDel([0x6a61c0])` (0x4ea8a0) and `SBigDel([0x6a61bc])` (0x4ea8b0).
  - None of these affects game state; they run only during process exit.

### 0x004ea930 `PlayerTriggerLists_AtExitDestructor` — static destructor of the eight player trigger list headers at 0x50e0d8
- Module: compiler-generated destructor for the trigger list globals (trigger objects bracket `victory.cpp..creep.cpp`), placed after the CRT · Relevance: script · Status: specified
- Signature: `__cdecl`, no arguments, no return value; preserves EBX, ESI and EDI.
- Behavior: the headers are 12 bytes each, at H(p) = 0x50e0d8 + 12·p for p = 0..7. The terminator link of header p has its previous-link pointer at H+4 and its signed next value at H+8. For p from 7 down to 0:
  1. While `next = [H+8]` is greater than 0 (a real node link, not an encoded terminator):
     - Let `L = next` and `prev = [L]`. If `prev` is 0, the loop re-reads `[H+8]` without progress. A well-formed list never reaches this case.
     - Otherwise unlink `L` with Storm TSLink semantics. The successor link is `~[L+4]` when `[L+4] ≤ 0`. Otherwise it is `[L+4] + (L − [prev+4])`, so the link offset is recovered from the predecessor's encoded next.
     - Store `prev` into the successor's previous-link field, store `[L+4]` into `[prev+4]`, and clear both words of `L`.
  2. When the list is empty and `[H+4]` is nonzero, unlink the terminator from itself the same way, using the last `next` value: `~next` for a non-positive value. Then clear `[H+4]` and `[H+8]`.
- Trigger nodes (0x968 bytes, allocated by owner expansion 0x4bdb00 with `SMemAlloc`) are only unlinked, never freed. The function runs only at process exit through `atexit`, so it has no effect on campaign behavior.
- Globals/fields: 0x50e0d8 is the player trigger list headers, 8 × 12 bytes; the per-header +0 word is not touched here. The dynamic initializer at 0x4024e0 sets each `[H+8] = ~(H+4)` (empty list) and registers this function with `atexit` (0x4d1630) at 0x40253b–0x402545.
- Callers/callees: no direct callers (atexit table only); no callees. The lists are used by 0x4bd5e0, 0x4bd920, 0x4bdb00, 0x4bddf0, 0x4be020, 0x4be190, 0x4be1d0, 0x4be3e0 and 0x4be500.
- Prior evidence: [native-triggers.md](../native-triggers.md) (header table, owner expansion 0x4bdb00).
