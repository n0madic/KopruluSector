# P13: Zerg orders and spell effects, cursor, fatal dialog, accelerators, window procedure and message pump

This package covers `0x43bc50`–`0x4407f0`. It spans the end of the object between `cunitsave.cpp` and `cur.cpp` (by content the Zerg unit object), `cur.cpp`, the object between `cur.cpp` and `dlgfatal.cpp`, `dlgfatal.cpp`, `error.cpp` and the objects between `error.cpp` and `fd.cpp`. The code falls into nine groups:

1. **Zerg order handlers** (`0x43bc50`–`0x43d290`). These are entries of the primary-order dispatcher `0x439420` and the secondary-order dispatcher `0x439310`. Each handler takes ECX = unit and returns nothing. They cover Birth, building morph, Drone landing and construction, Larva wandering and spawning, creep growth, Burrow/Unburrow, Infestation and the Nydus Canal.
2. **Zerg helpers**: Larva spawn-point search and side bookkeeping (`0x43c3b0`, `0x43c490`, `0x43d360`, `0x43d800`, `0x43d990`, `0x43da30`), creep stamping under building footprints (`0x43c130`, `0x43c220`), burrowed-state graphics (`0x43d940`, `0x43da00`, `0x43df40`).
3. **Zerg spell effects** called from the explosion dispatcher `0x4090e0` (Plague, Consume, Acid Spores, Dark Swarm, Ensnare, Spawn Broodlings). Their per-unit timers are serviced by `0x4351e0`, and their overlays are re-created by `0x434d10`.
4. **Cursor** (`0x43e410`–`0x43eb10`): 19 cursor GRPs, a dedicated screen layer, animation at 100 ms per frame, edge-scroll and hover cursor selection.
5. Two engine helpers that the linker placed in this range: the damage-type/size multiplier `0x43eb20` and the dirty-tile invalidator `0x43eb50`.
6. **Fatal error dialog** `rez\dlgFatal.bin` (`0x43ec00`–`0x43f090`).
7. **network.tbl** loader and getter (`0x43f0c0`, `0x43f0d0`). Despite the name, this table supplies many single-player messages, such as unit-creation errors and the screenshot notice.
8. **Accelerator tables and input-procedure table** (`0x43f100`–`0x43f330`), the main window procedure `0x43f600`, mouse/keyboard event dispatch (`0x43f480`, `0x43f520`, `0x43f5b0`, `0x4400d0`) and the message pump `0x4401c0`.
9. **Platform odds and ends**: quit request, PrintScreen screenshot, closing and relaunching Microsoft Office toolbar processes. The multiplayer map-transfer (`fd.cpp`) record management at the end is excluded.

**units.dat columns used** (descriptor `0x5014f0`): flingy `0x51faa8`, infestation result `0x51ff20` (types 106..201, read as `0x51fe4c + type*2`), construction image `0x51ffe0`, max HP `0x520708`, elevation `0x520a98`, movement flags `0x520b80`, ReturnToIdle order `0x520f20`, special flags `0x521660`, placement box `0x522728`, extents `0x522c38` (left, up, right, down WORDs), build time `0x5238b0`. **Overlay image ranges**: Defensive Matrix 371..373 and hit 374..376, Irradiate 380..382, Ensnare 384..386, Plague 388..390 (each base + overlay size 0/1/2 from `0x428d90`), Acid Spores 986..997 (`986 + size*4 + level`, level 0..3).

**Input globals**: `0x6d3154/0x6d3158` mouse x/y (0..639, 0..479); `0x6d315c` mouse state WORD (bit 0 moved since last pump, `0x2` left, `0x8` right, `0x20` middle button held); `0x665e58[256]` key-down bytes by virtual key (Shift `0x665e68`, Ctrl `0x665e69`, Alt `0x665e6a`); `0x665dec` reset callback; `0x665df0[19]` input procedures by event type; `0x665de8` active accelerator table; `0x665e30` WM_COMMAND handler (input slot 16); `0x66fd28` main window; `0x66fd24` application-active flag; `0x6662b8` glue/game state WORD (3 = in game, 2 = quit requested).

**Event record** (20 bytes, passed in ECX to the dialog dispatcher `0x4c2bb0` and to input procedures): `+0` user DWORD, `+4` DWORD parameter, `+8` WORD key/character/command, `+0xa` WORD modifiers, `+0xc` WORD event type, `+0xe/+0x10` WORD cursor x/y. Event types: 0 key down, 1 key repeat, 2 key up, 3 mouse move, 4/5/6 left down/up/double, 7/8/9 right, 10/11/12 middle, 13 idle, 14 user, 15 char, 16 command, 17 wheel up, 18 wheel down. The dispatcher `0x4c2bb0` offers the event to the dialog bound to that type (`0x6ce668[type]`), then to the dialog list `0x6ce6d8`; a nonzero result means consumed. Fields that a sender does not write keep stale stack contents, and each entry says which fields are written.

### 0x0043bc50 `OrderBuildNydusExit` — order 46 on a Nydus Canal
- Module: cunitsave.cpp..cur.cpp · Relevance: simulation
- Status: specified
- Signature: ECX = Nydus Canal (entrance); no return value.
- Behavior:
  1. Placement tile: `tx = (orderX − w/2) / 32`, `ty = (orderY − h/2) / 32`, with `w, h` = placement box of type 134 (`0x522940/0x522942`). Both divisions are signed and truncate toward zero.
  2. `ValidateBuildingPlacement`(builder = self, player = owner, tx, ty, 134, entry 0, vision 0, include unseen 1, ignore visibility 0). A nonzero result shows error string 856 to the local owner (`0x4464e0`(self, 0x358)) and ends the order (`0x42a5a0`).
  3. `CreateUnit`(134, orderX, orderY, owner). On failure it reports the creation error (`0x425020`(owner)) and ends the order.
  4. On the new exit E: `ReplaceUnitImages`(E, 1) (construction image); HP = units.dat max HP / 10 (unsigned); `IssueOrder`(E, 45); button set 228; `0x4b4dd0`(E) cancels creep-recession records under its footprint.
  5. Pairs both ways: `self+0xd0 = E`, `E+0xd0 = self`. Ends its own order.
- Callers/callees: dispatcher `0x439420`.
- Prior evidence: [Nydus](../native-nydus.md) (executed exit creation, pairing and placement inputs).

### 0x0043bd50 `OrderZergBirth` — order 41: an egg or cocoon finishes
- Module: cunitsave.cpp..cur.cpp · Relevance: simulation
- Status: specified
- Signature: ECX = unit.
- Behavior: Waits for order-signal bit 4; returns while it is clear. Then:
  1. Clears the bit. `keepPlace` = special flag TwoUnitsInOneEgg (`0x400`) set, or previous type `+0x88` = 59 (Cocoon).
  2. If TwoUnitsInOneEgg: `twin = 0x43b5e0`(self) (P12; creates the second unit next to the first and calls `0x43c090` when the parent was locally selected). If a twin exists, `0x48d320`(ECX = self, EDX = twin) registers it with the AI.
  3. If type ≠ 41 (Drone) and ≠ 42 (Overlord): `0x48d320`(self, self).
  4. `ReplaceUnitImages`(self, 0), then `CompleteUnitInPlace`.
  5. Unless `keepPlace`: `dy` = −7 when movement flags `0x520b80[type]` = `0xc1` (hover), else −42 when status bit `0x4` (air), else 0. The point (sprite x, sprite y + dy) is clamped with `ClampPointToMapForType`; if it differs from the sprite position, the unit is moved there (`0x43a270`). In the `keepPlace` case the unclamped position goes through the same clamp and move test.
  6. Unless previous type is 59 (Cocoon) or 97 (Lurker Egg): `SendToRally`(self, producer `+0x80`), and the same for the twin.
  7. `UnlockAndEndOrder`.
- Prior evidence: [Zerg construction](../native-zerg-construction.md) (Drone birth: image swap and y 442→435).

### 0x0043c130 `StampCreepRect` — creep under a tile rectangle
- Module: cunitsave.cpp..cur.cpp · Relevance: simulation
- Status: specified
- Signature: ECX = tile x, EDX = tile y, stack = [width, height, skip corners]; `ret 0xc`.
- Behavior: Rows run from y to y + height − 1 and columns from x to x + width − 1. Each row requires `y < map height` (`0x5264b6`), and each column requires `x < map width` (`0x5264b4`) (unsigned). ## Cursor (`cur.cpp`)

The cursor is drawn by screen layer 0 of the layer table `0x6d0b90` (20-byte records: `+0` enabled byte, `+1` flags, bit 0 = redraw; `+2/+4` x/y; `+6/+8` width/height; `+0x10` draw callback). Cursor GRPs use the standard GRP header: WORD frame count, WORD width, WORD height, then 8-byte frame headers {x offset, y offset, width, height (bytes), DWORD data}. Globals: `0x665d60` current GRP, `0x665d58` animation counter, `0x665d5c` next animation tick, `0x665d74` current cursor ID, `0x665d78[19]` loaded GRPs, `0x665d68` cursor-lock byte.

Cursor IDs (name table `0x5031c0`, folder `cursor\`): 0 arrow, 1 Illegal, 2 TargY, 3 TargR, 4 TargG, 5 TargN, 6 MagG, 7 MagR, 8 MagY, 9 Drag, 10 Time, 11 ScrollU, 12 ScrollUR, 13 ScrollR, 14 ScrollDR, 15 ScrollD, 16 ScrollDL, 17 ScrollL, 18 ScrollUL. The edge-scroll table `0x50320c[dx + 3·dy + 4]` holds WORDs 18, 11, 12, 17, 0, 13, 16, 15, 14.

### 0x004401c0 `PumpWindowMessages` — message pump and periodic input events
- Module: error.cpp..fd.cpp · Relevance: ui
- Status: specified
- Signature: ECX = flags (bit 0 run timers, bit 1 may block/sleep).

## Multiplayer map transfer (`fd.cpp` records)

These routines manage the file-transfer sessions used to download maps from other players. A session record links child records through Storm intrusive links (`{node, offset}` pairs). An offset ≤ 0 means `~offset` is the owner's pointer; otherwise the owner field is `node + offset − link offset`. They run only from the network chat command 'O' (`0x471860`), the map-download setup `0x477090` and lobby cleanup `0x474c30`/`0x474e60` (through `0x440730` and `0x440b60`; called only from the multiplayer chat-room dialog `0x450b30` and its handlers). In single player the session lists `0x5032b8` and `0x5032c4` are empty, so these routines never act on campaign play.

### 0x00440640 `UnlinkTransferRecord`
- Module: error.cpp..fd.cpp · Relevance: network

- Behavior: Empties the child list object at `+0x11c` (`0x4c4760`(ECX = record + `0x11c`)), then unlinks the list's own link `{+0x120, +0x124}` and the record's link `{+0, +4}`, zeroing each. Reason: multiplayer map transfer only.
