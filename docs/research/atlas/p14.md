# P14: Map file transfer, alliance/message dialogs, nearest-unit searches, forces, game start/teardown and MPQ file helpers

This package covers `0x440870`–`0x444930`: the tail of `fd.cpp`, `fd_user.cpp`, the objects that sort between `fd_user.cpp` and `game.cpp`, `game.cpp` and the head of `gamedata.cpp`. Its 111 functions fall into six groups.

1. **Lobby map/replay file transfer** (`0x440870`–`0x4418c0`, `fd.cpp`/`fd_user.cpp`). A peer-to-peer protocol that sends a `.scm`/`.scx`/`.rep` file to players who lack it, in 7 packet types through the send callback `0x665f88`. It only runs in a multiplayer lobby. All are specified since the network second pass (2026-11-14); the protocol is summarized under "Map transfer" in the shared data.
2. **In-game alliance and message-recipient dialogs** (`0x441980`–`0x442af0`, dialogs `rez\allyfltr.bin`, `rez\teamfltr.bin`, `rez\msgfltr.bin`). The minimap console (`0x46d130`) enables the message button (3) only in multiplayer games with more than one human, and the alliance button (4) in multiplayer games with more than one human, in multiplayer Use Map Settings games, and in **every replay playback**. Replay playback is reachable offline (single-player Load Replay; the multiplayer byte `0x672664` stays 0), where the alliance dialog acts as the replay vision filter, so the alliance-dialog functions are `specified`. The message dialog and the team-game variant (which needs `0x4b2d90`, false while `0x672664` = 0) are `excluded`; the recipient-mask builder `0x442070`, which game start also calls, is `specified`.
3. **Nearest-unit and callback searches over the spatial index** (`0x442b20`–`0x443110`). These are the simulation-critical queries that AI, spells, harvesting, Bullets and triggers use. All are `specified`.
4. **Forces** (`0x443180`–`0x443650`). The map `FORC` chunk loader, the force names and flags, and the alliance/shared-vision setup derived from force flags at game start. The lobby's slot searches (`0x4433d0`, `0x443480`, `0x443500`, `0x4435c0`, `0x443600`) and `SetForceName` `0x443650` are specified since the network second pass (2026-11-14); the lobby label helper `0x443580` is `excluded`.
5. **Game start and teardown** (`0x443680`–`0x444230`, `game.cpp`). The game-initialization sequence `0x443f40` (map/save loading, random seed, pools, DAT tables, triggers, UI), the console skin and in-game music choice, the reset of per-game state, and the teardown `0x443db0`.
6. **MPQ/DAT file helpers** (`0x4442b0`–`0x444890`, `gamedata.cpp`). The DAT column loader used by every `arr\*.dat` table, whole-file readers, and Storm wrappers that turn I/O errors into the fatal error path `0x4ceb90`.

The object between `fd_user.cpp` and `game.cpp` evidently holds several sources (the strings name the filter dialogs; the spatial search and the force code are separate subjects), but no assertion string names them, so the bracket is kept.

## Shared data and tables

**Player slot table** (`0x6726c8 + slot*36`, 12 slots; the lobby/map copy is `0x673d48`, the replay copy `0x66fd50`): `+4` Storm player ID (DWORD, `0x6726cc`), `+8` type (`0x6726d0`), `+9` race (`0x6726d1`), `+0xa` force 1–4 (`0x6726d2`, 0 = none), `+0xb` name (25 bytes, `0x6726d3`). Types: 0 none, 1 computer, 2 human, 3 rescue passive, 4 rescue active, 5 either/prefer computer, 6 either/prefer human (open), 7 neutral, 8 closed, 10 player left, 11 computer left. `0x4795a0` tests type 2; `0x4795e0` tests types 3–7.

**Force data** (from the map `FORC` chunk, `0x443320`):

| Address | Contents |
|---|---|
| `0x534890` + slot (8 bytes) | force of each of slots 0–7, 1-based after loading |
| `0x53487e + force*30` (force 1–4: `0x53489c`, `0x5348ba`, `0x5348d8`, `0x5348f6`) | force name, 30 bytes |
| `0x534897 + force` (force 1–4: `0x534898..0x53489b`) | force flags: `0x1` random start location, `0x2` allied, `0x4` allied victory, `0x8` shared vision |

**Alliance and vision state**: alliance matrix `0x534914 + p*12 + q` (BYTE: 0 enemy, 1 allied, 2 allied victory), shared-vision masks `0x5264cc + p*4` (bit q = p shares vision with q). Local player `0x508d50` (slot), `0x508d54`/`0x508d58` (Storm IDs), local vision masks `0x672668`/`0x67266c` (`<<8`), replay vision `0x67cc84`, replay flag `0x67cc90`, multiplayer byte `0x672664`, team-game test `0x4b2d90` (multiplayer and template byte `0x67294d`), loading-a-save DWORD `0x6a5e34`.

**Chat recipients**: message target selector `0x529040` (slot 0–7, 8 = everyone, 9 = allies) and recipient mask WORD `0x5264ba` (bit per **Storm player ID**).

**Unit spatial index** (P06/P08): X border array `0x5c99b8`, Y border array `0x5d03f8`, 8-byte entries `{DWORD unit index (1-based), DWORD coordinate}`, shared count `0x5c99b0`. A unit stores its entry indexes at `+0x13c` left, `+0x140` right, `+0x144` top, `+0x148` bottom. Unit index `i` ↔ `0x5da3a0 + (i−1)*0x150` (`0x4255f0` returns the base). Positions used by the searches are the **sprite** position (`unit+0xc` → sprite `+0x14` x, `+0x16` y, signed WORDs). Sprite flag `+0xe` bit `0x20` = hidden (the unit is not in the index).

**Dialog interact tables** (control ID *n* uses entry *n−1*; the count passed to `0x4c25b0` is in bytes):

|---|---|---|

| `0x50333c` (message dialog) | `0x10` (4) | IDs 1–3 `0x442960` (radio buttons "player", "everyone", "allies"), 4 `0x442af0` (player list box) |

**Map transfer** (group 1 and [P13](p13.md) `0x440640`–`0x4407f0`; specified in the network second pass of 2026-11-14). The host offers the current map (or replay) to every player that joins; a player without the file receives it in chunks from any seat that already has it.

- **Lists** (Storm `TSList`: a list object is `{DWORD link offset, terminator link}`, a link is `{pointer to the previous link, next}`, a `next` ≤ 0 is the bitwise NOT of the terminator address): offered files `0x5032b0` (terminator `0x5032b4`, head `0x5032b8`), active transfers `0x5032bc` (terminator `0x5032c0`, head `0x5032c4`). Both start empty (static constructors `0x4021f0`, `0x402210`).
- **Session globals**: `0x665f80` BYTE local Storm ID; `0x665f81` BYTE next file ID (0 at session start; `OfferLocalFile` refuses at `0xff`); `0x665f84` DWORD acknowledgement chunk size (packet capacity − 9); `0x665f88` send callback `stdcall(packet, length, Storm ID)` (every sender does nothing while it is 0); `0x665f8c` search-directory count (≤ 2) with the directories at `0x666098 + 260·i`; `0x665f90` download directory (260 bytes); `0x672960` the host's offered map record or 0 (`OpenMapTransferSession` `0x477090`, [P26](p26.md)).
- **Offered-file record** (one per file this seat offers; `AllocListRecord` `0x440cb0`, `0x128` bytes, zeroed): `+0` link; `+8` BYTE file ID; `+0xc` DWORD pending-join bits (bit n = Storm ID n joined Storm but its join request `0x40` has not run yet: set by `OnPlayerJoined` `0x4778e0`, cleared by `OnLobbyJoinRequest` `0x470af0` and `HandlePlayerLeftLobby` `0x477c20`); `+0x10` DWORD size; `+0x14` DWORD CRC; `+0x18` full path (260); `+0x11c` nested list object of peer nodes (terminator `+0x120`, head `+0x124`).
- **Peer node** (16 bytes, one per player the file was offered to, the host included): `+0` link; `+8` BYTE Storm ID; `+9` BYTE state: `0x10` offer sent and no status yet, otherwise the peer's transfer state from its last status packet, or 4 / 2 written by `RedirectDuplicateDownloads` `0x440d40` (paired as receiver / as uploader) until the next status; `+0xc` DWORD bytes the peer has (its last status).
- **Active transfer** (one per file this seat receives or holds, the host's own copy included; `0x48` bytes, zeroed): `+0` link; `+8` BYTE file ID; `+9` BYTE origin (the offering seat); `+0xc` DWORD size; `+0x10` DWORD CRC; `+0x14` file name (32); `+0x34` BYTE state: bit 1 exists (never cleared), bit 2 uploading to `+0x3c`, bit 4 receiving from `+0x3d`; the exact value 8 = failed (the local copy could not be read or the download could not be written); `+0x38` DWORD next offset to send; `+0x3c` BYTE upload target; `+0x3d` BYTE uploader the data comes from; `+0x40` DWORD bytes received (or loaded); `+0x44` buffer of `size` bytes (`SMemAlloc`, "fd_user.cpp" line `0x198`, zeroed).
- **Packets** (all fields little-endian and unaligned; a transfer is identified by the pair file ID and origin):

  | Type | Bytes | Layout | Sent by → to | Receiver |
  |---|---|---|---|---|
  | 0 status | 8 | `{0, ID, origin, state, DWORD received}` | `SendTransferStatus` `0x440e30`, any holder → the origin | `0x440db0`: update the peer node, then pair downloads |
  | 1 offer | 11 + name length | `{1, ID, DWORD size, DWORD CRC, name, 0}`, name < 32 bytes | `SendFileOffer` `0x4416a0`, origin → each joined player (itself included) | `0x441150`: create the transfer, look for a local copy, answer with a status |
  | 2 upload request | 7 | `{2, ID, target Storm ID, DWORD start offset}` | `SendUploadRedirect` `0x441850`, origin → a seat that has the file | `0x4415e0`: start sending to the target |
  | 3 cancel | 2 | `{3, ID}` | `SendTransferCancel` `0x441890`, origin → each peer | `0x441660`: free the transfer |
  | 4 data | 9 + n | `{4, ID, origin, DWORD offset, WORD n, n bytes}`, n ≤ 128 | `SendFileChunk` `0x441720`, uploader → target | `0x4413b0`: store, acknowledge, check and save when complete |
  | 5 ack | 7 | `{5, ID, origin, DWORD received}` | `SendChunkAck` `0x4417e0`, receiver → uploader | `0x441520`: send the next chunk |
  | 6 stop | 3 | `{6, ID, origin}` | `SendUploadStop` `0x441820` and inline in `0x4413b0`, receiver → uploader | `0x4415a0`: stop sending |

- **Transport.** The send callback is `SendMapDataChunk` `0x471800` ([P25](p25.md)): the packet travels as the direct chat-room message `{'O', WORD length, packet}` through `SendNetMessage` `0x474780` (Storm `SNetSendMessage`, message class 1, the channel of every chat-room message; not the turn stream). A message addressed to the sender's own Storm ID comes back through Storm's loopback, which is how the host offers the map to itself. On receipt `ReceiveChatRoomMessage` `0x471860` passes `'O'` to `DispatchFileTransferMessage` `0x4406c0` ([P13](p13.md)).
- **Driving.** Nothing is timed: every packet answers another one. `PollLobby` `0x474f00` ([P26](p26.md)) receives one direct chat-room message per call (whenever `PollLobbyNetwork` returns 0, that is before lobby state 9), and `LobbyUpdate` `0x450d80` ([P17](p17.md)) calls it once per pass of the chat room's modal loop, which never blocks in a multiplayer game (`GetNextWindowMessage` `0x440130`, [P13](p13.md): `PeekMessageA` and `Sleep(0)`). An upload starts with eight 8-byte chunks; every accepted chunk is acknowledged, and every acknowledgement makes the uploader send one more chunk of min(`0x665f84`, 128) bytes (128 in practice), so eight chunks stay in flight.
- **Flow.**
  1. Every seat entering a lobby runs `OpenMapTransferSession`: the session is reset, the download directory is `<user data>maps\download\` and the search directories `<user data>maps\` and `<install>maps\`. The host (`0x672970`) without a resumed save offers the current map (`OfferLocalFile` `0x440ab0`, file ID 0) into `0x672960`; a failure makes `InitJoinedLobby` `0x474c60` give up ("Unable to distribute map.").
  2. Each executed join request runs `OnLobbyJoinRequest` `0x470af0` ([P25](p25.md)) on every seat; only the host has a session record, and there `AddPeerToOfferedFile` `0x4409b0` adds the joiner's node and sends it the offer, then the joiner's pending bit is cleared. The host's own request runs inside `InitJoinedLobby`, so the host is a peer of its own offer.
  3. The offer creates the receiver's transfer. `FindLocalCopy` `0x441080` looks for a file with the same name, size and CRC (the host copies its own path); a copy is loaded and the transfer is complete. The receiver answers with a status: count = size, or 0.
  4. Each status updates the origin's peer node, and `RedirectDuplicateDownloads` pairs the first idle peer without the file (state 1, count ≠ size) with the first idle peer that has it (state 1, count = size): the latter gets an upload request to the former from its current count. The host is the first source; every peer that completes becomes another one.
  5. When the received count reaches the size, the receiver compares `ComputeBlockChecksum` `0x413ab0` (CRC-32, initial `0xffffffff`, no final inversion) with the offered CRC. A match writes the file (`SaveDownloadedFile` `0x4418c0`: `<download directory><name>`, which also becomes the current map path) and reports 1 / size; a mismatch restarts at 0 (status 1 / 0, so the origin pairs it again); a write failure leaves state 8. The uploader reports 1 / size when an acknowledgement reaches the size.
  6. A chunk at the wrong offset, past the end or at offset = size makes the receiver send a stop and its status. A player who leaves (`HandlePlayerLeftLobby`): the host drops its pending bit and node; every seat frees the first transfer that player offered and, for transfers it was sending or receiving, clears the bit, then re-sends the status of every remaining transfer, so the origin pairs again from the reported count. The session ends with `CancelOfferedFile` `0x440b60` (a cancel to each peer) and `ResetFileTransfers` `0x440730`.
  7. Progress: in lobby state 4 every seat calls `GetDownloadProgress` `0x440ee0` after each executed lobby turn (`PollLobbyNetwork` `0x46f3c0`, at most every 250 ms): Σ received · 100 / Σ size over its active transfers. A failed transfer gives leave reason 6 ("Unable to write scenario file"); otherwise `QueueDownloadStatus` `0x471590` sends lobby message `0x3d` through the turn stream when the percentage changed, and every seat shows it in the player's row as `"%3u"` when it is neither 0 nor 100 (`OnLobbyDownloadStatus` `0x470d90`, `SetSlotDownloadPercent` `0x4523a0`, `UpdateDownloadPercentLabels` `0x453cc0`).
  8. Start gate: `AllPeersHaveFile` `0x440ba0` = 1 when no join is pending and every peer node has state 1 and count = size. The Start button (`LobbyCommand` `0x4509d0`, gluAll `0x73` while it is 0), `StartLobbyGame` `0x4baed0` and `LobbyMapPreviewTimer` `0x450640` test it.

**Music table** for `0x443680`: first campaign mission key per race at `0x50334c` = `{Zerg 12, Terran 1, Protoss 22}` (keys ≤ 31) and `0x503350` = `{49, 40, 32}` (keys ≥ 32); rotating offset `0x503354` (initially −1).

### 0x00440c10 `TSListLinkNode` — Storm tagged-list insert

### 0x00442d90 `NearestUnitSweep` — expanding four-direction nearest search
- Module: fd_user.cpp..game.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = excluded unit (0 = none), EDX = center x (low 16 bits, signed), stack `[center y, xBack, yBack, xFwd, yFwd, rectangle*, callback, argument]`, `ret 0x20`; returns the best CUnit or 0.
- Behavior: Let `(L, T, R, B)` be the rectangle copied into locals (signed WORDs) and `(cx, cy)` the center. Initial best distance `D = ApproxDistance(0, max(cx−L, R−cx), 0, max(cy−T, B−cy))` (`0x405cf0`, argument order x1, x2, y1, y2), best = 0. Then repeat:
  1. `active = found = false`.
  2. **X backward** if `xBack ≥ 0`: u = owner of X entry `xBack`. If `u.x < L`, set `xBack` to stop (it becomes −2). Otherwise, if `T ≤ u.y < B`, `u ≠ excluded`, `callback(ECX = u, EDX = argument)` ≠ 0, and `d = ApproxDistance(u.x, cx, u.y, cy) < D`, then `D = d`, best = u, found. Decrement `xBack`; active.
  3. **X forward** if `xFwd < count`: u = owner of X entry `xFwd`. If `u.x < R`, apply the same candidate test (with `T ≤ u.y < B`); otherwise set `xFwd = count`. Increment; active.
  4. **Y backward** if `yBack ≥ 0`: stop when `u.y < T`; else candidate test with `L ≤ u.x < R`. Decrement; active.
  5. **Y forward** if `yFwd < count`: stop when `u.y ≥ B`; else candidate test with `L ≤ u.x < R`. Increment; active.
  6. If found this round, shrink the rectangle around the center: `L = cx − D` if `L < cx − D`; `R = cx + D` if `R > cx + D`; `T = cy − D` if `T < cy − D`; `B = cy + D` if `B > cy + D` (each stored as a 16-bit value).
  7. Continue while `active`.
  
  `u.x`/`u.y` are the candidate's **sprite** coordinates, not the border coordinates of the entry. A unit appears twice in each array, so the callback can run up to four times for one unit; only a strictly smaller distance replaces the best, so ties keep the first candidate in sweep order. A scan's stop test uses the current (possibly shrunken) rectangle. An entry whose unit index is 0 would yield a null unit and fault.
- Globals/fields: `0x5c99b8`, `0x5d03f8`, `0x5c99b0`, sprite `+0x14/+0x16`.
- Callers/callees: `0x442c20`, `0x442cc0`, `0x442d40`; calls `0x405cf0`, `0x4255f0`. Prior evidence: [combat AI](../native-combat-ai.md) (sweep order, strict improvement, rectangle tightening), [AI placement](../native-ai-placement.md), [harvesting](../native-harvesting.md).
