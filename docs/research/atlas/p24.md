# P24: Fog-of-war overlay and vision callbacks, the console minimap, modeless in-game dialogs, CD music, and network chat commands

This package covers `0x46c0d0`–`0x470460`: the tail of `mask.cpp`, the object between `mask.cpp` and `minimap.cpp` (which still holds `mask.cpp` code, the vision callbacks and shared dialog-button helpers), `minimap.cpp`, `modeless.cpp`, and the object between `modeless.cpp` and `net_chat_cmds.cpp`. Its 109 listed functions form six groups.

1. **Fog-of-war overlay** (`0x46c0d0`–`0x46c560`). `mask.cpp` turns tile visibility into a smooth darkness overlay over the 640×400 game view. The darkness levels are 0 (black, unexplored), 15 (`0x671a80 >> 1`, explored but not visible) and 31 (`0x671a80` = `0x1f`, visible). Four buffers are allocated per game: `0x670a78` (24 × 17 raw levels, one per map tile around the view, built by `0x46b9e0`), `0x670a70` (24 × 17 levels after the 3×3 blur 1-2-1/2-4-2/1-2-1 ÷ 16, also built by `0x46b9e0`), `0x670a74` (the copy of `0x670a70` that was last drawn) and `0x670a7c` (88 × 60 levels, one per 8×8-pixel block, from the bilinear expansion `0x46b910`). The 32 × 32 interpolation table `0x670a80` (4 bytes per pair of levels) is built by `0x46bfc0`. Drawing uses the 32 darkness rows of `Tileset\<t>\dark.pcx` at `0x66dd20` (256 bytes per level). The helpers `0x46b910`–`0x46c050` belong to P23. Tile flags `0x666454` (DWORD per tile): bits 0–7 = "not visible to player i", bits 8–15 = "not explored by player i"; the local masks are `0x672668` (visible) and `0x67266c` (explored, `<<8`). Replays use `0x67cc84` (vision byte) and `0x67cc88` (reveal all).
2. **Vision template callbacks** (`0x46c570`–`0x46c6a0`). The four reveal routines that `0x46bbb0` selects through the pointer table `0x4eeda0` = {`0x46c620` ground, `0x46c570` air, `0x46c6a0` ground clipped, `0x46c5b0` air clipped}. They are fully covered by [unit creation](../native-unit-creation.md#original-vision-templates-and-the-air-mask-defect), including the air-path defect that skips the last nine records.
3. **Shared dialog-button helpers** (`0x46c790`–`0x46c8a0`) used by in-game menus and glue screens.
4. **Console minimap** (`0x46c8e0`–`0x46eba0`, plus the unlisted terrain builder `0x46c990`). `minimap.cpp` owns the minimap dialog `rez\minimap.bin` (`0x671a8c`), its image control (`0x671f98`, child 1) and three buttons (children 2 terrain, 3 messaging, 4 diplomacy). See the data model below.
5. **Modeless dialogs and music** (`0x46ec70`–`0x46f2c0`). `modeless.cpp` opens and closes the single in-game modeless dialog (`0x672578`: menus, options, alliance, messaging, help) and streams the CD music tracks through Storm's DDA API with fade-in, fade-out and a "quiet" volume reduction.
6. **Network glue and chat commands** (`0x46f2f0`–`0x4703d0`). Storm provider records (also used by single player, which initializes provider 0 through `0x4757e0`), lobby polling, the Battle.net game status string, the in-game Network (latency) dialog, the ignore list and the `/whisper` `/squelch` `/ignore` command parser. Except for the provider records, the server-message handler and two list destructors that single player reaches with empty lists, the group is multiplayer-only; the Network dialog (`0x46f990`–`0x46fac0`), the lobby polling (`0x46f3c0`, `0x46f460`) and the game status string (`0x46f470`–`0x46f910`) are specified since the network second pass (2026-11-14); the ban list (`0x46fb10`–`0x46fc50`), the slash-command parser `0x46fd90` and its whisper and name helpers (`0x4701f0`–`0x4703d0`) were specified in the same pass; the Battle.net server-command queue (`0x46fcc0`, `0x470070`, `0x470150`) stays `excluded`. The same pass specified the minimap statistics getter `0x46c8e0` of group 4.

## Minimap data model

Geometry is chosen by `0x46d850` from the larger map dimension `max(0x5264b4, 0x5264b6)`:

| Larger map side | Minimap size W × H (`0x671fb8`, `0x671fbc`) | Scale WORDs: divisor `0x671fa8`, shift `0x671fb0`, pixels per minimap pixel `0x671fb4` | Terrain builder `0x671fc0` | Fog composer `0x671fc4` |
|---|---|---|---|---|
| 64 | 2·mapW × 2·mapH | 1, 1, 16 | `0x46ca20` | `0x46cea0` |
| 96, 128 | mapW × mapH | 1, 0, 32 | `0x46c920` | `0x46cd10` |
| 192, 256 | mapW/2 × mapH/2 | 2, 0, 64 | `0x46c990` | `0x46cdc0` |
| any other | previous values kept (128 × 128 after `0x46dc80`) | unchanged | unchanged | unchanged |

The size selection is a byte-indexed jump table: targets `0x46da5c` = {`0x46d88f`, `0x46d8e3`, `0x46d931`, `0x46d985`}, index bytes `0x46da6c` for side−64 in 0…192: 0 → 64 case, 32/64 → 1:1 case, 128/192 → half case, all other values → keep. WORD `0x671fac` is always 0. Map tile (tx, ty) maps to minimap pixel `(tx << shift) / divisor`.

Two 8-bit bitmaps `{WORD w, WORD h, DWORD pixels}`: `0x671fc8` (terrain colors, pixels `0x671fcc`) and `0x671fd0` (the composed image shown, pixels `0x671fd4`), both W × H, allocated in `0x46d850` (`minimap.cpp` lines `0x664`, `0x665`) and freed in `0x46dc80`. Color tables: `0x672078` (256 bytes: game palette index → minimap color index, built in `0x46e260`), and four 256-byte fog remap rows at `0x672178` selected by `visible·2 | explored`: row 0 `0x672178` = all byte `0x6d2377` (unexplored), row 1 `0x672278` = dark level 15 of `dark.pcx` (`0x66ec20`), rows 2 `0x672378` and 3 `0x672478` = identity. Blink and ping state: `0x671a8a` blink phase, `0x671a8b` "some unit blinked", 16 ping records at `0x671e98` (16 bytes: `+0` active byte, `+4` x DWORD, `+8` y DWORD, `+0xc` frame WORD 0…19, `+0xe` color byte), `game\blink.grp` at `0x671fd8`, 19 eight-byte color rows from `game\tblink.pcx` at `0x671fe0`. Display flags: `0x671a89` terrain hidden (Tab), `0x671a88` color mode (Shift+Tab: 0 player colors, 1 alliance colors on the minimap, 2 alliance colors on the minimap and in the game view), `0x671fa2` "terrain must be rebuilt", `0x671fa0`/`0x671fa4` WORD screen tile position last drawn, `0x671f9c` hovered control. Cursor clip rectangle while dragging `0x508bb0` = {left, top, right, bottom} in screen pixels (the dialog's y coordinate is relative to y = 315). Draw statistics `0x671e90` (box count) and `0x671e94` (XOR of drawn units' visibility masks) feed the multiplayer turn record only. Preview mode `0x666560` ≠ 0 exists only for the multiplayer lobby's map preview (`rez\minimappreview.bin`); in single player it is always 0.

Timers on the minimap dialog (UI timer `0x4c5960`): 1 = 1000 ms (2000 ms in multiplayer) → `0x46e8d0`; 2 = 200 ms → `0x46d360`; 3 = 200 ms → `0x46eba0`; 6 = 100 ms → `0x46ea90`; 5 = 500 ms → `0x46d240` only in replays or in multiplayer with more than one player or a Top-vs-Bottom game.

Child interact tables: `0x508c40` = {`0x46d6a0`, `0x46d0e0`, `0x46d0e0`, `0x46d0e0`} (16 bytes, normal) and `0x508c50` = {`0x46d6a0`} (4 bytes, preview). Event dispatch inside `0x46d6a0` uses the jump table `0x46d790` (types 3–14) and `0x46d7c0` (user codes 0–6); `0x46de70` uses the index table `0x46dfc0` and targets `0x46dfa8`.

## Music data

Track table `0x508c58`, 8 bytes per track `{DWORD file, BYTE kind, BYTE fade-in, BYTE next, BYTE 0}`; kind 1 loops (DDA flag `0x40000`), kind 2 plays once and continues with `next` when `0x46ee70` sees the end.

|---|---|---|---|---|
| 0 | none | 0 | 0 | 0 |
| 1–3 | `music\zerg1/2/3.wav` | 2 | 0 | 2, 3, 1 |
| 4–6 | `music\terran1/2/3.wav` | 2 | 0 | 5, 6, 4 |
| 7–9 | `music\protoss1/2/3.wav` | 2 | 0 | 8, 9, 7 |
| 10–12 | `music\zrdyroom.wav`, `trdyroom.wav`, `prdyroom.wav` | 1 | 1 | 0 |
| 13–15 | `music\zdefeat.wav`, `tdefeat.wav`, `pdefeat.wav` | 1 | 1, 0, 0 | 0 |
| 16–18 | `music\zvict.wav`, `tvict.wav`, `pvict.wav` | 1 | 1, 1, 0 | 0 |
| 19–21 | the same three victory files | 1 | 1, 1, 0 | 0 |
| 22 | `music\title.wav` | 1 | 0 | 0 |
| 23 | `music\terran2.wav` | 1 | 0 | 0 |
| 24 | `music\RadioFreeZerg.wav` | 2 | 0 | 1 |

State: `0x67257c` open Storm file handle, `0x672580` current track, `0x672584` target volume (DirectSound hundredths of dB, −10000 = silent), `0x672588` current fade volume, byte `0x67258c` playing, byte `0x67258d` quiet mode (volume − 750, floor −10000). Constants `0x4efc00` = −4000 (fade-out end) and `0x4efc04` = −3396 (fade-in start). The fade-in uses Win32 timer 3 on the main window `0x66fd28`.

### 0x0046c2d0 `UpdateFogMaskDirty` — rebuild levels and mark changed screen areas

### 0x0046c8e0 `GetMinimapDrawStats` — the two minimap statistics of the sync record
- Module: mask.cpp..minimap.cpp · Relevance: network
- Status: specified
- Signature: `__fastcall`, ECX = BYTE* out, EDX = BYTE* out; no return value.
- Behavior: `*ECX` = low byte of `0x671e94`; `*EDX` = low byte of `0x671e90`.
- What the two values are: `DrawMinimapUnits` `0x46d510` zeroes both and recomputes them on every minimap redraw.
  - `0x671e94` is the XOR, over every unit in the unit lists of players 0–11 that passes the minimap filters (not a subunit, not type 105, 202 or 203–213), of the mask m = sprite visibility byte `+0xc`, ANDed with the detection mask CUnit `+0xe4` when the unit has status bits `0x300` (`0x46e490`, `0x46e5b0`, `0x46e700`). The XOR is taken whether or not the unit is drawn, so bit p is the parity of the number of such units that player p can see.
  - `0x671e90` is the number of unit boxes drawn: `DrawMinimapUnitBox` `0x46cb80` increments it for every box, and `0x46d510` decrements it again for each fog-ghost box. In a game (preview flag `0x666560` = 0, no replay) that leaves the number of units with m & `0x672668` ≠ 0, the units the local minimap shows.

  With an untouched vision mask (`0x672668` = `1 << local player`), bit 0 of the count equals bit `local player` of the XOR. That is the receiver's test: `CheckSyncVisibilityHash` `0x47a570` ([P27](p27.md)) compares bit `sender` of its own record `+4` with bit 0 of `cmd[6]` of the sender's command `0x37`.
- When: synchronously in `PollTurn` `0x444cc0` ([P15](p15.md)) at every multiplayer turn boundary, after the turn's commands were executed and before the first frame of the turn: `RedrawMinimap` `0x46e0e0` recomputes, then `CaptureMinimapDrawStats` `0x47a2f0` copies. Unlike the sprite checksum ([P05](p05.md) `0x417610`) this does not wait for a draw, so it does not depend on how frames and draws interleave. The unit pass also decrements the minimap blink byte CUnit `+0x8a` of drawn local units; that is display state and is not hashed.
- Globals/fields: reads `0x671e94`, `0x671e90`.
- Callers/callees: only `0x47a2f0` (tail jump at `0x47a2fa`; raw-image scan), with ECX = `0x673f20` and EDX = `0x673f21`.
- Second pass (2026-11-14): excluded while the remake had no network play; specified for the network design.
