# P43: Dialog painting and presentation, UI timers, list/combo boxes, buttons, edit boxes and flic buttons

This package covers `0x4c4d40`–`0x4c8760` (87 functions). It continues the engine library run after [P42](p42.md): the tail of `dlg.cpp` (the dialog paint pass and the frame presenter), `timer.cpp` (the millisecond UI timer queue), `lbox.cpp` (list boxes and combo boxes), the button/option/check-box procedures and `edit.cpp` that follow it, and the start of `flc.cpp` (flic buttons with SMK overlays). Everything here serves menus, glue screens, briefings, score screens and in-game dialogs, so every function is in scope for offline single-player presentation. None is simulation code: nothing here touches the game RNG or the command queue.

How the pieces connect:

1. **Invalidation and painting.** Controls are invalidated through [P42](p42.md) `InvalidateControl` `0x4c4ae0`, which adds 16-pixel-aligned rectangles to the Storm region `0x6ce784` (`AddDirtyRect` `0x4c5490`). Once per presented frame, `PresentFrame` `0x4c5360` adds the tooltip-layer rectangles and calls the screen compositor `0x4caf10`. The compositor calls each screen layer's callback; layer 2 (`0x6d0bb8`, installed by `0x4c3530`) is `PaintDialogLayer` `0x4c4d90`. That function converts the region to rectangles, redraws every dirty control into its dialog's off-screen bitmap (`DrawControlClipped` `0x4c51c0`) and then copies the dialog bitmaps to the screen (`BlitDialogToScreen` `0x4c5630`). The blit composites the tooltip and the mouse cursor into the copy. `PresentFrame` finally deletes the region.
2. **UI timers.** `SetUiTimer` `0x4c5960` keeps a deadline-sorted singly linked queue of 28-byte nodes keyed by (owner control, u16 ID). `RunUiTimers` `0x4c5a20` runs from the message pump `0x4401c0`. It calls a node's callback, or sends user event 8 (timer tick) to the owner's interact procedure, and re-queues the node.
3. **List boxes and combo boxes** (`lbox.cpp`). A list owns three parallel 254-entry arrays (text pointers, flag bytes, u32 data), a page size, a top index, a selected index and a hover index. It may also own a vertical scroll bar created at initialization. A combo box (type 13) reuses all of the list code. It keeps a one-row closed field and temporarily grows its rectangle when it drops open.
4. **Buttons** (types 1–4), **edit boxes** (type 8) and **flic buttons** (type 14): stock interact and draw procedures, installed per type by the BIN fixup (tables in [P42](p42.md#control-and-dialog-data-model)).

## Shared data

**Control fields** follow [P19](p19.md#shared-data-and-tables) and [P42](p42.md#control-and-dialog-data-model). Flags `+0x18` used here: `0x1` dirty, `0x2` disabled, `0x8` visible, `0x80` hover, `0x200` hotkey prefix byte in the text, `0x1000` focus highlight, `0x2000` transparent, `0x10000` no letter spacing, `0x20000` plain (no frame art), `0x100000` (combo box) dropped open / (paint pass) drawn after its siblings, `0x8000000` (dialog) composited into another dialog's bitmap, `0x10000000` (dialog) composited onto the backdrop bitmap, (list) keyboard goes to its scroll bar and no hover highlight, `0x20000000` (list) tall-row art, `0x40000000` (button) pressed, (list) cursor tracking, (edit) caret visible, `0x80000000` (list) layout recalculation suppressed. Events and user codes are those of [P42](p42.md#control-and-dialog-data-model): type 14 is a user event, and its `+0` code is 1 destroy, 2 activated, 3 hotkey press, 4 hit test, 5 focus request, 6 focus lost, 8 timer tick (parameter = timer ID), 9 mouse enter, 10 post-load initialization, 11 value changed, 12 item about to be deleted (lists), 13 show, 14 hide.

**List/combo box fields** (types 12/13): `+0x36` scroll bar control (0 = none), `+0x3a` text pointer array (254 entries), `+0x3e` item flag bytes (low nibble = colour style, `0x10` = the text was copied and is owned), `+0x42` u32 item data array, `+0x46` u8 count, `+0x47` u8 capacity (254), `+0x48` u8 selected index (`0xff` = none), `+0x49` u8 row height, `+0x4a` u8 rows per page, `+0x4b` u8 maximum top index, `+0x4c` u8 (combo box) bit 0 = the list opens upward, `+0x4d` u8 top (first visible) index, `+0x4e` u8 hover index, `+0x50` s16 (combo box) top of the closed field, `+0x52` item draw callback (fastcall ECX = list, DL = index, stack `[row rect, x offset, y offset]`, `ret 0xc`).

**Edit box fields** (type 8): `+0x14` 256-byte text buffer (owned), `+0x36` u8 state (bit 0 modified, bit 4 `0x10` insert mode; the high nibble is also the text colour style), `+0x37` u8 scroll (first visible byte), `+0x38` u8 left margin, `+0x39` u8 top margin, `+0x3a` s16 visible text width, `+0x3c` u8 typing mode (mouse cursor hidden and mouse events captured), `+0x3e` u8 cursor byte index.

**Option/check box field**: `+0x36` u32 checked (0/1).

**Flic button fields** (type 14): `+0x36..+0x3c` s16 response rectangle (BIN values are control-relative; `InitFlcButton` adds the control origin), `+0x3e` s16 text glow level 0–100, `+0x40` s16 stereo pan, `+0x42` overlay list, `+0x46..+0x4c` s16 text rectangle (made absolute by the BIN fixup), `+0x4e` u8 text format byte (copied to `0x6d300e` before drawing). An overlay node: `+0x00` next, `+0x04` u32 flags (bit 0 fades with hover, bit 1 dims to 30 when not hovered, bit 2 passed to SVid as `0x40000`, bit 3 drawn only while hovered, bit 4 drawn with transparency), `+0x08` u16 fade level 0–100, `+0x0a` SMK file name, `+0x0e` SVid handle, `+0x12`/`+0x14` u16 x/y offset inside the control, `+0x16` bitmap `{s16 w, s16 h, pixels}`.

**Theme metric words** (written by `ApplyTheme` `0x4c31d0` from the theme node; frame numbers are dialog-GRP frames measured by `CreateTheme` `0x4c2ca0`): `0x6ce6ec` max(w, h) of frame 10, `0x6ce6f0` max(w, h) of frame 15, `0x6ce6f8` height of frame 16 (scroll arrow), `0x6ce700` width of frame 16, `0x6ce704` height of frame 29 (scroll thumb), `0x6ce714`/`0x6ce718` width/height of frame 28, `0x6ce71c`/`0x6ce720` frame 35, `0x6ce728`/`0x6ce72c` frame 47, `0x6ce724` width of frame 50, `0x6ce730`/`0x6ce734` frame 77, `0x6ce738`/`0x6ce73c` frame 59, `0x6ce744`/`0x6ce748` frame 71, `0x6ce740` width of frame 74.

**Paint globals**: `0x6ce778` backdrop bitmap (the screen `0x6d0b88` in game; a glue screen sets its own bitmap), `0x6ce77c`/`0x6ce77e`/`0x6ce780` u16 effect-colour indexes for image controls, combo boxes and composited dialogs, `0x6ce784` invalid region (Storm SRgn), `0x6ce788` the dialog whose bitmap receives `0x8000000` dialogs during a paint pass, `0x6ce78c` u32 rectangle count and `0x6ce790` up to 255 rectangles of 16 bytes (s32 left, top, right, bottom, made inclusive), `0x50ef44` inclusive screen clip {0, 0, 639, 479}, `0x50ef54` exclusive clip {0, 0, 640, 480}, `0x50ef64` paint list (Storm list header; head pointer `0x50ef6c`), `0x6cf788` the tooltip rectangle presented last frame (s32 left, top, right, bottom). Screen layers are 20-byte records from `0x6d0b90` ([P42](p42.md)): layer 0 cursor (`0x6d0b90` active, `0x6d0b92` x, `0x6d0b94` y, `0x6d0b96` w, `0x6d0b98` h), layer 1 tooltip (`0x6d0ba4` active, `0x6d0ba6` x, `0x6d0ba8` y, `0x6d0baa` w, `0x6d0bac` h), layer 2 dialogs. `0x6d0c40` is the current blit target bitmap.

**Text globals** ([native text](../native-text.md)): `0x6d300e` format byte, `0x6d3035` letter spacing, `0x6d3037` font height, `0x6d3038..0x6d303e` s16 clip rectangle, `0x50f160` word-wrap flag, `0x6d3114` caret glyph byte (set to `0xa6` by edit boxes).

**UI timer node** (28 bytes, `timer.cpp`): `+0x00` next, `+0x04` owner control, `+0x08` callback (fastcall ECX = owner, DX = ID) or 0, `+0x0c` u32 last fire tick, `+0x10` u32 period in ms, `+0x14` u16 ID, `+0x18` s32 smoothed lateness. Active queue `0x6cf798` (sorted by `last + period` ascending), queue of fired nodes `0x6cf79c`, search keys `0x6cf7a0` (owner) and `0x6cf7a4` (u16 ID). Generic list helpers (`effects.cpp..image.cpp`): `0x4cab80` push front, `0x4cab90` find first with predicate, `0x4cabc0` membership test, `0x4cabe0` sorted insert with a key callback (a node is inserted before the first node whose key is not greater than its own), `0x4cac30` unlink by search.

**Open combo box** `0x6cf7a8`: the combo box currently dropped open (0 = none).

**UI sound hook** `0x6ce664` (`0x4c3740` calls it with ECX passed through). This package passes 0 when a button becomes pressed under the cursor and 2 when a button activates.

## Entries

### 0x004c4d40 `SetDialogBackdropBitmap`
- Module: dlg.cpp..timer.cpp · Relevance: render · Status: specified
- Signature: fastcall, ECX = bitmap descriptor; no return.
- Behavior: `0x6ce778` = ECX. Dialogs with flag `0x10000000` are copied onto this bitmap (`0x4c5630`), and invalidation/re-invalidation compare it with the screen `0x6d0b88`.
- Callers/callees: game start `0x465aa0` (screen), glue setup `0x457f00` (dialog bitmap) and glue exit `0x457510` (screen), see [P19](p19.md).

### 0x004c4d50 `SetDialogEffectColors`
- Module: dlg.cpp..timer.cpp · Relevance: render · Status: specified
- Signature: fastcall, ECX = pointer to three u16; no return.
- Behavior: Copies the first u32 to `0x6ce77c` (u16 image index, u16 combo box index) and the third u16 to `0x6ce780` (composited-dialog index). The values are passed to `0x4ca7e0`(ECX = index, EDX = 0), which loads the effect colour byte `0x6cfd28[index]` into `0x6cfbc3` and sets the palette-effect dirty flag `0x50ef8c` when it changes.
- Callers/callees: `0x457f00` (theme `+0x10a`), `0x47bca0`.

### 0x004c4d70 `InvalidateAllDialogs`
- Module: dlg.cpp..timer.cpp · Relevance: render · Status: specified
- Signature: no arguments.
- Behavior: For each dialog in the open list `0x6ce6d8` (head first) calls `MarkControlDirty` `0x4c2840`.
- Callers/callees: `0x4cb590` (window restored: after full-screen invalidation `0x4cac50(639, 479)`).

### 0x004c4d90 `PaintDialogLayer` — screen layer 2 callback
- Module: dlg.cpp..timer.cpp · Relevance: render · Status: specified
- Signature: stdcall layer callback with two ignored stack arguments (layer parameter, layer rectangle); `ret 8`. Installed in layer 2 (`0x6d0bc8`) by `InitDialogSystem` `0x4c3530` with layer flags `0x20` (called every composite), rectangle 640×480.
- Behavior:
  1. `InvalidateBackdropDialogs` `0x4c5530`.
  2. Builds a temporary Storm list of 0x1c-byte nodes (allocated through `0x4d1690`/SMemAlloc), one per **visible** dialog of `0x6ce6d8`, appended in list order (head = topmost dialog first).
  3. Region to rectangles: if `0x6ce784` = 0 the count is 0. Otherwise `0x6ce78c` = 255 and Storm ordinal 529 (region to rectangles)(`0x6ce784`, &count, `0x6ce790`) fills up to 255 rectangles; every rectangle's right and bottom are then decremented by 1 (inclusive).
  4. Draw pass, dialogs from the **last** temporary node to the first (bottom to top). For each rectangle i in order: `CollectPaintTargets` `0x4c4910`(dialog, rect i) appends the dialog and every visible child overlapping the rectangle to the paint list `0x50ef64` (and clears their dirty bits). If it returned 1: walk the paint list from its head; unlink each node; a control with flag `0x100000` is moved, with a copy of rectangle i at node `+0x0c`, to a per-dialog deferred list; every other control is drawn now (`DrawControlClipped` `0x4c51c0`(control, rect i)) and its node freed (SMemFree, "delete"). Then `0x6ce788` = this dialog unless its flags contain `0x8000000`. After all rectangles, each deferred node is drawn with its saved rectangle (`0x4c51c0`) and freed (`0x4c46f0`), in list order. An open combo box therefore paints above its siblings.
  5. Blit pass, dialogs from the **first** temporary node to the last: for each rectangle, `BlitDialogToScreen` `0x4c5630`(dialog, rect).
  6. `0x6ce788` = 0; frees the temporary list.
- Embedded code: `0x4c51a0` (`DeleteInvalidRegion`, called from `ShutdownDialogs` `0x4c34e0`): if `0x6ce784` ≠ 0, SRgnDelete (`0x4d0328`) and `0x6ce784` = 0.
- Callers/callees: screen compositor `0x4caf10` (through the layer record).

### 0x004c51c0 `DrawControlClipped`
- Module: dlg.cpp..timer.cpp · Relevance: render · Status: specified
- Signature: fastcall, ECX = control or dialog, EDX = rectangle (4 × s32, screen coordinates, inclusive); no return (plain `ret`).
- Behavior: D = the control itself if its type is 0, else its parent `+0x32`. The rectangle is intersected with D's screen rectangle, translated to D-local coordinates (minus D.left/D.top), then clamped to `0x50ef44` {0, 0, 639, 479}; the result is stored as four s16. x offset = local left, y offset = local top. For a child control, the s16 rectangle is further intersected with the control rectangle (`IntersectRect16` `0x4c47a0`), and x = max(0, x − control.left), y = max(0, y − control.top) (computed from the values before that intersection). Type 5 sets the effect colour `0x4ca7e0`(`0x6ce77c`, 0); type 13 sets it from `0x6ce77e`. Then it sets the blit target `0x6d0c40` = D + `0x36` (the dialog's off-screen bitmap), calls the control's draw procedure `+0x2e`(ECX = control, EDX = x, stack `[y, &s16 rect]`) and restores the previous target.
- Callers/callees: `0x4c4d90`.

### 0x004c5330 `BlitDialogRect`
- Module: dlg.cpp..timer.cpp · Relevance: render · Status: specified
- Signature: fastcall, ECX = dialog, EDX = s16 screen rectangle; no return.
- Behavior: `BlitBitmapClipped` `0x4c3c70`(ECX = dialog bitmap `+0x36`, EDX = rect.left − dialog.left, stack `[rect.top − dialog.top, rect, dialog flags]`) to the current target.
- Callers/callees: `0x4c5630` (cursor branch).

### 0x004c5360 `PresentFrame`
- Module: dlg.cpp..timer.cpp · Relevance: render · Status: specified
- Signature: no arguments, no return.
- Behavior:
  1. `0x445de0` (when `0x445100` reports a game map, sets the vertical redraw window `0x666970` = max(0, `0x5264b2` − 4), `0x666974` = min(`0x5264b6` − 1, `0x5264b2` + 404) and calls `0x416a00`).
  2. `0x4cb590`: returns 0 unless `0x6d3188` (video initialized), the application-active flag `0x66fd24` and the main window `0x66fd28` are all nonzero and the window is not minimized. A pending full redraw (`0x6d0c4c`) invalidates the whole screen (`0x4cac50(639, 479)`), marks every dialog dirty (`0x4c4d70`) and is cleared. If it returns 0, go to step 5.
  3. Tooltip layer (only when `0x6d0ba4` ≠ 0): with width `0x6d0baa` ≠ 0, R = {x, y, x + w − 1, y + h − 1} clipped to `0x50ef44`; R is invalidated (`0x4c5490`) if left < right and top < bottom; the previous rectangle `0x6cf788` is invalidated under the same test; `0x6cf788` = R. With width 0: if the previous rectangle is all zero nothing happens; otherwise it is invalidated when non-empty and its top becomes bottom + 1 (empty).
  4. Composites and flips the layers (`0x4caf10`).
  5. Deletes the invalid region (SRgnDelete, `0x6ce784` = 0).
- Callers/callees: 17 callers including the game loop ([P15](p15.md)), glue screens ([P19](p19.md)), the modal loop `0x4c35c0`, palette fades `0x4cce50`/`0x4cceb0`.
- Prior evidence: [palette bootstrap](../native-palette-bootstrap.md) names it as an unexecuted boundary.

### 0x004c5490 `AddDirtyRect`
- Module: dlg.cpp..timer.cpp · Relevance: render · Status: specified
- Signature: fastcall, ECX = rectangle (4 × s32, inclusive); no return.
- Behavior: left and top are rounded down to multiples of 16 (`& ~15`); right and bottom become `(v + 16) & ~15` (exclusive). The result is clamped to `0x50ef54` {0, 0, 640, 480} (left/top raised to at least 0, right/bottom lowered to at most 640/480, signed). Creates the region `0x6ce784` (ordinal 524) when absent, then ORs the rectangle into it (ordinal 523, mode 2).
- Callers/callees: `InvalidateControl` `0x4c4ae0`, `InvalidateCursorOverDialogs` `0x4c4bc0`, `0x4c5360`, `0x4c5590`.

### 0x004c5530 `InvalidateBackdropDialogs`
- Module: dlg.cpp..timer.cpp · Relevance: render · Status: specified
- Signature: no arguments.
- Behavior: Only while the backdrop `0x6ce778` is the screen `0x6d0b88`: for each dialog of `0x6ce6d8` with flags `0x10000000` and `0x8` whose screen rectangle touches a set cell of the 40×30 grid of 16-pixel dirty cells `0x6d06d0` (`0x4cad10`(left, top, right, bottom)), calls `InvalidateDialogArea` `0x4c5590`. Such dialogs are redrawn whenever something beneath them changed.
- Callers/callees: `0x4c4d90`.

### 0x004c5590 `InvalidateDialogArea`
- Module: dlg.cpp..timer.cpp · Relevance: render · Status: specified
- Signature: fastcall, ECX = dialog.
- Behavior: Unless the dialog is transparent (`0x2000`) with no bitmap (`+0x10` = 0), adds its rectangle (`0x4c5490`). Then adds every visible child's rectangle offset by the dialog origin.
- Callers/callees: `0x4c5530`.

### 0x004c5630 `BlitDialogToScreen`
- Module: dlg.cpp..timer.cpp · Relevance: render · Status: specified
- Signature: fastcall, ECX = dialog, EDX = rectangle (4 × s32; only the low 16 bits of each are read); no return.
- Behavior: R = rectangle ∩ dialog rectangle (s16 compares). Nothing if R.top > R.bottom or R.left > R.right. Source offset = (R.left − dialog.left, R.top − dialog.top).
  - Flag `0x10000000`: effect colour from `0x6ce780` (`0x4ca7e0`), target = backdrop `0x6ce778`, blit the dialog bitmap (`0x4c3c70` with the dialog flags), restore the target, return.
  - Else flag `0x8000000`: the same, but the target is `0x6ce788` + `0x36` (the bitmap of the last painted dialog without this flag).
  - Otherwise, with the current target (the screen): if R overlaps the tooltip layer (`0x4c4850`), the tooltip is drawn into the dialog bitmap first (`SaveTooltipBackground` `0x419330`(bitmap, dialog.left, dialog.top), `DrawTooltipToBitmap` `0x419090`, [P06](p06.md)). Sets `0x6cfbdc` = 1 (`0x4ca880`). If R overlaps the cursor layer (`0x4c48b0`) and the cursor layer is active (`0x6d0b90`): saves the dialog-bitmap pixels under the cursor (`0x4cb140`), draws the cursor into the bitmap (`0x43e690`), blits (`0x4c5330`), restores those pixels (`0x4cb0b0`). Otherwise blits directly (`0x4c3c70`). Then `0x6cfbdc` = 0 and, if the tooltip was drawn, restores the bitmap under it (`RestoreTooltipBackground` `0x4192b0`).
- Callers/callees: `0x4c4d90`.

### 0x004c5840 `DeleteTimersOfOwner`
- Module: timer.cpp · Relevance: ui · Status: specified
- Signature: fastcall, ECX = owner.
- Behavior: Repeatedly finds the first node of the active queue `0x6cf798` with `owner` = ECX (predicate `0x4c5b60`), unlinks it and frees it (timer.cpp line `0xae`) until none remains. Then the same for the fired queue `0x6cf79c` (line `0xbb`).
- Callers/callees: control destroy (user code 1) in `ControlDefaultInteract` `0x4c1e90`.

### 0x004c58f0 `DeleteUiTimer`
- Module: timer.cpp · Relevance: ui · Status: specified

### 0x004c5960 `SetUiTimer`

### 0x004c5a20 `RunUiTimers`
- Module: timer.cpp · Relevance: ui · Status: specified
- Signature: no arguments; called by the message pump `0x4401c0`.
- Behavior: now = GetTickCount() (read once). Walks the active queue from its head:
  1. lateness = now − last − period (s32). If lateness ≤ 0, stop (the queue is sorted).
  2. If lateness < 500: `+0x18` += (lateness − `+0x18`) >> 5 (arithmetic). The field is not read anywhere else.
  3. last = now; remembers next = node `+0`.
  4. Callback ≠ 0: callback(ECX = owner, DX = ID). Otherwise sends the owner's interact procedure an event {code 8, parameter = ID, `+0x08` = the period (left in EDX), type 14, cursor `0x6d3154`/`0x6d3158`}.
  5. Unlinks the node from the active queue; if it was still there, pushes it on the fired queue `0x6cf79c` (a node deleted or replaced by its own callback is not pushed again; a replaced node was re-inserted and is moved to the fired queue here).
  6. If next is null, or next is no longer in the active queue (`0x4cabc0`), the walk stops; otherwise it continues with next.
  
  Finally every fired node is popped from the head of `0x6cf79c` and sorted back into the active queue. Its due time is now + period, so missed periods are not caught up.
- Prior evidence: [briefing loader](../native-briefing-loader.md) executed the expiry test and correction update (lateness 0 does not fire; `>> 5` below 500).
