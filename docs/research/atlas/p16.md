# P16: In-game input procedures and accelerator commands, melee AI start, and the Battle.net selection UI

This package covers `0x4486a0`–`0x44cf0f`: the object between `gametype.cpp` and `glubn.cpp`, `glubn.cpp`, the object between `glubn.cpp` and `glubnchat.cpp`, `glubnchat.cpp` and the head of the object before `glubncreate.cpp`. Its 59 functions fall into three groups.

1. **Game-start AI scripts** (`0x4486a0`). Game-type setup starts the custom-level AI script of every computer slot at its start location.
2. **In-game input** (`0x448760`–`0x448f20`). `0x448dd0` installs the in-game input procedures in the table `0x665df0[19]` (layout in [P13](p13.md)) and picks the left-click and right-click handlers for the current cursor mode (normal, building placement, targeting). `0x4487a0` is the in-game WM_COMMAND handler for accelerator commands: control groups, saved screen positions, game speed, centering on the selected unit, music/sound toggles and the game menus. The middle mouse button scrolls the map proportionally (`0x448cb0` plus embedded code `0x448d20`). The fixed-key producer for `font\font.gid` (`0x448f40`) also sits here. All of these are in scope.
3. **Battle.net selection UI** (`0x448fa0`, `0x449930`–`0x44cba0`). The interface table that `SNetSelectGame` receives (`0x44a4d0`), its art, sound, cursor, message-box and drawing callbacks, rich-text drawing over GDI, rank-number glyphs (`glue\battle.net\icons\number.pcx`), and the Create Game and map-browse dialogs (`DIALOG_CREATE_GAME`, `DIALOG_CREATE_BROWSE` from `rez\gluBNRes.res`). The glue loop runs the Battle.net screens only in glue state `0x66a274 = 4`. The interface table itself is different: `InitNetworkProvider` `0x4757e0` fills it with `0x44a4d0` and passes it to `SNetInitializeProvider` on every provider initialization, including provider 0 that `CreateLocalGame` `0x475220` uses for an offline game. So `0x44a4d0` runs offline and is `specified`. The callbacks it installs are only invoked by Storm's network-provider and Battle.net UI (`SNetSelectGame`, game lists, Create Game); nothing in the executable shows the local provider calling them (Storm itself was not traced). The rest of the group is therefore `excluded`.

**Embedded code `0x448780` (character procedure)**: ECX = event; `c` = WORD `+8`. If `c − '0'` ≤ 9 (unsigned), it selects control group `c − '0'` (`0x463ee0`, CL = group) without centering. Then, if `c` = 27 (Escape), it tail-jumps to `0x4bda80`, which in an offline game (and while `0x526524 < 32`) walks the trigger list of the local player (`0x50e0e0 + player*12`, player `0x508d50`, while the node pointer is > 0) and marks every trigger whose flags `+0x948` have bit 0 (value 1) set and bit `0x40` clear with bit `0x10`. For each such trigger it also sets WORD `0x6ca748` = 1, clears the local wait byte `0x6ca760[player]` and DWORD `0x6ca768[player]`, and calls `0x49db50`, `0x4a73e0` and `0x46aef0`. Escape therefore skips the current trigger wait/transmission. In multiplayer, or when `0x526524` ≥ 32, Escape does nothing.

**Accelerator command IDs handled by `0x4487a0`.** The handler reads the command ID as WORD `+8` of the event and sign-extends it; the IDs below are the unsigned WORD values. The command-to-key bindings live in accelerator resources 101/102/103 of the localized resource module (`0x6d0c54`), not in the executable. The executable only contains resource 113, which maps Shift+`1`…`9`,`0` (VIRTKEY | SHIFT) to 39891…39900. Jump tables: first stage byte map `0x448abc` (17 entries, index = ID − 40043) into targets `0x448a98` (9 entries); second stage byte map `0x448b70` (175 entries, index = ID − 39891) into targets `0x448ad0` (40 entries, entry 39 = return).

### 0x004486a0 `StartCustomLevelAIScripts` — start the AI script of every computer slot
- Module: gametype.cpp..glubn.cpp · Relevance: ai
- Status: specified
- Signature: no arguments; no return value.
- Behavior: For slot `s` = 0…7 in order (player slot table `0x6726c8 + s*36`): skip unless the type byte `0x6726d0 + s*36` = 1 (computer). Choose the script ID from the race byte `0x6726d1 + s*36`: in a Brood War game (`0x536720` ≠ 0) race 0 → `ZMCx`, 1 → `TMCx`, 2 → `PMCx`; otherwise `ZMCu`, `TMCu`, `PMCu` (DWORDs `0x78434d5a`, `0x78434d54`, `0x78434d50`, `0x75434d5a`, `0x75434d54`, `0x75434d50`). Any other race skips the slot. The start location is `x` = s16 `0x534a00 + s*4`, `y` = s16 `0x534a02 + s*4`. It builds the rectangle {left `x − 1`, top `y − 1`, right `x + 1`, bottom `y + 1`} (four DWORDs on the stack) and calls the launch gate `0x493970` (ECX = script ID, EDX = `s`, stack = rectangle pointer). The gate accepts a script ID listed in `0x508f70` or any slot whose type is 1, so every such slot starts its script whenever the script lookup `0x494d20` finds it.
- Globals/fields: `0x6726d0`, `0x6726d1`, `0x536720`, `0x534a00`.
- Callers/callees: only `0x448530` (game-type setup), when byte `0x67294b` ∈ {1, 3} and any of the bytes `0x672945`, `0x672949`, `0x67294f` is nonzero; otherwise that caller calls `0x482ee0` for each of the 8 slots instead.
- Prior evidence: [AI opcodes](../native-ai-opcodes.md) (launch gate `0x493970`).

### 0x004487a0 `GameCommandHandler` — in-game WM_COMMAND (accelerator) handler
- Module: gametype.cpp..glubn.cpp · Relevance: ui
- Status: specified
- Signature: ECX = event (type 16); command ID = WORD `+8`, sign-extended; no return value. Installed in slot 16 by `SetGameAccelerators` `0x43f140` and `SetAccelerators102` `0x43f120`.
- Behavior: (see the command table above)
  1. ID 40038 → `0x49ec00`; ID 40039 → `0x49ec40`. These run unconditionally.
  2. If the "waiting for players" modal loop is running (byte `0x67500c` ≠ 0, set by `0x47a810`), return.
  3. First stage: for IDs 40043…40059, the first jump table opens the named dialog or toggles the leaderboard. It always continues to step 4; those IDs fall to the second table's "return" entry.
  4. If the game is paused (`0x47cb60`, DWORD `0x67517c` ≠ 0), return.
  5. Second stage, for IDs 39891…40065:
     - Add/assign: `0x473df0`(CL = action 2 or 0, DL = group, stack 0, 0). That function queues the 3-byte command {`0x13`, action, group} with `0x476c80`. For any action other than 1 it only resets the double-tap memory `0x67264c` to `0xff`. For action 1 it also copies the unit list to `0x67261c` and centers on the group (`0x463d60`) when the same group was selected again within 500 ms (`GetTickCount`, `0x672650`); otherwise it records the group and time.
     - Center and select: `0x463ed0` (CL = group) calls `0x463d60` and then `0x463ee0`. `0x463d60` (group < 10 only) averages the signed sprite positions (`+0x14`/`+0x16`) of the group's units that exist, have `0x41fe20` = 0, are not hidden (sprite byte `+0xe` bit `0x20`) and pass `0x4291b0` (that test is waived for a one-unit group), and calls `SetScreenPosition`(x = (mean x − 320) & ~7, y = (mean y − 200) & ~7) when any unit counted. `0x463ee0` keeps the group's units that exist, are not hidden, belong to the local player `0x508d44` and pass `0x4291b0` (waived for a one-unit group); when none qualifies it does nothing. Otherwise it selects them locally (`0x423120`, `0x49cf80`) and queues command `0x13` action 1 with the double-tap check.
     - 40036: when `0x6ab4c4` ≠ 0, `0x422b10`(ECX = that unit).
     - 40056/40058: only when the multiplayer byte `0x672664` = 0; `0x474380`(ECX = new speed) queues the 2-byte command {`0x0f`, speed}. The speed changes only when the command executes.
     - 40060–40062: WORD `0x526550 + 4i` = low WORD of the screen x `0x543218`, WORD `0x526552 + 4i` = low WORD of the screen y `0x54321c`.
     - 40063–40065: `SetScreenPosition` `0x40b450`(ECX = s16 x, EDX = s16 y) of slot `i`.
     - Any other ID: nothing.
- Callers/callees: `0x49ec00`, `0x49ec40`, `0x47b300`–`0x47b380`, `0x4a6260`, `0x49b0b0`, `0x49af50`, `0x47cb60`, `0x473df0`, `0x463ed0`, `0x422b10`, `0x474380`, `0x40b450`.
- Callee notes: `0x49ec00` swaps music volume `0x6d313c` with its saved value `0x6aa98c` (nonzero → save and set 0; zero → restore) and applies it (`0x49ea60`). `0x49ec40` does the same for the effects volume `0x6d3140`/`0x6aaa50` only when the audio device `0x6aa954` exists; muting also stops the playing effect channels (`0x49eca0`). The save dialog requires `0x477800` (offline, or the local player is the lowest active player), `0x67294f` = 0 and no replay, and in multiplayer at least 120000 ms since `0x6a5ea0`. The load dialog requires offline and no replay.
- Prior evidence: none. **Contradictions (resolved, P08 and P36 corrected)**: [P08](p08.md) said `0x422b10` has no references, and [P36](p36.md) said `0x4a6260` has no direct call. Both are called from this function (`0x448850`, a tail jump from jump-table entry 30, and `0x44881b`, a direct call).

### 0x00448cb0 `BeginMiddleButtonScroll` — middle-down procedure
- Module: gametype.cpp..glubn.cpp · Relevance: ui
- Status: specified
- Signature: ECX = event; no return value.
- Behavior:
  1. `qx = (u32)(prevScreenX 0x543210 * 100) / (u32)(mapWidthPx WORD 0x543230 − 640)`; `qy = (u32)(prevScreenY 0x543214 * 100) / (u32)(mapHeightPx WORD 0x543234 − 400)`. Both multiplications wrap at 32 bits, and the divisions are unsigned.
  2. Anchor `0x667294` = s16 event x `+0xe` − `qx` + 50; `0x667298` = s16 event y `+0x10` − `qy` + 50.
  3. `HideCursorLayer` `0x43e590`; mouse-move procedure `0x665dfc` = `0x448d20`.
- Embedded code `0x448d20` (mouse move while scrolling): `px = clamp(mouseX 0x6d3154 − anchorX + 50, 0, 100)`, `py = clamp(mouseY 0x6d3158 − anchorY + 50, 0, 100)` (signed). It then calls `SetScreenPosition`(ECX = `(mapWidthPx − 640) * px / 100`, EDX = `(mapHeightPx − 400) * py / 100`), with signed 32-bit multiplication and division truncated toward zero. Every mouse pixel therefore moves the view by 1 % of the scrollable range, starting at the current percentage. The middle-up procedure `0x448dc0` ends the drag.

### 0x00448f10 `GameIdleThunk` — idle procedure (slot 13)
- Module: gametype.cpp..glubn.cpp · Relevance: ui
- Status: specified
- Signature: a 5-byte jump to `0x446ff0`.
- Behavior: (in `0x446ff0`) Decrements each nonzero UI sound cooldown, `0x667274` (unit selection sound), `0x667278` and `0x66727c`. Then the counter `0x667284`: if it was 0, it is reset to 1 and every unit in the active list (`0x425600`, next `+4`) with a nonzero byte `+0x87` (BWAPI `attackNotifyTimer`) has it decremented; otherwise it is just decremented. ### 0x00448f40 `MakeFontGidKey` — fixed-key producer for `font\font.gid`
- Module: gametype.cpp..glubn.cpp · Relevance: data
- Status: covered
- Signature: ECX = buffer, EDX = size `n`; no return value.
- Behavior: `srand(0x150b)`; fills `buffer[0..n−2]` with the low bytes of successive `rand()` results, skipping zero bytes, so it may draw more than `n − 1` times; then `srand(time(NULL))` and `buffer[n−1] = 0`. With `n = 20` the result is 19 nonzero bytes plus NUL. The CRT generator is separate from the game RNG.
- Callers/callees: `0x4634e0`, `0x4635d0` (font resource acquisition).
- Prior evidence: [font decoder](../native-font-decoder.md) (fixed-key producer section).
