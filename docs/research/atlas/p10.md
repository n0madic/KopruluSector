# P10: Unit movement state machine, collision escape and Protoss build/shield orders

This package covers the 85 functions from `0x42ad10` to `0x42f830` in the object that sorts between `cunitinit.cpp` and `cunitprotoss.cpp`. It falls into four groups.

1. **Unit movement dispatcher and its 36 state handlers** (`0x42ad10`–`0x42c670`). `0x42ad30` runs once per unit per object step, from `0x43a5f0`/`0x43a770`. It switches on movement-state byte CUnit `+0x97` through the jump table `0x42af44` and repeats while a handler returns nonzero. The state names below are OpenBW's (`UM_*`). They are reference labels; the numbers and behavior come from the 1.17 code.
2. **Movement helpers** (`0x42c790`–`0x42ed50`). These are movement reset and immobilization, the illegal-position escape search (`CheckIllegal`), collision geometry, slide-direction selection, blocker queries, neighbor position forecasting, terrain fitting and the group-move destination adjustment used by command processing.
3. **The ResetHarvestCollision order** `0x42e0d0` and the overlap collision-flag pass `0x42e600`.
4. **Protoss orders** (`0x42ee00`–`0x42f830`). These are PlaceProtossBuilding/CreateProtossBuilding, IncompleteWarping, WarpIn, InitializeArbiter, RechargeShieldsUnit/RechargeShieldsBattery, the ShieldBattery secondary order, the recharge-overlay removal, InitializePsiProvider and ArchonWarp. The main order switch `0x439420` (case `+0x4d`) and the secondary switch `0x439310` (case `+0xa6`) dispatch them.

## Shared data, fields and conventions

**CUnit fields** (1.16.1 BWAPI layout, confirmed by use). Flingy head: `+0x0c` sprite, `+0x10/+0x12` move target, `+0x14` move-target unit, `+0x18/+0x1a` next movement waypoint, `+0x1c/+0x1e` next target waypoint, `+0x20` movement flags (bit `0x01` turn pending, `0x02` moving, `0x04` braking/stop point, `0x08` no walk-animation changes, `0x20` order-queue flag), `+0x21` heading, `+0x23` current velocity direction, `+0x27` movement type (0 flingy.dat physics, 1 partial, 2 IScript), `+0x28/+0x2a` position, `+0x2c/+0x30` fixed position (×256), `+0x34` top speed, `+0x38` current speed, `+0x3c` next speed, `+0x40/+0x44` velocity, `+0x4a` velocity direction being prepared, `+0x4b` desired velocity direction. Unit fields: `+0x4c` owner, `+0x4d` order, `+0x4e` order state, `+0x4f` order signal (value `0x01` = IScript signal; "signal bit 1" below means this value), `+0x58/+0x5a` order target position, `+0x5c` order target unit, `+0x60` shields (×256), `+0x64` unit type, `+0x70` subunit/parent, `+0x74` order-queue head, `+0x8f` kill count, `+0x93` user-action flags, `+0x94` button set, `+0x97` movement state, `+0x98`+2·`+0xa4` build-queue slot, `+0xa2` energy, `+0xa6` secondary order, `+0xa8` HP gain, `+0xaa` shield gain, `+0xac` remaining build time, `+0xd0` psi-field sprite, `+0xdc` status flags, `+0xe2` secondary order state, `+0xe3` move-target timer, `+0xf8/+0xfc` psi-provider list prev/next, `+0x100` path record, `+0x104` pathing collision counter, `+0x105` pathing flags (bit 0 = elevation < 12, i.e. ground-pathing; bit 1 = moving to a legal position; bit 2 = abort that move), `+0x108` terrain safe rectangle (four WORDs, see [terrain sweep](../native-terrain-sweep.md)), `+0x112..+0x12f` status timers, `+0x134` AI, `+0x13c/+0x140/+0x144/+0x148` spatial endpoint indices.

**Status bits `+0xdc` used here** (OpenBW labels): `0x1` completed, `0x2` grounded building, `0x4` flying, `0x10` burrowed, `0x20` in bunker, `0x400` disabled, `0x1000` order not interruptible, `0x2000` IScript nobrk, `0x10000` can turn, `0x20000` can move, `0x40000` collision (stuck), `0x80000` immovable, `0x100000` ground unit (collides with ground units), `0x200000` no collide, `0x400000` pass-through for enemies, `0x800000` gathering, `0x2000000` turret walking, `0x10000000` speed upgrade, `0x40000000` hallucination.

**"At move target"** throughout means: move target `+0x10/+0x12` equals sprite position (`+0x0c`→`+0x14/+0x16`). The inlined test also contains `((status & 0x80000) ? 1 : 0) + 1 != 0`, which is always true, so the immovable bit has no effect on it. Out-of-package `0x41a250` returns 0 if not at target, else `1 + (immovable ? 1 : 0)`.

**Path record** (`+0x100`, a 128-byte pool record, see [path storage](../native-path-storage.md)): `+0x00` source, `+0x04` next point (packed), `+0x08` goal, `+0x0c` creation frame (copy of the object-step counter `0x52651c`), `+0x10` last collision unit ID (DWORD from `0x428bd0`: `(uniqueness<<11) | (index+1)`), `+0x14` last collision speed, `+0x18` state flags (bit 0 = move target changed), `+0x19` delay byte, `+0x1a` slide-free direction (`0xff` = none).

**Prepared-movement scratch globals** (from `0x40bcd0` and its variants; see [P03](p03.md)): `0x543280/0x543284` prepared pixel x/y (signed WORD), `0x543288/0x54328c` old pixel x/y (written by commit), `0x543290/0x543294` prepared fixed x/y, `0x543298` prepared speed.

**Unit dimensions** `0x522c38 + type*8`: signed WORDs left, up, right, down. A unit's sprite box at `(x,y)` is `[x−left, x+right] × [y−up, y+down]`, inclusive. Map pixel size: WORDs `0x543230` (width), `0x543234` (height).

**Out-of-package helpers named in entries.** `0x42ac20(u, allowNewPath)` `UpdatePathMovementState`: if at move target or flag `0x04` → state 11; else if status has both `0x40000` and `0x100000` → release path, state 12; else if `allowNewPath` and no path → candidate 22; else if path and path flag bit 0 → candidate 21; otherwise return 0. A candidate becomes 19 when the current state is 28..35. It returns 1 whenever it wrote a state. `0x42ab10` `CommitUnitMovement`: commit through `0x40bdb0`; if the pixel position changed, move the spatial endpoints by the delta (`0x419820`), and if the 32-pixel tile changed on either axis (signed truncating division), set `0x665b44` = 1; it returns the commit result. `0x42abb0` `MoveOrHaltOnCollision`: if `0x42da30` or `0x42d990` reports a collision, it commits stationary (`0x40be80`), runs `0x4229a0(u,1,moveTargetUnit)` when a move-target unit exists (result unused), sets speed 0, sets the move target to the sprite position (`0x40cca0`) and stops (`0x43a490`). Otherwise it commits with `0x42ab10`. `0x42aa60` clamps a flyer's move target into `[left, mapW−right−1] × [up, mapH−down−1]` and sets `0x80000` when it changed. `0x48e880` releases the path record (`+0x100` = 0). `0x48eb90(u, packedTarget)` is the waypoint consumer (see [path progress](../native-path-progress.md)): 1 = a waypoint exists or was produced, 0 = failure. `0x48ee40` is its reuse predicate. `0x428b50`/`0x428bd0` convert unit ID ↔ pointer. `0x4229a0(ECX=unit, range, target)` returns 1 when the approximate distance (`0x405cf0`) between the two unit boxes' edge gaps is ≤ range; a subunit uses its parent's box. `0x417220(ECX=sprite, anim, force)` starts an IScript animation on every image (11 Walking, 12 WalkingToIdle, 13 SpecialState1, 19 IsWorking, 20 WorkingToIdle, 21 WarpIn, 24 Disable). `0x478270(ECX=lo, EDX=hi, stack=source)` and `0x478200(ECX=source)` are the ranged and raw game RNG ([PRNG](../native-prng.md)).

## Entries

### 0x0042ad10 `AbortMoveToLegal` — request abort of a legal-position move
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = unit; returns 0.
- Behavior: If pathing flags `+0x105` bit 1 (moving to a legal position) is set, ORs in bit 2 (abort, consumed by MoveToLegal `0x42be70`). It always returns 0, so the callers' "nonzero" branches are dead and the stop always proceeds.
- Callers/callees: `0x43a490` and `0x43a4e0` (unit stop), before `0x40ce10` and the move-target clamp `0x41a4b0`.
- Prior evidence: none.

### 0x0042ad30 `ExecuteUnitMovement` — movement-state dispatcher
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = unit; callers ignore EAX.
- Behavior: Sets `0x665b44` = (`0x6663ec` ≠ 0 ? 1 : 0). It then loops: read `+0x97`; if > 35, return; otherwise dispatch through `0x42af44` (table above). A handler result ≠ 0 repeats dispatch with the possibly changed state in the same call; 0 ends the call. The inline cases are listed in the table. Cases 2, 6 and 8, and cases 18 and 22 when they return, end the call without looping. Cases 4 and 5 end with the tail call to `0x40bee0`. No RNG is consumed by the dispatcher itself.
- Globals/fields: `0x6663ec`, `0x665b44`, `+0x97`, path `+0x18/+0x19`.
- Callers/callees: `0x43a5f0` (main unit update, which then calls `0x423260` if `0x665b44` ≠ 0) and `0x43a770` (subunit update).
- Prior evidence: [movement FSM](../native-movement-fsm.md), [active IScript](../native-active-iscript.md).

### 0x0042afe0 `MoveState_AtMoveTarget` — state 11
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = unit; returns 1.
- Behavior: Releases the path (`0x48e880`). If the movement waypoint DWORD `+0x18` ≠ move target DWORD `+0x10`, copies it. If status has `0x100000` and flag `0x04` is clear, the state becomes 12 (CheckIllegal); otherwise 9 (AtRest).
- Prior evidence: [movement FSM](../native-movement-fsm.md).

### 0x0042b030 `MoveState_AtRest` — state 9
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = unit; returns 0 or 1.
- Behavior:
  1. Collision counter `+0x104` (unsigned byte): if at move target, it becomes 0; else if ≥ 3, it becomes 2; else if nonzero, it is decremented.
  2. *goNext* is true when flag `0x04` is set, or when the unit is at its move target and either flag `0x02` is set or the target waypoint `+0x1c/+0x1e` differs from position `+0x28/+0x2a` and `d = GetDirection(sprite → +0x1c)` differs from heading `+0x21` or from `+0x23`.
  3. If goNext: `0x40bcd0` (prepare) then `0x42abb0` (commit, or halt on collision).
  4. If status has both `0x40000` and `0x100000`: state 12, return 0.
  5. If not at move target and flag `0x04` is clear: state 17, return 1.
  6. If goNext was false: SetFlingySpeed(0) (`0x40c220`), SetNextTargetWaypoint(sprite position) (`0x40cbd0`), state 10.
  7. Returns 0.
- Prior evidence: [active IScript](../native-active-iscript.md) (state 0→9→10 row).

### 0x0042b3b0 `MoveState_FixCollision` — state 28
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = unit u; returns 0 or 1.
- Behavior:
  1. If `0x42ac20(u,1)` ≠ 0, return 1. (OpenBW passes `false` here; 1.17 passes 1, so a pathless unit moves to state 22 instead of continuing.) Then the counter increments, saturating at 255.
  2. b = unit for path `+0x10` (`0x428b50`). If b is null, b's sprite has hidden flag `0x20`, b's pathing bit 0 is clear, b has `0x200000`, b == u, or `0x42ebf0(ECX=b, EDX=u)` = 0: state 25, return 0.
  3. Result *r*:
     - If u has a move-target unit `+0x14` and `0x4229a0(u, 0, target)` → r = 1.
     - Else if `0x42e360(b, u.type, u.moveTarget)` (u's footprint at its move target touches b's box): if b's counter < 30 and not `0x42e400(b, b.moveTarget, u.type, u.moveTarget)`, then r = `0x42cde0(u,b)` ? 4 : 6; else r = (u.`+0x14` ≠ 0) ? 3 : 2.
     - Else if `0x42e360(b, u.type, u.waypoint +0x18)`: if b's counter < 30 and not `0x42e400(b, b.moveTarget, u.type, u.waypoint)`, r = `0x42cde0` ? 4 : 6; else r = 3.
     - Else: if b's flag `0x02` is set, side = `0x42cc70(u,b)`, v = b.`+0x23`, and r = 6 when (side 0 and (v ≤ 64 or v ≥ 192)), (side 1 and v ≤ 128), (side 2 and 64 ≤ v ≤ 192) or (side 3 and (v == 0 or v ≥ 128)). If not yet decided: s = b.`+0x97`, or 29 when b's counter > 2. If b is not at its move target and b's flag `0x02` is set: s ∈ {25,26} → r = 6; s == 29 → slide check; any other s → r = 4. Otherwise (b at target or not moving) → slide check. Slide check: r = (`0x42dc70(u,b)` ≥ 0) ? 7 : 5.
  4. If `(0x52651c − path+0x0c)` < 7 (unsigned) and 3 ≤ r ≤ 5: `0x42c810(u)`, return 0 (stay in 28).
  5. Apply r: 1 → `0x42c7a0` then clear `0x80000`, state 11. 2 → `0x42c7a0`, state 11. 3 → state 23. 4 → state 24. 5 → state 19 and SetFlingySpeed(0). 6 → state 29. 7 → path `+0x10` = ID(b), path `+0x1a` = `0x42dc70(u,b)` (evaluated again), state 31. r = 8 → state 30 (`0x42b6b5`, entry 7 of the result jump table `0x42b6dc`) exists in the code but is never produced: every branch yields r ∈ 1..7 (the side-direction table `0x42b6cc` only selects among the r = 6 tests). Returns 0.
- Callers/callees: `0x42cc70`, `0x42cde0`, `0x42dc70`, `0x42e360`, `0x42e400`, `0x42c7a0`, `0x42c810`.
- Prior evidence: none (OpenBW `movement_UM_FixCollision` has the same decision table).

### 0x0042b700 `MoveState_FixTerrain` — state 34
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = unit; returns 0 or 1.
- Behavior: The counter increments first (saturating at 255). If `0x42ac20(u,1)` ≠ 0, return 1. SetFlingySpeed(path `+0x14`), then prepare (`0x40bcd0`). If `0x42d990` (terrain/bounds) = 0 and `0x42d900` (unit blocker) = 0: commit (`0x42ab10`), flags |= 1, state 25, return 0. Otherwise the walk-animation gate runs (as `0x42c810`). If `+0x23` ≠ GetDirection(sprite → waypoint), commit turn only and return 0. Else path `+0x1a` = `0x42db60(u)`, state 35, return 0.

### 0x0042b7f0 `MoveState_Flyer` — state 7
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = unit; returns 0.
- Behavior: Clamps the move target (`0x42aa60`), prepares (`0x40bcd0`) and computes the repulse result `rep = 0x481880(u)`. It then clamps only the **prepared pixel** position, with 16-bit arithmetic: x < left → x = left; x + right ≥ mapW → x = mapW − right − 1; the same for y with up/down and mapH. The prepared fixed position `0x543290/94` is **not** clamped, so the committed fixed and pixel positions can disagree after a clamp. It commits (`0x42ab10`) and calls `0x4815d0(u, rep)` (repulse-cell maintenance; when being repulsed and the move target is within 24 pixels on both axes, the move target and waypoint snap to the new position).
- Prior evidence: [active IScript](../native-active-iscript.md).

### 0x0042b8d0 `MoveState_FollowPath` — state 25
- Module: cunitinit.cpp..cunitprotoss.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = unit; returns 0 or 1.
- Behavior:
  1. If `0x42ac20(u,1)` ≠ 0, return 1. If `0x48eb90(u, moveTarget)` = 0: state 22, return 1.
  2. spd = `+0x3c` before preparing. Prepare (`0x40bcd0`). If movement type `+0x27` == 0, spd = `+0x38` after preparing.
