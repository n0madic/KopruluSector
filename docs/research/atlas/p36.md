# P36: Console status panels — unit status data, fluff masks, leaderboard, menu button, portrait and resources

This package holds the in-game console panels between `statdata.cpp` and `statres.cpp`. Its pieces are:

- **Unit status panel** (`statdata.cpp` tail, 0x4a25b0–0x4a5a00). Dialog `0x6aab34`, loaded from `rez\statdata.bin` by `0x4a1f10` (P35), shows the selected unit: name, hit points, shields, energy or timer, a status line, kills, up to four weapon/armor/shield/ammo slots, training queue, research or upgrade progress, supply, resource amount, transport cargo and the twelve-unit multi-selection. A per-unit-type table at `0x50ba50` (228 rows of 12 bytes: `u32 type id`, `needsRefresh()`, `draw(panel)`) selects one of a small set of layouts. The per-frame driver `0x4a2aa0` calls `needsRefresh` and redraws only when a cached value changed. Mode byte `0x6aab31` remembers which layout is shown, and the controls are addressed by their signed dialog index (`wIndex`, `+0x20`). Value caches live at `0x6aab68`–`0x6aabcd`. Hover tooltips are dispatched by `0x4a2380` (P35) to the builders in this package.
- **Console fluff masks** (`statfluf.cpp`). These are per-race lists of transparent dialogs that copy pieces of the console bitmap over the map edge.
- **Leaderboard** (`statlb.cpp`, `rez\statlb.bin`). This is the UMS trigger leaderboard: types `0x11`–`0x15` and `0x21`–`0x25` use one value column, and type `0x28` ("Greed") uses minerals and gas columns.
- **Game-menu button** (`statmisc.cpp`, `rez\stat_f10.bin`) with its "Game Menu (F10)" tooltip.
- **Unit portrait** (`statport.cpp`, `rez\statport.bin`, `arr\portdata.tbl`): idle and talking SMK selection, the portrait RNG, fade-in noise, trigger transmissions and the transmission camera position. The RNG, idle/talking choices, mode setter, decode gate and fade timer were executed by [native-audiovisual](../native-audiovisual.md). That document stays authoritative on its probes. This atlas adds the open, restart and timer chains.
- **Resource panel** (`statres.cpp`, `rez\statres.bin`, `game\icons.grp`): icon-plus-text controls, an animated resource counter and supply text.

Many callbacks in this range are reached only through stored pointers (dialog interact or update slots, unit-type table rows, timer callbacks), and Ghidra did not split them into separate functions. Each one is documented inside the atlas entry whose address range contains it, under "Embedded code".

## Shared conventions

**Dialog control fields** (BWAPI `dialog`, confirmed at every use here): `+0x04..+0x0b` rect `left, top, right, bottom` (s16), `+0x14` text pointer, `+0x18` flags (bit 1 dirty, bit 2 disabled, bit 8 visible), `+0x20` s16 index, `+0x22` control type (0 = dialog, 2 = button, 9 = left static), `+0x24` u16 `wUser`, `+0x26` u32 `lUser`, `+0x2a` interact callback, `+0x2e` update/draw callback, `+0x32` parent dialog, `+0x42` first child (dialogs). Engine helpers used throughout:

| Helper | Behavior |
|---|---|
| `0x4c2200(ECX=ctrl or dialog, DX=index)` | Finds the child with that `wIndex`. A non-dialog argument is first replaced by its parent. |
| `0x4c2890(ECX)` | Shows a control (no-op if visible), then marks it dirty. |
| `0x4c22f0(ECX)` | Hides a control (no-op if hidden), then marks it dirty. |
| `0x4c2840(ECX)` | Marks dirty (sets flag bit 1 and queues its rect). |
| `0x4c2280` / `0x4c2910` | Disable / enable. |
| `0x4c2900(ECX, EDX=bool)` | Shows when EDX ≠ 0, otherwise hides. |
| `0x4c25b0(ECX=dialog, EDX=table, stack size)` | Assigns `interact = table[index-1]` to each child with `0 < index` whose table entry is non-null. The stack argument is the table size in bytes; `size/4` is stored in `0x6ce65c` but does not bound the walk. `ret 4`. |
| `0x4c5960(ECX=ctrl, EDX=id, stack period_ms, callback)` | Creates a repeating UI timer. `0x4c58f0(ECX, EDX=id)` deletes it. |
| `0x4a7d70(CX=id)` | Returns `stat_txt.tbl` string `id` (1-based). |
| `0x4cb860(buf, size, fmt, ...)` | `vsnprintf` that always NUL-terminates. |
| `0x418f60(ECX=x, EDX=y, stack text)` | Draws the floating tooltip box. `0x4191d0` hides it. |

**Status-panel helpers from P35** used here (each takes `ECX=panel`): `0x4a1ec0`/`0x4a2440` get/set mode `0x6aab31`; `0x4a1ef0` hides every control after index −7 in child-list order; `0x4a1ed0` hides all children; `0x4a1ab0(EDX=index, stack u16)` stores `wUser`, shows, dirties. Show-run helpers show each child from a start index through an end index, inclusive and in list order: `0x4a2450` [−40 … 17], `0x4a2480` [−30 … 13], `0x4a24b0` [−15 … 8], `0x4a24e0` [−35 … 15], `0x4a2510` [−10 … −13], `0x4a2540` [−20 … 12].

**Status-panel unit helpers** (other packages): `0x428b20` displayed type (the build-queue head when `0x43c040` reports an incomplete Lair/Hive/Greater Spire/Spore/Sunken morph, else `unit+0x64`); `0x428d10` displayed name (empty above type 227; map string when `units.dat` name override `0x524458` is nonzero; else `stat_txt[type+1]`); `0x428d60(ECX=unit)` race of the unit's own type `unit+0x64` from group flags `0x523c40` (bit 0 → 0 Zerg, bit 2 → 2 Protoss, bit 1 → 1 Terran, else 4); `0x41b2b0` build progress percent `(buildTime[t] − unit+0xac) × 100 / buildTime[t]` with `t` = queue head for Egg/Cocoon/Lurker Egg/morphing buildings; `0x41b330` "current work target" (orders `0x1e`/`0x21`/`0x22` or `0x42f240` → `+0x5c`; secondary order `0x26`/`0x3f` or building-addon test `0x435990` → `+0xec`; else null); `0x41b300(ECX=unit, stack i)` build queue entry `queue[(slot+i) % 5]`; `0x407b10` "busy" (queue head ≠ 228, or `0x435990`, or `0x42f240`); `0x407b50` "disabled" (status `0x400`, lockdown `+0x117`, stasis `+0x119` or maelstrom `+0x124`).

**Slot `lUser` record** (12 bytes from SMemAlloc, created by `0x4a2570`): `+0 GRP*`, `+4 u16 frame`, `+6 u16 kind`, `+8 u16 id`. Kinds: 0 weapon, 1 armor upgrade, 2 shield upgrade, 3 unit/ammo count, 4 tech, 5 upgrade, 6 empty queue slot. GRPs: `0x6aaa70` race `cmdbtns.grp` (button backgrounds), `0x6aaa74` `cmdicons.grp` (icons), `0x6aab28` `tranwire.grp` (cargo and selection wireframes; `0x6aab2c` is `grpwire.grp`).

**DAT columns** used (resolved from the native DAT descriptor table at `0x501368`/`0x5014f0`): units `0x520458` shields enabled (u8), `0x520540` shields (u16), `0x520708` HP (s32, ×256), `0x520c68` rank, `0x5211d8` ground weapon, `0x5213a8` air weapon (130 = none), `0x521660` special flags (u32; bit 0 building, `0x40` hero, `0x800`, `0x2000` resource container, `0x8000` detector, `0x200000` spellcaster), `0x521bc0` armor upgrade (60 = none), `0x521d90` armor, `0x523358` portrait, `0x5238b0` build time, `0x523c40` group flags, `0x523d28` supply provided, `0x523ef8` space required, `0x523fe0` space provided; upgrades `0x524c50` icon, `0x524cd0` label; techdata `0x51f810` research time, `0x51f970` icon, `0x51f9c8` label; weapons `0x524e10` label, `0x5256c0` damage upgrade, `0x525c80` damage, `0x525d88` bonus, `0x525f18` factor, `0x5262c8` icon. Upgrade level `0x49a470(ECX=player, DX=upgrade)`.

**Status-panel value caches**: `0x6aab68` HP (also `[12]` HP of the multi-selection), `0x6aab6c[8]` cargo HP, `0x6aab98` u16 energy high byte, `0x6aab9a` u8 "progress" flag (`0x4a5320`), `0x6aab9c[12]` u16 multi-selection types, `0x6aabb4` shields>>8, `0x6aabb8[8]` cargo unit indexes, `0x6aabc8`/`0x6aabca` u16 secondary values (supply, resource amount, hangar count, timer/10), `0x6aabcc` u16 sum of shown upgrade levels.

## Unit-type layout table `0x50ba50`

Row = `{u32 id, needsRefresh, draw}`, indexed by `unit+0x64` of the status unit. Rows 91, 92, 161, 191–193, 202 and 214 store id 0, but dispatch is by index, so the id field is unused. The distinct (refresh, draw) pairs are:

| Unit types | needsRefresh | draw |
|---|---|---|
| Default: every type 0–104 not listed below | `0x4a55e0` | `0x4a4e40` generic unit |
| 4, 14, 18, 33, 91, 92, 105, 191–193, 204–208 (no-stat types) | `0x4b8e80` (returns 0) | `0x4a3f00` name only |
| 85, 101, 119, 153 | `0x4a55e0` | `0x4a3f00` |
| 158 | `0x4a5180` | `0x4a3f00` |
| 11, 69, 125 (Dropship, Shuttle, Bunker) | `0x4a5410` | `0x4a4af0` transport |
| 13, 128, 129, 203, 209–213, 215–227 (spider mine, crystals, traps, powerups) | `0x4a53f0` | `0x4a4030` |
| 36, 59, 97 (Egg, Cocoon, Lurker Egg) | `0x4a52a0` | `0x4a3840` morph |
| 42, 57 (Overlord, Yggdrasill) | `0x4a53a0` | `0x4a3fd0` |
| 63, 68 (Dark Archon, Archon) | `0x4a5160` | `0x4a3160` summon |
| 72, 81, 82, 83 (Carrier, Warbringer, Gantrithor, Reaver) | `0x4a51f0` | `0x4a3540` hangar trainer |
| 106–201 except 119, 125, 128, 129, 153, 158 and 191–193; also 202 and 214 | `0x4a5180` | `0x4a3310` building |

## Entries

### 0x004a25b0 `StatDataSendCancelCommand` — cancel button on the status panel
- Module: statdata.cpp..statfluf.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, `ECX` = clicked control; no return value. Called (not tail-jumped) by the slot interact handler embedded at `0x4a2830` (see `0x4a2770`) on user event 2; that handler then returns 1.
- Behavior: Does nothing when replay flag `0x67cc90` ≠ 0. Switches on `u16 wIndex − 2` with byte map `0x4a2648` (16 entries) and jump table `0x4a2638` (`0x4a25d6`, `0x4a25e0`, `0x4a2601`, return):
  - Index 2–6 (queue slots): queues command `0x20` (CancelTrain) with a u16 slot of `wIndex − 2` (3-byte command via `0x474420` → `0x476c80`).
  - Index 15: mode `0x6aab31` 7 → command `0x31` (CancelResearch, 1 byte). Mode 8 → `0x33` (CancelUpgrade). Other modes do nothing.
  - Index 17: if the status unit `0x6ab4c4` type is not 36/59/97 → command `0x34` (CancelAddon). For an Egg, Cocoon or Lurker Egg, `0x407b50(unit)` = 0 sends command `0x18`, and a disabled unit gets no command. BWAPI calls `0x18` CancelConstruction and uses `0x19` for unit morphs; this path sends `0x18` for eggs.
  - All other indexes: nothing.
- Callers/callees: `0x474400/20/40/60`, `0x473eb0` (command builders), `0x407b50`.

### 0x004a2660 `DrawStatusButtonBackThenIcon` — update callback for queue/progress buttons
- Module: statdata.cpp..statfluf.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, `ECX` = control, `EDX` and two stack words unused, `ret 8`.
- Behavior: Calls `0x4a26c0` (background), then `0x4a2770` (icon). If `ctrl+0x14` text is non-null, it selects font `0x6d3024` (`0x4ce160`) and sets format byte `0x6d300e = 0x44`. The clip rect `0x6d3038..0x6d303e` becomes the control rect. It draws the text at `(left, top)` with `0x4cdf20`, then deselects the font. Installed by `0x4a2570` for every slot except indexes 9–12.

### 0x004a26c0 `DrawStatusButtonBackground` — centered `cmdbtns.grp` frame
- Module: statdata.cpp..statfluf.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, `ECX` = control.
- Behavior: Frame = `wUser`, plus 1 if flag `0x40000000` (pressed state) is set. Reads the frame header from `0x6aaa70` via `0x463bd0` (an index ≥ the frame count selects frame 0, [P22](p22.md)). The width is `min(frameW, right−left+1)` and the height `min(frameH, bottom−top+1)`. The frame is drawn at `x = left + (ctrlW − w)/2`, `y = top + (ctrlH − h)/2` (signed halves) through the RLE blitter `0x405e1e`, which uses the current remap `0x501021`.

### 0x004a2770 `DrawStatusButtonIcon` — icon with ticon palette slice
- Module: statdata.cpp..statfluf.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, `ECX` = control.
- Behavior: Uses palette slice `k = 3` when the control is enabled and of type 2 (button), otherwise `k = 4`. Copies the 16 bytes at `0x6aaa88 + 16k` (the six 16-byte rows of `unit\cmdbtns\ticon.pcx`) into remap `0x501021`. Draws frame `lUser.frame` of `lUser.grp` unclipped, centered as in `0x4a26c0`. Afterwards restores the identity remap `0x501021[i] = i` for i = 0–15.
- Embedded code `0x4a2830` `StatSlotInteract` (interact for indexes 2–6, 9–12, 15 and 17; see table below): event `+0xc` = 3 (mouse move) → `0x4a1ae0` hover update; event 14 (user) switches on `dwUser` through table `0x4a28c0`: 0 → `0x4a2570` (allocate the 12-byte record, choose the draw callback); 1 → SMemFree `lUser` if non-null (file `0x4eff10`, line `0x281`); 2 (activate) → `0x4a25b0` and return 1; 4 → return 1 if visible; 6 → if this control is hovered (`0x6aab38`), hide the tooltip and clear `0x6aab38`; 3 and 5 fall through. All other paths chain to the default interact `0x4f10f8[ctrlType]`.
- Statdata interact table `0x4eff50` (indexes 1–44): 1 `0x4a82e0`; 2–6 `0x4a2830`; 7 `0x4a1d40`; 8 `0x4a2350`; 9–12 `0x4a2830`; 13, 14 `0x4a1d40`; 15 `0x4a2830`; 16 `0x4a1d40`; 17 `0x4a2830`; 18–32 `0x4a2940`; 33–44 `0x4a21d0`.

### 0x004a2aa0 `UpdateStatusDataPanel` — per-frame refresh driver
- Module: statdata.cpp..statfluf.cpp · Relevance: ui
- Status: specified
- Signature: no arguments; called each frame by `0x4a7ee0`.
- Behavior:
  1. No status unit (`0x6ab4c4` = 0): if force flag `0x6aab30` is set, it hides every child of panel `0x6aab34` (each through `0x4c22f0`) and sets mode `0x6aab31 = 0`.
  2. Selection count `0x6ab4c0 == 1`: when `0x6aab30` is set or `table[type].needsRefresh()` returns nonzero, it calls `table[type].draw(ECX=panel)`, then `0x4a82a0` (P37) and `0x4a2b70`.
  3. Several units: when `0x6aab30` is set or `0x4a52d0()` reports a change, it calls `0x4a3e70(panel)` then `0x4a2b70`.
  4. Always clears `0x6aab30`.

### 0x004a2bf0 `ShowWeaponArmorSlotTooltip` — tooltip for slots 9–12
- Module: statdata.cpp..statfluf.cpp · Relevance: ui
- Status: specified
- Signature: `__fastcall`, `ECX` = hovered control. Uses status unit `U = 0x6ab4c4`.
- Behavior: Reads the record `r = lUser`. Builds text in a 128-byte local and switches on `r.kind` (table `0x4a2ed8`):
  - Kind 0 (weapon `w = (u8)r.id`): bonus = `0x420e40(U, w)` = `bonus[w] × upgradeLevel(owner, damageUpgrade[w]) × f`, damage = `0x420eb0(U, w)` = `damage[w] × f`. Here `f` = `factor[w]`, forced to 2 for unit types 32, 10, 65 and 77 and to 1 for type 58. Format `"%s\n%s %d+%d"` (`0x4eff3c`) when bonus ≠ 0, else `"%s\n%s %d"` (`0x4efe70`). Arguments: weapon label `stat_txt[0x524e10[w]]`, `stat_txt 0x309` "Damage:", damage, bonus. For w = 103 (Halo Rockets) it uses `"%s\n%s %d+%d %s"` / `"%s\n%s %d %s"` with trailing `stat_txt 0x515` "per rocket".
  - Kind 1: `b = 0x43ab10(U)`: the owner's level of `armorUpgrade[U.type]`. With expansion flag `0x536720` set, types 39 and 48 add 2 when they carry hero flag `0x40` or the owner has upgrade 52 (Chitinous Plating); see [native-damage](../native-damage.md). Text: upgrade label `stat_txt[0x524cd0[r.id]]`, "Armor:" (`0x30a`), base armor `0x521d90[U.type]`, `b`.
  - Kind 2: `b` = upgrade 15 level of the owner. Text: label of `r.id`, "Shields:" (`0x30b`), 0, `b`.
  - The three kinds above draw with `0x418f60` at `(ctrl.right + parent.left, ctrl.top + parent.top)` (parent offsets 0 when the control is a dialog).
  - Kind 3 (`r.id − 13`, byte map `0x4a2efc`, jump table `0x4a2ee8`): id 13 → weapon 6, label "Spider Mines" (`0x31a`); id 73 → weapon 79, "Interceptors" (`0x317`); id 85 → weapon 82, "Scarabs" (`0x318`). These format `"%s\n%s %d+%d"` / `"%s\n%s %d"` with label, "Damage:", damage, bonus as above. Id 14 → plain "Nukes" (`0x319`). Kind 3 shows through `0x4a1d80(ECX=ctrl, EDX=text)`. Other ids, and kinds above 3, return without touching the tooltip.
