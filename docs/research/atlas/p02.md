# P02: GRP blitters, DAT requirement gates, cost/supply checks, gateway list and the Bullet hit machinery

This package covers the object files that sort between the start of the game image and `cbullet.cpp`: hand-written GRP kernels, a few `<start>`-bracket gameplay helpers, `bnetgw.cpp`, and the head of the Bullet code. It falls into six groups.

1. **Indexed GRP kernels** (`0x4060c3`–`0x40730e`). These are the normal/mirrored drawing kernels installed in the image draw table at `0x5030d4 + method*12` (see [P03 shared data](p03.md#shared-data-and-tables)). They share the ABI ECX = destination x, EDX = destination y, stack `[frame header*, crop*, drawing parameter]`, `ret 0xc`. They read the bitmap descriptor `0x6d0c40` (WORD stride at `+0`, pixel pointer at `+4`). Work state lives in fixed scratch globals `0x501121` (line-offset base), `0x501125` (row advance), `0x501129` (pixels to skip), `0x50112d` (pixels to draw), `0x501131` (rows left), `0x501139` (wrap limit = bitmap + `0x4b000`), `0x50113d` (threshold byte) and `0x501142` (texture cursor). They are fully specified and probed in [pixel blitters](../native-pixel-blitters.md) and [pixel effects](../native-pixel-effects.md).
2. **Allocation glue and player-name defaults** (`0x407460`–`0x4074a0`).
3. **General DAT requirement evaluator** (`0x407570`–`0x408280`). One bytecode interpreter is shared by the order, research, technology-use and upgrade gates. Each gate owns a built-in table and a lazily built offset array. All are covered by [DAT requirements](../native-dat-requirements.md).
4. **File-name validation and cost/supply helpers** (`0x408300`–`0x408820`). Cost checks cache per-player prices in `0x53dad0` (minerals), `0x53db00` (gas) and `0x53db30` (supply). They test current stocks `0x5263d0`/`0x526400` and the race supply arrays, and debit or refund stocks. They are covered by [training](../native-training.md), [production](../native-production.md) and [Zerg construction](../native-zerg-construction.md).
5. **Battle.net gateway list** (`0x408860`–`0x408d20`, `bnetgw.cpp`). This is registry/text-file management of the gateway list. It is excluded.
6. **Bullet creation, hit effects and state handlers** (`0x408f00`–`0x40a1c0`). They act on the 100-record Bullet pool (`0x53db90`, `0x70` bytes each; see [projectiles](../native-projectiles.md) and [P03](p03.md)). The group holds the weapon-explosion dispatcher with its splash callbacks, the per-state movement handlers, Bullet initialization, the pool initializer and save-load fix-up, and three unit-geometry helpers that sort into this object.

**Halo Rockets offset ring** `0x502620`: signed DWORD `(dx, dy)` pairs: (1,1), (51,31), (7,12), (−36,−52), (−49,25), (40,−46), (−4,−19), (28,50), (50,−15), (−54,−13), (11,−53), (15,−9), (−19,50), (−17,8). These are followed by the terminator (0,0) at index 14. The ring index wraps to 0 when the next entry's `dx` is 0.

**Weapon DAT columns used here** (indexed by weapon byte): explosion type `0x5258e0`, behavior `0x5257d0`, Flingy `0x524f18` (DWORD), lifetime `0x525858`, launch spin `0x526028`, max range `0x5254b8` (DWORD), inner/medium/outer splash radius `0x525968`/`0x525a70`/`0x525b78` (u16), damage `0x525c80`, bonus `0x525d88` (u16), upgrade `0x5256c0`, target flags `0x5251a8`.

**Splash scratch globals**: ground-splash mode `0x541770` (1 = ground pass, 0 = air second pass), air-splash candidate count `0x541774` and candidate array `0x541778` (DWORD unit pointers, not bounds-checked here). Lurker hit history: `0x540768` holds 32 slots × 16 `{source, target}` pairs; the cursor is `0x541768` and the used count `0x54176c`. The bounce query context is `0x53db80/84/88` (source / current / previous target). The launch-spin memory is `0x540760` (last spawner) and `0x540764` (spin sign).

## Entries

### 0x004060c3 `DrawGrpTextureMaskMirrored` — mirrored mask copy of the warp texture through a main frame
- Module: <start>..bnetgw.cpp · Relevance: render
- Status: covered
- Signature: ECX = x, EDX = y, stack `[frame header*, crop*, texture buffer*]`, `ret 0xc`.
- Behavior: Walks the main frame's RLE lines of the crop in mirrored order. The destination starts at `row(y) + x + crop.width` and moves left, with pre-decrement writes and a per-row advance of `stride + width`. It first skips `frameWidth − crop.width − crop.left` source pixels, splitting a packet that crosses the boundary. For each pixel of an opaque packet (literal or repeat alike), it writes the next byte of the texture cursor `0x501142` (initialized from the stack argument). The main frame's colors are ignored. Transparent packets advance the destination and the texture cursor by the same count without writing. The cursor is never reset per row. Skipped (cropped) source pixels do not advance it.
  - Split transparent packet (quirk, unlike every other kernel in this package and unlike the normal counterpart `0x405f64`): when a transparent packet of length `L` crosses the skip boundary with `r` pixels inside the crop, the code at `0x406193` first advances the destination by `r` and reduces the remaining width by `r`, then jumps into the ordinary transparent handler at `0x4061fb` with the full length `L`. The destination therefore advances by `r + min(L, width − r)`, the remaining width drops by `r + L`, and the texture cursor advances by `min(L, width − r)` instead of `r`. Later opaque pixels of that row land shifted, and the row may end early. Opaque packets that cross the boundary are split correctly (`r` pixels drawn). The linked specification does not describe this case.
- Globals/fields: `0x6d0c40`, scratch `0x501121..0x501142`.
- Callers/callees: method-12 mirrored wrapper `0x40e880`, after it has drawn texture frame `0x543a40[param]` into scratch `0x59c2b0`. The normal counterpart is `0x405f64` (outside this package).
- Prior evidence: [pixel effects](../native-pixel-effects.md) (warp texture, 126 complete cases).

### 0x004074a0 `AssignDefaultComputerPlayerNames` — give computer/rescue/neutral slots their race-and-color names

### 0x00408300 `IsInvalidFileName` — reject file names with forbidden characters or DOS device names
- Module: <start>..bnetgw.cpp · Relevance: platform
- Status: specified
- Signature: ECX = name, EDX = buffer length limit, stack `[allowPath]`, `ret 4`. Returns 1 = **invalid**, 0 = valid.
- Behavior:
  1. `0x476e20(name, limit, limit, 0, 0)` returns 0 when the string is not terminated within `limit` bytes or contains any byte 0x01–0x1f. In that case the function returns 1.

  8. Otherwise it returns 0.
- Globals/fields: `0x5025b8` reserved-name table.
- Callers/callees: profile creation `0x40d7c0`, save/load UI `0x441150`, `0x45a320`, `0x472f50`, `0x498d20`, `0x49b120`.

     - 0/1: miss test; on a miss the offset is subtracted (WORD) from the point `+0x58/+0x5a` and `+0x62 |= 1`. Then the move target is set to the point (`0x40cca0`).
     - 7: set `+0x63` = 3, then as 0/1.
     - 2/4: miss test that shifts the sprite (`0x40cd80(sprite − offset)`) and sets flag 1.
     - 3: place the sprite at the point (`0x40cd80`).
     - 5: nothing.
     - 6: source status `|= 0x80000000`, then `0x425700(source)` (`+0x93 |= 4`, issue Death).
     - 8: ring index `i` = low byte of spawner word `+0x130`, stored in `+0x6c`. The point is reduced by `ring[i]` (WORD) and becomes the move target. The spawner word becomes `i+1`, or 0 when `ring[i+1].dx` = 0.
     - 9: offset `0x40c270(+0x21, (maxRange+20)<<8)`; point = spawner sprite + (offset >> 8); it becomes the move target.
  7. The miss test (only with both target and source nonnull) is: `(rand15(source 1) & 255) ≤ 0x41fd10(src, tgt)`. On a miss, the offset is `0x40c270(heading, 30)`, using the heading argument, not `+0x21`. Without a target or a source there is no RNG call and no miss.
