# P42: Creep engine, CHK chunk reader, TBL loaders and the dialog/control framework

This package covers `0x4bfea0`–`0x4c4bc0` (140 functions). It starts with the last SHA-1 routine of the game run and then enters the engine library run (`creep.cpp` … `dlg.cpp..timer.cpp`). Its pieces are:

1. **SHA-1 update** (`0x4bfea0`), the companion of `Sha1Init`/`Sha1Final`/`Sha1Transform` in [P41](p41.md).
2. **Creep engine** (`0x4bff60`–`0x4c0e60`). A self-contained tile engine that owns the creep tile words of MTXM, a per-tile backup of the replaced tile word, a per-tile border-overlay byte, the creep border GRP and the neighbor-shape tables. Game code reaches it through four callbacks installed at map load. [Trigger creep](../native-trigger-creep.md) already executed most of its geometry; this package documents the callback protocol, the tile mutators and the rendering hook.
3. **CHK chunk reader** (`0x4c1020`–`0x4c12e0`), the `.cnd` ladder-certificate scan (`0x4c1350`) and two TBL helpers (`0x4c13b0`–`0x4c1400`).
4. **Control framework** (`0x4c1470`–`0x4c2a00`, `ctrl.cpp`): the default interact procedures of dialogs and static/image controls, focus, hover, hotkeys, keyboard navigation, show/hide/enable/disable, hit testing.
5. **Dialog framework** (`0x4c2a30`–`0x4c4bc0`, `dlg.cpp`): dialog initialization, the topmost-first dialog list, the event dispatcher with per-event capture and hotkey press timers, the modal loop, deferred destruction, UI themes (GRP plus metrics), the draw procedures of every built-in control type, frame/tiled-art blitters and screen invalidation.

## Creep engine data model

The engine is initialized by `InitCreepEngine` `0x4c0690`, called from the map loader `0x445a30` with the MTXM array `0x666458`, the map size in tiles and the file `Tileset\<era>.grp`.

| Global | Meaning |
|---|---|
| `0x6ca7a0` | MTXM tile words (u16 per tile, row-major, `w·y + x`). A tile is **creep** when `(word & 0x7ff0) == 0x10` (CV5 group 1). |
| `0x6ca7a4` | Backup map, u16 per tile: the tile word that creep replaced (0 = none). Allocated zeroed. Saved and loaded by `0x498d20`/`0x499890` through `0x4c0320`. |
| `0x6ca7a8` | Border map, u8 per tile: border-overlay frame + 1 for a non-creep tile next to creep (0 = none). Saved/loaded through `0x4c02f0`. |
| `0x6ca7ac`, `0x6ca7b0` | Map width and height in tiles (s32). |
| `0x6ca7b4` | Creep border GRP (frame data offsets already converted to pointers). |
| `0x6ca7b8` | Callback 0 "tile changed": `(x, y, mode, new MTXM word, &pixel rect)`; game: `0x4b4040`. |
| `0x6ca7bc` | Callback 1 "is creep for borders": `(x, y)`; game: `0x4b45f0` (tile flag `0x40000000`, creep shown in the display tile). Null → MTXM group test. |
| `0x6ca7c0` | Callback 2 "defer border refresh": `(x, y)`, nonzero skips the border recomputation; game: `0x4b4560` (tile not visible to the local player, see [P39](p39.md)). |
| `0x6ca7c4` | Callback 3 "change record": receives a pointer to a 24-byte before/after record (layout in `0x4c0ca0`); null in the game. |
| `0x6ca7c8` | Shape table, 512 bytes (index = neighbor mask). |
| `0x6ca9c8` | Shape rank table, 128 bytes. |
| `0x6caa48` | Tables-built flag (set once per process). |
| `0x6caa50` | Spread candidates: 8 buckets × 240 entries × `{s32 x, s32 y}`. |

**Neighbor table** `0x4f0fd8` (9 pairs of s32 `dx, dy`): index 0 `(+1,+1)` SE, 1 `(0,+1)` S, 2 `(−1,+1)` SW, 3 `(+1,0)` E, 4 `(−1,0)` W, 5 `(+1,−1)` NE, 6 `(0,−1)` N, 7 `(−1,−1)` NW, 8 `(0,0)` the tile itself.

**Tile mutation protocol.** Every change goes through `ApplyCreepTileChange` `0x4c0ca0`(x, y, mutator, arg). The mutator is a stdcall with five arguments (backup word pointer, border byte pointer, pointer to a mode slot, MTXM word pointer, arg) and returns nonzero when it changed the tile. Three mutators exist: add creep `0x4c0c40` (mode 0), remove creep `0x4c0bc0` (mode 1) and set border `0x4c0d90` (mode 2). After a change, callback 3 (if any) and callback 0 run. In the game callback 0 (`0x4b4040`) sets the display-tile redraw bit for mode 2; for modes 0/1 it copies the new megatile into the display map unless the tile is hidden from the local player, and sets (mode 0) or clears (mode 1) tile flag `0x40000000`.

**Border shapes.** For a non-creep tile, mask bit `i` is set when neighbor `i` (0–7) is creep (callback 1). The border byte becomes `rank[shape[mask]]`. Shape table rule for index `u` (0–511): if `u & 0x100`, 0x7f; otherwise start at 0 and OR: `9` if bit 4 (W), `0x24` if bit 3 (E), `2` if bit 6 (N), `0x10` if bit 1 (S), `1` if bits 6 and 7, `4` if bits 5 and 6, `8` if bits 1 and 2, `0x20` if bits 0 and 1; finally OR `0x40` if (`b & 0x21`) = 0x21 or (`b & 0xc`) = 0xc. The rank table numbers the shape values that occur anywhere in the 512-byte table in increasing value order. The resulting 38 shapes and ranks are: 0→0, 2→1, 3→2, 6→3, 7→4, 9→5, 11→6, 16→7, 18→8, 19→9, 22→10, 23→11, 24→12, 25→13, 26→14, 27→15, 36→16, 38→17, 48→18, 50→19, 52→20, 54→21, 56→22, 58→23, 79→24, 94→25, 95→26, 103→27, 109→28, 111→29, 115→30, 119→31, 121→32, 123→33, 124→34, 125→35, 126→36, 127→37. Every other rank byte is 0. A border byte `v` ≠ 0 draws frame `v − 1` of the creep GRP.

**Provider area.** "Large" area types: Lair 132, Hive 133, Spore Colony 144, Sunken Colony 146 always; Hatchery 131 and Creep Colony 143 only when completed. Their area is ±320 by ±200 pixels around the center, with the ellipse `dx²·100 + dy²·256 ≤ 10,240,000` (signed 32-bit, wrapping) measured from tile centers `(32·x + 16, 32·y + 16)`. Other types use their placement footprint `0x522728` (s16 width, s16 height). Details and probes: [trigger creep](../native-trigger-creep.md#providers-bounds-and-owner-independent-retention).

## Control and dialog data model

Control/dialog fields are those of [P19](p19.md) with these additions used here: `+0x1c` u16 unused here, `+0x1e` u16 show delay in milliseconds (counted down in 100 ms steps), `+0x24` u16 `wUser` (base art frame for buttons and check boxes), `+0x26` u32 user value, `+0x36` (dialog) 8-byte off-screen bitmap descriptor `{s16 w, s16 h, ptr}`, (option/check box) u8 checked state, `+0x3e` (dialog) focused ("active") control, `+0x42` (dialog) first child, `+0x46` (dialog) hover control, `+0x4a` (dialog) modal idle callback. Lists `0x6ce6d8` (open dialogs) and `0x6ce6d4` (dialogs waiting for destruction) are singly linked through `+0x00` with push-to-front insertion (`0x4cab80`) and unlink-by-search (`0x4cac30`, returns the node or 0). The head of `0x6ce6d8` is the topmost dialog.

**Flags `+0x18`** as used in this package: `0x1` dirty (pending repaint), `0x2` disabled, `0x4` owns the BIN buffer (set on the root by the loader; destroying the root frees it), `0x8` visible, `0x10` accepts events, `0x20` bitmap is shared (not freed), `0x40` cancel button, `0x80` hover, `0x100` virtual-key hotkey, `0x200` character hotkey, `0x400`/`0x800`/`0x4000` font size, `0x1000` focus highlight, `0x2000` transparent, `0x10000` text without letter spacing, `0x20000` plain (no frame art), `0x40000` translucent, `0x80000` default (Enter) button, `0x04000000` dialog being initialized, `0x10000000` controls: art on the right side; dialogs: also mark the screen dirty grid on invalidation, `0x20000000` dialog: no focus tracking; button: three-part tiled art, `0x40000000` dialog: active; control: pressed, `0x80000000` dialog: consumes unhandled events (modal).

**Events** (20 bytes): `+0x00` u32 user code, `+0x04` u32 parameter, `+0x08` u16 key (virtual key or character), `+0x0a` u16 key flags, `+0x0c` u16 event type, `+0x0e`/`+0x10` s16 cursor x/y (absolute). Event types: 0 key down, 1 key repeat, 2 key up, 3 mouse move, 4 left down, 5 left up, 6 left double, 7 right down, 8 right up, 9 right double, 10–12 middle button, 13 idle, 14 user, 15 character, 16 command (WM_COMMAND, sent straight to the registered handler `0x665e30`), 17 wheel up, 18 wheel down (window procedure `0x43f600`, [P13](p13.md)). A user event synthesized by the framework has type 14, the cursor copied from `0x6d3154`/`0x6d3158`, parameter 0 unless stated, and bytes `+0x08..+0x0b` left uninitialized. User codes as handled here: 0 create, 1 destroy, 2 close (dialog), 3 activate (press), 4 hit test, 5 focus request, 6 focus lost, 7 re-centre ([P21](p21.md)), 8 timer tick (parameter = timer ID), 9 mouse enter, 10 post-load initialization, 11 value changed, 13 show, 14 hide.

**Eligible control**: visible (`0x8`), not disabled (`0x2`), ID ≠ `0xffff`, and either ID bit 15 set or flag `0x10` (`0x4c2400`). Several loops use the shorter test "not disabled, visible and `0x10`" (or `(flags & 0x1a) == 0x18`); entries say which.

**Global state:** `0x6ce654` last control found by a search, `0x6ce658` number of initialized dialogs, `0x6ce65c` u16 last binding array size / 4, `0x6ce660` dialog list changed, `0x6ce664` control sound hook, `0x6ce668[19]` per-event-type capture control, `0x6ce6b4 + 8k` (k = 0–3) hotkey press slots `{u32 deadline, control}`, `0x6ce6dc` modal result, `0x6ce6e0` theme GRP, `0x6ce6e4` modal idle hook, `0x6ce6ec…0x6ce760` theme metrics (set by `0x4c31d0`), `0x6ce76c`/`0x6ce770` s16 line pen x/y, `0x6ce784` Storm invalid region.

**UI themes.** A theme node is 0x14c bytes in the Storm list at `0x50ef38` (link offset 0, terminator `0x50ef3c`/`0x50ef40`; count `0x6ce768`): `+0x08` file name, `+0x10c` GRP, `+0x110…+0x14a` frame metrics (listed at `0x4c2ca0`).

**Screen layers** ([P06](p06.md), [P13](p13.md)): 20-byte records from `0x6d0b90`; layer 0 cursor, layer 1 tooltip, layer 2 (`0x6d0bb8`) dialogs, painted by `0x4c4d90`.

## Entries

### 0x004bfea0 `Sha1Update`
- Module: victory.cpp..creep.cpp · Relevance: data
- Status: library
- Signature: fastcall, ECX = SHA-1 context, EDX = data, stack `[length]`; `ret 4`.
- Behavior: Standard SHA-1 update. Index = (bit count low `+0x14` >> 3) & 63. It adds `8·length` to the 64-bit bit count (`+0x14` low, `+0x18` high; carry when the new low value is below `8·length`, plus `length >> 29`). If index + length ≥ 64 it fills the 64-byte buffer `+0x1c` to 64, transforms it (`Sha1Transform` `0x4bec30`), then transforms each further full 64-byte block **in place in the caller's data** (the transform writes into the block it processes, starting with the byte-swapped words, so the caller's buffer is modified), and buffers the remainder at offset 0. Otherwise it appends to the buffer.
- Callers/callees: `0x461b80` (ladder report), `0x49d370` ([P34](p34.md)), `Sha1Final` `0x4beaa0`.

### 0x004bff60 `BuildCreepShapeTable`
- Module: victory.cpp..creep.cpp · Relevance: render
- Status: covered
- Signature: no arguments, no return.
- Behavior: Zeroes `0x6ca7c8[512]` and fills it with the shape rule in the data model above (index ≥ 256 → 0x7f).
- Prior evidence: [trigger creep](../native-trigger-creep.md#original-border-lookup-and-ranked-spread) (every byte compared). The resolved contents are listed in the data model.

### 0x004c0010 `BuildCreepShapeRanks`
- Module: victory.cpp..creep.cpp · Relevance: render
- Status: covered
- Signature: no arguments, no return.
- Behavior: Zeroes `0x6ca9c8[128]`. For v = 0…127 ascending, if any of the 512 shape bytes equals v, `rank[v]` = running counter (u8), then the counter increments. 38 shapes receive ranks 0–37.
- Prior evidence: [trigger creep](../native-trigger-creep.md#original-border-lookup-and-ranked-spread).

### 0x004c0060 `CountCreepNeighbors`
- Module: victory.cpp..creep.cpp · Relevance: simulation
- Status: covered
- Signature: fastcall, ECX = tile x, EDX = tile y; returns the count (0–8) in EAX.
- Behavior: Counts the eight neighbors (not the tile itself) whose MTXM word is group 1. Bounds use unsigned compares against the map size, so x − 1 or y − 1 below zero counts as outside.
- Callers/callees: receding allocation `0x4b3f30`, `0x4b4230`, spread `0x4c0e60`.
- Prior evidence: [trigger creep](../native-trigger-creep.md#receding-pool-and-old-area-updates).

### 0x004c0250 `QueryCreepSustainArea`
- Module: victory.cpp..creep.cpp · Relevance: simulation
- Status: specified
- Signature: fastcall, ECX = tile x, EDX = tile y, stack `[callback]`; `ret 4`; returns the callback's result.
- Behavior: Builds the pixel rectangle around the tile centre ±640 horizontally and ±400 vertically: left `32x − 624`, top `32y − 384`, right `32x + 656`, bottom `32y + 416`. Clipping per axis: if left < 0 then left = 0, **else if** right ≥ 32·width then right = 32·width − 1; the same for top/bottom with the height. It then calls `callback(x, y, &rect)` (stdcall, three arguments). The game callback `0x4b4170` runs the spatial query for a grounded Zerg building that sustains the tile (`0x4c0830`).
- Callers/callees: `0x4b46e0`, `0x4b47f0`, `0x4c0960`.
- Prior evidence: [trigger creep](../native-trigger-creep.md#providers-bounds-and-owner-independent-retention) (query and its results).

### 0x004c03b0 `DrawCreepBorderTile`
- Module: victory.cpp..creep.cpp · Relevance: render
- Status: specified
- Signature: fastcall, ECX = tile x, EDX = tile y, stack `[terrain-cache offset]`; `ret 4`.
- Behavior: Reads border byte `v = 0x6ca7a8[w·y + x]` (no bounds check). - Callers/callees: tile renderer `0x40ac20` ([P03](p03.md)), only for megatiles whose display word has bit `0x8000`.

### 0x004c03f0 `ForEachCreepNeighbor`
- Module: victory.cpp..creep.cpp · Relevance: simulation
- Status: specified
- Signature: fastcall, ECX = tile x, EDX = tile y, stack `[callback, arg]`; `ret 8`; returns an index 0–9.
- Behavior: For i = 0…8 in table order (`0x4f0fd8`): `nx = x + dx[i]`, `ny = y + dy[i]`; skips tiles outside `0 ≤ nx < width`, `0 ≤ ny < height` (signed). Otherwise calls `callback(i, &MTXM[nx, ny], nx, ny, arg)` (stdcall, five arguments). Returns the first i whose callback returned 0, or 9.
- Callers/callees: `0x4c0470`, `0x4c0960`, `0x4c0aa0`, `0x4c0ba0`, `0x4c0c00`, `0x4c0dc0`, `0x4c0e60`.

### 0x004c0470 `RefreshCreepBorderAt`
- Module: victory.cpp..creep.cpp · Relevance: render
- Status: specified
- Signature: neighbor callback (stdcall: index, MTXM pointer, x, y, arg); `ret 0x14`; always returns 1.
- Behavior: Tests whether tile (x, y) is creep (callback 1 if installed, else the MTXM group test). If it is **not** creep: mask = 0; `ForEachCreepNeighbor(x, y, 0x4c0e00, &mask)` sets bit i for every creep neighbor i (bit 8, the tile itself, is lost because the shift happens in a byte); then `ApplyCreepTileChange(x, y, 0x4c0d90, mask)` stores the border byte. Creep tiles keep their border byte unchanged.

### 0x004c0690 `InitCreepEngine`
