# P30: Local path geometry, terrain contours and the pathing save block

This package covers `0x488910`–`0x48cb90` (42 functions). It contains three objects: the tail of the local-search geometry code between `sai_banker.cpp` and `sai_contourscreate.cpp`, `sai_contourscreate.cpp` itself, and the start of the object before `sai_loadsave.cpp`. The functions form five groups.

1. **Local search geometry** (`0x488910`–`0x48a7a0`). The local path search `0x491f50` keeps a context at `0x69d930` (layout below). Before each node expansion `0x491ba0` resets it, `0x488320` ([P29](p29.md)) builds the expansion box and collects nearby terrain edges (`0x488600`, P29) and unit edges (`0x488910`) into four sorted local edge arrays, and `0x48a750` runs up to four quadrant generators. Each generator walks out from the node to the box limits or the first blocking edge, emits candidate neighbor points through `0x488220` (P29), and records the swept rectangle as a visited area. The generators are equivalent, branch for branch, to the four cases of OpenBW's `add_neighbors`. [Local paths](../native-local-paths.md) executes this chain in complete original calls (with no unit blockers).
2. **Edge queries and extents** (`0x488df0`–`0x489320`, `0x48b720`, `0x48c300`–`0x48c5e0`). Extent setup, import of the global contour arrays, a sorted insert with merging, binary searches and nearest-edge finders.
3. **Terrain contour creation** (`0x48a7f0`–`0x48b600`). Map start builds the 1024 × 1024 walk grid, traces every blocked boundary into four direction arrays of 8-byte edges, sorts them and frees the grid. Covered by [contours](../native-contours.md) and [region generation](../native-region-generation.md).
4. **Footprint, sweep and clipping** (`0x48b780`–`0x48bec0`, `0x48c6d0`). Point fit, safe-rectangle contraction and the directional sweep on the global contours. Covered by [contour fit](../native-contour-fit.md) and [terrain sweep](../native-terrain-sweep.md). Also a Cohen–Sutherland segment clipper.
5. **Pathing save** (`0x48c6c0`–`0x48cb90`). Converts the pointers of the pathing structure to indices, writes it, the contours and the path-node pool into the save buffer, then restores the pointers.

## Data model

**Edge record** (8 bytes, all arrays): `+0` axis, `+2` start, `+4` end (signed WORDs), `+6` direction (0 top, 1 right, 2 bottom, 3 left), `+7` info. Info bits 0–1 select the extent added to start, bits 2–3 the extent added to end, bit 4 and bit 5 are the two corner modes ([contours](../native-contours.md)). "Inner-expanded" means axis + I[dir], start + I[info & 3], end + I[(info >> 2) & 3]. "Outer-expanded" uses O in the same way.

**Contour context** (0x38 bytes). One instance is the global contour structure `*(*0x69b584 + 0x97a1c)`. The local search context `0x69d930` begins with the same header.

| Offset | Meaning |
|---|---|
| `+0x00..+0x0c` | four edge-array pointers (top, right, bottom, left) |
| `+0x10..+0x16` | four WORD counts |
| `+0x18..+0x1e` | four WORD capacities (global structure only) |
| `+0x20..+0x26` | inner extents I = [up, −right, −down, left] |
| `+0x28..+0x2e` | WORDs [1, −1, −1, 1] (written and copied; not read in this package) |
| `+0x30..+0x36` | outer extents O = [up + 1, −right − 1, −down − 1, left + 1] |

**Local search context** `0x69d930` (0x12d8 bytes), after the header:

| Offset | Meaning |
|---|---|
| `+0x38/+0x3a` | node position px, py |
| `+0x3c` | searching unit |
| `+0x40` | goal point (packed; `0x83008300` = none) |
| `+0x44` | target unit or 0 |
| `+0x48..+0x4e` | target unit box left, top, right, bottom (`0x8300` each when none) |
| `+0x50..+0x5c` | nearest blocking edge per direction (top, right, bottom, left) or null |
| `+0x60/+0x62` | box minimum x, y · `+0x64/+0x66` box maximum x, y |
| `+0x68..+0x6f` | zeroed by `0x488ee0`, never read |
| `+0x70` | neighbor count (WORD) · `+0x72` goal-found byte · `+0x73` quadrant mask byte |
| `+0x74` | 32 neighbor records {x WORD, y WORD, flags byte, is-goal byte, 2 unused} |
| `+0x174..+0x180` | saved global edge-array pointers · `+0x184..+0x18a` saved counts |
| `+0x18c` | visited-area count (WORD) · `+0x190` visited areas, 8 bytes {x0, y0, x1, y1}, room for 40 |
| `+0x2d0..+0x2d6` | local edge counts · `+0x2d8/+0x6d8/+0xad8/+0xed8` local edge arrays, 128 records each |

Neighbor insertion `0x488220` (P29) takes ECX = context and stack [x, y, flags, tag]; the tag is never read (the generators pass 0x0b, 0x0c, 0x15, 0x16, 0x1f, 0x20, 0x29, 0x2a). It ignores the node position itself. A point equal to the goal point, or on the target-unit box perimeter when `+0x44` ≠ 0, is a goal: flags 0xff, is-goal 1, `+0x72` = 1, appended without a duplicate check. Otherwise an existing record with the same position gets `flags &= new`, else the point is appended. Nothing is added once the count reaches 32.

**Unit finder.** `0x5c99b0` count (signed WORD), X-sorted array `0x5c99b8` and Y-sorted array `0x5d03f8` of {DWORD unit index (1-based into the unit table returned by `0x4255f0`, stride 0x150), DWORD coordinate}. CUnit `+0x13c/+0x140` hold the unit's left/right entry indices in the X array, `+0x144/+0x148` its top/bottom entry indices in the Y array.

**Pathing structure** `*0x69b584` (0x97a20 bytes, BWAPI `SAI_Paths`): `+0` region count WORD, `+4` pointer into the WORD neighbor pool at `+0x92bfc`, `+8` end pointer of the 6-byte split-tile array at `+0x2000c`, regions at `+0x449fc` (64 bytes; `+0xc` neighbor-list pointer, inline list at `+0x2c`), `+0x97a1c` contour structure pointer. Path nodes: pool pointer `0x69b574` (the pool `*0x69b574` holds 1024 × 128 bytes), free-list head `0x69b570`.

**Contour-creation tables** (`0x48a7f0`):

| Table | Contents |
|---|---|
| `0x508ee8[16]` first blocked direction of a nibble | −1, 0, 1, 0, 2, 0, 1, 0, 3, 0, 1, 0, 2, 0, 1, 0 |
| `0x508ef8[16]` start mode | −1, then 1 except 0 for nibbles 9, 11, 13, 15 (top and left both set) |
| `0x508f08[8]` start offset {dx, dy} by d + 4·mode | (−1,−1) (8,−1) (8,8) (−1,8) (0,−1) (8,0) (7,8) (−1,7) |
| `0x508f28[8]` end offset {dx, dy} by d + 4·next | (8,−1) (8,8) (−1,8) (−1,−1) (7,−1) (8,7) (0,8) (−1,0) |
| `0x508f48[4]` grid step (WORD) | −1024, 1, 1024, −1 |
| `0x508f50[4]` cell step {dx, dy} | (0,−1) (1,0) (0,1) (−1,0) |
| `0x508f58[4]` diagonal step {dx, dy} | (1,−1) (1,1) (−1,1) (−1,−1) |

Walk-grid globals: `0x69b55c` grid pointer, `0x5264b4/0x5264b6` map width/height in tiles (WORD), `0x54323c` map megatile-ID array, `0x666448` VF4 record count, `0x66644c` VF4 data.

## Functions

### 0x00488910 `AddLocalUnitEdges` — collect blocking unit boxes as local edges
- Module: sai_banker.cpp..sai_contourscreate.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = local search context.
- Behavior: Runs four scans of the unit finder. Each uses `0x419500(array, start, 1)` (first coordinate ≥ start) and walks forward while the coordinate is within the bound. An entry counts only if it is the edge the unit owns on that side. Its edge record is then checked against the box, then the unit must be the target unit (`+0x44`) or pass `0x42e490(unit, EDX = searching unit +0x3c)`. Qualifying edges go through `0x488f00` into the local array. The cursor is reset to the array base before every insert (it does not carry over between inserts, unlike in `0x488600`), while the end pointer starts at base + current count × 8 and carries over. At the end the count WORD is rewritten from the end pointer.

  | Dir | Finder | Start | Continue while | Owner index | Record (axis, start, end, info) | Box test |
  |---|---|---|---|---|---|---|
  | 0 top | Y | min.y − I0 − 1 | coord < py − I0 | `+0x148` | bottom, left, right, 0x3d | I1 + left ≤ max.x and min.x ≤ I3 + right |
  | 1 right | X | px − I1 | coord ≤ max.x − I1 + 1 | `+0x13c` | left, top, bottom, 0x32 | I2 + top ≤ max.y and min.y ≤ I0 + bottom |
  | 2 bottom | Y | py − I2 | coord ≤ max.y − I2 + 1 | `+0x144` | top, left, right, 0x3d | as top |
  | 3 left | X | min.x − I3 − 1 | coord < px − I3 | `+0x140` | right, top, bottom, 0x32 | as right |

  Coordinates come from the finder entries: the axis is the scanned entry, and start/end are read from the other array at the unit's stored indices. All comparisons are signed 16-bit except the loop bound, which is 32-bit after sign extension. There is no capacity check for the 128-record arrays.
- Callers/callees: `0x488320` (after terrain edges `0x488600`).

### 0x00488f00 `InsertLocalEdge` — sorted insert with merge
- Module: sai_banker.cpp..sai_contourscreate.cpp · Relevance: simulation
- Status: specified
- Signature: `__thiscall`, ECX = context, stack = [record*, &cursor, &end]; `ret 0xc`.
- Behavior: Scans from `*cursor` toward `*end` for the first entry e with e.axis > r.axis, or e.axis = r.axis and inner-expanded e.end ≥ inner-expanded r.start (all signed). If e has the same axis and inner-expanded e.start − 1 ≤ inner-expanded r.end (the check e.end + 1 ≥ r.start is implied), the record is merged: e.start = min(e.start, r.start), e.end = max(e.end, r.end) on raw values, `*cursor` = e, and the count is unchanged. Otherwise the entries from e to the end move up 8 bytes and r is copied to e, or appended when no stop entry exists. `*cursor` = the inserted slot and `*end` += 8. No capacity check. Because the cursor carries over, callers must insert in ascending order.
- Callers/callees: `0x488600`, `0x488910`.

### Quadrant generators: common rules

All four (`0x489880`, `0x48a240`, `0x489d50`, `0x489360`) take `__fastcall` ECX = local context and return 0 in practice. Each has two phases. Phase A moves horizontally from the node and may move py to the reached edge. Phase B moves vertically from the updated py. Notation: (px, py) = `+0x38/+0x3a`; lo, hi = box min/max; NE[d] = `+0x50 + 4d`; add(x, y, f) = `0x488220`; c = outer-expanded copy of the found record (`0x489320`); "inner axis" of a record = axis + I[dir]. FindTop/Right/Bottom/Left are `0x48c5e0`/`0x48c4e0`/`0x48c300`/`0x48c400`. Visit(a, b, X, Y) = normalize the rectangle of corners (a, b), (X, Y) (`0x48a7a0` or inline), then `0x489070`, then `0x4890e0`. All coordinates are signed 16-bit. Walking "next" or "previous" stops at the array bounds.

### 0x0048a7f0 `BuildTerrainContours` — trace the walk grid into four edge arrays
- Module: sai_contourscreate.cpp · Relevance: simulation
- Status: covered
- Signature: `__fastcall`, ECX = contour structure.
- Behavior: Geometry, info encoding, growth and sorting are specified in [contours](../native-contours.md). The full procedure:
  - Capacities (`+0x18..+0x1e`) are set to 5000. Allocation (SMemAlloc) gives 40000 bytes for array 0 and capacity × 8 for arrays 1–3. Each array is zeroed and the counts are cleared.
  - Loop over the cells returned by `0x48af50(grid = *0x69b55c)` (x, y). Let v = the cell byte, d = `0x508ee8[v & 15]` and m = `0x508ef8[v & 15]`. If d = 2, the start moves to (x − 1, y + 1) and d, m are read again from that cell. The start point is S = (8x, 8y) + `0x508f08[d + 4(m & 1)]`. Bit d of the cell is flipped.
  - Step loop (re-entered for every edge). Let n = (d + 1) & 3. Flip bit d of the current cell. For the first edge of a contour this second flip hits the start cell again, so its bit d is restored at that point. While the current cell lacks bit n: the neighbor at stride `0x508f48[n]` must have bit d, otherwise next = 1 and the walk stops. If it has bit d, move into it ((x, y) += `0x508f50[n]`), flip its bit d, and continue. When bit n is present, next = 0.
  - The end point is E = (8x, 8y) + `0x508f28[d + 4·next]`. If any count equals its capacity, `0x48b040` grows all four arrays. A record is appended to array d with dir byte d. The fields are top {S.y, S.x, E.x}, right {S.x, S.y, E.y}, bottom {S.y, E.x, S.x} and left {S.x, E.y, S.y}. The low six info bits follow the formula in the linked document, and the existing bits 6–7 are kept.
  - If next = 0, then d = n. If next = 1, (x, y) += `0x508f58[d]` and d = (d − 1) & 3. Then m = next and S = E. The trace ends when E equals the contour's start point, and bit d of the final cell is flipped.
  - The assertion "write me!" (`0x4cc190`) for a next value other than 0 or 1 is unreachable.
  - After the last contour the walk grid is freed (SMemFree; `0x69b55c` keeps the stale pointer). `0x48b600` shrinks the arrays, and each array is `qsort`ed (`0x4d4490`, 8-byte elements, comparator `0x48ad40`).
- Callers/callees: `0x48af10`.
- Prior evidence: [contours](../native-contours.md).

### 0x0048c6d0 `ClipSegmentToRect` — Cohen–Sutherland clipping
