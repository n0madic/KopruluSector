# P01: PKWARE DCL compression, crash reporter and hand-written terrain/GRP blitters

This package covers the code linked before the first named game object (`bnetgw.cpp`), `0x401000`–`0x4060c3`. It holds three unrelated library groups.

1. **PKWARE Data Compression Library 1.11** (`0x401000`–`0x40219b`). This is the stock implode/explode coder with its CRC-32. The copyright banner at `0x50e500` identifies it: "PKWARE Data Compression Library for Win32 … Version 1.11". `compress.cpp` (`0x4137d0`, `0x413940`, `0x413a40`, `0x413ab0`, `0x413ae0`) is the only user. Save-game and other chunked game state passes through it: data is cut into blocks of `0x2000` bytes and imploded with **binary mode (type 0) and a 1024-byte dictionary**. A block is stored raw when compression does not shrink it. A CRC-32 over the whole uncompressed buffer is checked after explode. The function bodies, work-structure offsets and every static table match the public StormLib `pklib` reconstruction (`implode.c`, `explode.c`, `crc32.c`). The atlas therefore marks them `library` and records the StormLib name of each. A remake can use any DCL-compatible implementation. It must keep the parameters above and the CRC convention described at `0x402160`.
2. **"crashy" crash reporter** (`0x4025d0`–`0x405990`). This is the Blizzard crash-report subsystem used by the engine's crash handlers in `vidblit.cpp..font.cpp` (`0x4cb910`, `0x4cbc00`, `0x4cbe00`, `0x4cc1a0`). Those handlers write `Crash.txt` and `Minidump.dmp` into `%TEMP%\BlizzardError\<date time>\` and launch `BlizzardError.exe`. This group covers exception-name formatting, the unhandled-exception filter, thread enumeration and EBP-chain stack walks, register dumps, the module list (psapi, Toolhelp or PEB), PE/CodeView parsing, DbgHelp symbol lookup, and a dedicated minidump worker thread. Only the setup runs in a normal session: at startup `0x4cc1a0` (called from `0x467e00`) runs `0x4049e0` through `0x402c90` (critical sections, two events and the worker thread `0x404870`, which names itself with `0x404120` and then blocks on its request event), records the application directory (`0x402ca0`) and installs the top-level filter (`0x402ab0`). Everything else runs only after an exception reaches the filter or an engine crash handler. None of it reads or writes game state, so it cannot affect offline campaign simulation or presentation, and every function is `excluded`.
3. **Hand-written assembly kernels** (`0x4059f0`–`0x4060c3`). These are register-convention routines with no C prologue conventions:
   - terrain ring-cache row copiers to the 640-pixel game screen (`0x4059f0`, `0x405a43`, `0x405aad`);
   - the 8×8 minitile blitter into the cache (`0x405af0`);
   - the creep-edge GRP blitter into the cache (`0x405d40`);
   - the placement-box checker stipple (`0x405c12`);
   - the two **approximate-distance** functions (`0x405c90`, and `0x405cf0`, which simulation and AI call from 55 sites);
   - the normal GRP RLE kernel (`0x405e1e`) and the warp-texture mask copy (`0x405f64`).

Between `0x405c6a` and `0x405c90` there are three 8–9-byte stubs: `0x405c70` (`rdtsc`, stores EDX:EAX to `[ECX]`), `0x405c78` (`cli`, then the same) and `0x405c81` (`rdtsc`, `sti`, then the same store). Only `0x405c70` is an atlas function; it was added late and is listed in the A01 package, not here. A full-image scan finds no call, jump or pointer to any of the three. They are timing helpers with no game effect.

## Shared data and tables

**Terrain ring cache.** Base pointer `0x543240`. Size `0x49800` bytes = 672×448 pixels, row stride `0x2a0`. Offsets are reduced mod `0x49800` by subtraction. The screen origin is (`0x543218` x, `0x54321c` y). Both are pixel values, multiples of 8 (see [P03](p03.md)), so the screen's cache offset is `(y*0x2a0 + x) mod 0x49800`. The VR4 minitile pixels are at `[0x543244]`: 64 bytes per minitile image. The creep-edge GRP header pointer is `[0x6ca7b4]`.

**Screen buffer.** `0x6d0b88` is a bitmap descriptor of the full game screen: WORD width/pitch `+0`, DWORD pixels at `0x6d0b8c`. The row copiers write with a fixed destination stride of `0x280` (640). Only `0x405aad` uses the descriptor pitch, and only for its starting row. A 640-wide screen buffer is therefore assumed.

**Current drawing descriptor** `0x6d0c40`: a pointer to {WORD width (stride), WORD height, DWORD pixels}, used by `0x405e1e` and `0x405f64`.

**Blitter scratch globals.** These DWORDs live in the writable data at `0x501000+`; the original kernels use them instead of stack locals:

| Address | Use |
| --- | --- |
| `0x501000` | row width in bytes for `0x4059f0` (initial value 0) |
| `0x501021` | 256-byte current color remap applied by `0x405e1e` (documented in [pixel blitters](../native-pixel-blitters.md)) |
| `0x501121` | frame payload base pointer (row-offset table base) |
| `0x501125` | destination row advance (stride − drawn width) |
| `0x501129` | crop left (pixels to skip per row) |
| `0x50112d` | crop/frame width |
| `0x501131` | rows remaining |
| `0x501139` | terrain-cache end pointer (`[0x543240] + 0x49800`) for `0x405d40` |
| `0x501142` | source cursor for the mask copy `0x405f64` |

**GRP frames.** A frame header is 8 bytes: x offset BYTE `+0`, y offset BYTE `+1`, width BYTE `+2`, height BYTE `+3`, and a DWORD payload pointer `+4` (absolute after load). The payload starts with one WORD offset per row, relative to the payload base. Each row is a packet stream: `b & 0x80` skips `b & 0x7f` pixels; else `b & 0x40` repeats the next byte `b & 0x3f` times; else the next `b` bytes are literal colors. See [pixel blitters](../native-pixel-blitters.md).

### 0x00401000 `implode` — PKWARE DCL compressor entry
- Module: <start>..bnetgw.cpp · Relevance: data
- Status: library
- Signature: cdecl `(read_buf, write_buf, work_buf, param, int *type, int *dsize)` → 0 ok, 1 invalid dictionary size, 2 invalid type.
- Behavior: StormLib `implode`. It stores the callbacks/param at work `+0x9b4/+0x9b8/+0x9b0`, the type at `+0x14` and the dictionary size at `+0x18`. It sets dsize_bits = 4/5/6 and mask 0xf/0x1f/0x3f for 1024/2048/4096. It builds the literal code tables: binary type 0 uses 9-bit codes `2*byte`; ASCII type 1 uses `ChBitsAsc`/`ChCodeAsc`. It adds the 16 length-code families, copies `DistBits`/`DistCode`, and runs `0x4011a0`. The `compress.cpp` caller always passes type 0 and dictionary 0x400.
- Callers/callees: `0x413940`; `0x4018f0`, `0x4011a0`.
- Prior evidence: none.

### 0x004011a0 `WriteCmpData` — implode main loop
- Module: <start>..bnetgw.cpp · Relevance: data · Status: library
- Signature: cdecl `(TCmpStruct *)`.
- Behavior: StormLib `WriteCmpData`. It reads input in 0x1000-byte chunks through the read callback into the sliding window `+0x29d0` and hashes pairs with `0x401a20`. For each position it finds the longest repeat with `0x401520`, using a one-byte lazy-match check. It emits literals or length/distance codes through `0x401860`, and finally the end code (`+0x3a1`/`+0x9ac`). It flushes through the write callback. Header bytes at `+0x1fca/+0x1fcb` are type and dsize_bits.
- Callers/callees: `0x401000`; `0x401520`, `0x401860`, `0x4018f0`, `0x401930`, `0x401a20`.
- Prior evidence: none.

### 0x00401520 `FindRep` — longest-match search
- Module: <start>..bnetgw.cpp · Relevance: data · Status: library
- Signature: cdecl `(TCmpStruct *, BYTE *input)` → match length (0 or 2..0x204); distance−1 stored at work `+0`.
- Behavior: StormLib `FindRep`. It walks the pair-hash position list (`+0xdc8` heads, `+0x49d0` positions) and extends matches up to 0x204 bytes. For matches over 10 bytes it uses a KMP-style skip table at `+0x9bc`.
- Callers/callees: `0x4011a0`.
- Prior evidence: none.

### 0x00401860 `OutputBits` — append bits to compressed output

### 0x00401ae0 `explode` — PKWARE DCL decompressor entry
- Module: <start>..bnetgw.cpp · Relevance: data · Status: library
- Signature: cdecl `(read_buf, write_buf, work_buf, param)` → 0 ok, 1 bad dictionary bits (not 4..6), 2 bad type (not 0/1), 3 fewer than 5 input bytes, 4 abort/corrupt (Expand returned 0x306).
- Behavior: StormLib `explode`. It reads up to 0x800 bytes into `+0x2234`. Header byte 0 is type and byte 1 is dsize_bits; the bit buffer starts with byte 2. For ASCII it builds `ChBitsAsc` decode tables via `0x402060`. It builds the length and distance decode tables via `0x402020` and runs `0x401c60`.
- Callers/callees: `0x413a40` (work buffer 0x3134 bytes; output block at most 0x2000); `0x4018f0`, `0x401c60`, `0x402020`, `0x402060`.
- Prior evidence: none.

### 0x00401c60 `Expand` — explode main loop
- Module: <start>..bnetgw.cpp · Relevance: data · Status: library
- Signature: cdecl `(TDcmpStruct *)` → last decoded value (0x305 end, 0x306 error).
- Behavior: StormLib `Expand`. It decodes literals and copies into window `+0x30` (output position starts at 0x1000). It copies matches byte by byte, so overlaps are allowed. Each time the position reaches 0x2000 it writes 0x1000 bytes and slides the window. At the end it flushes the remainder.
- Callers/callees: `0x401ae0`; `0x401d60`, `0x401f10`, `0x4018f0`.
- Prior evidence: none.

### 0x00401d60 `DecodeLit` — decode a literal or length
- Module: <start>..bnetgw.cpp · Relevance: data · Status: library
- Signature: cdecl `(TDcmpStruct *)` → 0..0xff literal byte; 0x100..0x304 a repeat whose length is value − 0xfe; 0x305 end of stream; 0x306 input exhausted/corrupt.
- Behavior: StormLib `DecodeLit`. Flag bit 1 means a length: it uses the `LengthCodes` table and extra bits (`ExLenBits`/`LenBase`), with the special end tolerance for value 0x10e. Flag bit 0 means a literal: 8 raw bits for binary, or the ASCII tables `+0x2c34/+0x2d34/+0x2e34/+0x2eb4` for ASCII.
- Callers/callees: `0x401c60`; `0x401f90`.
- Prior evidence: none.

### 0x00402160 `crc32_pklib` — CRC-32 update
- Module: <start>..bnetgw.cpp · Relevance: data
- Status: library
- Signature: cdecl `(BYTE *buf, unsigned *size, unsigned *crc)` → updated CRC in EAX. `*crc` is read, not written.
- Behavior: For each byte: `crc = table[(crc ^ byte) & 0xff] ^ (crc >> 8)` with table `0x50eb28` (standard reflected CRC-32). There is no initial or final inversion inside: `compress.cpp` passes 0xffffffff as the start value and compares the raw result.
- Callers/callees: `0x4137d0`, `0x413ab0`, `0x413ae0`.
- Prior evidence: none.

### 0x00402a10 `CrashUnhandledExceptionFilter` — top-level SEH filter
- Module: <start>..bnetgw.cpp · Relevance: platform · Status: excluded (crash reporting only)

### 0x00402b00 `GetStackRegionBounds` — locate a thread stack
- Module: <start>..bnetgw.cpp · Relevance: platform · Status: excluded (crash reporting only)
- Signature: ECX = stack address, EDX = out top, stack out base, `ret 4` → bool.
- Behavior: `VirtualQuery` must report committed, private, read-write memory, and the region end (the top) must lie above the address. The base is the allocation base. ### 0x00405f64 `MaskCopyThroughFrame` — copy a source buffer through a frame's opaque pixels
- Module: <start>..bnetgw.cpp · Relevance: render
- Status: covered
- Signature: ECX = x, EDX = y, stack `[frame header, crop, source pointer]`, `ret 0xc`.
- Behavior: The same traversal, left skip and right clip as `0x405e1e`. Within the visible crop, each literal or repeat pixel writes the next source byte (the frame's own colors are ignored).
