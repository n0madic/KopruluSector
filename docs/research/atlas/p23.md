# P23: Scenario (CHK) loading, map archives, on-screen text lines and the fog-of-war overlay

This package covers `0x467e50`–`0x46c0cc`: the object `maphdr.cpp` and the start of the object between `maphdr.cpp` and `mask.cpp`. Its 90 functions fall into six groups.

1. **CHK section handlers** (`0x467e50`–`0x469320`, 30 functions). One callback per scenario section, reached only through the version descriptors below. Each copies or interprets one section into the game globals. In scope.
2. **UNIT-section helpers** (`0x469360`–`0x469600`, `0x469810`, `0x4698e0`, `0x46a180`–`0x46a320`, `0x46a420`). Unit creation from map records, start-location markers, Nydus/addon pairing lists and initial unit properties. In scope.
3. **Map files, archives and headers** (`0x469440`, `0x469560`–`0x469700`, `0x469970`–`0x469ed0`, `0x46a610`, `0x46a640`, `0x46b0b0`–`0x46b8d0`). Opening the map MPQ, locating `staredit\scenario.chk`, version validation, the header/game/briefing section groups, map defaults, save-game DAT override blocks and the current-map path. In scope; the `.cnd` ladder-marker probe and its signature check run only for non-campaign map files.
4. **Post-load and palette helpers** (`0x46a370`, `0x46a390`, `0x46a3b0`, `0x4697c0`). Unit visibility refresh and tileset color cycling. In scope.
5. **On-screen text lines** (`0x46a760`–`0x46b070`, 14 functions). The 11-line message area, the error line, chat formatting, trigger text, expiry and drawing. In scope (single-player shows trigger text, errors and cheat messages through it).
6. **Fog-of-war overlay and sight reveal** (`0x46b910`–`0x46c070`, 11 functions). Tile visibility reveal, the smoothed 8-pixel fog-level map and the screen darkening blitters, plus the vision cheats. In scope.

## Shared conventions

**Section callbacks.** Every handler is `__stdcall(chunk, length, header)` with `ret 0xc` and returns nonzero on success. `chunk` is the section node the CHK reader built; `length` is the section's byte length; `header` is the caller's 32-byte header record or 0. `0x4c12b0`(ECX = chunk, EDX = destination) copies the whole section payload (bounded by the buffer end; see [briefing loader](../native-briefing-loader.md#required-sections-and-duplicate-handling)). A zero return aborts the dispatcher `0x4c12e0` without undoing earlier writes. Storm thunks: `0x4d001c` `SMemAlloc`, `0x4d0022` `SMemFree`, `0x4d003a` `SMemZero`, `0x4d0076` `SErrSetLastError`, `0x4d0028` `SStrCopy`, `0x4d0040` `SStrLen`, `0x4d00a0` `SStrChrR`, `0x4d01f0` `SFileOpenArchive`, `0x4d01ea` `SFileCloseArchive`, `0x4d00ca` `SFileOpenFileEx`, `0x4d00b2` `SFileCloseFile`, `0x4d021a` `SFileLoadFileEx`, `0x4d0220` `SFileUnloadFile`, `0x4d005e` `SStrVPrintf`. CRT: `0x4d0c60` memset, `0x4d08a0` strrchr. Error code `0x57` is `ERROR_INVALID_PARAMETER`. Allocation file/line arguments use `"maphdr.cpp"` (`0x4eec10`).

**Header record (32 bytes, caller-owned).** `+0x00` SPRP (WORD scenario-name string, WORD description string), `+0x04` FORC (20 bytes), `+0x18` VER (WORD), `+0x1c` condition type DWORD written by the archive opener. `0x46b5c0` zeroes it before loading.

**`0x447db0`(ECX = 0)** is `IsUseMapSettings` (1 = UMS). Several handlers call it twice and ignore the second result.

**CHK version descriptors** `0x4eeb80` (3 × 40 bytes): `{u32 version, header table, count, briefing table, count, melee table, count, UMS table, count, u32 expansion required}`. Table rows are 12 bytes `{tag, callback, required}`. The resolved tables are:

Versions: 59 (`0x4eeb80`), 63 (`0x4eeba8`), 205 (`0x4eebd0`, expansion required). The table order matters: overrides precede `UNIT`, so preplaced units are created with the map's stats; in v59/v63 UMS, `UNIx`/`UPGx`/`TECx`/`PUPx`/`PTEx` overwrite `UNIS`/`UPGS`/`TECS`/`UPGR`/`PTEC` when present. The unlisted function `0x468a20` (the `TYPE` callback) is `mov eax, 1; ret 0xc`.

**Text-line state** (group 5). 13 lines of 218 (`0xda`) bytes at `0x66ff00`: lines 0–10 are the message ring, line 11 (`0x67085e`) an auxiliary line, line 12 (`0x670938`) the error line. Per line: expiry tick DWORD `0x670a14[13]`, color byte `0x670a48[13]`, flag byte `0x670a58[13]` (bit 0 = trigger text). `0x670a12` = next ring slot (the oldest line). `0x670a6c` = line height, `0x670a68` = line spacing (WORDs). Ring line at slot `i` is drawn in row `(i − next + 11) mod 11` at y = `0x70 + row × spacing`, x 10…630. Line 12 is at (10, `0x127`), line 11 at (420, 24) clipped at x 620. No code writes line 11 (only the reset memset and the readers reference `0x67085e`), so it stays empty. `0x4cac50`(ECX = left, EDX = top, stack [right, bottom]) marks 16 × 16 screen cells dirty.

**Fog state** (group 6). Tile flags DWORD array `[0x666454]`: bits 0–7 = "not visible to player i", bits 8–15 = "not explored by player i". Fog levels are 0 (black) … 31 (`0x671a80`, fully lit). Buffers allocated by `0x46c1e0` (P24): `0x670a78` raw 24 × 17 tile-level grid, `0x670a70` smoothed grid, `0x670a74` previous smoothed grid (408 bytes each), `0x670a7c` 88 × 60 byte level map at 8-pixel resolution (`0x14a0` bytes). `0x670a80` is a 32 × 32 DWORD horizontal-interpolation table. `0x66dd20` is the 32 × 256 darkening remap (row = level). Screen pixels at `[0x6d0b8c]` with stride 640; camera pixel position `0x543218`/`0x54321c`, camera tile `0x5264b0`/`0x5264b2`.

## Functions

### 0x00467e50 `LoadVcodSection` — verify the map's VCOD block
- Module: maphdr.cpp · Relevance: data
- Status: specified
- Signature: section callback (`ret 0xc`).
- Behavior: Finds the executable's own resource type `"VCOD"`, ID 202 (`FindResourceA(NULL, 0xca, "VCOD")`), takes its size, loads and locks it; any failure returns 0. `length` must equal the resource size, else 0. Allocates `length` bytes (line `0x494`; failure → 0) and copies the section into it (failure → free, line `0x497`, return 0). Computes `ComputeVcodHash` `0x464560`(ECX = section copy, EDX = length, stack [`0x673d48`, `0x1b0`]) and the same with ECX = the resource, frees the copy (line `0x49f`) and returns 1 iff both hashes are equal. The hashed data are the 12 × 36-byte map setup records `0x673d48`, which hold the `OWNR`/`SIDE` values loaded just before (header table order).
- Prior evidence: [ComputeVcodHash](p14.md) (opcode semantics).

### 0x00468f30 `LoadUnitSection` — `UNIT` preplaced units
- Module: maphdr.cpp · Relevance: simulation
- Status: specified
- Signature: section callback.
- Behavior: The [mission-units contract](../native-mission-units.md#ordered-section-processing-and-admission) gives the admission order. Complete sequence:
  1. `length` must be a multiple of 36, else 0. Allocate (line `0x391`; null → 0) and copy (failure → free line `0x394`, 0). Allocate a zero-filled 32-byte start-location buffer (flags 8, line `0x399`; null → free records, 0).
  2.   3. Copy the 32-byte start buffer to `0x534a00` (8 × {WORD x, WORD y}).
  4. Pair Nydus canals: repeat `head = 0x4698e0(head)` until null; then addons: `head = 0x469810(head)` until null.
  5. Free records (line `0x3eb`) and start buffer (line `0x3ec`), then for every unit of the active list `0x425600` (via `+4`) `UpdateUnitSpriteVisibility` `0x438c20`, then `MarkPowerDirty` `0x42ffc0`. Returns 1.

### 0x00469260 `LoadFogMaskSection` — `MASK`
- Module: maphdr.cpp · Relevance: simulation
- Status: specified
- Signature: section callback.
