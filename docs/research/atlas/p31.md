# P31: Pathing save data, computer-AI orders and lifecycle, path records and region generation

This package covers `0x48cbd0`–`0x4911e0` (73 functions): `sai_loadsave.cpp`, the AI-glue object between it and `sai_path.cpp`, `sai_path.cpp` and `sai_pathcreate.cpp`. The functions form six groups.

1. **Pathing save block** (`0x48cbd0`, `0x48e600`). Restores the region object, the collision-contour context and the 1024-record path pool from a saved game, then turns stored indices back into pointers.
2. **Computer-AI orders** (`0x48cd70`–`0x48d2e0`, `0x48de70`, `0x48dee0`, `0x48e180`). Order handlers for ComputerAI 156, AIPatrol 159, RescuePassive 161 and Neutral 162, the per-unit-type AI step called from ComputerAI, the burrow and siege decisions, and the chase-rejection predicate used by target acquisition.
3. **AI lifecycle and script helpers** (`0x48d320`, `0x48d380`, `0x48db70`–`0x48e170`). Completed-unit AI assignment, generic AI removal, AI initialization/free/save/load wrappers, the per-frame AI step and its timers, the script opcodes `player_enemy`, `player_ally`, `switch_rescue` and `move_dt`, and nearest-enemy queries.
4. **Reaction spells** (`0x48d3a0`, `0x48e580`, `0x48e5c0`). The AI spell-casting dispatcher, fully specified in [combat AI](../native-combat-ai.md).
5. **Path records and waypoints** (`0x48e690`–`0x48f000`). The 128-byte path record pool, packing and restoring search contexts, the waypoint consumer used by the movement state machine, and route-distance estimates.
6. **Region generation** (`0x48f060`–`0x4911e0`). Building the region object `*0x69b584` from map terrain: terrain classes, rectangles, expansion, merging, compaction, adjacency, connectivity groups, split cells and route-cut ranks. [Region generation](../native-region-generation.md) executed most of these routines; the entries below add the exact step order and the details the report leaves implicit.

## Data model

**Region object** `*0x69b584` (`0x97a20` bytes; layout in [region generation](../native-region-generation.md)): `+0` WORD region count, `+4` large-neighbor pool cursor, `+8` split-record end pointer, `+0xc` tile raster (256 × 256 WORDs, row stride 256), `+0x2000c` split records (6 bytes: mask, region for clear bits, region for set bits), `+0x449fc` regions (64 bytes each, maximum 5000), `+0x92bfc` large-neighbor WORD pool, `+0x97a1c` collision-contour context. Region record: `+0` class WORD (`0x1ff9` middle ground, `0x1ffa` high ground, `0x1ffb` other walkable, `0x1ffd` unwalkable, `0x1fff` unused; values below 5000 are region IDs only in the raster), `+2` group WORD (`0x4000` = reserved), `+4` tile count WORD, `+6` ground-neighbor prefix count, `+7` total neighbor count, `+8` path-search backreference, `+0xc` neighbor-ID pointer, `+0x10/+0x14` center (8.8 fixed; tile units during generation), `+0x18` bounds (left, top, right, bottom WORDs; tile units during rectangle creation, pixels after a refresh), `+0x20` route-cut rank, `+0x21` count of ID-0 neighbors, `+0x2c` inline storage for up to ten neighbor IDs.

**Path record pool** `*0x69b574` (`0x20000` bytes, 1024 records of 128 bytes), free head `0x69b570`. A free record holds at `+0` the one-based index of the next free record (0 = none) and at `+4` its own one-based index. A live record ([path storage](../native-path-storage.md)): `+0` source point, `+4` next point, `+8` goal, `+0xc` creation frame, `+0x18` flags byte, `+0x19` retry timer (`0x48ef10` clears both as one WORD), `+0x1b` full region-chain count (low byte), `+0x1c` stored region count, `+0x1d` current region index, `+0x1e` point count, `+0x1f` current point index, `+0x20` points (4 bytes each) followed by region IDs (2 bytes each).

**Path-search context** (stack, 0x16c–0x174 bytes): `+0` unit, `+4` source point, `+8` destination point, `+0x18` adjusted destination, `+0x1c` partial flag, `+0x1e` "destination adjusted" byte, `+0x1f` new value for status bit `0x80000`, `+0x20` region chain (≤ 50 WORDs), `+0x84` region cursor, `+0x86` region count, `+0x88` points, `+0x150` point index, `+0x152` point count, `+0x154` full chain count low byte, `+0x160/+0x162` source/destination region IDs.

**Walk grid** `*0x69b55c`: 1024 × 1024 bytes, one per 8 × 8 mini-cell, negative = blocked ([region generation](../native-region-generation.md)). Tile (x, y) starts at byte `4·(1024·y + x)`.

**Other globals.** `0x69b560` terrain-changed flag (set by a dying building or an opening door); `0x69b564` AI economy countdown; `0x69b568` 300-frame countdown; `0x69b56c` six-period counter; `0x69b580` region-overflow flag; `0x6726d0 + 36·p` player controller byte (1 computer, 2 human, 3 rescuable); `0x534914 + 12·a + b` alliance byte (0 enemy); `0x6b1a74[8]` per-player AI region arrays (52-byte records; byte `+5` region state, `+0x28` patrol unit, [P38](p38.md)); `0x5264b4/0x5264b6` map width/height in tiles; `0x666454` per-tile terrain flags (DWORD, map-width stride); `0x54323c` map megatile IDs; `0x66644c` VF4 data; `0x5349d8` elapsed game seconds; units.dat tables `0x520d50` computer idle order, `0x520e38` human idle order, `0x520f20` return-to-idle order, `0x521008` attack-unit order, `0x521660` special-ability flags.

## Functions

### 0x0048cbd0 `LoadPathingSaveBlock` — restore regions, contours and path pool from a save
- Module: sai_loadsave.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = buffer; returns 1, or 0 on a version mismatch.
- Behavior: The buffer starts with a WORD version and a WORD contour flag. A version other than 14 returns 0. Otherwise:
  1. `0x69b570` = DWORD `+4` (the free head, still a one-based index).
  2. `0x4911e0` allocates and zeroes a new region object; the `0x97a20` bytes at `+8` are copied into it.
  3. If the contour flag is nonzero: allocate 0x38 bytes (SMemAlloc, `sai_LoadSave.cpp` line 447), store the pointer at object `+0x97a1c`, copy the next 0x38 bytes into it, call the empty `0x4be950`, then allocate four arrays of `8·n` bytes where `n` is the signed WORD at header `+0x10`, `+0x12`, `+0x14`, `+0x16` (pointers into header `+0`, `+4`, `+8`, `+0xc`), and copy each array from the following buffer bytes in that order. Without the flag, `+0x97a1c` keeps the raw saved value.
  4. Copy the next `0x20000` bytes into the existing path pool `*0x69b574`.
  5. `0x48c940` converts stored indices back into pointers: each region's neighbor pointer (`-1` → its own inline array `+0x2c`, otherwise object `+0x92bfc + 2·index`), the pool cursor `+4` (`+0x92bfc + 2·index`), the split end `+8` (`+0x2000c + 6·index`) and the free head (one-based index → record address).
  6. `0x48e600` (no-op validation). Return 1.
- Callers/callees: saved-game loader `0x499890`.

### 0x0048cd70 `Order_ComputerAI` — order 156
- Module: sai_loadsave.cpp..sai_path.cpp · Relevance: ai
- Status: specified
- Signature: `__fastcall`, ECX = unit.
- Behavior: Does nothing while the order timer `+0x54` is nonzero. Otherwise sets it to 15, then:
  1. Larva (35): run `OrderLarva` `0x43cd90`; if `IsUnitInactive` `0x41fe40` is then true, return.
  2. Medic (34): if `0x4ae8e0` (a military AI record whose assigned region `+0x10` has state byte `+5` = 0) tail-call `0x4afd40` (relocate it to the nearest of its owner's regions in state 4 or 5); otherwise issue order 175 (Medic idle) and return.
  3. No AI record (`+0x134` = 0): issue the units.dat computer idle order `0x520d50[type]` and return.
  4. AI unit step `0x48e180`; nonzero ends the visit.
  5. By AI record type byte `+8`: 2 → worker step `0x487580`; 3 → building step `0x487110`, then timer = 45 if it returned nonzero, else 3; 4 → military step `0x4b1010`, timer = 3; any other type → issue the computer idle order. Every one of these cases then continues with step 6.
  6. Repair trip: if the race (`0x428d60`) is 1 (Terran), the type is Mechanical (`0x521660` bit `0x40000000`), `0x4b0580(unit, 0)` is 0 (not a military unit in a region of state 1, 2, 8 or 9), `(hp + 255) >> 8` differs from `GetUnitMaxHitPoints` `0x409c90`, status `0x20000` is set, the plague (`+0x11a`) and irradiate (`+0x118`) timers are 0 and the type is not a worker (`0x521660` bit 8): find the town's builder SCV (`0x432bb0`); if found issue Follow (49) on it, then return (also when none is found).
  7. Siege Tank (5): `0x48dee0`. Otherwise, a Burrowable type (`0x521660` bit `0x100000`): `0x48de70`.
- Prior evidence: [combat AI](../native-combat-ai.md), [unit AI](../native-unit-ai.md), [AI paid roster](../native-ai-paid-roster.md), [AI wave](../native-ai-wave.md).

### 0x0048cee0 `Order_AIPatrol` — order 159
- Module: sai_loadsave.cpp..sai_path.cpp · Relevance: ai
- Status: specified
- Signature: `__fastcall`, ECX = unit.
- Behavior: Returns while the timer `+0x54` is nonzero; then sets it to 15 and switches on the order state `+0x4e`:
  - 0: with an order target unit `+0x5c`, copy its sprite position into `+0x58/+0x5a` and move there (`RequestMoveToPoint` `0x43a070`). Otherwise, if `0x4b0af0` (continue the patrol of the region whose AI region record `+0x28` patrol unit is this unit, [P38](p38.md)) or `0x4adf80` (claim the first region in state 1, 2, 7, 8 or 9 with no patrol unit and move to its center) succeeds, set state 1; else state 2.
  - 1: when `0x4b0af0` fails, set state 0.
  - 2: if `0x4adf80` succeeds, set state 1. Otherwise, once arrived (`GetMoveArrival` `0x41a250`), pick a neighboring region point with `0x4afb20` (uses RNG) and move to it.
  - Other states: nothing.

### 0x0048cfb0 `Order_Neutral` — order 162: turn hostile when attacked
- Module: sai_loadsave.cpp..sai_path.cpp · Relevance: ai
- Status: specified
- Signature: `__fastcall`, ECX = unit.
- Behavior: Only acts when the attacker field `+0x7c` is set, and always clears it at the end. The rest is skipped when the attacker's sprite is hidden (sprite flags byte `+0xe` bit `0x20`), when the attacker is undetected by the unit (`IsUnitUndetectedBy` `0x40a180`), or when both have the same owner. Otherwise:
  1. The unit's owner becomes a computer (`0x6726d0[36·owner] = 1`). Alliance bytes owner→attacker and attacker→owner become 0 (enemy).
  2. If `CanAttackTarget(unit, attacker, 1)`: `ClearOrderTarget` `0x41df90`, issue the units.dat attack-unit order `0x521008[type]` on the attacker, and the same for the subunit when `IsSubunit` `0x420000` accepts `+0x70`. Otherwise issue the return-to-idle order `0x520f20[type]`.
  3. `0x4b1fe0(unit)` registers it with the owner's AI.
  4. Every other unit of the owner (list `0x4256f0`, link `+0x6c`) that is active and not a subunit: if status `0x40` is clear, issue its return-to-idle order; if `0x40` and `0x20` are both set, issue BunkerGuard (5); with only `0x40`, no order. Then the subunit attack order on the attacker as above and `0x4b1fe0(member)`.
- Prior evidence: dispatcher table in [P12](p12.md).

### 0x0048d120 `Order_RescuePassive` — order 161
- Module: sai_loadsave.cpp..sai_path.cpp · Relevance: ai
- Status: covered
- Signature: `__fastcall`, ECX = unit.
- Behavior: As in [special orders](../native-special-orders.md). Details: the scan runs only with timer `+0x54` = 0 and sets it to 1. The rectangle is sprite position ±64 (WORD arithmetic) for `QueryUnitsInRect` `0x422330`. The rescuer is the first candidate whose owner's controller byte is 2. The whole-depot branch applies when (status `0x1` completed, or type 133 Hive, 132 Lair, or 131 Hatchery with `0x43c040` true) and status `0x2` is set and the type has ResourceDepot (`0x1000`). It then transfers every active unit in the rescued player's list (next pointer saved before the transfer) through `ChangeUnitOwner` `0x426ed0(unit, rescuer's owner, 1)`. Otherwise only this unit is transferred. Each transferred unit receives BunkerGuard 5 when status `0x20` is set, else the human idle order `0x520e38[type]`. Then `PlayRescueSound` `0x446b30(unit)` and `0x4a7ed0`. The query is always released (`0x4222b0`).
- Callers/callees: order dispatcher `0x439420` and hidden-unit dispatcher `0x439e20`.

### 0x0048d3a0 `TryAiReactionSpell` — AI spell dispatcher
- Module: sai_loadsave.cpp..sai_path.cpp · Relevance: ai
- Status: covered
- Signature: `__fastcall`, ECX = caster, EDX = reactive flag; returns 1 when a spell order was issued.
- Behavior: As in [combat AI](../native-combat-ai.md) "Reaction spells". With EDX = 0 the dispatcher first requires `0x4833c0(owner)` (PlayerAi byte `0x67d295 + 0x4e8·player` = 0) and returns 0 otherwise. The tables above resolve the dispatch. Each attempt is readiness `0x48e580(caster, order, [tech])` → selector(caster, reactive) → "already this order on this target" check (returns 0 from the whole dispatcher) → reservation `0x48e5c0`. Exact chaining confirmed in the assembly:
  - Battlecruiser: Yamato only. Defiler: Plague, then Dark Swarm if Plague is not ready or its reservation fails (in every chain a failed selection, which yields a null target, also fails the reservation). Science Vessel: EMP, Matrix, Irradiate. Arbiter: Stasis, then Recall (selector `0x433140` takes only ECX). High Templar: Storm, then Hallucination only if current energy's high byte equals `GetMaxEnergyWhole` `0x434a80`. Corsair: Web. Ghost: Lockdown, then the nuke path (player check `0x4832a0`, silo `0x436f60(ghost, 1, ghost)`, selector `0x432f40` (ECX only; it returns with a plain `ret`, so the 1 pushed before the call stays on the stack and becomes the reservation mask), order NukePaint 126 with mask 1; success writes the Ghost into `*(silo+0xd0)+0x80` and calls `0x483270(owner)`).
  - Queen: with campaign flag (`IsCampaignAi` `0x4831e0`), `Rand15` source 42 low byte = 1 goes to Parasite first, any other value to Broodlings first. Without the flag, the full-energy test selects Parasite first. Parasite not ready → return 0 if the flag is set, else Broodlings (`0x48d56a`: `je` to Broodlings when `0x4831e0` returns 0). A failed Parasite selection or reservation returns 0. Broodlings success also queues Move (6) to the Queen's own position (`0x429ee0`). A failed or unready Broodlings goes to Ensnare when the flag is set or energy is full; otherwise it returns 0.
  - Medic: Restoration. Only when Restoration is ready but its reservation fails, and `0x482450` is true and the current order is not 180, the second selector `0x433000` with reservation follows. When Restoration is not ready or both attempts fail, Optical Flare is tried, only at full energy. Its reservation result is returned.
  - Dark Archon: Feedback, Mind Control, then Maelstrom when energy ≥ min(cost(186) + cost(182), max energy) (`NeedsMoreEnergy` `0x434b50` = 0) and `CanUseTech(31)` = 1.
- Callers/callees: AIGuard `0x41e7f0`, `0x4361b0`, `0x43c810`, `0x487110`, `0x4aebc0`, `0x4b1010`.
- Prior evidence: [combat AI](../native-combat-ai.md), [reaction spells](../native-reaction-spells.md).

At each cell with value ≥ 5000 (unassigned class), `0x490b80(obj, x, [y, &box, class])` gives a box. `tries++`; a strictly larger area replaces the best (box and class). If `bestArea ≥ prevArea` or `tries > 25`, stop: `sy = best.top`, `sx = best.right`. Otherwise jump the scan to column `box.right` (the current box, not the best) in the same row. A scan that wraps back to its start without stopping leaves `sx, sy` unchanged.
  2. If the count ≥ 5000: `0x69b580 = 1`, free the walk grid `0x69b55c` if set (SMemFree, line 882) and zero it, report fatal error `ReportNetError` `0x474a00(network.tbl index 0x61, detail "The map could not be loaded because it had too many obstructions…", [0, 0, fatal 1])` and return 0. This check happens before the done test.
  3. `prevArea = area of best`. Area 0 → return 1 (nothing unassigned remains).
  4. `0x490180(obj, &best, [id = count])` fills the box. The center is `(left + w/2, top + h/2)` in tiles (signed halving).
  5. Grow the box by one tile on each side, clamped to 0 and the map size `0x5264b4/6`. Then `0x48fff0(obj, &box, [id, class])`. Store the box at `+0x18`, the class at `+0`, and increment the count.
  6. If area ≤ 6 and `expanded` = 0: set `expanded`. For every region `first`..count−1, grow its stored box by one tile (clamped) and rerun `0x48fff0` with its own ID and class.

### 0x00490500 `CollectRegionNeighbors` — ordered, deduplicated adjacency
- Module: sai_pathcreate.cpp · Relevance: simulation
- Status: specified
- Signature: `__fastcall`, ECX = object, EDX = region ID, stack [record]; `ret 4`.
- Behavior: Scans tiles from `bounds/32` (signed, truncating) in row-major order. For each tile equal to the ID, it reads the eight neighbors (`0x490a60`) in order.   - BL: (2..3, 0..1) and (4..5, −2..−1); then (2..3, −2..−1), or else (4..5, 0..1).
  - BR: (2..3, 2..3) and (4..5, 4..5); then (2..3, 4..5), or else (4..5, 2..3).

More than 10: the record's pointer `+0xc` = cursor and the cursor advances `2n` bytes. Otherwise they are copied to inline `+0x2c`, the rest of the ten slots are filled with `0x1fff` and `+0xc` points there. `+7 = n`, `+0x21 = 0`. The pool has no bounds check.
