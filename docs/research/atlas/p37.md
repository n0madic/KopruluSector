# P37: Resource panel, status-UI lifecycle, wireframe colors, system survey, AI unit strength and regional military AI

This package covers the end of the in-game console code and the start of the computer-player regional military layer. Its pieces are:

- **Resource panel tail** (`statres.cpp`, 0x4a78b0–0x4a79c0). Dialog `0x6ab3f4` (`rez\statres.bin`) with `game\icons.grp` in `0x6ab3f0`. A 20 ms timer callback `0x4a79c0` fills the supply, gas and mineral controls through the P36 text setters, and the trigger countdown text uses control index −10.
- **Status-UI lifecycle** (`status.cpp`). Per-game creation `0x4a7d80` and teardown `0x4a7bc0` of every console dialog, `game\<race>console.pcx` (`0x6ab504`), `rez\stat_txt.tbl` (`0x6ab4f8`), the selection snapshot used by the status panel (`0x6ab4c0` count, `0x6ab4c4` leader unit, `0x6ab4c8[12]` units) and the per-frame driver `0x4a7ee0`.
- **Wireframe colors** (`statwire.cpp`, `unit\wirefram\wirefram.grp` in `0x6ab524`, `game\twire.pcx` colors in `0x6ab50c[24]`). Twelve entries of the global color-remap table `0x501021` (palette indices `0xc0–0xc1` shields, `0xd0–0xd3` hit-point sections, `0xd8–0xdb` outline) are recolored from the selected unit's hit points and shields before a wireframe is drawn, then restored to identity.
- **System survey and network-game log** (between `statwire.cpp` and `teams.cpp`, 0x4a8390–0x4a8dd0). These write JSON and a log under `%LOCALAPPDATA%\Blizzard Entertainment\System Survey\ProductData\` and launch `SystemSurvey.exe`. They are excluded: they never feed back into the game.
- **AI unit strength** (0x4a8f30–0x4a9a20). The 228-entry type-strength tables `0x6ac530` (air, mode 0) and `0x6ac8c0` (ground, mode 1), per-unit cached strengths `+0x138`/`+0x13a`, target scoring and regional target choice. Most of this is executed and recorded in [combat AI](../native-combat-ai.md) and [strategic targets](../native-strategic-targets.md).
- **Regional military AI** (`TAI_Captain.cpp`, the assertion name in `0x4aa310`/`0x4aaeb0`). Each player has an array of AI region records `0x6b1a74[player]` (one per terrain region, `0x34` bytes), a shared pool of 1000 MilitaryAI nodes `0x6acc50`, state changes `0x4ab900`, reachability cache `0x6b1aa0`, target selection, donor selection, defense recipes and the per-state handlers reached from dispatcher `0x4b0ce0`.

## Shared conventions

**AI region record** (`0x34` bytes; `regions[p] = 0x6b1a74[p]`, record of region ID `r` at `regions[p] + 0x34·r`), confirmed at every use here:

| Offset | Field |
|---|---|
| `+0x00` u16 | terrain region ID |
| `+0x02` u16 | destination region ID (support/attack target) |
| `+0x04` u8 | owner player |
| `+0x05` u8 | state 0–9 |
| `+0x06` u8 | priority (written by `0x4ab900`) |
| `+0x07` u8 | retry counter (decremented by dispatcher `0x4b0ce0` before each handler) |
| `+0x08` u8 | flags: `0x01`, `0x04` (cleared by the dispatcher), `0x20` (low-strength dispersion allowed), `0x40` (no requirement decay) |
| `+0x09` u8 | state-7 wait counter |
| `+0x0a` u16 | ground military count |
| `+0x0c`/`+0x0e` u16 | needed ground / needed air strength |
| `+0x10`/`+0x12` u16 | local ground / local air strength |
| `+0x14`/`+0x16` u16 | all-assigned ground / air strength |
| `+0x18`/`+0x1a` u16 | enemy **air** / enemy **ground** strength (`0x4abf90`) |
| `+0x1c`/`+0x20` | air target unit / ground target unit |
| `+0x24` | slowest member (`0x4ab870`) |
| `+0x28` | detector unit |
| `+0x2c` | MilitaryAI pool pointer (`0x6acc50`) |
| `+0x30` | first MilitaryAI node of this region |

**MilitaryAI node** (20 bytes, pool `0x6acc50`, 1000 nodes, free-list head at pool `+0x4e20`): `+0` next, `+4` previous, `+8` u8 AI type (4 = military; guard records use type 1 and keep their home point at `+0x12`/`+0x14`), `+0xc` unit, `+0x10` region record. A unit's AI record pointer is `unit+0x134`.

**Map pixel size** is u16 `0x543230` (width) × `0x543234` (height). The terrain base is `0x69b584`; the 64-byte terrain region record of ID `r` starts at `base + 0x449fc + 64·r` with `+0` accessibility word (`0x1ffd` = inaccessible), `+2` connectivity group, `+4` tile count. Approximate distance `0x405cf0` is specified in [P01](p01.md). Game RNG `0x478200(ECX = source)` is specified in [P26](p26.md).

**Unit type numbers** used below: 0 Marine, 1 Ghost, 2 Vulture, 5 Siege Tank (siege), 9 Science Vessel, 11 Dropship, 13 Spider Mine, 30 Siege Tank (tank), 32 Firebat, 34 Medic, 35 Larva, 36 Egg, 37 Zergling, 41 Drone, 42 Overlord, 43 Mutalisk, 45 Queen, 46 Defiler, 47 Scourge, 50 Infested Terran, 59 Cocoon, 64 Probe, 65 Zealot, 67 High Templar, 69 Shuttle, 71 Arbiter, 72 Carrier, 73 Interceptor, 81 Warbringer, 82 Gantrithor, 83 Reaver, 84 Observer, 85 Scarab, 97 Lurker Egg, 103 Lurker, 124 Missile Turret, 125 Bunker, 144 Spore Colony, 162 Photon Cannon, 194–199 beacons. Units.dat `0x521578` is the "AI internal" byte (bit 0 used here); `0x521660` special flags (`0x1` building, `0x8` worker, `0x10` subunit, `0x400` two units per egg, `0x8000` detector, `0x200000` spellcaster).

### 0x004a79c0 `UpdateResourcePanel` — 20 ms timer of `statres.bin`
- Module: statres.cpp..status.cpp · Relevance: ui
- Status: specified
- Signature: timer callback (`ECX` = the dialog); no return value. Created by `0x4a7850` (P36).
- Behavior:
  1. `c` = child with index 1 (`0x4c2200`). Save the viewer `v0 = 0x508d50`. `snap = 0`.
  2. In a replay (`0x67cc90` ≠ 0): the reference unit is `0x6ab4c4` when the selection count `0x6ab4c0` is 1, else the first snapshot entry `0x6ab4c8[0]`. If the count is 0 or that unit's owner `+0x4c` is 11, set `0x50d7d8 = −1` and hide `c` and each following sibling while its index (`+0x20`, signed) ≤ 5; return. Otherwise `0x508d50 = owner`, `snap = (owner ≠ 0x50d7d8)`, `0x50d7d8 = owner`.
  3. For race `r` = 0, 1, 2 with icon frames 4, 5, 6: `used = 0x414320(r, viewer)`, `max = 0x414360(r, viewer)`. If `max` ≠ 0: `0x4a7640(c, frame, used, max)` and advance `c` to the next sibling (`+0`). A race with zero maximum supply does not consume a control.
  4. Gas: `0x4a76e0(c, frame = u16(0x5264c2 + 1), &0x6ab3fc, gas 0x526400[viewer], snap)`; advance. Minerals: `0x4a76e0(c, frame 0, &0x6ab3f8, minerals 0x5263d0[viewer], snap)`; advance.
  5. Hide each remaining sibling while it exists and its index ≤ 5.
  6. In a replay restore `0x508d50 = v0`.
- Globals/fields: `0x50d7d8` = viewer last shown in a replay (−1 none). The gas icon always uses the local race byte, even when a replay shows another player.

### 0x004a7f50 `SetWireframeHitPointColors` — four hit-point sections
- Module: status.cpp..statwire.cpp · Relevance: render
- Status: specified
- Signature: `__fastcall`, ECX = unit.
- Behavior:
  1. `mark = 0x6ab50e`; all four bytes `0x5010f1..f4 = mark`.
  2. `max = 0x520708[type] >> 8` (signed); if 0, `max = (hp+255) >> 8`, or 1 when that is 0 (hp = `+8`). `row = ((hp+255) >> 8) · 9 / max` (signed). Table = `0x50d7dc` when `+0xe1` (wireframe randomizer) bit 0 is set, else `0x50d804`.
  3. For k = 0..3: `s = (((+0xe1 >> k) & 7) · 3) / 7` (0..3). Starting at `s`, step cyclically (wrap 4 → 0) to the first slot still equal to `mark`. Set that slot to `0x6ab50c[table[row][k]]`.
- The randomizer byte thus permutes which wireframe section shows which color. A unit with HP above its maximum gives a row above 9 and reads past the table; this does not occur with valid data.
