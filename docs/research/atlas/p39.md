# P39: Guard AI pool, attack staging search, targeting mode, team helpers, production gate, in-game text box, receding creep, tips and title screens

This package runs from the last computer-player military helpers through `teams.cpp`, `textbox.cpp`, the receding-creep pool, `tips.cpp` and the start of `title.cpp`. Its pieces are:

- **Attack staging search** `0x4b1810`, called by `ChooseAttackStaging` `0x4b1710` (P38). It runs a five-layer breadth-first search over the AI region graph from a classification-3 region and picks a staging region by layer order `[4, 3, 5, 6, 2]` (table `0x50da70`).
- **Guard AI** (computer "guard" records, AI type 1). One shared pool of 1000 records lives at `0x6b6908`, and eight per-player `(pool pointer, list head)` pairs sit at `0x6be610 + 8·p` / `0x6be614 + 8·p`. This part covers pool initialisation, save and load, attachment and detachment, home positions, return-home orders and the periodic rebuild `0x4b2320`. Most of it is executed and recorded in [guard lifecycle](../native-guard-lifecycle.md) and [computer combat](../native-computer-combat.md).
- **Targeting mode** (command-card orders that wait for a map click): bytes `0x6be650` (active) and `0x6be651`–`0x6be653` (unit, ground and fogged-unit orders).
- **Team helpers** (`teams.cpp`). These read the 36-byte player slots at `0x6726c8` (`+0` index, `+4` Storm ID, `+8` controller/slot type, `+9` race, `+0xa` force, `+0xb` name) and the team-game globals: mode `0x67294d`, leaders `0x5264ab[team]`, leader list `0x5264ac[4]`. Team games need the multiplayer byte `0x672664` (`0x4b2d90`), so single player never takes those branches. The active-player iterator `0x4b3160`/`0x4b3170` used by triggers also lives here.
- **Unit-production gate** `CanTrainUnit` `0x4b32a0` with its recipe-offset initialiser and error word `0x6be654`. These are covered by [requirements](../native-requirements.md).
- **In-game text box** (`rez\<race>textbox.bin`, dialog `0x6be65c`). The message/cheat entry line opened with Enter. Mode byte `0x6be658`: 0 closed, 1 single-player entry, 2 send to all, 3 send to allies, 4 send to one player. In single player a submitted line is only run through the cheat recogniser.
- **Receding creep** (the "creep life" pool). It holds 1024 20-byte nodes at `0x6be698`, buckets 0–9 (heads `0x6c4698 + 4·b`, u16 counts `0x6c46c0 + 2·b`, bucket 9 = free list, free count `0x6c46d2`), 1024 hash heads at `0x6c3698`, the recede timer `0x6c46d4` and the dead-provider retry timer `0x6c46d8`. The creep engine (`creep.cpp`, `0x4c0690`) receives three callbacks from `LoadTilesetAndTerrain` `0x445a30`: `{0x4b4040 tile changed, 0x4b45f0 tile shows creep, 0x4b4560 tile hidden from viewer, 0}`. Most of this is executed and recorded in [trigger creep](../native-trigger-creep.md).
- **Tips dialog** (`rez\tips_dlg.bin`, `rez\tips.tbl` in `0x6c46dc`, tip index `0x6d3144`, option bit `0x100` of `0x6d3148` "show tips at start") and the **title screen** (`rez\titledlg.bin` in `0x6c46f4`, `glue\title\title.pcx`, `glue\title\tFont.pcx`).

## Shared conventions

**Guard record** (32 bytes, `0x6b6908 + 32·i`, i = 0…999; free head pointer at pool `+0x7d00`; block size `0x7d04`), confirmed at every use here:

| Offset | Field |
|---|---|
| `+0x00` / `+0x04` | next / previous (player list or free list) |
| `+0x08` u8 | AI type = 1 |
| `+0x09` u8 | death count (saturates at 100) |
| `+0x0c` | parent unit (null = waiting for a replacement) |
| `+0x10` u16 | unit type to keep |
| `+0x12` / `+0x14` s16 | home x / y (where the unit returns) |
| `+0x16` / `+0x18` s16 | original placement x / y |
| `+0x1c` u32 | time of the last replacement request (elapsed time `0x5349d8`) |

Saved form: links and list heads become `index + 1` (0 = null), and parent becomes a packed unit reference (`UnitToPackedRef` `0x428bd0` / `UnitFromIndexUnchecked` `0x428ba0`).

**Receding-creep node** (20 bytes, base `0x6be698`): `+0`/`+4` bucket next/previous, `+8`/`+0xc` hash next/previous, `+0x10` u8 tile x, `+0x11` u8 tile y, `+0x12` u8 bucket (0–8 = neighbouring-creep count, 9 = free). Hash key: `(17·y + x) & 1023` (computed in 16 bits). Saved form: each of the four links and every head becomes `(p − 0x6be698) / 20 + 1` (signed division), 0 = null; it is restored as `0x6be684 + 20·n`.

**Tile flag dword** `0x666454[x + width·y]` (width u16 `0x5264b4`, height u16 `0x5264b6`): low byte = not-visible mask, bits 8–15 = not-explored mask, `0x10000` walkable, `0x40000` unwalkable, `0x400000` has creep, `0x800000` unbuildable, `0x8000000` occupied, `0x10000000` creep receding, `0x20000000` partially walkable, `0x40000000` creep shown in the display tile. The creep engine's own tile map is `0x6ca7a0` (= `0x666458`). A word with `(w & 0x7ff0) == 0x10` (cv5 group 1) is a creep tile. The display tile map is `0x54323c`.

**Dialog events** (dialog library): event WORD `+0xc` type: 0 key down, 1 key repeat, 2 key up, 3 mouse move, 4–6 left down/up/double, 7–9 right, 10–12 middle, 13 idle, 14 user, 15 char. DWORD `+0` user code (0 init, 1 destroy, 2 activate) and WORD `+8` key or character. Control: `+4`/`+6`/`+8`/`+0xa` s16 left/top/right/bottom, `+0x14` text, `+0x18` flags (font size bits `0x4c00`), `+0x20` ID, `+0x2a` interact procedure, `+0x2e` draw procedure, `+0x32` parent dialog. `0x4c2200(ECX = dialog, EDX = ID)` finds a child, `0x4c2890` shows, `0x4c22f0` hides, `0x4c2900(EDX ≠ 0 ? show : hide)`, `0x4c2840` invalidates and `0x4c1470` is the default dialog procedure.

## Entries

### 0x004b1810 `FindAttackStagingRegion` — choose a staging region by layered region search
- Module: statwire.cpp..teams.cpp · Relevance: ai
- Status: specified
- Signature: custom `__fastcall` with `ret 0x14`. ECX = player, EDX = start region ID, stack [class array (byte per region ID), x, y, allow-shallow flag, all-neighbours flag]. Returns region ID + 1, or 0.
- Behavior:
  1. `class[start] ≠ 3` → return 0.
  2. Zero a 2500-byte layer array `L`; `L[start] = 1`. `n = GetRegionCount()` (`0x481b00`).
  3. For layer `d = 1` to 5: for each region `r = 1 … n−1` with `L[r] = d`, take its neighbour list. The all-neighbours flag ≠ 0 selects `GetRegionAllNeighbors` `0x481ad0` (all entries), else `GetRegionGroundNeighbors` `0x481ab0` (ground prefix). A neighbour `q` is marked `L[q] = d + 1` when the player's AI region record state (`regions[p] + 0x34·q + 5`) is 0, 5 or 4, `L[q] = 0` and `class[q] = 6`. Marks made during a pass can be expanded later in the same pass only when `q > r` and `d + 1 = d`, which never happens, so each pass expands exactly one layer.
  4. `best = 99 999 999`; fallback = 0 with largest tile count `maxTiles = 0`, both persisting across depths. For each depth `t` of the table `0x50da70` = `[4, 3, 5, 6, 2]` in order:
     - `t < 4` and allow-shallow = 0 → skip this depth.
     - For `r = 1 … n−1` (ascending): skip when the region record flags (`+8`) have `0x20`, or `L[r] ≠ t`. Tile count `c` = u16 terrain region `+4` (`0x69b584` base `+0x449fc + 64·r + 4`). If `c > maxTiles`, then `maxTiles = c` and fallback = r + 1. If `c ≥ 60`: centre from `GetRegionCenter` `0x481a30`, `dist = ApproxDistance(x, y, centre)` `0x405cf0`, and if `dist < best` (unsigned, strict) then best = dist and candidate = r + 1.
     - A candidate found at this depth → return it.
  5. After all depths: return the fallback when `IsCampaignAi(player)` `0x4831e0`, else 0.
- Callers/callees: Only `ChooseAttackStaging` `0x4b1710`.
- Prior evidence: [campaign attack](../native-campaign-attack.md#region-classifications-and-positive-staging-selection) (positive single-candidate cases).

### 0x004b2320 `RebuildGuards` — periodic guard cleanup and replacement requests
- Module: statwire.cpp..teams.cpp · Relevance: ai
- Status: covered
- Signature: `__fastcall`, ECX = player.
- Behavior: For each record of the player's list (caching next, stopping once the head is null):
  1. Campaign AI with death count ≥ 3 → recycle the record.
  2. Otherwise, an attached record is recycled only when its parent has status `0x40000000` (hallucination), else kept.
  3. A parentless record with timestamp t ≠ 0 waits until elapsed `0x5349d8 > deadline`. The deadline is `t + 300` when deaths ≠ 0, otherwise `t + 5 + floor(time/15)`. Here time = u16 build time `0x5238b0[type]` (type 30 read as 5) plus the parent's time for 44/62 (Mutalisk), 63 (Dark Templar), 68 (High Templar) and 103 (Hydralisk).
  4. When the original-placement region passes `0x4aea70`: Zergling (37) or Scourge (47) first try `0x4af750` (nearest free unit). Found → `0x48dbc0` removes its old AI, home = original placement, parent = unit, `unit+0x134` = record, ComputerAI order 156 via `0x42a2c0`. The timestamp is not written. Otherwise `0x482a40`(player, record) and `+0x1c` = elapsed.
- Callers/callees: Per-player slow AI service (call at `0x483488`).
- Prior evidence: [guard lifecycle](../native-guard-lifecycle.md#periodic-service-and-cleanup-order), [guard transfer](../native-guard-transfer.md).

### 0x004b2db0 `SetupTeamGameSlots` — slot layout of a team game at game start
- Module: teams.cpp..textbox.cpp · Relevance: simulation
- Status: specified

- Signature: no arguments, no return value.

  2. Leaders: for force f = 4 down to 1, the leader is the slot with the smallest Storm ID (`+4`, unsigned) among the slots 7 down to 0 of type 2 or 1 and force f.   3. For f = 1 … 4 with a leader: its 36-byte record is appended to a local leader list and its slot is reset from the setup record (`RestoreSlotFromMapSetup` `0x479c40`).
  4. For slot s = 0 … 7 whose type is now 2, 1, 3, 4 or 7 (`0x4795b0`): a type 1 is set to 0 and the record is dropped (the other computers of a computer team do not become players); any other record is appended to a local member list.

  6. For each leader, in ascending force order: list the slots 0 … 7, ascending, whose type is 6, 5, 3, 4 or 7 (`0x4795e0`), n entries.   10. If the local slot `0x508d50` is of type 2: `0x508d50` = `0x5264ab[its force]`, the leader's slot. `0x508d54` keeps the seat's own slot.
  11. `0x672878[0…7]` = 8; for i = 7 down to 0, with r = `0x672898[i]` (r = 8 reads record 8): slot r of type 2 → `0x672878[i]` = `0x5264ab[the force of slot r]`; of type 9 → `0x672878[i]` = r.
