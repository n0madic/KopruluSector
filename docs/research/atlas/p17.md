# P17: Battle.net create/profile/message-box glue, the briefing action handlers and portrait control, and the multiplayer lobby

This package covers `0x44cf10`–`0x451140`: `glubncreate.cpp`, `glubnicon.cpp`, `glubnokcancel.cpp`, `glubnprofile.cpp`, the object between `glubnprofile.cpp` and `glubrfport.cpp`, `glubrfport.cpp`, and the head of the object before `gluchat.cpp`. Its 103 functions fall into three groups.

1. **Battle.net glue** (`0x44cf10`–`0x44fc10`, 63 functions). The Create Game and map-browse dialogs (art, owner-drawn list items, registry-persisted choices), the 28 × 14 icon sheet `glue\battle.net\icons\icons.pcx`, the Battle.net message box (`OK_DIALOG`/`BIGOK_DIALOG`/`OKCANCEL_DIALOG`/`BIGOKCANCEL_DIALOG`) and the player-profile dialogs (`DIALOG_PROFILE`, `DIALOG_STATIC_PROFILE`). The glue loop reaches them only in glue state 4 (Battle.net), through the `SNetSelectGame` interface table `0x44a4d0` (see [P16](p16.md)). They are `excluded`. Five getters in `glubncreate` are the exception: the map-selection screen of every custom game (`0x45dfc0`, `glumap.cpp`, also offline) calls them, so they are `specified` with their offline values.
2. **Briefing actions and briefing portraits** (`0x44fcd0`–`0x4505a0`, 25 functions). These are the ten-entry MBRF action table `0x503908`, the MBRF interpreter `0x44fee0`, and the `gluBrfPort` portrait control of the campaign ready rooms (`rez\readyp/t/z` dialogs built by `glurdy.cpp`). All of it is in scope, because every campaign mission starts with a briefing.
3. **Multiplayer lobby** (`0x4505f0`–`0x4510b0`, 15 functions). These handle `rez\gluChat.bin` (glue state 3) and the join screen's control callback. Glue state 3 is entered only from Create Game when the multiplayer byte `0x672664` ≠ 0 (`0x455550`) or from Join (`0x459130`, multiplayer only). They are `excluded`.

## Shared data and tables

**Dialog control fields** (as in [P36](p36.md), confirmed at each use here): `+0x04..+0x0b` s16 rect `left, top, right, bottom`, `+0x14` text pointer, `+0x18` flags (bit 0 dirty, bit 3 visible), `+0x20` s16 control ID, `+0x22` u16 type, `+0x24` u16 `wUser`, `+0x26` u32 `lUser`, `+0x2a` interact callback, `+0x2e` update/draw callback, `+0x32` parent, `+0x42` first child. Engine helpers: `0x4c2200`(ECX = dialog or control, DX = ID) finds a child; `0x4c2890` shows; `0x4c22f0` hides; `0x4c2900`(EDX ≠ 0 ? show : hide); `0x4c2840` marks dirty; `0x4c2280` disables. UI timers: `0x4c5960`(ECX = owner, DX = timer ID, stack `[duration ms, callback]`) creates or *replaces* the owner's timer with that ID (GetTickCount clock, see [briefing loader](../native-briefing-loader.md#briefing-waits-and-the-ui-clock)). A timer keeps firing every `duration` ms until `0x4c58f0`(ECX = owner, DX = ID) deletes it. A dialog event is `+0` u32 user code, `+8` u16 key, `+0xc` u16 event type; type 14 is the user/dialog event, with code 1 = destroy and code 10 = post-load initialization.

**MBRF action record** (32 bytes, same layout as TRIG actions): `+0x00` u32 location, `+0x04` u32 string ID, `+0x08` u32 WAV string ID, `+0x0c` u32 time (ms), `+0x10` u32 player field (MBRF uses its low byte as the portrait slot 0–3), `+0x14` u32 number, `+0x18` u16 unit type, `+0x1a` u8 action ID, `+0x1b` u8 modifier, `+0x1c` u8 flags (bit 0 = "already waited" entry flag, bit 1 = disabled).

**Briefing action table `0x503908`** (10 pointers, indexed by action ID, no bounds check in `0x44fee0`):

| ID | Handler | Action |
|---|---|---|
| 0 | `0x4b8e70` | None (never called: ID 0 ends the list first) |
| 1 | `0x44fcd0` | Wait |
| 2 | `0x44fd10` | Play WAV |
| 3 | `0x44fda0` | Display Text Message |
| 4 | `0x44fdc0` | Set Mission Objectives |
| 5 | `0x44fde0` | Show Portrait |
| 6 | `0x44fe00` | Hide Portrait |
| 7 | `0x44fe10` | Talking Portrait |
| 8 | `0x44fe30` | Transmission |
| 9 | `0x44fec0` | Enable Skip Tutorial |

**Briefing UI controls** (dialog `0x66b40c`, set by `0x460a70`): ID −10 text box (Display Text, `0x460fa0`), −11 objectives text (`0x460d20`), 15–18 the four portrait slots (`15 + slot`), 19 and −13 the skip-tutorial controls (`0x461170`). The portrait controls receive interact `0x44ffd0` from the ID-indexed override arrays `0x508320` (entries 14–17 at `0x508358..0x508364`), `0x508390` (`0x5083c8..`) and `0x508400` (`0x508438..`), one array per ready-room race.

**Briefing portrait state** (`lUser` of a portrait control, 20 bytes from `SMemAlloc`, created by `0x450080`):

| Offset | Type | Meaning |
|---|---|---|
| `+0x00` | u16, u16 | video bitmap width 120, height 112 |
| `+0x04` | ptr | 120 × 112 pixel buffer (`0x4cb200`, `gluBrfPort.cpp` line `0x103`) |
| `+0x08` | handle | Storm video handle (`SVidPlayBegin`), 0 = none |
| `+0x0c` | u16 | flags: bit 0 talking, bit 1 show-on-first-frame |
| `+0x0e` | u16 | portrait ID (index into `portdata`) |
| `+0x10` | u8 | previous talking variant (anti-repeat). It is never initialized: the first talking draw compares against heap garbage |
| `+0x11` | u8 | x offset of the video inside the control = (control width − 120) / 2 |
| `+0x12` | u8 | y offset = (control height − 112) / 2 |

**Briefing portrait globals**: `0x667bb0` `arr\portdata.tbl` image; `0x51bd40[110]` idle stems and `0x51bef8[110]` talking stems (TBL string pointers after `0x450130`; the same arrays as the in-game portraits in [P36](p36.md)); `0x667bb4`, `0x667bb8`, `0x667bbc`, `0x667bc0` the four idle-weight byte columns of `portdata.dat` (the four descriptors from the one whose data pointer is `0x51c0b0`); frame overlays `0x667bc4 + 8i` (idle, `<R>Frame1..4.pcx`) and `0x667be4 + 8i` (talking, `<R>FrameH1..4.pcx`), i = slot, 8-byte bitmap descriptors `{u16 w, u16 h, ptr pixels}`, with R = `glue\ReadyP\P`, `glue\ReadyT\T` or `glue\ReadyZ\Z` (callers `0x4613c0`, `0x461600`, `0x461840`). The draw routine indexes them as `0x667b4c + 8·ID` and `0x667b6c + 8·ID` for control IDs 15–18. Briefing wait byte `0x667bac` (shared by Wait and Transmission).

**Battle.net tables** (excluded code, resolved for completeness): Create Game fonts `0x503400` = {8 pt Arial, 10 pt Arial, 13 pt "Time New Roman" (misspelled face, so GDI substitutes)}; message-box bold fonts `0x503550` = {8 Arial, 10 Arial, 13 Times New Roman}; profile Storm-GDI fonts `0x5038a4` = {7 Arial 400, 10 Arial 400, 10 Arial 700, 16 Arial 400}; profile dialog fonts `0x5038d4` = {8 Arial 400, 10 Arial 400, 10 Arial 700, 13 "Time New Roman" 400}; browse icons `0x5033f4` = {`iClosed.pcx`, `iMap.pcx`}; popup backgrounds `0x503568` = {`spopup`, `lpopup`, `srpopup`, `lrpopup`}`.pcx`; message-box button IDs `0x503578` = {0x455, 2}; message-box templates `0x5034d0` = {`OK_DIALOG`, `BIGOK_DIALOG`} (types with `type & 0xf` = 0) / `0x503510` = {`OKCANCEL_DIALOG`, `BIGOKCANCEL_DIALOG`}, each two 32-byte names (small, big); icon cell `0x5034c0` = {28, 14}; profile keys `0x4ecf58` (StarCraft) / `0x4ed078` (Brood War), 18 entries `{key, flags, control ID, max length}`: `profile\sex` (0x40e, 8), `profile\age` (0x40f, 4), `profile\location` (0x411, 40), `profile\description` (0x412, 200), then 14 read-only keys (flag 4, no control) under `Record\Star\…`/`Record\SEXP\…`: mode 0 wins, losses, disconnects, last game, last game result; mode 1 wins, losses, disconnects, rating, high rating, `DynKey\Star\1\rank` (`DynKey\SEXP\1\rank`), high rank, last game, last game result.
