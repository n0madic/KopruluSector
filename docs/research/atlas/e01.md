# E01: Functions without their own atlas entry (oracle gaps and final gap pass)

The [full-game emulation oracle](../full-game-emulation.md) ran the original `StarCraft.exe` through boot and 64 campaign missions (65 runs). Its coverage comparison ([evidence](../evidence/full-game-emulation.json), `coverage`) found executed code that had no atlas entry of its own:

- 45 function starts that the private Ghidra index knows but no package lists (`executed_without_atlas_status`). Earlier packages described most of them inside a neighboring entry ("embedded" or "unlisted" code), and three static initializers only in prose.
- 96 groups of executed blocks outside every atlas function body (`executed_code_outside_atlas_function_bodies`). Most are tails of functions whose Ghidra size is too short. 23 groups start after padding or a `ret` (`likely_unlisted_functions_executed`).

Every executed outside block was checked against raw-image references (`call`/`jmp`/`jcc` rel32, short jumps and little-endian pointers) and against the preceding instruction. The distinct function starts among the 96 groups are 22 of the 23 listed first blocks (`0x4b322a` is an exit block of `NextActivePlayer`), the first blocks of five groups that do not follow padding (`0x433f20`, `0x4366f0` and the ready-room procedures `0x461320`, `0x461560`, `0x4617a0`, all reached through pointers or a dispatcher jump), and 15 further starts inside multi-function groups: `0x432a60`, `0x432ac0`, `0x4332c0`, `0x433f40`, `0x436720`, `0x436820`, `0x437890`, `0x437a00`, `0x437b50`, `0x437ba0`, `0x4ac7c0`, `0x4ac870`, `0x4ac9b0`, `0x4aca00` and `0x4acbc0`. The other 69 groups are continuation blocks: fall-through after a call or a conditional branch, or targets of short jumps inside the same function, whose Ghidra body size is too short.

This package therefore has 88 entries: the 45 + 23 listed addresses and the 20 further starts. Three of them are not functions (`0x4a59ad` and `0x4a63fd` are jump-table cases that Ghidra split, `0x4b322a` is an exit block); each is described with its containing function, as [A01](a01.md) does for similar labels. Each entry names the earlier entry that mentioned it (`Parent`).

Status counts: 12 specified, 163 covered, 1 excluded, 3 library (179 entries). The first 88 entries were written from the disassembly, and their oracle run counts confirm that each address executes in offline campaign play.

**Entries added in [F03](f03-final-fixes.md).** The final pass added 30 entries so that every function start of the private Ghidra index has its own JSON object somewhere in the atlas: the 29 game functions that earlier packages described only inside a neighboring entry or mentioned in passing (status `covered` when the parent describes them completely, otherwise `specified`), and the registry saver `0x4be880`, which Ghidra did not split from `0x4be820`. None of these 30 executed in the oracle runs: most are callbacks of spells, status-panel rows or exit-time cleanup. The static destructors and CRT addenda of the same gap list (`0x4d3fc0`, `0x4ea150`–`0x4eaad0`) are in [C01](c01.md) as `library` entries.

**Unsplit functions added in F03.** A scan for function starts that Ghidra merged into a neighbouring body (method in the [F03 appendix](f03-final-fixes.md#appendix-unsplit-function-scan)) found 56 starts without an object of their own. Each now has an entry here: 49 `covered` (the containing entry already described them; the behavior is restated from the disassembly), 1 `excluded` (modem code), 3 `specified` since the network second pass of 2026-11-14 (the lobby countdown timer `0x47a1a0`, the race-change thunk `0x474ef0` and the slot type drop-down `0x453770`) and 3 `library` (static destructors). They are not in the Ghidra function list, so the oracle has no run counts for them.

**Tail-jumped functions added in F04.** A scan of padding-delimited starts against `jmp`/`jcc` rel32 targets ([F04 appendix](f03-final-fixes.md#appendix-f04-tail-jump-scan)) found five game functions that are reached only by a conditional tail jump and that Ghidra merged into a neighbouring body: `0x451680` and `0x4517a0` (lobby countdown text, `specified` since the network second pass of 2026-11-14), `0x4808c0` (replay user-select flags), `0x4a15a0` (multi-selection command-card merge) and `0x4b0980` (Broodling AI assignment), the last three `covered`. The x87 dispatchers found by the same scan are in [C01](c01.md).

## Errors found in the parent entries

- [P37](p37.md) `0x4ac690`, bullet `0x4acbc0` (region state 7): the retry byte `+7 = 5` is written to the destination record D (`mov byte [edi+7], 5` at `0x4acc8e`, EDI = D), not to the record that changes to state 5. Entry `0x4acbc0` here is therefore `specified`.
- [A01](a01.md) introduction: `0x402460`, `0x402480` and `0x4024e0` are said to be "in P01 and C01". Neither package has entries for them; C01 mentions `0x4024e0` in prose and S01 mentions the other two. They are specified here.
- [P12](p12.md) introduction: `0x4372c0` is not documented in `0x437290` and `0x43a880` is not documented in `0x43a800`. Their descriptions are under [P11](p11.md) `0x435a70` and [P12](p12.md) `0x438cd0`.
- [P39](p39.md) `0x4b1fe0`: "Otherwise it tail-jumps to `AttachGuardRecord` `0x4b2010`" reads as part of the stub `0x484f40`. The stub only returns when its test fails; the jump to `0x4b2010` is the caller's branch for types without AI flag `0x2`.
- [V01](v01.md) item 1 lists `0x432950` as a reader of status `0x20000` (Ensnare). `0x432950` is the EMP energy callback, which tests `0x40000000`; the Ensnare reader is the separate function `0x432ac0` (`0x432af6`).
- [P36](p36.md) `0x4a5910`: user event 0 of `0x4a5990` also continues to the default procedure after marking the dialog dirty.

All other parent descriptions matched the disassembly.
