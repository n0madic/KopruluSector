# P27: Player-slot setup, sync records, elapsed time, in-game menus and message boxes, command-card actions, building placement and the unit placement search

This package covers `0x478970`–`0x47ea20`: the end of `net_record.cpp` and the object after it, `okcancel.cpp`, the object between `okcancel.cpp` and `opt_dlgs.cpp`, `opt_dlgs.cpp`, the object after it, `placebox.cpp`, and the object between `placebox.cpp` and `replay.cpp`. Its 236 atlas functions form nine groups.

1. **Replay command buffer glue** (`0x478970`–`0x478a10`). These load and save the recorder buffer of [P26](p26.md) and switch it between recording and playback.
2. **Player-slot setup** (`0x478a20`–`0x47a030`). The runtime player-slot table `0x6726c8` (12 × 36 bytes) is filled from the map setup records `0x673d48` (same layout) when a map header is loaded (`0x479bf0`). At game start (`StartGame` `0x443f40`) the code resolves random races (`0x478ee0` with the balanced picker `0x47a030`), turns lobby slot types into game types and shuffles start positions (`0x479340` → `0x479a00`/`0x479430`), and finally shuffles the color table (`0x41d460`). The lobby slot actions (open, computer, close, move, team setup) are multiplayer only and excluded.
3. **Lobby countdown** (`0x47a140`–`0x47a210`): multiplayer only, excluded.
4. **Synchronization records** (`0x47a250`–`0x47a630`). After every sent turn the game queues the 7-byte sync command `0x37` (`0x47a300`). It carries a hash from a 16-entry ring of sync records that `0x47a490` advances every executed turn. Single player builds and checks these records too. With a single player the comparison always succeeds, so they never change the game.
5. **Elapsed game time** (`0x47a610`–`0x47a7f0`). A `GetTickCount`-based seconds clock. The score screen, the save file, replays and Battle.net reports read it. Pauses are subtracted from it (`0x47cc10` → `0x47a620`).
6. **Waiting-for-players dialog** (`0x47a810`–`0x47aba0`). This is the `rez\timeout.bin` loop that runs while network turns are overdue.
7. **Message boxes and in-game menus** (`0x47acd0`–`0x47bdc0`, `okcancel.cpp`, `opt_dlgs.cpp`). It holds the glue and in-game OK and OK/Cancel boxes, the wait box, and the in-game menu tree: game menu, help, options, objectives, abort, restart and quit. A menu-depth counter `0x671a81` makes "Previous" return to the parent menu. The dialogs get a 9-slice tile frame drawn from `dlgs\tile.grp` (`0x47bb70`).
8. **Command-card button actions and pause control** (`0x47c110`–`0x47ca50`, `0x47cb20`–`0x47cc60`). These are the callbacks of the console button sets. They start targeting with an order triple (`0x4b28b0`), start building placement (`0x47d3a0`), or send a command (P25 senders). The group also holds the font color table loaders and the pause state.
9. **Building placement and the placement search** (`0x47cc80`–`0x47ea20`). This group holds the placement cursor (`placebox.cpp`) with its preview bitmaps, the validation and execution of the build command `0x0c`, the melee start units (`0x47e100`), and the unit placement search `0x47dc30`/`0x47e340` with its collision callback `0x47ea20`. That search is used by unit creation, unloading, Recall, Nydus and powerups, and is specified here in full.

## Data model

**Player-slot record** (36 bytes; runtime table `0x6726c8 + 36·s`, map setup copy `0x673d48 + 36·s`, 12 entries each, the code iterates the first 8): `+0` DWORD slot number, `+4` DWORD Storm ID (−1 = none), `+8` type, `+9` race, `+0xa` force (0 = none, 1–4), `+0xb` name (25 bytes).

Slot types as this code uses them: 0 inactive, 1 computer (in game), 2 human, 3 rescuable, 4 (treated like 3), 5 computer slot (lobby/setup), 6 open (lobby/setup), 7 neutral, 8 closed. `StartGame` turns 5 into 1, and 6 and 8 into 0 (`0x479340`). Races: 0 Zerg, 1 Terran, 2 Protoss, 5 User Select (turned into 6 by `0x46b5c0`), 6 Random.

### 0x00478970 `LoadRecordedCommandsGlobal` — `0x478640` on `*0x673d40`
- Module: net_record.cpp..okcancel.cpp · Relevance: simulation
- Status: specified
- Signature: ECX = replay file; returns the result of `LoadRecordedCommands` `0x478640`(ECX = recorder `*0x673d40`, stack [file]).

### 0x00478980 `SaveRecordedCommands` — write the command buffer to a file
- Module: net_record.cpp..okcancel.cpp · Relevance: simulation
- Status: specified
- Signature: ECX = file; returns nonzero on success, 0 on failure.
- Behavior:
  1. r = `*0x673d40`. If a block is open (`+0x14` ≠ 0), its length byte at `+0x14 − 1` = low byte of (`+0xc` + `+8` − `+0x14`), and `+0x14` = 0. `+0x18` is kept, so commands recorded later in the same frame are appended without a new block header.
  2. `WalkRecordedBlocks` `0x478430` (no effect).
  3. `0x4137d0` (compressed write, ECX = data, EDX = size, stack [file]) of the 4-byte used count `+0xc`. 0 → return 0.
  4. used ≤ 0 (signed) → return the step-3 result. Otherwise write `used` bytes from `+8`; return that result, or 0 when it is 0.
- Callers/callees: replay save `0x480080`, save game `0x498d20`.

### 0x00478a30 `ApplyTeamSetupToMapSlots` — team and Top-vs-Bottom forces for joiners
- Module: net_record.cpp..okcancel.cpp · Relevance: network
- Status: excluded (multiplayer lobby: only caller `InitJoinedLobby` `0x474c60`)
- Behavior: Nothing in a replay (`0x67cc90`) or unless a team game (`0x4b2d90`) or Top vs Bottom (`0x447e70`). Team game: for team t = 0 … team count (`0x4b2bc0`) − 1 and n = 0 … players per team (`0x4b2b10`) − 1, the next setup record k < 8 gets type 6, race = record 0's race (`0x673d51`) and force t + 1. The team-game pass writes the records directly. Top vs Bottom: an uninitialized 8-DWORD local force list gets 1 for the first `0x447c90()` records whose type is 6, 5, 3, 4 or 7 and 2 for the remaining such records. Then, still only on the Top-vs-Bottom path, every record 0–7 with a nonzero type gets type 6 and the force from that list; records 1–7 also take record 0's race, and record 0 keeps its own. A record of another nonzero type (for example 8) gets an uninitialized stack value as its force.

### 0x00478ee0 `ResolveRandomRaces` — give every Random slot a race
- Module: net_record.cpp..okcancel.cpp · Relevance: simulation
- Status: specified
- Signature: no arguments. Uses the game RNG through `RandRange` `0x478270` (source `0x90`); the caller decides whether the RNG is enabled.
- Behavior:
  1. Reset the picker: `0x673ef8` = `0x673efc` = `0x673f00` = 0, `0x673f04` = 3.
  2. m = number of slots 0–7 with race 6 and type 2 or 5.
  3. For slot s = 7 down to 0 with race 6: if the type is 2 or 5, `list[k]` = `PickRandomRace` `0x47a030`(ECX = k, EDX = m), k++ (the slot keeps race 6 for now); otherwise race = `RandRange(0, 2)`. Then, in a team game (`0x4b2d90`) and when the slot's type is 1 or 5, every slot 0–7 in the same force gets this slot's race byte (still 6 for a type-5 slot).
  4. If m ≠ 0, 16 swaps: a = `RandRange(0, m−1)`, b = `RandRange(0, m−1)`, swap `list[a]`, `list[b]`.
  5. For slot s = 7 down to 0 with race 6 and type 2 or 5: race = next `list` entry (from index 0). If step 3 turned more slots to race 6 than m, the extra slots read unset entries of the 8-byte local list.
- Callers/callees: `StartGame` `0x443f40`, `SetLocalRaceAndResolve` `0x479c90`.

### 0x004790b0 `RestoreMultiplayerSaveSlots`
- Module: net_record.cpp..okcancel.cpp · Relevance: network
- Status: excluded (returns at once unless the multiplayer byte `0x672664` is set; `StartGame` calls it only when loading a save)
- Behavior: Multiplayer only. Lobby types 5 → 1, 6 and 8 → 0 for all 12 slots. It copies the first 8 records, clears all 12, and puts each slot of type 2, 1, 3, 4 or 7 at the position `0x471850`(slot) (saved start positions). Non-human slots get Storm ID −1, `+0` is renumbered, and `0x4793b0`(`0x508d58`) runs. In a team game, for each force f = 1–4 that has a human slot (`0x4b2d20`) but no computer slot (`0x4b2cf0`) and whose leader slot `0x5264ab[f]` is not human, it swaps the leader record with slot `0x4b2930`(f) and renumbers both `+0`. It then runs `0x4793b0` again, maps a human local player to its force leader `0x5264ab[force]`, resets `0x672878[0..7]` to 8 and, for each i whose record `0x672898[i]` is human, sets `0x672878[i]` to that record's force leader.
