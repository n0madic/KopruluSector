# S02: Storm's network layer (SNet)

Package S02 specifies the network layer of the 1.17 install's `storm.dll` (SHA-256 `2c48536982309f7f03ee72908e7d2fff22aa40838c03f71b98c43775dd6313ae`, preferred base `0x15000000`): the object `SNet.cpp` at `0x15020040`–`0x15028500`. The range holds 112 Ghidra functions. 36 of them are StarCraft's imports, which [S01](s01.md) specifies; S02 revisits those entries (S01's "Phase N" paragraph lists the changes) and gives the other 76 an entry here: SNet's internal functions and the exports StarCraft does not import. With U01 (`standard.snp`'s UDP provider) it is stage N0 of the [network phase](../../phase-network.md). The wire format is collected as a format document in [storm-udp.md](../../formats/storm-udp.md).

**Method.** Static analysis, as for S01: Ghidra's decompilation of the exact DLL, checked against capstone disassembly for calling conventions, field widths, signedness and order. The binary, the decompiler output and the analysis database stay in the private workspace; no decompiled code is reproduced here. The full-game emulator executes this code only on the single-player provider 0 path (S01's runtime cross-check), where there are no remote records; everything below about remote players is a static result. Material from outside the binary was not used as evidence.

**Review (2026-11-17).** An independent reviewer re-derived every entry from the disassembly and checked the wire behavior against the network recordings of the full-game emulator (two- and four-player LAN games: packet captures of the virtual LAN and each player's SNet call log). 67 entries are confirmed and 9 corrected (`0x15020040`, `0x15020460`, `0x15021280`, `0x15021740`, `0x150217f0`, `0x15021fa0`, `0x150231b0`, `0x15023540`, `0x15024170`); the State table, Turns step 3, Joining step 2 and the pump thread's loop were corrected with them. The recordings' counts, and what they do not exercise, are in [storm-udp.md](../../formats/storm-udp.md#runtime-confirmation-2026-11-17).

**Addresses.** Storm addresses are virtual addresses at base `0x15000000`; "game" addresses are `StarCraft.exe`'s at base `0x400000`.

**Scope notes.**
- The last three functions of the range (`0x150281b0`, `0x150282d0`, `0x15028410`) belong to the next object, `SReg.cpp`. They are the registry helpers that S01's SReg section already describes, so they are `covered`, with module `storm.dll SReg.cpp` and relevance `platform`.
- Three pieces of code in the range are not Ghidra functions and have no entry: the pump thread's start routine `0x15022780` ([Threads and locks](#threads-and-locks)), the handler of control command 10 at `0x15023df0`, which only returns (`ret 4`), and the jump table `0x15025574` of `SNetGetGameInfo` (data).
- `excluded` here means: StarCraft does not import the export, or the code serves only Storm's own provider-selection dialog, which StarCraft never opens.

## Protocol summary

### State

SNet keeps all of its state in globals guarded by one critical section.

| Global | Meaning |
|---|---|
| `0x1506b904` | SNet critical section; every export and the pump thread hold it while they touch any state below |
| `0x1506b91c` | event-queue critical section; guards only the queued-event list `0x15066744` (header) / `0x15066748` (head) |
| `0x1506671c` / `0x15066724` | provider list (header / head; terminator `0x15066720`), filled once by `ScanProviders` `0x15022a30`; loaded flag `0x1506b8f0` |
| `0x1506b8ec` | current provider record (0x238 bytes) |
| `0x1506b8e4` | the provider's module handle |
| `0x1506b8e0` | the provider's function table, copied into a zeroed 0x70-byte buffer; 0 = no provider |
| `0x1506b8f4` | the 8 KB send buffer, allocated and locked when caps flag bit 0 is set |
| `0x1506b8e8` | send clock (tick at which the provider is modelled to be idle) |
| `0x1506b8f8`, `0x1506b8fc`, `0x1506b900` | pump event (auto-reset), pump stop flag, pump thread handle |
| `0x15066728` / `0x15066730` | remote player records (header / head), in creation order |
| `0x15066734` / `0x1506673c` | the local player record (a list of at most one) |

| `0x1506b934`–`0x1506b940` | name table: capacity, count, buffer (0x80 bytes per id), growth step |
| `0x1506b9d8`, `0x1506b958`, `0x1506ba58` | game name, stat string, password (0x80 bytes each) |

### Player records

A player record is 0x214 bytes, zero-filled at creation (`CreatePlayerRecord` `0x150204c0`). Classes are indexed c = 0..3.

| Offset | Field |
|---|---|
| +0x000 | list link |
| +0x008 | name (0x80) |
| +0x088 | description (0x80) |
| +0x108 | 16-byte provider address |
| +0x118 | flags: 4 joining (enters at a later turn), 8 dropping |
| +0x11C | tick last heard (any non-relayed packet) |
| +0x120 | tick of the last turn resend request about this player |
| +0x124 | tick of the last ping sent |
| +0x128 / +0x12C | last / largest round-trip time (ms) |
| +0x130 + 12c | outgoing queue of class c: sent packets not yet acknowledged |
| +0x160 + 12c | receive queue of class c, sorted by sequence |
| +0x190 + 12c | delivered list of class c (the message handed to the caller last) |
| +0x1C0 | turn history: delivered class-2 packets kept for resends |
| +0x1CC + 2c | u16 next sequence to send to this player (+0x1D0 = turns sent to it) |
| +0x1D4 + 2c | u16 next sequence to consume from this player (+0x1D8 = its next turn) |
| +0x1DC | u16 last class-2 ack received from this player |
| +0x1DE + 2c | u16 cumulative ack owed to this player |
| +0x1E6 + 2c | u16 ack last sent to this player |
| +0x1F0 + 4c | u32 ack timer start (0 = no ack pending) |
| +0x200 | host flag |
| +0x204 | connecting flag (handshake in progress) |
| +0x208 | tick of the connect request |
| +0x20C | drop reason |
| +0x210 | u16 drop turn |
| +0x212 | id (`0xFF` = none) |
| +0x213 | old id (the id before a drop; `0xFF` = none) |

Each list is a Storm intrusive list: a 12-byte header {link offset, terminator, head}; a head or next value ≤ 0 ends a walk, and nodes are appended at the tail, so every list iterates in insertion order. A packet node is 0x20 bytes:

| Offset | Field |
|---|---|
| +0x08 | address pointer |
| +0x0C | packet (header + payload) |
| +0x10 | packet length |
| +0x14 | 1 = Storm owns address and packet (freed by SMemFree); 0 = the provider's (returned through its FreePacket slot) |
| +0x18 | creation or receipt tick |
| +0x1C | timer: on send, the send clock after transmission; on receipt, now − max(L,50) + max(L/2,25); reset to now when a resend or a gap request is made |

### Packets

Every SNet packet is one provider datagram: a 12-byte little-endian header followed by the payload.

| Offset | Size | Field |
|---|---|---|
| +0 | u16 | checksum |
| +2 | u16 | length: 12 + payload |
| +4 | u16 | sequence (per destination and class) |
| +6 | u16 | ack: the next sequence the sender expects from the destination in this class |
| +8 | u8 | class 0–3 |
| +9 | u8 | command (class 0 only; 0 elsewhere) |
| +10 | u8 | sender's id (`0xFF` before the sender has one) |
| +11 | u8 | flags: 1 ack only, 2 resend request, 4 relayed |

**Checksum** (`0x15021c50`, `0x15021ca0`). Over the bytes from +2 to the end, walked from the last byte to the first: `a += byte`, minus 255 when `a` exceeds 254; then `b += a`. With `lo = b mod 255` (the code computes it as the byte `b + b/255`) and `hi = a`: byte +1 = `0xFF − (lo + hi) % 255`, byte +0 = `0xFF − (byte1 + hi) % 255`. A receiver runs the same sum over the whole packet and accepts it only when the 16-bit result is 0.

**No compression, encryption or fragmentation.** Nothing in SNet calls a compressor or a cipher, and a payload larger than one datagram is not split. With the locked send buffer (caps flag bit 0, set by UDP) a packet above `0x1F00` bytes, or a send to more than 16 addresses, is silently not sent. The size is not checked against the provider's maxmsg; StarCraft limits its own turns to min(maxmsg, 0x200).

### Classes and commands

| Class | Use | Ordered | Acknowledged | Recovered by |
|---|---|---|---|---|
| 0 | control: SNet's own commands | yes | yes | sender retransmits the queue head |
| 1 | messages (`SNetSendMessage`) | yes | yes | sender retransmits the queue head |
| 2 | turns (`SNetSendTurn`) | yes, per sender | collectively | receivers ask (resend requests), any seat can relay |
| 3 | datagrams (`SNetSendDatagram`, not used by StarCraft) | by sequence per sender, without waiting for gaps | no | nothing |

Class-0 packets are delivered in sequence by `DispatchControlPackets` `0x15023e40`, which raises SEvt `'SNET'` type 2 with the command as id; `SNetInitializeProvider` registers these handlers. The handler argument is `{address pointer, payload pointer, payload size, u8 sender, u8 command}`.

### Reliability

- **Sequences.** A sender numbers each class per destination record (+0x1CC + 2c, u16, wrapping). Command 1 always carries sequence 0 and does not advance the counter. Loopback packets (to the local record) get the local record's own counters.
- **Acks.** Every packet carries, at +6, the cumulative ack the sender owes the destination in that class (+0x1DE + 2c). On receipt of a non-relayed packet `ProcessAck` `0x15021030` frees the destination's outgoing packets of that class whose sequence is older than the ack; for class 2 it also stores the ack in +0x1DC. A standalone ack (flags 1, sequence = ack) goes out when an ack is owed (+0x1DE ≠ +0x1E6) and its timer (+0x1F0) has run for `max(L/2,25)` ms in classes 0 and 1, or `max(5L,250)` ms in class 2.
- **Retransmission.** Classes 0 and 1: only the head of a destination's outgoing queue is retransmitted, when `now − node+0x1C ≥ (maxmsg + 128 + length)·1000 / bytesPerSec + 2·(max(L,50) + 100)` (maxmsg already reduced by 16; integer division). Class 2 is never retransmitted on a timer.
- **Gaps.** For classes 0–2, when a destination's receive queue holds a packet beyond a missing sequence, `RunNetTimers` `0x15020b80` sends a 12-byte resend request (flags 2, sequence = the first missing one) when the later packet's timer is due, then every `max(L,50)` ms. The request is answered from the requester's outgoing queue (or, for class 2, from the answering seat's turn queue and history).
- **Receipt.** A packet whose sequence is older than the next expected one is dropped; in classes 0 and 1 this also forces an ack to be resent (+0x1E6 = +0x1DE − 1, timer started). A duplicate of a queued packet replaces nothing: the new copy is freed. Other packets are inserted in sequence order. Classes 0 and 1 then advance +0x1DE over the contiguous run and start the ack timer.
- **Collective turn ack.** On every received turn the seat recomputes one class-2 ack for all remotes: the first turn u, starting at the sender's next turn, that some eligible remote has not delivered into its queue (eligible: has an id and is not joining, or joins at or before u). Every eligible remote's +0x1E2 becomes u and its ack timer starts. A seat therefore acknowledges turn u to anybody only once it holds turn u from everybody, and `TrimTurnHistory` `0x150205c0` keeps each delivered turn until every remote has acknowledged it.
- **Relays.** A 13-byte resend request names (byte +12) the player whose turn is missing. A seat that holds that turn in the named player's queue or history marks its stored copy as relayed (flags | 4, checksum recomputed) and resends it to the requester. A relayed packet is attributed by its sender byte instead of its address, and its ack field is ignored. If the named player has been dropped at the answering seat, the answer also includes a command 0x0C with that seat's drop turn and reason.

### Turns

- `SNetSendTurn` sends the turn as class 2 to every remote that has an id and whose turns-sent counter (+0x1D0) equals the local record's, then appends it to the local receive queue (loopback), and signals the pump.
- `SNetReceiveTurns` (T = the local next turn):
  1. `ProcessDrops` `0x150218e0`; joining players whose next turn equals T lose the joining flag and get event 2; queued events are dispatched outside the lock; `TrimTurnHistory`.
  2. Status words per slot: `0x10000` the record exists and is not joining; `0x20000` its turn-T packet is at the head of its queue; `0x40000` the slot is local, or the player was heard within `max(4L,1000)` ms, or it is being dropped and its turn T is present.
  3. For each present remote P: when P's turn T is missing and P's resend-request tick (+0x120) is 0 or at least `max(L,50)` ms old (and less than 2³¹ ms), a request {sequence = P's next turn +0x1D8, ack = the recipient's class-2 ack +0x1E2, class 2, flags 2} goes to every remote with an id (to P alone when P has none): 12 bytes to P, 13 bytes (byte 12 = P's id) to the others. Then, whether or not P's turn is missing, P is pinged (class-0 command 4) when nothing is queued in its class-0 outgoing queue and it was neither heard from nor pinged for `max(4L,1000)/2` ms.
  4. When every present slot has turn T, each slot's packet moves to the history and the call returns it; the local turn becomes T+1.
- Delivery is lockstep: a turn is returned only when every present player's turn T is there, and every seat walks the same turn numbers.

### Messages and datagrams

- Targets: −2 = every remote with an id; −1 = the same plus the local record (loopback); otherwise one player by id (the base is subtracted first; the local record is searched first, so a seat can message itself).
- `SNetReceiveMessage` picks, among records whose next class-1 packet is at the queue head and who are not joining, the one whose queued packets are oldest by receipt tick, and hands over one message per call. Datagrams (class 3) are picked the same way among any queue heads, joining players included.

### Joining

Joiner J, host H:

1. J: `SNetJoinGame` leaves any game (reason 2), asks the provider for the game's record (`GetGameInfo`, slot +0x14). The record's program id (+0x134) and version (+0x138) must equal J's own (`0x1506bae8`/`0x1506baec`; StarCraft 1.17 passes version `0xD5`), else `0x85100079`. Both fields are preset to J's own values before the call, so the check only fails when the provider reports other values.
2. J creates H's record (connecting, control sequences +0x1CC/+0x1D4/+0x1DE = 1, so command 1 carries ack 1 and J's next control packet has sequence 1), sends command 1 `{u32 1}` three times in a row, and drops it from its own outgoing queue, so it is never retransmitted.
3. H: a command 1 from an address whose record took a connect request less than `max(4L,1000)` ms ago is a repeat and is ignored. Otherwise H deletes any record of that address, creates a fresh connecting record that expects control sequence 1, and replies command 2 `{u32 1}`.
4. J's command-2 handler replies command 3. J waits for command 2 for `max(12L,5000)` ms (5000 ms with UDP); no answer → `SNetLeaveGame(1)` and error `0x4D0`.
5. J sends command 7 {name, description, password} and waits for command 9 or 10 for the same time (→ `0x4D0`).
6. H rejects with command 10 when the game holds `max players` players already, mode bit 8 (closed) is set, the password differs (case-insensitive; an empty game password accepts any), or no id below `0xFF` and below max players is free. Otherwise H gives J the lowest free id (local and remote records searched), sets J's next turn to H's turns sent (J is joining when that is ahead of H's next turn), and sends J, in order: command 8 (game info), command 6 for H, command 6 for every other remote with an id, command 15, command 9 (template). Then command 6 about J to every other remote, and finally a resend of every turn in H's own turn queue to J. H sets mode bit 2 when the game is now full and re-advertises.
7. J: command 8 sets J's id, turn counters and game data; each command 6 creates a record (and replays J's own turns to it, of which there are none yet); command 9 stores the id byte, keeps the template and queues event 1. J's local id is still `0xFF` until command 9, so no event 2 is raised for the players already in the game.
8. J: still no id after the wait → `SNetLeaveGame(1)` and `0x85100067` for every kind of rejection; success → events dispatched outside the lock; if the game ended meanwhile → `0x85100069`.

### Leaving, dropping and host migration

- **Leave** (`SNetLeaveGame`): a host stops advertising; every remote with an id gets command 0x0B {u32 turns sent to it, u32 reason}, transmitted three times (one send and two resends). The records are then freed, so a lost 0x0B is never retransmitted. The receiver flags the sender's record as dropping with that turn and reason.
- **Drop** (`SNetDropPlayer`): flags the player as dropping at its next turn (+0x1D8 at this seat) and sends command 0x0C {id, turn, reason} to the other remotes, which overwrite their drop turn and reason for that id. `SNetDisconnectAll` flags every remote the same way and sends nothing.
- **Removal** (`ProcessDrops`, run at the start of `SNetReceiveTurns`, `SNetReceiveMessage`, `SNetReceiveDatagram` and `SNetGetOwnerTurnsWaiting`): a dropping player with an id whose next turn has reached the drop turn ((u16)(next − drop turn) < 0x8000) gets event 3 (data = the u32 reason), loses its flags, keeps its id as old id and gets id `0xFF`. The record stays (its turns can still be relayed) until `RunNetTimers` deletes it 50 s after it was last heard. Storm never drops a silent player by itself; it only reports him through status bit `0x40000`.
- **Event 3 reasons** are what the leaving or dropping seat passed: StarCraft's own `SNetLeaveGame` calls pass `0x477e50`'s argument or 3, and 3 from its other callers (S01); Storm's internal leaves pass 1 (failed join or advertising) or 2 (creating or joining while in a game); `SNetDestroy` passes 3; the game calls `SNetDropPlayer` with 3 (`0x4778e0`) or `0x40000006` (`0x477060` from `ResolveDesync` `0x47a630`, [P27](p27.md)) and `SNetDisconnectAll` with `0x40000006`.
- **Host migration.** When a seat that is not host removes a player, it looks at the remotes still having an id: if none of them is host and the seat's own id is lower than all of theirs (or none remain), it sets its host flag and sends command 0x0D {its id} to them; receivers move the host flag to that id. The new host clears the full bit when there is room and re-advertises.

### Leave ordering (replay command 0x57)

- A voluntary leave carries the leaver's turns-sent count T_leave, which is the same number at every seat (turns go to all seats alike). A seat removes the leaver only when it has delivered all of the leaver's turns below T_leave; until it has received the 0x0B, the leaver stays present and turn T_leave cannot complete. The removal happens in the `ProcessDrops` that precedes the delivery of turn T_leave, at the latest at the start of that `SNetReceiveTurns` call; an earlier `SNetReceiveMessage` call can raise event 3 first.
- The game stores the reason in its event-3 handler `0x477a00` and acts on it in `0x477da0`, which runs only after a successful `SNetReceiveTurns` ([P26](p26.md)). The first success after the removal is the call that returns turn T_leave. So every seat records `HandlePlayerLeftGame`'s replay command 0x57 right after receiving turn T_leave, the same turn everywhere: deterministic, provided each seat obtains all of the leaver's turns below T_leave. Missing ones can be relayed by any seat that holds them, since the leaver's record and its history survive the removal.
- If all three 0x0B datagrams are lost, the leaver stays present without turns; the game's own timeout then drops him through `SNetDropPlayer`, with the drop reason instead of the leave reason.
- A drop (0x0C) carries the dropping seat's view of the player's next turn. A seat that has already delivered that turn applies the drop at its next `ProcessDrops`, possibly at a later turn than the dropping seat, so drops decided by single seats (`ResolveDesync` `0x47a630`, [P27](p27.md)) are per-seat events. Storm aligns late seats only partly: a seat asked for a dropped player's turn answers with its 0x0C.

### Game list and advertising

- **Advertising** (`AdvertiseGame` `0x15021be0`): provider slot +0x40 with the game name, password, stat string, mode, uptime in seconds, game type, program data +0x28, ladder type and a 12-byte player record {u32 12, u32 players (the local player plus remotes with an id, 0 when not in a game), u32 max players}. Hosts re-advertise after a join, a removal and a mode change.
- **Listing** (`CopyGameList` `0x150217f0`, used by `SNetEnumGamesEx` and ordinal 104): the provider's list (slot +0x28) is copied entry by entry, skipping entries with any of bits `0xB` (password, full, closed) in their flags byte +4, so private, full and closed games are never shown. Record: +0 id, +4 flags, +0xC 16-byte address, +0x24 game type, +0x28 name, +0xA8 stat string, +0x128 next, +0x12C extra-data pointer, +0x130 extra-data size, +0x134 program id, +0x138 version. Ageing and removal of stale entries are the provider's (U01).

### Timers

L is the provider's caps latency (+0x22C of the provider record). The UDP provider's latency is 50 ms (U01), which puts every value at its floor:

| Global | Value | UDP (ms) | Use |
|---|---|---:|---|
| `0x15066708` | max(5L, 250) | 250 | class-2 ack delay |
| `0x1506670c` | max(12L, 5000) | 5000 | each wait of the join handshake |
| `0x15066710` | max(4L, 1000) | 1000 | "heard recently" (status `0x40000`); repeat window of command 1; half of it = turn-wait ping interval |
| `0x15066714` | max(L/2, 25) | 25 | class-0/1 ack delay; first gap request after a later packet |
| `0x15066718` | max(L, 50) | 50 | gap and turn resend-request interval; part of the retransmit interval; sleep at the end of `SNetLeaveGame` |
| constant | 20000 | 20000 | idle ping per remote (`RunNetTimers`) |
| constant | 50000 | 50000 | deletion of a record without id after silence |

The retransmit interval with UDP (maxmsg 488, 100,000 bytes a second) is `(616 + length)·1000/100000 + 300`, 306–311 ms. The send clock adds `(length + 64)·count·1000 / bytesPerSec` ms per provider send.

### Threads and locks

- **Pump thread** `0x15022780`, created by `StartPumpThread` `0x15021d90` at `THREAD_PRIORITY_HIGHEST`. Loop: wait on the event `0x1506b8f8` with the timeout `RunNetTimers` returned last (INFINITE at first); exit when the stop flag is set; enter the SNet lock; with no provider loaded, leave the lock and end the thread; otherwise, when the event was signalled, poll the provider's external messages (`0x15021e10`) and receive packets (`0x15021fa0`), then run the timers and keep their result as the next timeout, and leave the lock.
- The event is handed to the provider's Initialize so that the provider signals it when data arrives; `SNetSendTurn`, `SNetSendMessage` and `SNetSendDatagram` signal it too. Packets are read only after a signal. The 20-second idle ping does not shorten the timeout, so it is sent only when the thread wakes for another reason. `SNetReceiveTurns` does not signal the event: when the last timer pass left nothing pending, a control packet it sends (its ping) is not retransmitted until a datagram arrives or the game sends something.
- Control-command handlers run on the thread that receives the packet (the pump thread, or the `SNetJoinGame` caller during its handshake), with the SNet lock held.
- User events (SEvt `'SNET'` type 1) are queued under the event lock and dispatched on the caller's thread with the SNet lock released, by `SNetReceiveTurns`, `SNetReceiveMessage`, `SNetReceiveDatagram` and `SNetJoinGame`.
- `SNetJoinGame` keeps the SNet lock for its whole handshake and pumps the provider itself (`PumpUntilControl` `0x15023f40`, 10 ms sleeps), so the pump thread waits on the lock meanwhile.
- `SNetDestroy` sets the stop flag, signals the event and waits for the thread.

### Corrections to earlier statements

- S01 said `SNetLeaveGame` transmits 0x0B twice: it is sent three times (one `SendPacket` and two `ResendPacket` calls).
- S01's step 4 of `SNetReceiveTurns` ("frees the turn buffers delivered by the previous call") holds in single player only: `TrimTurnHistory` frees a delivered turn once every remote has acknowledged it, which in single player is at the next call.
- The 2500 ms "still alive" window of `0x475ac0` ([P26](p26.md)) is the executable's own; Storm's per-player window is `max(4L,1000)` = 1000 ms with UDP. Both statements stand.
- S01's provider order (unranked providers by name, then SCBL, MODM, IPXN, BNET) is confirmed: the comparator returns rank(new) − rank(existing) and a new record goes before the first existing one it outranks; the ranks are BNET 0, IPXN 1, IPXW 2, MODM 3, SCBL 4, MSDP 5, others `0x7fffffff`.

### 0x15020b80 `RunNetTimers` — pings, gap requests, retransmissions and acks
- Module: storm.dll SNet.cpp · Relevance: network · Status: specified

### 0x15021fa0 `ReceivePackets` — read, check and file every waiting datagram
- Module: storm.dll SNet.cpp · Relevance: network · Status: specified

  2. Dropped (returned to the provider) unless: R and the local record exist; length ≥ 12; header length between 12 and the datagram length; class ≤ 3; the checksum sums to 0; and, when not joining, not relayed and the sender byte is not `0xFF`, `FindRecordById`(sender) is R.

  4. Not relayed: R's last-heard = now; `ProcessAck`(R, class, header ack).
  5. Flags 1 (ack only): done.
  6.
