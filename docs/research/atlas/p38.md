# P38: Computer-AI regions (captains) — region states, military groups, attack planning, reactions to attacks

This package covers `0x4acca0`–`0x4b1710` (90 functions), the tail of the object between `statwire.cpp` and `teams.cpp`. Its allocation strings name it `TAI_Captain.cpp`. The code maintains, for each of the eight players, one **AI region record** per map region. A record holds the region's AI state, its strength needs, its threat targets and a list of the **military AI records** of units assigned to it. On top of that table sit the AI-script opcodes that change regions (`help_iftrouble`, `capt_expand`, `implode`, `value_area`, `clear_combatdata`, `attack_prepare`, `rush`, `eval_harass`, `send_suicide`, bunker/turret/transport/patrol opcodes). The package also holds the periodic regional scheduler, regional recruitment and production, the computer reaction to being attacked, and the military group-movement predicates used by ComputerAttackMove.

The functions form six groups.

1. **Script opcodes on regions** (`0x4acca0`–`0x4ad9e0`, `0x4ade10`, `0x4aded0`, `0x4af300`–`0x4af6d0`, `0x4b05c0`, `0x4b0600`, `0x4b0ec0`–`0x4b0fe0`, `0x4b11b0`, `0x4b13d0`, `0x4b1710`). The AI script dispatcher `0x493a60` ([P32](p32.md), [AI opcodes](../native-ai-opcodes.md)) calls them.
2. **Periodic regional AI** (`0x4acdf0`, `0x4adbd0`, `0x4adcf0`, `0x4af930`, `0x4b0ce0`, `0x4b0d70`, `0x4b1500`, `0x4b15d0`). The per-step scheduler visits 333 region slots per object step and dispatches each region by state; state handlers live in P37 (`0x4ac690`–`0x4acbc0`), as do the state changer `0x4ab900` and the strength/target providers `0x4a9330`, `0x4a9800`, `0x4a9820`.
3. **Military AI records** (`0x4ad9a0`, `0x4ad9c0`, `0x4ae760`, `0x4ae960`, `0x4b0770`, `0x4b1010`, `0x4afd40`, `0x4b13d0`): allocation into a region, removal, transfer, save/load index encoding and the per-unit military step.
4. **Reaction to attacks** (`0x4aebc0`, `0x4ae3e0`, `0x4af220`–`0x4af2c0`, `0x4b1380`, `0x4ae080`, `0x4ae040`, `0x4b0210`).
5. **Group movement and patrol** (`0x4adf80`, `0x4afaf0`, `0x4afb20`, `0x4afec0`, `0x4aff20`, `0x4b09c0`, `0x4b0af0`, `0x4b0e10`, `0x4af810`).
6. **Region marking used by towns and production** (`0x4ae220`, `0x4ae380`, `0x4b0030`, `0x4b00a0`, `0x4b0be0`, `0x4b1420`, `0x4b1470`, `0x4b0960`, `0x4b14d0`, parent/pair selectors `0x4b0250`–`0x4b0430`).

## Data model

**AI region array** `0x6b1a74[8]` (`g_aiRegions`): one pointer per player to `count` records of `0x34` bytes, indexed by map region ID (record 0 exists but every loop here starts at ID 1). `0x4b0640(0)` allocates 2500 records per player at game start; `0x4b0640(1)` shrinks each array to the actual region count; `0x4af920` frees them. Layout (matches [combat AI](../native-combat-ai.md#regional-scheduler-and-state-layout), confirmed at every access below):

| Offset | Meaning |
|---|---|
| `+0x00` | u16 region ID (set at init; 0 for record 0) |
| `+0x02` | u16 stored destination region ID (attack target, staging→destination) |
| `+0x04` | u8 owner player |
| `+0x05` | u8 state (0 idle, 1/2 attacked or moving group, 3 abandoned, 4 defend/expand, 5 own buildings, 6 main base, 7, 8 attack staging, 9 attack in progress) |
| `+0x06` | u8 defense priority (written together with `+5` as the WORD `+5`) |
| `+0x07` | u8 retry countdown (decremented by `0x4b0ce0`) |
| `+0x08` | u8 flags: `0x01` defend/build here, `0x02` Bunker wanted, `0x04` recently patrolled (cleared by every `0x4b0ce0` visit), `0x10` Missile Turret wanted, `0x20` under attack, `0x40` non-campaign defense |
| `+0x0a` | u16 count of non-air military members |
| `+0x0c` / `+0x0e` | u16 needed ground / air strength |
| `+0x10` / `+0x12` | u16 local ground / air strength (members inside the region) |
| `+0x14` / `+0x16` | u16 assigned ground / air strength (all members) |
| `+0x18` / `+0x1a` | u16 enemy air / enemy ground strength |
| `+0x1c` / `+0x20` | air target unit / ground target unit |
| `+0x24` | slowest member (group leader) |
| `+0x28` | patrol/detector unit claimed for this region |
| `+0x2c` | pointer to the military-record pool (`0x6acc50` in every record) |
| `+0x30` | head of the military record list |

**Military AI pool** `0x6acc50` (`g_militaryAiPool`): 1000 records of 20 bytes; the free-list head is the DWORD at `+0x4e20` (`0x6b1a70`). Record: `+0` next, `+4` prev, `+8` AI type byte = 4, `+0xc` unit, `+0x10` region record. `+0xa` (a WORD inside the record's `+8` DWORD) holds the region ID where the unit last received HarassMove (written by `0x4ada90`). Units point to their record through `CUnit+0x134`.

**Common predicate "valid military"**: unit `+0x134` nonnull, record type byte `+8` = 4, record `+0xc` = the unit, and units.dat special-ability flag `0x1` (building, `0x521660[type]`) clear.

**State reset when leaving state 0** (inline copy in `0x4acca0`, `0x4ad430`; the same work `0x4ab900` performs): `v = default_min(owner)` (PlayerAi `+0x222`, `0x4837d0`) when the owner is campaign AI (`0x4831e0`, PlayerAi flag `0x20`), else 0; if the terrain region is inaccessible (`0x481bb0`, class `0x1ffd`) then needed ground = 0 and needed air = `v`, else needed ground = `v`, needed air = 0; zero `+0x10`…`+0x2b`; destination `+2` = 0.

**Other globals**: `0x6b1a94`/`0x6b1a98` scheduler player/region cursors; `0x6b1a9c` alert pass flag (0 near pass, 1 far pass); `0x6b6900` "Interceptor alert already sent this frame"; `0x6b1aa0` (20000 bytes) and `0x6b68c0` (32 bytes) region-reachability scratch used by P37 `0x4ab330`/`0x4abe90`, zeroed by `0x4b0640`; `0x6ac530[228]` / `0x6ac8c0[228]` per-type air / ground strength DWORDs (read by `0x4a97e0`/`0x4a97f0`); `0x534914 + 12·a + b` alliance byte (0 enemy, 1 allied, 2 allied victory); `0x6726d0 + 36·p` controller byte (1 computer); `0x5349d8` elapsed game seconds; `0x5264cc[p]` shared-vision masks; PlayerAi `0x67d068 + 0x4e8·p` (layout in [P28](p28.md)); unit counts `0x529604` (all, `0x4143c0`) and `0x52c0c4` (completed, `0x4143e0`), both `[type·12 + player]` DWORDs.

**CUnit fields used**: `+0x4c` owner, `+0x4d` order, `+0x54` order timer, `+0x5c` target, `+0x64` type, `+0x6c` next of player, `+0x70` subunit, `+0x74` order-queue head, `+0x7c` auto-target, `+0x80` connected unit / container, `+0xc0` Interceptor parent, `+0xc8`/`+0xc9` hangar counts, `+0xdc` status (`0x1` completed, `0x2` grounded building, `0x4` air, `0x10` burrowed, `0x20` in building, `0x40` loaded, `0x100` cloaked, `0x800` cloaked by an Arbiter, `0x3000` order-locked, `0x8000` cannot attack, `0x20000` see shared facts), `+0x117` Lockdown, `+0x123` blinded, `+0x124` Maelstrom, `+0x126` acid spore count, `+0x134` AI record, `+0x138`/`+0x13a` cached air/ground strength.

## Functions

### 0x004acca0 `HelpAlliesInTrouble` — script `help_iftrouble`
- Module: statwire.cpp..teams.cpp · Relevance: ai
- Status: specified
- Signature: `__fastcall`, ECX = player `p`; no return value.
- Behavior: `n` = region count (`0x481b00`). For each other player `q` = 0..7 in order, skip unless `alliance[p][q]` ≠ 0, `alliance[q][p]` ≠ 0 and `n` > 1. For region `r` = 1..n−1: when `p`'s record has state ≠ 0, `q`'s record has state 0 and a nonzero ID, it applies the state reset to `q`'s record (campaign/default_min of `q`), clears flag `0x20`, and writes the WORD `+5` = `0x2804` (state 4, priority 40). It writes directly; it does not call `0x4ab900`. `q = p` also qualifies when self-alliance is set, but then the state test cannot pass.
- Callers/callees: AI script opcode `0x6e` in `0x493a60`.

### 0x004acdf0 `EvaluateGlobalAttackOpportunity` — strength census and forced attacks
- Module: statwire.cpp..teams.cpp · Relevance: ai
- Status: specified
- Signature: no arguments, no return. Tail of the AI economy timer `0x48df50`.
- Behavior:
  1. Returns while elapsed seconds `0x5349d8` < 360, or when any of players 0..7 is campaign AI (`0x4831e0`).
  2. Zeroes four 8-DWORD arrays: `own[]`, `team[]`, `hostile[]`, `rival[]`. Walks the active unit list (`0x425600`, next `+4`); skips inactive units (`0x41fe40`) and owners ≥ 8. With `g` = cached ground strength `+0x13a` (u16) and owner `o`: `own[o] += g`. If the type has none of flags `0x1`/`0x8` (building, worker): `team[q] += g` for every `q` with `q == o` or `alliance[o][q] == 2`. For every `q`: `hostile[q] += g` when `alliance[q][o] == 0` or `alliance[o][q] == 0` (buildings and workers included).
  3. For each row `r` and column `c` (both 0..7): if `alliance[r][c] == 0`, `rival[c] = max(rival[c], team[r])` (unsigned).
  4. For each player `p` with controller 1: `0x482cb0(p, rival[p] < own[p])` (sets or clears PlayerAi flag `0x200`, which suppresses unit requests). Then if (`team[p]` ≥ 6000 or elapsed ≥ 2700) and `hostile[p]` ≠ 0 and `team[p]` > 2·`hostile[p]` (unsigned 32-bit): `SendSuicide` `0x4b11b0(p, DL = 0)` and `StartAttackGrouping` `0x483ad0(p, 0)`.
- Prior evidence: [AI wave](../native-ai-wave.md) (360-second gate), [frame](../native-frame.md) (cadence).

### 0x004ad230 `ResetAttackGroupRegions` — region part of `attack_clear`
- Module: statwire.cpp..teams.cpp · Relevance: ai

### 0x004ad310 `CaptainExpand` — script `capt_expand`
- Module: statwire.cpp..teams.cpp · Relevance: ai
- Status: specified
- Signature: `__fastcall`, ECX = player, EDX = small-only flag (the opcode passes 0).
- Behavior: Runs one pass with the given flag; when the flag was 0 it runs a second pass with flag 1. Each pass:
  1. Zeroes a 2500-byte mark array.
  2. For regions 1..n−1, considering only regions with terrain tile count (`+4` of the terrain region) ≤ 10 when the flag is set: clear record flag `0x01`; if the player is campaign AI also clear `0x40`; if the state > 3, mark every neighbor ID (`0x481ad0`, all neighbors).
  3. For regions 1..n−1: when marked and in state 0: `0x4ab900(record, 4)`, flags `|= 0x01`, and `|= 0x40` for campaign AI.
  The second pass therefore extends the defended area by one more ring through small regions only.

### 0x004ad430 `ImplodeRegions` — script `implode`
- Module: statwire.cpp..teams.cpp · Relevance: ai
- Status: specified
- Signature: `__fastcall`, ECX = player.
- Behavior: In ascending region order 1..n−1, for each record in state ≤ 3: walk its neighbor list (all neighbors) counting neighbors whose live state is ≤ 3; stop at the second such neighbor. Only if the walk reached the end (at most one neighbor in state ≤ 3, including zero neighbors) and the ID is nonzero: if the state is 0 apply the state reset; then clear flag `0x20` and write WORD `+5` = `0x2804` (state 4, priority 40). States 1–3 are overwritten without reset. Changes made earlier in the same scan are visible to later neighbor counts.

### 0x004ad550 `EvaluateRush` — script `rush`
- Module: statwire.cpp..teams.cpp · Relevance: ai
- Status: specified
- Signature: `__fastcall`, ECX = player `p`, EDX = kind, stack [x, y]; `ret 8`; returns 1 when the enemy matches the kind's "weak" profile, else 0.
- Behavior:
  1. `PrepareAttack` `0x4af300(p, x, [y, 0, 0])`; nonzero → return 0.
  2. `g` = PlayerAi WORD `+0x21e` (`0x483800`); the point becomes the center of region `regions[p][g−1].+2`.
  3. Scans the active list for active units with the building flag that are enemies of `p` (`0x429110`, alliance `[p][owner]` = 0; owner 11 uses the sprite's player). With `d` = approximate distance (`0x405cf0`) from sprite to the point: if `d` ≤ 320 and the owner equals the current best owner, stop; otherwise if `d` ≤ best distance (start 99,999,999), the owner becomes best (ties go to the later unit). No candidate → return 0.
  4. `0x483770(p, 1)` (clear roster, attack word and grouping time, reset regions).
  5. With `e` = best owner, completed counts `C(t)` (`0x4143e0(t, e)`), `T` = Marines + min(4·Bunkers, Marines) (`0x4aa4c0`), `Z` = 2·Sunken Colonies + Hydralisks (`0x4adde0`), `A` = 2·Spore Colonies + Hydralisks + Mutalisks (`0x4adb90`), all unsigned:

     | Kind | Returns 1 when |
     |---|---|
     | 0 | all-units counts (`0x4143c0`, including unfinished) of Barracks 111, Spawning Pool 142 and Gateway 160 are all 0 |
     | 1 | T ≤ 16, Z ≤ 10, Zealots ≤ 6 |
     | 2 | T ≤ 24, A ≤ 10 |
     | 3 | T ≤ 5, Z ≤ 2, Hydralisk Dens = 0, Zealots ≤ 1 |
     | 4 | T ≤ 16, Z ≤ 10, Zealots ≤ 8 |
     | 5 | T ≤ 6, Z ≤ 6, Zealots ≤ 3 |
     | 6 | T ≤ 12, Sunken Colonies ≤ 1, Dragoons ≤ 1 |
     | 7 | Siege Tanks (5) = 0, Queens (45) = 0, Zealots ≤ 6 |
     | 8 | T ≤ 5, Z ≤ 2, Zealots ≤ 1 |
     | 9 | T ≤ 9, Z ≤ 4, Zealots ≤ 5 |
     | 10 | T ≤ 4, Z ≤ 4, Zealots ≤ 2 |
     | 11 | T ≤ 10, Z ≤ 10, Zealots ≤ 5 |
     | 12 | T ≤ 16, A ≤ 5, Scouts + Dragoons ≤ 2 |
     | 13 | T ≤ 24, A ≤ 10, Scouts + Dragoons ≤ 7 |
     | > 13 | never (return 0) |
