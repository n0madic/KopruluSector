# ADR 0025: Seats, the network branches and the shared state

Status: accepted (2026-11-15). The user approved phase M's design inline on 2026-11-15 ([phase M](../phase-multiplayer.md)): the original's network branches in `kp_core` under the multiplayer byte, several seats in one deterministic game, the seat-local state out of a shared hash, and a turn hub that stands for the network. Stage M5 (the network branches) is built (2026-11-16, decisions 1–8; team games, decision 9), and stage M6 (the seats, the shared hash and the turn hub, decisions 10–16) too (2026-11-16). Phase M's acceptance (stage M7, 2026-11-16) passed: [phase M](../phase-multiplayer.md#m7-acceptance); the network branches stay fixture-verified.

## Context

Until phase M the native core played one person's game.

- **No multiplayer byte.** The original tests `0x672664` in 36 places of the simulation and its commands. Koprulu took the single player's branch everywhere, or refused the network's commands (`0x0d`, `0x0e`, `0x1d`, `0x57`) in replays.
- **Waits nobody ends.** A single player's Transmission and Center View wait until the interface releases them, by the real time and outside the command stream. A network game cannot wait on one machine's interface: the original's Transmission waits its time there (`0x4b60e0`, the `cmovne` on `0x672664` at `0x4b616e`) and its Center View does not wait at all.
- **Pauses, cheats and saves are a single player's.** The result dialog paused the game on the player's machine (`kp_triggers.c`); the pause, speed, cheat, save and load commands had no network gate.
- **The emulator plays no network game.** The original plays a replay with the byte at 0 (the Single Player menu clears it, the Multiplayer menu sets it, [P20](../research/atlas/p20.md)), and no network transport is emulated (no SNet HLE, the user's choice). The branches under the byte cannot be observed.

## Decision

### Stage M5: the network branches

1. **The multiplayer byte is the setup's** (`g->setup.multiplayer`, `0x672664`, ADR 0024 decision 1): 0 offline and in every replay. Each branch below tests it as the original does; at 0 every single-player branch and every oracle stays as it was.
2. **The commands among the players play in a replay** (`kp_network.c`), as the original plays them without the byte:
   - `0x0e` alliances (`ExecAlliance` `0x4731d0`): when the game allows alliances (`0x4474d0`), the issuer's twelve stances from two bits each; the circles' colours follow (`RefreshAllianceColors` `0x41d7b0`, `kp_refresh_alliance_colors`; a replay's are all 0 but player 11's 1) and allied targets that are no enemies are dropped (`ClearAlliedOrderTargets` `0x4721c0`, which the alliance trigger shares);
   - `0x0d` shared vision (`ExecSharedVision` `0x473280`, `CanShareVisionWith` `0x447600`);
   - `0x1d` the order Nothing for the selection (`0x472b40`);
   - `0x57` a player leaving (`ExecLeaveGame` `0x472da0` → `HandlePlayerLeftGame` `0x477a60`, a replay's only): network.tbl's `0x4b`, the player's trigger list goes and it takes its result (`PlayerLeftGame` `0x4be3e0`, `PlayerDroppedFromGame` `0x4be190`, `kp_trigger_player_left`), its selection row empties (`0x49c7d0`, `kp_clear_selection_row`).

   `kp_session` no longer refuses `0x57`: only what the recorder leaves out (`kp_record_excluded`) is refused from a turn source.
3. **A defeat is the original's** (`ApplyPendingResults` `0x4be020`): `AnnouncePlayerDefeat` `0x4bd4a0` outside Use Map Settings (a human's name with network.tbl `0x35`, a computer's number with `0x36`), then `RetirePlayer` `0x4bd7a0` whole: the controller defeated, the units player 11's, or killed in Sudden Death and Capture the Flag, the player out of a replay's vision.
4. **The triggers' network branches** (`kp_triggers.c`):
   - Transmission waits the action's time, and `TickTriggerClocks` `0x4be410` ends the wait on every seat; the portrait's end releases nothing (`kp_trigger_release_wait`, `0x4a7300`);
   - Center View moves the local player's screen at once and does not wait (`KP_EVENT_CAMERA` with `KP_CAMERA_SET`, the screen clamped by `SetScreenPosition` `0x40b450`);
   - Pause Game and Unpause Game do nothing;
   - the result dialog does not pause the game;
   - Escape's skip finds no trigger (`0x4bda80`);
   - `ApplyPendingResults` takes no cheat's result and frees the list of each player with a result other than Ignore Defeat (`FreeTriggerList` `0x4609c0`).
5. **The commands' network branches** (`kp_commands.c`, `kp_cheats.c`):
   - the speed command is a single player's (`0x473310`); cheats run only when the template allows them (`AreCheatsEnabled` `0x447640`, byte `0x11`) and never in a network game (`ApplyCheatFlags` `0x40d9d0`);
   - pauses: a network game's human with pauses left may pause (`CanPlayerPause` `0x47cb20`) and spends one (`0x47cc60`); each player has 3 at a new game's start (`ResetPauseCounts` `0x47cb90`). The count is game state (`g->pauses`, saved, `KP_SAVE_VERSION` 5). The pause's event carries the pauses left for network.tbl's `0x39`;
   - a pause or a resume cancels the cursor modes at the turn's end (`0x672985`, `ExecuteGameTurn` `0x4768a0` → `CancelCursorModes` `0x448c20`; `g->turn_cancels_cursor`, a turn's scratch);
   - a save never runs in a tournament (`0x447d00`), and in a network game only for the lowest Storm ID still in the game (`0x4771e0`); a load is a single player's (`0x4729e0`);
   - the latency command shows network.tbl `0x45` plus its extra turns, at most 2 (`0x476d10`).
6. **A critter dies of its annoyance only offline** (`PlayUnitSelectSound` `0x446c30`).
7. **The branches are fixture-verified.** Each has a unit test after the disassembly (`test_multiplayer`); none is observed in the original. The replay commands of decision 2 are observed: the public replays play them in `state_check.py --kind public` and `public-full`.
8. **What waits for the seats:** the network's player state (`0x673818`, `IsStormPlayerActive` `0x4780a0`) for the save's lowest Storm ID and live chat wait for a hub that carries leaves and messages (`TODO:`, decision 16); the latency's extra turns are the hub's (decision 13).
9. **Team games** (stage M5d; `IsTeamGame` `0x4b2d90`: the multiplayer byte and the template's teams `0x67294d`), after the disassembly:
   - **slots:** `SetupTeamGameSlots` `0x4b2db0` (`kp_gametype.c`): each force's leader is its human or computer of the lowest Storm ID; its record moves to the force's slot, a fixed or a random one (RNG source `0x20`), the members go to the first free slots. The team size is 4, 3 or 2 for 2, 3 or 4 teams (`GetTeamSize` `0x4b2b10`, any other count refused with error `0x5d`, network.tbl `0x49`); Top vs Bottom has two teams (`0x4b2bc0`). The lobby's races (`RecordSlotSummary` `0x47e290`, `0x5264a0`) and the leaders (`0x5264ac`) are setup state (`g->setup.race_summary`, `g->setup.leader`, saved, `KP_SAVE_VERSION` 5);
   - **seats play as their leaders:** the local player `0x508d50` is the seat's leader and the seat's record `0x508d54` is its own slot (`g->local_record`); a command runs as the issuer's leader (`KP_COMMAND_PLAYER`, `0x508d44`) and with the issuer's record (`g->command_record`, `0x508d48`): its selection row, control groups, pauses and saves are the record's (`kp_execute_command`, `kp_setup_record_player`). A seat's errors and their sounds show only when the command's record is the seat's;
   - **start units and supply:** `CreateTeamStartingUnits` `0x47eb00`: each leader gets the town hall of its block's first lobby race and the workers of its block's races in turn; the supply maxima are the leaders' only, 400 per member of the race (`CountTeamRace` `0x4b2c00`, `InitUnitCountsAndSupplyMax` `0x414400`);
   - **triggers:** `NextActivePlayer` `0x4b3170` walks the teams' leaders, so the trigger lists, Opponents, the alliances' scans and the minimap's slots run over them (`kp_trigger_active_players`, `kp_trigger_candidates`);
   - **messages:** a defeat and Capture the Flag's messages name the force (`GetForceName` `0x4b2bf0`, network.tbl `0x12` + force; `KP_EVENT_FORCE_MESSAGE`), and a chat line carries the sender's force name; Capture the Flag's beacons are the leaders' (`0x4480f0`);
   - **dashed circles:** the units in the selection rows of the seat's team mates carry dashed circles in their owner's colour (`IsTeamAllySelectionRow` `0x49c2b0`, `IncrementDashed` `0x423100`, `DecrementDashed` `0x4230e0`, images `0x23b`..`0x244`), at most the team's size less one per sprite; the alliance colours, a sprite's change and a morph keep them (`0x41d7b0`, `0x4169c0`), a unit's removal clears them, and a save strips them and restores them at its load.

   The emulator plays no network game, so the team branches are fixture-verified (`test_multiplayer`'s four team cases).

### Stage M6: the seats, the shared hash and the turn hub

10. **The seat's state is a class of the save's walk** (`SEAT_PART`, `KpStateRange.seat`, `KpSnapshotField.seat`): saved and restored as before (a save is one seat's) and left out of a second hash, `kp_shared_hash` (`KP_SHARED_HASH_VERSION` 1), which two seats of one game have the same while their simulations agree. `kp_state_hash`, `KP_HASH_VERSION` and `KP_SAVE_VERSION` stay: the plan's hash version bump became a second hash, so the oracles and saves that compare the whole state are untouched. The seat's state is what a machine's interface and view write: the local selection and its circles' colours, the Psi fields shown, the screen, the placement, the order marker, the command's player between turns, the CRT generator, the remembered terrain, the creep's borders and shown bit, the fog ghosts and the selection pools, the VIEW section; and what the interface's queries leave behind, which no answer of the simulation depends on: the images' bounds (`img.x`, `img.y`, which the redraw refreshes, `RefreshAllSpriteBounds` `0x415700`, and only the draw and the interface's pick read), the rectangle query's marks (`kp_units_in_rect` clears them at its stamp's wrap now, so no query depends on the ones before it) and the requirement evaluator's last error and offsets cache (`0x66ff60`, `0x407d50`…; every check of the simulation writes the error before it reads it).
11. **The images world is hashed in a canonical order.** A fog ghost and the placement cursor take a sprite and images from the shared pools, as the original's do, so the pools' slots differ by seat. The shared hash walks the rows' sprites by a content key, sorted (the sprite's fields without the seat's selection bits `0x0f`, its images' fields and drawing class), and hashes every sprite reference (a unit's, a lone thingy's, a Pylon's Psi field) by its sprite's key. An image's drawing method is the seat's view of a cloak (methods 2 and 5 one class, 4 and 7 another, 0, 3, 6 and 16 none: a hallucination's and the local player's view of a cloaked unit). A Psi field's hidden flag and visibility follow the seat's shown fields.
12. **The core keeps the seat's interface out of the simulation:** the critter's annoyance is decided in the core under the multiplayer byte (`0x446c30`), the command's player is the local player's again after each turn (`ExecuteGameTurn` `0x4768a0` ends with `0x508d44 = 0x508d50`, `0x508d48 = 0x508d54`), and a frame between turns runs without the turn manager (`kp_run_frame_between_turns`).
13. **The turn hub stands for the network** (`kp_hub.{h,c}`, `KP_TURNS_SEATS`): each seat's commands go into its outgoing turn (`QueueTurnCommand` `0x476c80`: a full turn is sent first, a command past 16 turns in transit dropped); a seat polls a turn every `0x666404[speed]` frames (`PollTurn` `0x444cc0`, `SetSpeedTable` `0x445110` with the hub's provider's 8 turns a second: 2 frames at Fastest); at a poll it receives every seat's turn or waits, tops its turns in transit up to the target (2, plus the latency command's extra turns, `0x672990`, set as each seat runs `0x55`), and runs the turn by the Storm IDs from 7 down (`ExecuteGameTurn` `0x4768a0`). The keep-alive `0x05`, the sync command `0x37` and `ResolveDesync` `0x47a630` are not carried: the seats' shared hash replaces the sync check. A network transport implements the same calls later.
14. **The checks:** `test_seats` runs every scenario and every recorded custom game as a network game with each other human or computer player a seat and compares the shared hash every step; a field that differs between the seats outside the canonical sections fails, and each seat field's change is shown to leave the hash. The fuzz target `turns` checks the hub's lists, order and bounds.
15. **`koprulu --map PATH --seats N`** is the development mode: the lobby's first N − 1 computers seated (`kp_seats_setup`), one session per seat over one hub, the window showing one seat with its console and the others following its frame without an interface; after each frame the shared hashes are compared and the first difference stops the game with a report (the frame, the sections, the dump's categories, the snapshot's fields). Ctrl+Alt+digit and the script's `seat N` switch the seat shown. Its first run found the three seat states of decision 10 that `test_seats` could not, since all its seats queried and drew alike.
16. **Not carried yet** (`TODO:`): a seat's leave or drop (`SNetLeaveGame`, the other seats' `HandlePlayerLeftGame` `0x477da0`), chat messages beside the turns (`SNetSendMessage`, recorded as `0x5c` by `0x475b40`), so the save's lowest Storm ID still counts every human record. The original's own desync risks stay as they are: a cloak begun on an image of method 16 (a hallucination's or a burrowed unit's view) and a Psi field made while the images pool is exhausted depend on the seat.

## Consequences

- A network game's branches exist before any transport: the seats of stage M6 and a later network play them.
- A saved game of version 4 does not load (ADR 0021): the pauses left are new state.
- The original's branches that need the network's leaves and messages stay `TODO:` until the hub carries them (decision 16).
- A team game's dashed circles are the seat's (the selection pools and the sprite's bits `0x06`, out of the shared hash); its errors are events, no state.
- A seat's save is that seat's: two seats' saves of one moment differ in the seat's state and in the images pools' slots, never in their shared hash.
- A network transport later replaces the hub's in-process streams; the sessions, the shared hash and `--seats` stay.
