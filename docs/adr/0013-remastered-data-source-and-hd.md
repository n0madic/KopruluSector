# ADR 0013: StarCraft: Remastered as the only data source, and its HD art

Status: accepted (2026-10-26). The user approved the plan (inline design document and plan file, 2026-10-26): import every resource the remake needs from a StarCraft: Remastered install alone, the original graphics as well as the HD art, so a player needs one distribution, not two; the HD art is drawn by an HD renderer; HD2 (×2) and HD (×4) are both imported and chosen by scale; enUS only for now; no Carbot skin. Evidence: [Remastered as a data source](../research/remastered.md). Amends the plan's "Scope V1" (CASC/Remastered was outside V1). Its rule that the HD art comes from the converter only is replaced by [ADR 0019](0019-install-or-repack-converter-in-c.md) (phase C, 2026-11-11): an install's HD art is read and built at run time, the containers come only from the repack (the HD world since stage C5, 2026-11-12: the packs laid out from the anims at a mission's start, the phones' sets transcoded by `kp_convert repack`; the interface, portraits and console since stage C6, 2026-11-12: laid out at start by the placement table `defs/scr/hd-ui-<profile>.json`, the portraits Remastered's WebM by name, `HDPV` removed).

## Context

The converter reads a verified Brood War 1.17.0.1 install (profile `bw-1.17.0.1`: StarCraft.exe and five MPQs) and every oracle checks the palette-indexed data it produces. Remastered's CASC storage keeps most of those files byte for byte, some under `SD/`, the enUS locale or another name, grows the tilesets by appending, and holds the rest only in its own formats (RGBA DDS, DXT `*.dds.grp`, WebM, XML and JSON). Its executable's code is encrypted. Measured on 1.23.10.13515 over the 4,376 files the conversion reads: see the research note's table.

## Decision

1. **Sources.** The conversion reads a `Source` (`converter/source.py`): the MPQ `Resolver` (`--data`) or `ScrSource` (`--scr`, `converter/casc/source.py`), which presents a Remastered install as profile `bw-1.17.0.1`'s files under their MPQ paths. No conversion step reads the executable: its requirement tables and the digest of its VCOD resource are in `defs/` (`defs/dat/requirements-*.json` `words`, `defs/chk/*.json` `vcod_resource.sha256`), checked against the executable by `test_dat` and `test_chk`.
2. **The manifest.** `defs/scr/inputs-<profile>.json` lists every file the conversion reads from the 1.17 install with its size and SHA-256, and the names it looks for and does not find (`absent`): hashes and names only (until 2026-11-11 also the files it could not read, `unreadable`: the one, PAB05ura.wav, was the reference copy's damage, not the release's, issue #2; `scr-manifest` keeps a damaged copy's committed entry). `python3 -m converter scr-manifest --data DIR` runs the whole conversion over a recording source and writes it (since 2026-11-12 `kp_convert manifest DIR`: the runtime's loaders over a recording `kp_res`, the damaged copy's row kept alike; [ADR 0019](0019-install-or-repack-converter-in-c.md)).
3. **Lookup and status.** `ScrSource` tries, for an MPQ path, the moved-files table, then the prefixes `SD/`, the root, `locales/enUS/Assets/SD/`, `locales/enUS/Assets/`, and rebuilds what is derivable (a grown tileset's prefix of the manifest's size, with the CV5 groups Remastered filled in emptied again; `.vx4` from `.vx4ex`). Each file gets a status, written to `reports/scr-import.json`: `exact` (a copy has the manifest's hash), `derived` (rebuilt to it), `differs` (no candidate reaches it; the first copy is used), `unlisted`, `missing`. A name absent in 1.17 stays so, so the conversion sees 1.17's data set.
4. **What 1.17 alone has.** Where Remastered has no exact copy the SC:R build uses Remastered's data as an `approximation` (plan §8): portraits and glue movies (lossy WebM), strings Remastered edited, frames kept only in DXT, the music and mission speech it re-recorded. Data that is not art, text or audio (the dialogs' numeric structure, string id order) may go into `defs/` like the interface tables. The 1.17 install stays the reference of every oracle and golden.
5. **HD art.** Imported from the user's install only, never shipped: `.anim` sprites (diffuse, team colour mask) and HD terrain (one tile per megatile) for HD2 and HD, drawn by an RGBA world pass at the window's resolution under the palette-indexed interface (`--graphics original|hd|auto`). The simulation and the index oracles do not change; HD is an `approximation` (ADR 0011 point 5).

## Stages

- **R0** (2026-10-26): exe-free conversion, `Source`, `ScrSource` with the exact, moved and tileset files, the manifest, `reports/scr-import.json`, `compare_outputs` (containers of two sources section by section). On 1.23.10.13515: 2,823 exact and 29 derived of 4,376; `missions --scr` gives the 64 mission containers with the same sections as from 1.17.
- **R1** (2026-10-27): rebuilds from Remastered's own formats (`converter/casc/rebuild.py`), judged by the manifest's extras (`rebuild.describe`: an image's index plane, colour plane, palette and varying PCX header bytes; a dialog GRP's frame table; an SMK's header and the PCX palette its colours match):
  - **PCX** from the SD RGBA DDS with the palette of a PCX of the same palette group that Remastered keeps exactly (alpha 0 → index 0, an opaque colour → its lowest index, a translucent one → its highest, else the nearest); block padding cut, an HD image sampled, a console's rows padded above. Statuses `derived` (bytes equal), `equivalent` (indices and palette), `colour-equal`, `approximation`.
  - **TBL**: `stat_txt` is Remastered's TBL with 1.17's last 8 strings from its XML (exact); the others from the XML by string id, inner NULs at the recorded positions (`defs/scr/texts-<profile>.json`: ids and NUL positions, no text).
  - **Dialog BIN**: each dialog's skeleton (its bytes with every string zeroed, in the texts file) with its texts: names (dialog, bitmap and SMK file names) as recorded, the rest from Remastered's `RC3.xml` (equal texts in order, else an equal text anywhere, else its own entry if at least 0.6 similar; a replaced label such as "Collections" for "Campaign Editor" stays empty); a longer text is appended with its pointers moved. 52 of 69 equal the originals.
  - **Dialog GRPs** (the glue's `Dlg.grp`): the frame table recorded, frames from `SD/glue/<theme>/dlg.dds.grp` (DXT1, another theme's when its own is missing) in the theme's palette; the glue's `arrow.grp` is the game's `cursor\arrow.grp` in the theme's palette.
  - **SMK**: KPV1 from the WebM (`docs/formats/kpd.md`, `kp_smk.c`); since ADR 0018's stage D6 KPW1, the WebM itself behind the SMK's header and its screen's palette.
  - On 1.23.10.13515: 2,837 exact, 227 derived, 6 equivalent, 19 colour-equal, 605 approximations (549 movies, 25 dialog GRPs, 17 dialogs, 9 PCX, 5 TBL), 682 Remastered copies that differ (674 WAVs, 7 briefing texts, 1 PCX); none missing. Every command runs from `--scr` alone (`tools/product.sh` takes `KOPRULU_GENERATED`), and `kp_load_check` loads all 304 containers under ASan. Against the 1.17 conversion, the containers whose sections differ are `portraits.kpd`, `ui.kpd`, `strings.kpd`, `sounds.kpd` (`MUSL`, the re-recorded music) and the sounds of the packs and missions (the OGG streams' serials follow the output directory, and the mission speech was altered); the missions, rules, scripts, tilesets, atlases and `grpmeta` equal.
- **R2** (2026-10-27): `python3 -m converter hd` (`converter/emit/hd.py`, `formats/anim.py`): HD packs beside the SD packs, frame for frame, and HD tilesets (docs/formats/packs.md). On 1.23.10.13515 every one of the 832 GRPs has HD frames (830 anims, the counts equal the GRPs'), every tileset one tile per megatile.
- **R3** (2026-10-27): the HD world (`kp_gfx`; `--graphics original|hd|auto`, auto from a scale of 2 when the art is there: HD above a scale of 3 on a computer, else HD2; the development checks keep the original). `kp_present/kp_hd.c` loads the HD packs (their frame table shares the SD table's global frames) and makes an atlas of the megatiles the map uses (since 2026-11-01 a 2D array of layers at most 2048 on a side, GLES 3.0's least texture size; [phase 10](../phase10.md#kp_present-reviews-fixes-2026-11-01)); `kp_gfx` draws into an RGBA target of the logical screen times the art's scale, with premultiplied colour and the ranks as depth (each family drawn in rank order since 2026-11-01: they blend, and in slot order a translucent texel could cut out an image under it; [phase 10](../phase10.md#hd-images-in-rank-order-2026-11-01)): the HD terrain, the overwriting images with their owner's team colour (Remastered's mix(c, c × team, mask), the player's brightest tunit colour) and the hallucination colours, the destination images (shadows darken by half, blend banks' glows add, trans50 and cloak blends at half), the distortion images faint, the fog as a smooth darkening from its levels, the health bars from the bars texture; then the canvas and the cursor over it at the window's resolution (translucent canvas texels at half) and the vector text. BC1/BC3 pages are uploaded as blocks where the context takes S3TC (`kp_gb_compressed` tries it), else decoded (`kp_present/kp_bcn.c`). The choice is made when the world is built (a game started at once is laid out first).
- **R4** (design approved by the user, 2026-10-27, inline design document; ETC2/ASTC kept as a sub-stage of its own at the user's request): R4a streaming of the HD pages, R4f ETC2/ASTC for phones, R4c the palette's fades and the water on the HD world, R4d the HD interface, R4e HD portraits and glue movies, R4b web HD2. Every failure of the HD path falls back to the SD art of that place.
  - **R4a** (2026-10-27): the HD packs (schema 2) keep each frame's blocks, packed by image into 2048² pages (80–82 % full; HD2 354 MB, HD 1.4 GB). The runtime opens a pack from its header and frames and streams its pages: `kp_present/kp_hd_cache.c` keeps a fixed number of slots (the layers of the HD textures, `KP_HD_BUDGET`: 768 MB on a computer, 384 MB on a phone; `--hd-budget MB`) holding the pages the drawn images show, the least recently wanted page evicted first and never one wanted by the current image data, a page refused a slot waiting `KP_HD_RETRY` changes; `kp_app_hd.c` reads (and, without S3TC, decodes) the pages on a thread, the main thread uploads four a frame, and the first frame with images waits for its own. A frame whose page is not resident, or that has no HD art, is drawn from the SD atlas in its palette colours at the logical scale (its shadow at half). zerg02 in HD (×4) runs in 33 slots of 200 MB (R3 uploaded 1.7 GB); frame medians on macOS: zerg02 HD2 0.43–0.47 ms against the original's 0.64–0.69 ms, bench_combat HD2 0.65–0.75 ms against 0.56–0.64 ms.
  - **R4f** (2026-10-27): phones get HD2 in ETC2 RGBA8 (EAC alpha), EAC R11 and ETC2 RGB8 blocks, which GLES 3.0 requires everywhere, transcoded from the BC pages by `kp_hd_etc2` (`kp_hd_phone` since 2026-11-05) when `tools/product.sh` stages a phone's data (`kp_present/kp_etc.c`: the encoder writes ETC1's individual and differential modes; [packs](../formats/packs.md)); the HD pack's `HEAD` names its pages' format, `kp_gfx` uploads each format's blocks where the context takes them (`kp_gb_takes_blocks`) and the loader decodes them where it does not. `--graphics auto` now draws HD2 on a phone too. ASTC was not written then: ETC2 is part of every GLES 3.0, at the same size, and an ASTC encoder of useful quality is a much larger piece of work (written since 2026-11-05 over the Arm encoder: After R5, the phones' pages). On the Fold7 (Adreno 830, which also takes S3TC and ASTC) zerg02 in HD2 from ETC2 blocks runs at a frame median of 2.68 ms against the original's 4.92 ms; the play checks and the autotest stay equal.
  - **R4c** (2026-10-27): the HD world follows the screen palette: `kp_palette_tone` makes, from the tileset's palette and the one uploaded (the colour cycles and entry 0 left out), what each level of each channel has become (the fades, the brightness option; grey when `kp_palette_grayscale` greyed it), and the HD composite tones the world with it before the interface (`KP_TEX_HD_TONE`). Water and lava move: the HD tilesets carry Remastered's water masks (`WMAP`, `WMSK`) and `water.kpd` its two animated normal maps; the HD terrain (`KP_GFX_HD_TERRAIN_FS`, written here from the idea, not Remastered's shader) reads the bottom shifted by the normals, scrolled across the map and blended between frames, where both the texel and the shifted one are water, and brightens the crests; the water's clock is real time from the world's start. The normals are ETC2 on phones too.
  - **R4d** (2026-10-27), the HD interface: `ui.kpd` (`HDUI`, [packs](../formats/packs.md)) holds the interface's HD art per SD file; the canvas has an item plane (`kp_ui_canvas_hd`, `kp_ui_canvas_add_item`: per pixel the item of the draw that wrote it, an item naming its SD file, frame and rectangle); `kp_app_hd_ui.c` resolves the frame's items to their HD frames, reads and decodes those not yet in the interface's atlas (`KpHdUiAtlas`, RGBA layers of 2048² or 4096²) and hands kp_gfx the item table, and the HD composite draws an item's image where the plane names it, over the SD texel by its alpha, or, for the console's pieces, in its own silhouette over the world. The console: each group is drawn from its race's piece, and a filler from the neighbouring piece where it reaches over the gap (Remastered's pieces carry the panels a wide screen shows), else from a column of the left group's piece stretched; the glue screens go through the same composite when they have items. The frames drawn inside the dialogs come from the interface's image log (`kp_ui_images.c`, on with `kp_ui_set_hd`; it only watches the drawing, `test_kp_ui.hud_panels_hold_with_the_image_log`): a GRP frame (`kp_ui_draw_grp_rle`), a theme frame and a capture of the console (the command card's and status panel's backgrounds) record the pixels they wrote, blits carry them to their target, and composing a dialog (`kp_ui_image_owners`) gives each pixel still holding an image's value to that image's item; a smaller image whose rectangle holds a pixel of the larger one it lies over (the one that wrote most of its rectangle) takes it when the larger one was drawn first (an icon over its button) or the pixel is still the smaller one's (a wireframe under its panel painted again with the same pixels), and lies over the larger one's item (`under`); a piece the larger one drew over later (a frame's edge under a portrait) keeps only its own pixels, so the render draws the HD button, then the HD icon over it; a tinted image also takes the plain background of its rectangle (`test_kp_ui.image_owners_layer_by_area`). A frame drawn through a colour map (the command icons' slices) is tinted with the mean colour of the indices it wrote over its HD image's mean brightness. A picture the interface decoded from a PCX (`kp_ui_picture`: glue backgrounds, the score and briefing screens) draws its HD image wherever it is blitted. The HD wireframe (`wirefram.dds.grp`: a layer per part side by side) draws its layers in the colours the status panel's colour map gives the parts: the shields and the outline (its brightest of four shades) first, the four hit point parts over them. The cursor's frame is drawn from its HD frame over the composite (uniforms, no item). The console's pieces stand on the screen's bottom, the outer ones at the edges of an 853-wide screen and the centre one where its edges match the SD status panel's (an earlier placement by colour put it 12 pixels low, the unit's name over the panel's frame). A PCX's HD art is taken only when it is the SD picture drawn again (`hd_ui.same_picture`: the correlation of their luminance gradients at least 0.5; the same pictures measure 0.76–1.0): Remastered drew most glue screens anew for its own layout (backgrounds −0.02–0.21, the ready rooms' panels, the popups −0.42–−0.28), and their frames would not lie under the SD dialogs (the briefing's panels beside Remastered's), so 128 of HD2's 188 pictures stay SD.
    Since 2026-11-05 the console's HD pieces are drawn whole, each over the last, with two more frames for the wings' tiles ([ADR 0011](0011-interface-panels-and-layouts.md), "The console composed from whole pieces"); a piece over another names it as its item's `under`, so its translucent edge shows that piece in the composite.
  - **R4e** (2026-10-27), the HD portraits: `portraits.kpd` (`HDPV`, [packs](../formats/packs.md); `converter/emit/hd_video.py`) holds each portrait movie's HD2 WebM as KPV1 with the SD movie's frame count, rate and ring frame (both variants: HD2's 224 × 240 fill the console's portrait at 4 × too; 621 of 621 movies, 281 MB; since ADR 0018's stage D6 the WebM as it is, 72.8 MB, decoded by `kp_webm.c`, and read from a Remastered install's CASC when `--data` names one). The movie's player keeps its file and the frame shown (`KpUiVideo.path`, `shown`), and with the image log on the portrait's bitmap is an image of that frame (`kp_ui_video_image`) wherever it is drawn: the console's portrait carried by its blit, the briefing's four by the briefing's own (`kp_ui_image_blit`). `kp_app_hd_ui.c` reads a clip when its movie is first shown into one of six slots (the one shown longest ago taken), decodes the item's frame on the CPU (`kp_smk`, `kp_smk_palette`) into the slot's place in the atlas and draws it filling the item, its middle cut to the item's shape. Remastered's HD glue movies are not imported: the main menu's are drawn for its own layout (1700 × 700 against SD's 320 × 116), the campaign's are SD's size.
  - **R4b** (2026-10-27), HD2 on the web: the page preloads only the HD2 files' heads (packs, `ui.kpd`, `portraits.kpd` up to their first bulk section) and their sizes (`generated/web_sizes.txt`, since the cinematics' packs are listed there too; `tools/web_hd_heads.py`, 379 KB on 1.23.10.13515) and fetches the rest from the files served beside it as HTTP Range requests (`kp_app_fetch.c`: `emscripten_fetch`, `-sFETCH=1`; a server answering 200 has the range cut out; elsewhere the same calls read at once): the pages through the loader without threads (a page is a result once its two ranges came), the interface's frames and the portraits' clips as they are first shown (SD meanwhile), the tileset and water whole (the world is drawn in its original art until they came, then uploaded again in HD). The web build takes HD2 only. `tools/web_serve.py` serves the build with byte ranges (`python3 -m http.server` answers 200). terran01 fetched 48 MB of HD2's 664 MB. The HD composite's samplers outnumbered WebGL 2's 32 texture units: each program's samplers now read units 0, 1, … in order (`kp_gfx_gl.c`).
- **R5** (2026-10-27, approved by the user after an inline design: two render paths with clear roles instead of one), the modern effects in any art: `--fog original|smooth` and `--water on|off`, by default the art's (the original's: its own fog and still water, unchanged; the HD art's: both), the development checks always the original's. Either effect over the original's art draws it through the RGBA path of the HD world (`kp_gfx_effects`), at the whole screen scale up to 4: the RGBA terrain reads the original's megatile sheet in the palette's colours (its cycles and fades as they are, no tone over them), the images their SD frames as the HD world's fallback does (now also the size outlines and health bars, a blend at half, a distortion's faint brightness, which the fallback used to drop; a blend bank's glow, a flame or an SCV's exhaust, is the over blend that fits its table row since 2026-11-07, [phase 10](../phase10.md#the-scvs-exhaust-in-sd-with-the-water-on-2026-11-07): the first version added the palette colour of the source value, which for a glow is a row of the bank, not a colour), the interface over it as in HD. `--fog original` there is the original's dark rows per fragment (the terrain's, the images' and the bars' indices through the row of their level; the blends' colours darkened by its light), `smooth` the HD world's darkening pass; one fog level code serves the index pass too (`FOG_LEVELS`). The water needs an imported variant's tileset for its masks (HD2's, read at half their resolution; on the web fetched with `water.kpd`); without one the water stays still. The index path stays the reference: on zerg01 the RGBA terrain with the original's fog equals it pixel for pixel; the play checks' fog and palette checks and the autotest are unchanged (0 mismatches). In HD, `--water off` stills the water; the HD art's fog is always smooth. A frame costs the same (zerg01 at 2560x1634: median 4.4 ms with both effects, 5.0 ms without). The settings screen (2026-10-27, approved by the user): the in-game Video Options are our own dialog `koprulu\video.bin` (`defs/ui/koprulu-dialogs.json`, built by `converter/formats/dialog.py`) in place of the original's `rez\video.bin`, whose colour cycling is gone (always on): the gamma (the original's 60..140, now applied: the palette, a glue screen's, and the HD interface's art through the composite's exponent), the art (Auto, Original, HD 2x, HD 4x; a variant not imported, or x4 on a phone or the web, disabled), the fog, the water and the text (Auto and their values; the animated water disabled without an imported variant's water masks, the vector text without TrueType fonts; the fog's Original choice shows only over the original's art, the HD art's fog being always smooth), the portraits and, since 2026-11-02, the HD sprites' lighting (Auto, Off, On; Auto is on; On disabled without an imported HD variant, on the phones and where the context does not take the BC blocks or `--hd-decode` is given); every change shows at once (the world's art loaded again in the game, `kp_world_frame`: kp_gfx's objects deleted (`kp_gfx_reset`; until 2026-10-31 they were dropped as a lost context's and leaked), so no HD textures stay; also when the scale makes auto pick another imported variant), Cancel puts all back, OK keeps them in the profile (`VOPT`); a flag given on the command line wins for its run (OK keeps the profile's value of an option the flag gave unless the dialog changed it), the development checks keep the original's and save nothing; `tools/ui_check.py` does not compare the dialog with the original's captures; `--video-check DIR` (in `tools/ci.sh` with `KOPRULU_APP`) clicks every choice in a game and checks the options and the world's art after each, then Cancel and OK. The masks come with the HD tileset's tiles (11 MB on the web for jungle).
- After R5 (2026-10-27, from the user's comparison with Remastered): the HD art's team colours are the players' minimap colours (`tminimap.pcx`, the colours that name the players and Remastered's team colours) instead of the brightest `tunit` shade, which made team-masked art garish (the Zerg Beacon's flesh); the lighting layers (`normal`, `specular`, `ao_depth`, `bright`, `emissive`) were not applied then, so lit parts stayed brighter than in Remastered (applied since 2026-11-02, below). Remastered lights the world's sprites in a deferred pass (read from its shaders, 2026-11-02). Per pixel it takes a normal from `normal`'s red and alpha, mirrored with the frame, and the ambient occlusion and depth from `ao_depth`. It lights them with a white directional light from (200, 50, 500) plus a specular term, adds point lights from a light buffer, the effect buffer's shadow and the emissive, and mixes the result over the plain colour by a per-sprite amount. The per-sprite amount, the lighting scale and the point lights' sources live in the executable and have not been found yet. The world now draws the game's display megatiles, so creep shows in both arts (it never did: the map's tiles were read once from the scenario). Creep's edges followed: the original draws frame b − 1 of the tileset's `.grp` over a tile whose megatile word has bit 15 and whose border byte b is not 0 (`0x40ad1b`, `0x4c03b0`); the SD frames go into the megatile sheet's cells after the megatiles (TSET `EDGE`), the HD art's (`TileSet/<name>.dds.grp`, DXT1 with alpha) into an RGBA texture array (HDTS `EDGE`, kept as RGBA by `kp_hd_phone` since ETC2 RGB has no alpha), the frame per cell in the terrain map's second channel (RG16UI). A Zerg Beacon's own tiles carry no creep in the original either (its footprint is occupied when the creep is placed; the emulator's initial state of zerg01 has the same megatiles and border bytes there), so grass shows at its sides where the edges do not cover it.
- After R5, the lighting (2026-11-02, the design left to us by the user): the HD sprites are lit as Remastered lights them, in the HD world's images pass instead of its deferred one (its `sprite_forward_lit` variant does the same per sprite; the formulas are restated, no shader code is copied). An image is lit when its anim has `normal` and `ao_depth` (HD2: 216 of 858 images, 35 % of the frames' area; `emissive` in 85 of them); the converter packs the lit images first, on pages of their own, and keeps those pages' four layers as their blocks: `normal` and `ao_depth` BC3, `specular` and `emissive` BC1, 3 bytes a pixel more (`HDPK` schema 3, [HD packs](../formats/packs.md); `bright` is left out). HD2 has 50 pages, 20 of them lit, 540 MB of packs; HD 193 pages, 72 lit, 2.0 GB. The runtime gives the lit pages slots of their own (`kp_hd_cache_lit`), the budget split between the two kinds in proportion to their pages (`kp_hd_slots_split`; terran02 in HD at the 768 MB budget: 27 slots for its 60 lit pages and 46 for its 104 others, in HD2 every page its slot; at 100 MB in HD2 3 and 5), and kp_gfx holds their layers two a slot in two texture arrays (`KP_TEX_HD_LIGHT` BC3: the normal map and the occlusion; `KP_TEX_HD_GLOW` BC1: the specular and the emissive colours). An overwriting sprite in a lit slot takes its normal from the normal map's red and alpha (x mirrored with the frame, z = sqrt(max(1 − x² − y², 0.1)), normalized) and the occlusion from `ao_depth`'s green; its colour (team colour and hallucination applied first) becomes (lambert × colour + highlight × specular) × occlusion + emissive, the white light from (200, 50, 500), the highlight the half vector's cosine to the 16th power where the lambert term is positive, the eye over the view at half its width and a quarter of its height and 500 logical pixels up (Remastered's lighting scale taken as the target's pixels a logical pixel, so the half vector is one per frame: `KP_U_LIGHT`). A selection circle (a solid row) stays unlit. Choices of ours where the executable, whose code is encrypted, would tell: the per-sprite amount is 1 (`KP_HD_LIGHT_AMOUNT`, TODO), so a lit sprite is about half as bright on average as unlit (the mean occlusion 0.70–0.80 and lambert 0.72–0.74 of the HD2 pages measured); no point lights, no bloom, no `bright`; the destination and distortion families (shadows, glows, cloaks) unlit. `--lighting on|off|auto` and the Video Options' Lighting (Auto: on; kept in the profile's `VOPT` as its seventh value, a profile before it reads as Auto); a change makes the HD pages' slots again (`hd_slots`), so without the lighting its layers' memory goes to more slots (terran02 in HD: 128 slots instead of 73); the phones' packs had no lighting layers until 2026-11-05 (After R5, the phones' pages); decoded pages (`--hd-decode`, a context without S3TC) are drawn unlit; the web fetches the four layers' byte ranges with a lit page's. If the GPU cannot hold the layers the world falls back to unlit slots. ## Consequences

- One install is enough; with both, the 1.17 one stays the reference and the manifest shows exactly where the SC:R build departs from it.
- A new Remastered build is checked by the manifest, not trusted: a changed file shows as `differs`.
- The converter needs ffmpeg for Remastered's WebM, as for SMK; the runtime gains no dependency (the optional cinematics are the exception, a build option with its own decoder: [ADR 0015](0015-video-decoder.md)).
