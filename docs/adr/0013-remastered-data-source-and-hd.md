# ADR 0013: StarCraft: Remastered as the only data source, and its HD art

Status: accepted (2026-10-26). The user approved the plan (inline design document and plan file, 2026-10-26): import every resource the remake needs from a StarCraft: Remastered install alone, the original graphics as well as the HD art, so a player needs one distribution, not two; the HD art is drawn by an HD renderer; HD2 (×2) and HD (×4) are both imported and chosen by scale; enUS only for now; no Carbot skin. Evidence: [Remastered as a data source](../research/remastered.md). Amends `IMPLEMENTATION_PLAN.md` "Scope V1" (CASC/Remastered was outside V1).

## Context

The converter reads a verified Brood War 1.17.0.1 install (profile `bw-1.17.0.1`: StarCraft.exe and five MPQs) and every oracle checks the palette-indexed data it produces. Remastered's CASC storage keeps most of those files byte for byte, some under `SD/`, the enUS locale or another name, grows the tilesets by appending, and holds the rest only in its own formats (RGBA DDS, DXT `*.dds.grp`, WebM, XML and JSON). Its executable's code is encrypted. Measured on 1.23.10.13515 over the 4,376 files the conversion reads: see the research note's table.

## Decision

1. **Sources.** The conversion reads a `Source` (`converter/source.py`): the MPQ `Resolver` (`--data`) or `ScrSource` (`--scr`, `converter/casc/source.py`), which presents a Remastered install as profile `bw-1.17.0.1`'s files under their MPQ paths. No conversion step reads the executable: its requirement tables and the digest of its VCOD resource are in `defs/` (`defs/dat/requirements-*.json` `words`, `defs/chk/*.json` `vcod_resource.sha256`), checked against the executable by `test_dat` and `test_chk`.
2. **The manifest.** `defs/scr/inputs-<profile>.json` lists every file the conversion reads from the 1.17 install with its size and SHA-256, the names it looks for and does not find (`absent`) and the files it cannot read (`unreadable`): hashes and names only. `python3 -m converter scr-manifest --data DIR` runs the whole conversion over a recording source and writes it.
3. **Lookup and status.** `ScrSource` tries, for an MPQ path, the moved-files table, then the prefixes `SD/`, the root, `locales/enUS/Assets/SD/`, `locales/enUS/Assets/`, and rebuilds what is derivable (a grown tileset's prefix of the manifest's size, with the CV5 groups Remastered filled in emptied again; `.vx4` from `.vx4ex`). Each file gets a status, written to `reports/scr-import.json`: `exact` (a copy has the manifest's hash), `derived` (rebuilt to it), `differs` (no candidate reaches it; the first copy is used), `unlisted`, `unreadable`, `missing`. A name absent or unreadable in 1.17 stays so, so the conversion sees 1.17's data set.
4. **What 1.17 alone has.** Where Remastered has no exact copy the SC:R build uses Remastered's data as an `approximation` (plan §8): portraits and glue movies (lossy WebM), strings Remastered edited, frames kept only in DXT, the music and mission speech it re-recorded. Data that is not art, text or audio (the dialogs' numeric structure, string id order) may go into `defs/` like the interface tables. The 1.17 install stays the reference of every oracle and golden.
5. **HD art.** Imported from the user's install only, never shipped: `.anim` sprites (diffuse, team colour mask) and HD terrain (one tile per megatile) for HD2 and HD, drawn by an RGBA world pass at the window's resolution under the palette-indexed interface (`--graphics original|hd|auto`). The simulation and the index oracles do not change; HD is an `approximation` (ADR 0011 point 5).

## Stages

- **R0** (2026-10-26): exe-free conversion, `Source`, `ScrSource` with the exact, moved and tileset files, the manifest, `reports/scr-import.json`, `compare_outputs` (containers of two sources section by section). On 1.23.10.13515: 2,823 exact and 29 derived of 4,376; `missions --scr` gives the 64 mission containers with the same sections as from 1.17.
- **R1** (2026-10-27): rebuilds from Remastered's own formats (`converter/casc/rebuild.py`), judged by the manifest's extras (`rebuild.describe`: an image's index plane, colour plane, palette and varying PCX header bytes; a dialog GRP's frame table; an SMK's header and the PCX palette its colours match):
  - **PCX** from the SD RGBA DDS with the palette of a PCX of the same palette group that Remastered keeps exactly (alpha 0 → index 0, an opaque colour → its lowest index, a translucent one → its highest, else the nearest); block padding cut, an HD image sampled, a console's rows padded above. Statuses `derived` (bytes equal), `equivalent` (indices and palette), `colour-equal`, `approximation`.
  - **TBL**: `stat_txt` is Remastered's TBL with 1.17's last 8 strings from its XML (exact); the others from the XML by string id, inner NULs at the recorded positions (`defs/scr/texts-<profile>.json`: ids and NUL positions, no text).
  - **Dialog BIN**: each dialog's skeleton (its bytes with every string zeroed, in the texts file) with its texts: names (dialog, bitmap and SMK file names) as recorded, the rest from Remastered's `RC3.xml` (equal texts in order, else an equal text anywhere, else its own entry if at least 0.6 similar; a replaced label such as "Collections" for "Campaign Editor" stays empty); a longer text is appended with its pointers moved. 52 of 69 equal the originals.
  - **Dialog GRPs** (the glue's `Dlg.grp`): the frame table recorded, frames from `SD/glue/<theme>/dlg.dds.grp` (DXT1, another theme's when its own is missing) in the theme's palette; the glue's `arrow.grp` is the game's `cursor\arrow.grp` in the theme's palette.
  - **SMK**: KPV1 from the WebM (`docs/formats/kpd.md`, `kp_smk.c`).
  - On 1.23.10.13515: 2,837 exact, 227 derived, 6 equivalent, 19 colour-equal, 605 approximations (549 movies, 25 dialog GRPs, 17 dialogs, 9 PCX, 5 TBL), 682 Remastered copies that differ (674 WAVs, 7 briefing texts, 1 PCX); none missing. Every command runs from `--scr` alone (`tools/product.sh` takes `KOPRULU_GENERATED`), and `kp_load_check` loads all 304 containers under ASan. Against the 1.17 conversion, the containers whose sections differ are `portraits.kpd`, `ui.kpd`, `strings.kpd`, `sounds.kpd` (`MUSL`, the re-recorded music) and the sounds of the packs and missions (the OGG streams' serials follow the output directory, and the mission speech was altered); the missions, rules, scripts, tilesets, atlases and `grpmeta` equal.
- **R2** (2026-10-27): `python3 -m converter hd` (`converter/emit/hd.py`, `formats/anim.py`): HD packs beside the SD packs, frame for frame, and HD tilesets (docs/formats/packs.md). On 1.23.10.13515 every one of the 832 GRPs has HD frames (830 anims, the counts equal the GRPs'), every tileset one tile per megatile.
- **R3** (2026-10-27): the HD world (`kp_gfx`; `--graphics original|hd|auto`, auto from a scale of 2 when the art is there: HD above a scale of 3 on a computer, else HD2; the development checks keep the original). `kp_present/kp_hd.c` loads the HD packs (their frame table shares the SD table's global frames) and makes an atlas of the megatiles the map uses (since 2026-11-01 a 2D array of layers at most 2048 on a side, GLES 3.0's least texture size; [phase 10](../phase10.md#kp_present-reviews-fixes-2026-11-01)); `kp_gfx` draws into an RGBA target of the logical screen times the art's scale, with premultiplied colour and the ranks as depth (each family drawn in rank order since 2026-11-01: they blend, and in slot order a translucent texel could cut out an image under it; [phase 10](../phase10.md#hd-images-in-rank-order-2026-11-01)): the HD terrain, the overwriting images with their owner's team colour (Remastered's mix(c, c × team, mask), the player's brightest tunit colour) and the hallucination colours, the destination images (shadows darken by half, blend banks' glows add, trans50 and cloak blends at half), the distortion images faint, the fog as a smooth darkening from its levels, the health bars from the bars texture; then the canvas and the cursor over it at the window's resolution (translucent canvas texels at half) and the vector text. BC1/BC3 pages are uploaded as blocks where the context takes S3TC (`kp_gb_compressed` tries it), else decoded (`kp_present/kp_bcn.c`). The choice is made when the world is built (a game started at once is laid out first).
- **R4** (design approved by the user, 2026-10-27, inline design document; ETC2/ASTC kept as a sub-stage of its own at the user's request): R4a streaming of the HD pages, R4f ETC2/ASTC for phones, R4c the palette's fades and the water on the HD world, R4d the HD interface, R4e HD portraits and glue movies, R4b web HD2. Every failure of the HD path falls back to the SD art of that place.
  - **R4a** (2026-10-27): the HD packs (schema 2) keep each frame's blocks, packed by image into 2048² pages (80–82 % full; HD2 354 MB, HD 1.4 GB). The runtime opens a pack from its header and frames and streams its pages: `kp_present/kp_hd_cache.c` keeps a fixed number of slots (the layers of the HD textures, `KP_HD_BUDGET`: 768 MB on a computer, 384 MB on a phone; `--hd-budget MB`) holding the pages the drawn images show, the least recently wanted page evicted first and never one wanted by the current image data, a page refused a slot waiting `KP_HD_RETRY` changes; `kp_app_hd.c` reads (and, without S3TC, decodes) the pages on a thread, the main thread uploads four a frame, and the first frame with images waits for its own. A frame whose page is not resident, or that has no HD art, is drawn from the SD atlas in its palette colours at the logical scale (its shadow at half). zerg02 in HD (×4) runs in 33 slots of 200 MB (R3 uploaded 1.7 GB); frame medians on macOS: zerg02 HD2 0.43–0.47 ms against the original's 0.64–0.69 ms, bench_combat HD2 0.65–0.75 ms against 0.56–0.64 ms.
  - **R4f** (2026-10-27): phones get HD2 in ETC2 RGBA8 (EAC alpha), EAC R11 and ETC2 RGB8 blocks, which GLES 3.0 requires everywhere, transcoded from the BC pages by `kp_hd_etc2` when `tools/product.sh` stages a phone's data (`kp_present/kp_etc.c`: the encoder writes ETC1's individual and differential modes; [packs](../formats/packs.md)); the HD pack's `HEAD` names its pages' format, `kp_gfx` uploads each format's blocks where the context takes them (`kp_gb_takes_blocks`) and the loader decodes them where it does not. `--graphics auto` now draws HD2 on a phone too. ASTC is not written: ETC2 is part of every GLES 3.0, at the same size, and an ASTC encoder of useful quality is a much larger piece of work. On the Fold7 (Adreno 830, which also takes S3TC and ASTC) zerg02 in HD2 from ETC2 blocks runs at a frame median of 2.68 ms against the original's 4.92 ms; the play checks and the autotest stay equal.
  - **R4c** (2026-10-27): the HD world follows the screen palette: `kp_palette_tone` makes, from the tileset's palette and the one uploaded (the colour cycles and entry 0 left out), what each level of each channel has become (the fades, the brightness option; grey when `kp_palette_grayscale` greyed it), and the HD composite tones the world with it before the interface (`KP_TEX_HD_TONE`). Water and lava move: the HD tilesets carry Remastered's water masks (`WMAP`, `WMSK`) and `water.kpd` its two animated normal maps; the HD terrain (`KP_GFX_HD_TERRAIN_FS`, written here from the idea, not Remastered's shader) reads the bottom shifted by the normals, scrolled across the map and blended between frames, where both the texel and the shifted one are water, and brightens the crests; the water's clock is real time from the world's start. The normals are ETC2 on phones too.
  - **R4d** (2026-10-27), the HD interface: `ui.kpd` (`HDUI`, [packs](../formats/packs.md)) holds the interface's HD art per SD file; the canvas has an item plane (`kp_ui_canvas_hd`, `kp_ui_canvas_add_item`: per pixel the item of the draw that wrote it, an item naming its SD file, frame and rectangle); `kp_app_hd_ui.c` resolves the frame's items to their HD frames, reads and decodes those not yet in the interface's atlas (`KpHdUiAtlas`, RGBA layers of 2048² or 4096²) and hands kp_gfx the item table, and the HD composite draws an item's image where the plane names it, over the SD texel by its alpha, or, for the console's pieces, in its own silhouette over the world. The console: each group is drawn from its race's piece, and a filler from the neighbouring piece where it reaches over the gap (Remastered's pieces carry the panels a wide screen shows), else from a column of the left group's piece stretched; the glue screens go through the same composite when they have items. The frames drawn inside the dialogs come from the interface's image log (`kp_ui_images.c`, on with `kp_ui_set_hd`; it only watches the drawing, `test_kp_ui.hud_panels_hold_with_the_image_log`): a GRP frame (`kp_ui_draw_grp_rle`), a theme frame and a capture of the console (the command card's and status panel's backgrounds) record the pixels they wrote, blits carry them to their target, and composing a dialog (`kp_ui_image_owners`) gives each pixel still holding an image's value to that image's item; a smaller image whose rectangle holds a pixel of the larger one it lies over (the one that wrote most of its rectangle) takes it when the larger one was drawn first (an icon over its button) or the pixel is still the smaller one's (a wireframe under its panel painted again with the same pixels), and lies over the larger one's item (`under`); a piece the larger one drew over later (a frame's edge under a portrait) keeps only its own pixels, so the render draws the HD button, then the HD icon over it; a tinted image also takes the plain background of its rectangle (`test_kp_ui.image_owners_layer_by_area`). A frame drawn through a colour map (the command icons' slices) is tinted with the mean colour of the indices it wrote over its HD image's mean brightness. A picture the interface decoded from a PCX (`kp_ui_picture`: glue backgrounds, the score and briefing screens) draws its HD image wherever it is blitted. The HD wireframe (`wirefram.dds.grp`: a layer per part side by side) draws its layers in the colours the status panel's colour map gives the parts: the shields and the outline (its brightest of four shades) first, the four hit point parts over them. The cursor's frame is drawn from its HD frame over the composite (uniforms, no item). The console's pieces stand on the screen's bottom, the outer ones at the edges of an 853-wide screen and the centre one where its edges match the SD status panel's (an earlier placement by colour put it 12 pixels low, the unit's name over the panel's frame). A PCX's HD art is taken only when it is the SD picture drawn again (`hd_ui.same_picture`: the correlation of their luminance gradients at least 0.5; the same pictures measure 0.76–1.0): Remastered drew most glue screens anew for its own layout (backgrounds −0.02–0.21, the ready rooms' panels, the popups −0.42–−0.28), and their frames would not lie under the SD dialogs (the briefing's panels beside Remastered's), so 128 of HD2's 188 pictures stay SD.
  - **R4e** (2026-10-27), the HD portraits: `portraits.kpd` (`HDPV`, [packs](../formats/packs.md); `converter/emit/hd_video.py`) holds each portrait movie's HD2 WebM as KPV1 with the SD movie's frame count, rate and ring frame (both variants: HD2's 224 × 240 fill the console's portrait at 4 × too; 621 of 621 movies, 281 MB). Remastered's HD glue movies are not imported: the main menu's are drawn for its own layout (1700 × 700 against SD's 320 × 116), the campaign's are SD's size.
  - **R4b** (2026-10-27), HD2 on the web: the page preloads only the HD2 files' heads (packs, `ui.kpd`, `portraits.kpd` up to their first bulk section) and their sizes (`generated/hd/hd2/sizes.txt`; `tools/web_hd_heads.py`, 379 KB on 1.23.10.13515) and fetches the rest from the files served beside it as HTTP Range requests (`kp_app_fetch.c`: `emscripten_fetch`, `-sFETCH=1`; a server answering 200 has the range cut out; elsewhere the same calls read at once): the pages through the loader without threads (a page is a result once its two ranges came), the interface's frames and the portraits' clips as they are first shown (SD meanwhile), the tileset and water whole (the world is drawn in its original art until they came, then uploaded again in HD). The HD composite's samplers outnumbered WebGL 2's 32 texture units: each program's samplers now read units 0, 1, … in order (`kp_gfx_gl.c`).

- After R5 (2026-10-27, from the user's comparison with Remastered): the HD art's team colours are the players' minimap colours (`tminimap.pcx`, the colours that name the players and Remastered's team colours) instead of the brightest `tunit` shade, which made team-masked art garish (the Zerg Beacon's flesh); the lighting layers (`normal`, `specular`, `ao_depth`, `bright`, `emissive`) are still not applied (TODO), so lit parts stay brighter than in Remastered. Remastered lights the world's sprites in a deferred pass (read from its shaders, 2026-11-02). Per pixel it takes a normal from `normal`'s red and alpha, mirrored with the frame, and the ambient occlusion and depth from `ao_depth`. It lights them with a white directional light from (200, 50, 500) plus a specular term, adds point lights from a light buffer, the effect buffer's shadow and the emissive, and mixes the result over the plain colour by a per-sprite amount. The per-sprite amount, the lighting scale and the point lights' sources live in the executable and have not been found yet. The layers' pages need a new pack schema (+1 to +2.5 bytes a pixel), so the design waits for the user's approval. The world now draws the game's display megatiles, so creep shows in both arts (it never did: the map's tiles were read once from the scenario). ## Consequences

- One install is enough; with both, the 1.17 one stays the reference and the manifest shows exactly where the SC:R build departs from it.
- A new Remastered build is checked by the manifest, not trusted: a changed file shows as `differs`.
- The converter needs ffmpeg for Remastered's WebM, as for SMK; the runtime gains no dependency (the optional cinematics are the exception, a build option with its own decoder: [ADR 0015](0015-video-decoder.md)).
