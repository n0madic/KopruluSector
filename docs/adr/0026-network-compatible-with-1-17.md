# ADR 0026: Network play compatible with 1.17

Status: accepted (2026-11-17). The user approved phase N's design inline on 2026-11-17 ([phase N](../phase-network.md)). Stage N0 (the research of Storm's network layer and the UDP provider) is done, and so are stages N2 ([its additions](#addition-stage-n2-the-state-machines-and-their-transports)), N3 (the lobby), N4 ([its additions](#addition-stage-n4-the-game-over-the-network)), N5, which replaced decision 6's relay ([its additions](#addition-stage-n5-a-host-by-its-address-instead-of-the-relay)), and N6, the acceptance ([its additions](#addition-stage-n6-acceptance)). The review after N6 added protections of the protocol ([its addition](#addition-the-review-of-the-network-play)).

## Context

Phase M ([ADR 0025](0025-seats-and-network-branches.md)) left the original's network branches in `kp_core` under the multiplayer byte and several seats of one game in one process over a turn hub, with no network under them. The executable has no transport: `StarCraft.exe` calls Storm's network API (SNet, in `storm.dll`), and Storm sends its packets through a provider loaded from a `.snp` file. Until phase N the atlas specified only the executable's side ([replay and network notes](../research/replay-network-notes.md#network-play)).

Network play could follow the original's protocol or a protocol of the remake's own. A protocol of its own would play only with Koprulu. The web cannot send UDP and cannot listen, and phones sit behind NATs, so any design needs some relay for them.

## Decision

1. **Compatible with the original.** Koprulu implements Storm's network layer and `standard.snp`'s "Local Area Network (UDP/IP)" provider (`'UDPN'`) byte for byte, so a Koprulu seat and an original 1.17 seat play one game. Battle.net, IPX, the cable and modem providers and version 1.16.1 stay out, and so does resuming a saved game of a lobby that mixes Koprulu and the original, whose saves differ (Koprulu answers "Save Game File Not Found", as the original does without the file).
2. **The specification is the atlas.** Storm's network layer is package [S02](../research/atlas/s02.md), the UDP provider [U01](../research/atlas/u01.md), and the wire format [storm-udp.md](../formats/storm-udp.md). Each entry was reviewed independently from the disassembly. The wire format was then checked on the original's own traffic (decision 3): every one of 26,923 datagrams of 20 recorded games had a valid checksum and length.
3. **The oracle is the original over an emulated Winsock.** The [full-game emulator](../research/full-game-emulation.md) runs the real `storm.dll` and `standard.snp`, and replaces only `ws2_32` and `wsock32` by a virtual LAN between emulator instances, with a bridge to real UDP on the loopback. Its recordings (the datagrams, Storm's calls, the turns, the lobby's screens, every instance's states) stay in the private workspace. Phase M's "no SNet HLE" is superseded: the network's branches can now be observed.
4. **The layers follow the original's split:**
   - `kp_core`: the simulation and its network branches, and the sync command `0x37`'s inputs byte for byte (`ComputeSyncValue` `0x47a360`, the sprite visibility checksum `0x417540`–`0x417610`). The original computes the checksum in its draw path; Koprulu takes it inside the step, right after the first frame past a turn boundary, with the camera's row from the seat's interface.
   - `kp_core/src/ui`: the original's Multiplayer screens.
   - `kp_app`: the game's network code (turn manager, lobby protocol, map transfer, chat, leaves).
   - `kp_app/net`: `kp_snet` (Storm's SNet, with the API the executable calls) over providers (UDP, the relay, an in-process loop for tests).
5. **Storm and its providers are pure state machines.** Datagrams and the time go in; datagrams and events come out; there is no I/O inside. Tests drive them from recorded traffic and with simulated time.
   - **Sockets:** a thin driver per platform puts them on sockets.
   - **Threads:** on the native platforms a network thread runs the state machines (acknowledgements, resends, pings), so that a long mission load does not miss Storm's timeouts. On the web the main loop runs them.
   - **Determinism:** the time changes only when a turn arrives, never what it holds.
6. **The web and the internet go through `koprulu-relay`** (not built: replaced on 2026-11-21 by [stage N5's addition](#addition-stage-n5-a-host-by-its-address-instead-of-the-relay)). It is a virtual LAN over TCP and WebSocket that carries Storm's UDP datagrams unchanged, broadcasts within a room, and does not understand the game. TLS is a proxy's (Caddy or nginx) in front of it; the native clients connect over plain TCP. Its framing gets its own format document with stage N5.
7. **Nothing of Koprulu's own goes on the wire.** An original peer would not understand it. Desyncs are caught by the original's sync command and resolved by its `ResolveDesync` `0x47a630`, whose result in a split 1v1 (each side drops the other and wins) is kept. Between Koprulu seats in tests and in `--seats`, the shared state hash of ADR 0025 is compared besides.

## Consequences

- Koprulu's network peers interoperate with 1.17. Data identity needs no check of its own: Koprulu's rule files equal 1.17's ([replay and network notes](../research/replay-network-notes.md#the-rule-files-of-117-and-remastered-2026-11-14)), and Storm's checks at join (program ID, version `0xD5`, the lobby's version 5) are the original's.
- The original's provider has weaknesses a peer must never trigger: a receive error (a datagram over 504 bytes among them) ends that receiving thread for good, and an advertisement whose strings run past its length makes the receiver fail fatally. Koprulu's sender never produces either, and its receiver rejects both instead of failing.
- Two instances cannot share one machine's port 6112 (the original sets no `SO_REUSEADDR`). Local tests use the in-process loop provider or the emulator's virtual LAN.
- On iOS, broadcasting needs Apple's multicast entitlement. Without it an iOS seat finds games by their address (stage N5).
- The sync command makes Koprulu's simulation answerable to the original's every turn: any divergence from 1.17 in a mixed game drops a seat, which is the strongest check the remake has had.

## Addition: stage N2, the state machines and their transports

Built on 2026-11-17 ([phase N](../phase-network.md#n2-kp_snet-and-the-udp-provider-done-2026-11-17)).

1. **Two state machines, no third provider.** `kp_snp_udp` is the provider and `kp_snet` is SNet over it. The in-process provider of decision 4 (`kp_snp_loop`) is not built: the tests and the fuzz targets run the UDP provider itself over an in-process LAN (`kp_net_lan`), so Koprulu↔Koprulu checks carry the bytes a 1.17 peer gets. The relay of stage N5 will be another transport under the same provider.
2. **The pump belongs to the driver.** `kp_snet_pump` is one pass of Storm's network thread: the driver runs it when a datagram arrived (signalled) or when the wait the last pass returned has run out. `kp_net_sock` waits on the sockets and starts no thread. The network thread of decision 5 belongs to the game's network code (stage N4), which owns the driver. `kp_snet_join_game` alone pumps for itself, as `SNetJoinGame` does, and waits through the host's sleep.
3. **Several programs on one machine share a port map.** The original binds ports 6111 and 6112 without `SO_REUSEADDR`. `kp_net_sock` therefore maps virtual hosts 10.0.0.k to the loopback ports BASE+2k and BASE+2k+1, which is the network oracle's bridge. A program outside the map binds two adjacent ports and is 10.0.1.n to the bridge, which is how Koprulu joins an emulated 1.17 game.
4. **The acceptance is the original's recorded traffic.** `test_net_trace` replays each recorded player's inputs on the emulator's clock: the datagrams that arrived, StarCraft's calls of SNet, and Storm's passes, with each pass's preemptions. Every datagram Koprulu sends must be the original's, byte for byte and in order, each within 50 ms of the original's time; every result, wait and event must equal the original's.
5. **Departures from the original are listed in the headers.** They cover only inputs the original mishandles (a datagram over 504 bytes, an advertisement whose strings overrun, a short control command, a handler that deletes the record being dispatched) and bounds on the memory that forged addresses grow (remote records, filed packets, queued datagrams, listed games). None of them changes a datagram that a 1.17 peer sends or accepts.

## Addition: stage N4, the game over the network

Built on 2026-11-18 ([phase N](../phase-network.md#n4-the-game-over-the-network-done-2026-11-18)).

1. **The sync ring is the seat's network state.** `KpSync` (`kp_sync.{h,c}`) lives in `KpNetGame`, and its functions only read the game. It is neither saved nor hashed: the view's row and the vision mask it reads are the seat's own. Decision 4's sprite checksum is taken in the step after the turn's first frame, with the view's first row from the interface (`KP_SCREEN_Y`).
2. **The network's player table is the host's.** `net_state` in `KpGame` (`0x673818`: active, left) is set by the network at the start and at a leave. The core reads it for the save command's lowest active Storm ID and for a team game's leave. It is neither saved nor hashed (a resumed game's comes from its lobby), so the save's version did not change for it. The drop vote and the drop flags (`0x529042`) stay in `KpNetGame`. The setup's Storm IDs of slots 8..11 differ between a host and its joiners in the original too (`0x57eee0`), so they became the seat's: `KP_SAVE_VERSION` 6, `KP_SHARED_HASH_VERSION` 2.
3. **The wait is a state, not a modal loop.** `WaitForLaggingPlayers` `0x47a810` runs its own message loop in the original. In Koprulu, `kp_netgame_game_turn` answers "wait", the session runs no frame, and the flow draws timeout.bin over the stopped game each frame. A leaver's `0x57` goes first into the turn's list as the leaver's command: the replay records and plays it, while in the live game it changes nothing, since the network already handled the leave.
4. **Network saves are Koprulu's own, at the original's place.** Each seat writes Koprulu's save container with one more section, NETG (what the lobby reads from the original's file), as `maps/save/<name>.mlt`, at the end of the step that ran the save command (`ExecSaveGame` `0x472f50` saves within the turn), so every seat's save is of one frame; its name is checked as the original's `IsInvalidFileName` `0x408300` checks it. The original reads it as unreadable, and the product reads the original's so too; only the oracle reads the original's (decision 1: no mixed resume). A resume restores the slots (`RestoreMultiplayerSaveSlots` `0x4790b0`) on the map's setup before the start, and again on the loaded game.
5. **No network thread yet.** The main loop pumps Storm each frame, the network's waits included; decision 5's thread for a long load is left as a `TODO:` (`kp_netplay.h`). The product's two-process game and the mixed games ran without a timeout.
6. **`--seats` stays on the turn hub.** The network game is a fourth kind of turns (`KP_TURNS_NET`) beside the hub's, not the hub moved onto the network's turn manager as the plan had it. The seats keep the shared hash's check every frame but have no leave, drop or chat (`TODO:` in `kp_hub.h`: the seats as network games on the in-process LAN).
7. **The mixed game's dumps are compared through the replay.** The oracle dumps the original's state before an object step, the session at a frame's end, so the emulated seats' dumps and Koprulu's do not line up step for step. Instead, the original's own `0x37` check passes on every turn of the mixed game, and the original's playback of Koprulu's replay equals Koprulu's at every step (`state_check.py --kind koprulu-net`). Koprulu's playback of a network replay equals its live game (`test_netplay`), once the fields a playback sets by design are set aside: the multiplayer byte, the slot summary, and the turn counter, which counts frames there.

## Addition: stage N5, a host by its address instead of the relay

Decided by the user and built on 2026-11-21 ([phase N](../phase-network.md#n5-a-host-by-its-address-and-the-phones-done-2026-11-21)).

1. **No relay for now; the web has no network play.** Decision 6 is not built. The browser cannot send UDP, so the web keeps its Multiplayer unsupported (`TODO:` in `kp_netplay.h`: a relay or WebRTC later). The native programs reach each other directly.
2. **The internet by the host's address.** Koprulu's provider can be given a host's socket A (`kp_snp_udp_direct`): each of its game-list requests goes there besides the broadcast, and that host's game is listed at its port + 1. The request is the original's datagram, which a 1.17 host answers, so decision 7 holds: nothing of Koprulu's own goes on the wire. The host forwards its two UDP ports; three or more seats need each other reachable too, as Storm's peers send directly, so a virtual LAN (ZeroTier, Tailscale) is the documented way when a NAT is in between, and the one way for a 1.17 joiner.
3. **The address is the player's.** The join screen gets Koprulu's Address, a record appended to `gluJoin.bin` and shown only when the network takes an address, with its own popup (`koprulu\address.bin`); `--lan-host` and the profile keep it. A name is resolved by the system's resolver, IPv4 only, on a thread of its own: the screens never wait for DNS, and the Address popup waits for the answer with Cancel still working.
4. **The phones' local network.** Android declares `INTERNET` (SDL's template has it commented out) and `CHANGE_WIFI_MULTICAST_STATE`, and holds the Wi-Fi multicast lock while the provider's sockets are open. iOS declares `NSLocalNetworkUsageDescription`; without the multicast entitlement it finds games by their address.

## Addition: stage N6, acceptance

Decisions 1 and 2 are the user's (2026-11-21); all three were checked on 2026-11-21 ([phase N](../phase-network.md#n6-acceptance-2026-11-21)).

1. **The native network thread waits for a need.** The plan's thread that pumps Storm while a mission loads is not built. A melee map's load holds the main loop about 0.2 s on a Mac and 0.3 s on a Galaxy Z Fold7, within Storm's one second of silence. `TODO:` in `kp_netplay.h` keeps it, with these figures.
2. **`--seats` stays on the turn hub** (`TODO:` in `kp_hub.h`). The plan moved the hub onto the network's turn manager; the hub is a tool of the tests and the oracle that no player sees.
3. **The lobby keeps the original's one message a pass.** One pass a frame makes a map's transfer as fast as the slower seat draws. Taking the messages more often is open in the tracker.

## Addition: the review of the network play

The user asked for a review of phase N and then for its defects fixed together with protections of the protocol (2026-11-21, [phase N](../phase-network.md#review-2026-11-21)). The departures below only touch input that an honest 1.17 or Koprulu peer never sends, so decision 7 holds: no datagram of an honest game changes, and the trace goldens are unchanged.

1. **Storm's control commands are authenticated by address.** Since stage N5 a host is reachable from the internet, and Storm takes its control commands and relayed packets from any address: one forged datagram stopped a game or ran as the host's turn. `kp_snet` now takes the join's commands only from the joined game's address, the drop, new host, mode and ladder commands and player info only from a record with a player id, and a relayed packet only in class 2 from a participant's address. Its memory bounds are per record (a record with an id files at most 1024 packets, one without 256, those without an id together less than half of the 16,384), since one global bound let one address stop every seat's turns; class 3, which StarCraft never reads, is not filed. The records themselves are bounded without keeping a player out: a datagram that fails the header's checks makes no record, and once 1024 are kept a new address takes the place of the stranger (no player id) heard least recently, so a flood of forged addresses cannot fill them. The list is in `kp_snet.h`.
2. **A network game ignores a command it cannot run.** A core refusal stops the seat, and every seat runs every seat's commands, so a refusal in a network game was one modified seat ending the game for all. The restart command 0x08 is the original's single player's only (`ExecRestartGame` `0x472e20`); a targeted order past orders.dat and the control group 18 of record 7 are ignored there as Koprulu's departure. Offline they stay refusals ([ADR 0022](0022-turn-source-and-fuzzing.md#stage-t2-fuzzing)).
3. **A failed session leaves Storm's game.** Any other refusal (a turn that does not split, a resumed save that does not load) still stops the seat; the seat now leaves Storm's game at once and shows network.tbl's "A network error has occured." on the console's error line, so the others see a leave instead of waiting for its turns until `timeout.bin` drops it. The original has no refusal.
4. **The lobby takes from another seat only what the original's honest seats send.** A start 0x3c only from the host; race, team and force requests only until the host has built the start information 0x48; a map offer only from the host; a departed seat's transfers all removed. A walk of a turn's lobby messages ends once Storm's game was left inside it, as the left game frees the turn (the original reads on in the freed turn). The list is in `kp_netgame.h` and `kp_transfer.h`.
5. **The network's text is windows-1252 without losses.** The interface is UTF-8 (ADR 0016), the network's names and chat are windows-1252. A character the code page lacks becomes `?` in a name or a chat line (it was dropped, so a Cyrillic profile name was empty and Storm refused the game) and `_` in a transferred map's name. A network save's name must be windows-1252, since every seat writes the save under the name in the save command: the save dialog answers network.tbl's "Invalid character." otherwise.
6. **The race ready room's leaves reach the game.** Koprulu builds the session before the ready room, for the briefing; the original builds the game after it (`RunGameSession` `0x467ba0`'s `StartGame`), from the records a leave in the room has restored (`HandlePlayerLeftLobby` `0x477c20` in the glue). At the room's Start a network game whose records changed is built again from them before its first turn (`kp_netgame_setup_changed`), so a player who left there is not in the game, as in the original and on a 1.17 seat.
7. **A socket that fails stops reading.** The provider's reads stop until it is chosen again, the player sees the network error once, and Storm's waits sleep instead of spinning. A too long `--lan-host` is refused instead of cut.
