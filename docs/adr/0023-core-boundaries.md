# ADR 0023: The native core's boundaries

Status: accepted (2026-11-15). The user approved the design inline on 2026-11-15: no mutable static state in the native core (stage A), the simulation and the interface as two libraries (stage B), the outer layers' reads of the units through a named list of fields, with the interface's writes to a unit through the simulation's functions and out of the state hash (stage C), and the stops a scenario decides refused before its game (stage D; the user chose the check alone, without loading custom maps). Stages A to D are built. Phase M's stage M2 ([ADR 0024](0024-game-setup-and-custom-maps.md), decisions 13 and 14) ported what some of stage D's refusals stood for: the Flag, Opponents and the two Modify actions play, and a map string past STR reads as the original's copy ends, so `validate_strings` is gone.

## Context

Two games and two interfaces have to live in one process: a rewind that shows a preview of the restored game while the played one goes on, tests that run games on threads, a viewer next to a player. Three things stood in the way, and a fourth made a game die in the middle.

- **One library.** `kp_core` held the simulation and the interface's rules (ADR 0010) in one directory and one library: nothing stopped the simulation from including the interface, and `kp_files.c` did (`kp_ui_pcx` for its PCX helpers, which only the interface's data, the presentation's lookups, the HD interface and the converter call).
- **Static state.** The menus (`kp_ui_menus.c`) kept the controls of their screens in twelve file-scope variables (the popups' procedures, the login, campaign, load and Load Replay screens' dialogs and lists, the episode button's result), so a second interface opening a screen overwrote the first's. The creep borders' rank tables (`kp_creep.c`) and the Ogg CRC table (`kp_webm.c`) were built on first use, a data race between threads even though the values are the same. `kp_ui_establishing_text` returned a static buffer, and the game menu filled a static array on each call.
- **The units' records open to all.** The interface read the units' fields as `g->u.<field>[n]` in 285 places, the scripts' flow (`kp_script_flow.c`) in 31 and the health bars (`kp_health_bar.c`) in 8; any field of the 161 was in reach. The interface also wrote three: the minimap blink's counter and colour (`+0x8a`, `+0x8b`, `kp_ui_minimap.c`, `kp_ui_portrait.c`) and the attack notices' silence (`+0x87`, `kp_ui_voice.c`). All three depend on who the local player is, and all three were in the state hash's units section, so a viewer's and a player's hashes would have differed for the same game.
- **Stops in the middle of a game.** `kp_mission_from_chk` (`kp_chk.c` only checks the version and the sections' sizes) refused a reachable trigger past the tables, Opponents, the two Modify actions and Order and Move Unit past the locations. A good part of the 213 `kp_game_fail` sites that a scenario's bytes decide was still met only when the game reached it: a counter of slot 12 or of a unit type past the table, Kill or Remove Unit of such a slot, Set Alliance with slot 12, Set Deaths past the aggregates, a leaderboard's unit type, a map string without its terminator, a Flag, a start location of slot 12, an AI script reaching an opcode not ported (the melee scripts') or reading outside its binary.

## Decision

1. **No mutable static or global state in `native/kp_core/src`.** A table is a constant, written out or generated (`tools/native/crc32_table.py` writes the Ogg CRC's next to the CRC-32's); state belongs to `KpGame` or `KpUi`.
   - The creep borders' rank by neighbour mask is one constant table (`KP_CREEP_BORDER_RANKS`, `RANK[SHAPE[mask]]` of BuildCreepShapeTable 0x4bff60 and BuildCreepShapeRanks 0x4c0010); only masks 0..255 index it.
   - The menus' variables are fields of `KpUiMenus` (`popup_procs`, `saved_result`, `login_dialog`, `map_list` (then `replay_list`) and the rest), with the values the statics started with. `KpUiMenus.modal[].saved_result`, which nothing used, is gone. The episode button draws through `kp_ui_flc_draw_button` instead of keeping the flic button's draw function.
   - The one process-wide variable left is `kp_smk.c`'s `video_codec`, set once before any game (`kp_smk_set_video`).
   - `tools/boundaries.sh` (a step of `tools/ci.sh`) reads the sources for a static that is no function and no constant, and fails on any but `video_codec`.
2. **Two libraries** (stage B). `native/kp_core/src/core` and `src/defs` build `kp_sim`; `src/ui` builds `kp_ui`, which links `kp_sim`. `kp_sim`'s include paths do not hold `src/ui`, so an include of the interface from the simulation fails to compile; the C++11 check sees both.
   - `src/ui` holds the interface's rules (`kp_ui*.{h,c}`) and what only the interface and the layers over it use: the portraits' movies (`kp_smk`, `kp_index_map`) and the fog's view (`kp_fog_view`, presentation state, ADR 0009).
   - The shared readers stay in the simulation: `kp_kpf`, `kp_files`, `kp_text`, `kp_utf8`, `kp_wav`, `kp_grp`; `kp_draw.c` too (it reads `kp_images_internal.h`).
   - The PCX helpers moved to the interface as `kp_ui_pcx_pixels`, `kp_ui_pcx_file` and `kp_ui_pcx_prefix` (`kp_ui_data.h`).
   - `kp_present` and `kp_oracle_lib` link `kp_ui`; no target links only `kp_sim` yet (the tools reach the interface through the data, `kp_data.h`, and the session, `kp_session.h`).
3. **The units through named fields** (stage C). `KP_UNIT_VIEW_FIELDS` in `kp_game.h` lists the 53 fields that the interface, the scripts' flow and the health bars read; each gets `kp_unit_get_<field>(g, n)` (`kp_unit_get_loaded(g, n, k)` for the eight transport slots). The other fields have no getter outside the simulation.
   - The interface's writes go through four functions of the simulation (`kp_combat.c`, next to `kp_notify_attacked`, which sets the same fields): `kp_unit_set_blink` (a talking portrait's ping, RequestUnitTalking 0x4a7200), `kp_unit_blink_step` (the minimap's count-down, DrawLocalMinimapUnits 0x46e490), `kp_unit_silence_attack_notice` and `kp_units_tick_attack_notices` (the attack notices, ADR 0010).
   - These three fields (`KP_UNIT_VIEW_STATE`: `attack_notify_timer`, `last_event_timer`, `last_event_color`) are the units' view state. The save keeps them in a section of their own, `VIEW`, after `WRLD`; the state hash's total folds every section but `VIEW`, and the save's table lists `VIEW`'s hash too, which the load checks. `KP_SAVE_VERSION` is 3 (schema `0x009a8709ec54eb16`), `KP_HASH_VERSION` 2.
   - `tools/boundaries.sh` fails on `->u.` or `KpUnits` in `native/kp_core/src/ui`, `native/kp_app` and `native/kp_present`. The tests and the oracle's tools reach the records on purpose and are not checked.
   - TODO: the local selection (`SELN`: `local_selection`, `circle_colors`, the sprites' selection flags) is view state as well, but the simulation's commands read it; it stays in the hash until it moves out of `KpGame`.
   - TODO: `KpUi.game` stays a mutable pointer. A `const` one needs the rest of the local player's state out of `KpGame` (the selection, the screen's and the placement's scalars, `crt`, `events`).
4. **The scenario checked before its game** (stage D). Each check repeats a runtime stop and names it; only what runs is checked, as `validate_triggers` did: the evaluated conditions (ignored ones skipped, the first type 0 ends them) and the actions before the first type 0 not ignored. The messages have `validate_triggers`' form (`TRIG: trigger T action A: …`).
   - `kp_mission_from_chk` (`kp_mission.c`): `condition_stops` (the counters Command, Bring with a location, Accumulate, Kill, Deaths and Score of a direct slot 12 or from 27, `read_slot`; the counters and rankings of a unit type past the table other than Any Unit, Men, Buildings and Factories), `action_stops` (Kill and Remove Unit of such a slot; Set Alliance with slot 12; Set Deaths of a type past the aggregates for a slot below 8; a leaderboard of units or kills of such a type; Create Unit (with Properties) of the Flag at a location), `validate_strings` (every id up to STR's count whose offset slot is inside STR names a string terminated inside it: any consumer reads them, the map's name and the forces' too), `validate_units` (a preplaced start location of slot 12 or more, a preplaced Flag). The runtime's checks stay as guards.
   - The Flag is a policy, not a stop: the runtime stops only when a worker takes it or it goes home (`kp_powerup.c`), and Capture the Flag is outside the V1 profile, so a Flag created or preplaced is refused before the game rather than in it.
   - `kp_mission_check_ai` (called by `kp_start` before its `setjmp`, with the game's binaries): each script a Run AI Script (At) that runs names goes through `kp_aiscript_check`, the closure of `scdata/analyze/ai.py` (every address operand and the fallthrough up to a terminator; the panic block's target in `aiscript.bin`, where `kp_ai_town.c` runs it, and none for a block of 0, which GetPanicBlock takes as no block) with the return address the interpreter keeps for all scripts (2026-11-22): a state is a PC and that address, a call goes on where its routine returns, and a return jumps to the address and clears it, so a return without its call, or the outer one of nested calls, goes on at PC 0. Which address a return takes after a script waited inside a call depends on the order the other scripts run in, so the closure follows each script alone. On the install's 293 scripts no return runs without its call, and the closure reaches the same instructions as before (`ai.py`, an upper bound for its analyses, still takes a call's continuation directly and stops at a return). It refuses an opcode not ported (since phase M's stage M3 none: it refuses `fatal_error`) and a read outside the binary. It ignores the launch gate (a human's script is checked too), and no mission of the catalog needed it.
   - The operands' widths are the profile's table `AIOP`, which `tools/defs_c.py` writes from `defs/ai/bw-1.17.0.1.json` (`ai.section`); `kp_ai_bins_from_files` takes it with the binaries. The opcodes not ported were one table (`UNPORTED` in `kp_aiscript.c`), which `kp_aiscript_ported` answered from; since phase M's stage M3 every opcode has its case, the table is gone, and the check refuses a script that can reach `fatal_error` (the original's fatal error).
   - The CHK fuzz target runs both checks (the AI one with the game's data).
   - Not in this stage: loading custom maps (outside the catalog, without MPAK) and a glue dialog for a refusal; the catalog's missions all pass, so the refusal is not reachable from the product yet (the TODO at `kp_flow.c`'s `KP_GLUE_LOAD`, a popup when a game does not start, stays). The stops no scenario can decide (the internal invariants and capacities) cannot be checked by reading a map.
5. **Caches of the tools stay per process.** `kp_runner.c`'s data roots and speech sources serve one thread; `kp_test` runs its jobs as processes. A lock comes with the first tool or test that runs games on threads (a TODO in `kp_runner.c`).

## Consequences

- `test_kp_core.creep_border_ranks_are_the_original_tables` rebuilds the two tables as the original does and compares the 256 ranks.
- `test_hud.two_interfaces_keep_their_own_screens` opens Load Replay on two interfaces whose screens are other controls; each keeps its own dialog and list.
- `test_save.view_state_is_saved_outside_the_total` changes the three view fields through the functions: the total and the other sections' hashes stay, `VIEW`'s changes, and a save and a load bring the values back.
- `test_chk.runtime_stops_are_refused` patches the fixture's triggers, units and strings for each refusal and for the records the runtime takes (Bring and the rankings At without a location, a group or the current player, slots from 8 for Set Deaths, an ignored action, an action after the end); `original_missions` and `remastered_missions` load all 64 missions and pass each one's AI scripts through `kp_mission_check_ai`.
- `test_aiscript.scripts_are_checked_before_a_game` checks synthetic binaries (an unreachable `fatal_error` passes, a jump to one, a target outside, a truncated operand, the panic block from `bwscript.bin`, an ordinal past the table, a damaged `AIOP`) and the mission's Run AI Script actions; `every_opcode_reads_its_aiop_operands` (until stage M3 `ported_opcodes_are_the_interpreters`) runs each ordinal 0..0x72 on its own, fails on one without a case, and where it goes on, checks that the second instruction is at `AIOP`'s length of the first (or at a jump's target), so the check skips as many bytes as the interpreter reads.
- The tests' own statics (host callbacks' counters in `test_hud.c`, `test_kp_ui.c`, `kp_fuzz.c`) stay: the suites run as processes.

## Addition: the headless application in layers (2026-11-27)

`kp_app_core` had grown to 36 sources in one static library: the converter linked the network and the flow it never
calls, and nothing kept the data's readers from including the session or the network game. Since the architecture
review of 2026-11-27 it is three libraries, each over the ones before it:

1. **`kp_app_data`**: the original data (MPQ, CASC, SCR and the repack, ADR 0018), the catalog and the languages, the
   cinematics' files, the replay file and the command record. `kp_convert_lib` links it alone.
2. **`kp_app_net`**: Storm's layer and its UDP provider, the LAN game list, the network game and its saves, the
   multiplayer screens' network, the viewers and the map transfer (ADR 0026, 0027), over `kp_app_data`.
3. **`kp_app_flow`**: the session, the console, the seats and the turn hub, the scripts, the screens and the games, the
   flow's files, over `kp_app_net`. The product and `kp_oracle_lib` link it.

`CMakeLists.txt` names each layer's modules (`KP_APP_DATA_MODULES`, `KP_APP_NET_MODULES`, `KP_APP_FLOW_MODULES`) and
refuses a source of `native/kp_app` that is in none. The sources stay in one folder (the paths the documents name), so
the include path cannot keep the layers apart: `tools/boundaries.sh` reads those lists and fails on a source or header
that includes a later layer's header, directly or through others, with the chain (a header without a source,
`kp_casc.h`, `kp_ogg_crc_table.h`, is under them all). The session sits with the turn hub and the turns in the flow:
their headers include each other.
