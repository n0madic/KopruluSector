# ADR 0018: The game reads the original data at run time

Status: accepted (phase D, 2026-11-10; the user approved the plan and its choices). It replaces the plan's rule "no MPQ reading and no parsing of the original formats at run time" (the implementation plan's "Consequences", kept outside the repository) and changes the converter's role ([ADR 0004](0004-resource-packs.md), [ADR 0013](0013-remastered-data-source-and-hd.md)). Stages and their state: [docs/phaseD.md](../phaseD.md). Item 5 (the converter's role) and item 3's fallback from a repack to the install are replaced by [ADR 0019](0019-install-or-repack-converter-in-c.md) (phase C, 2026-11-11): the folder `--data` names is the only source, and the converter is `kp_convert`, in C.

## Context

The offline conversion into `generated/*.kpd`, `*.kpm` and packs came from Defold: bob built the atlases, the engine's resource counts were limits, Lua could not afford parsing (ADR 0003, 0004). Since ADR 0012 the runtime is C over SDL3 and none of that holds.

A large part of the containers is the original files unchanged: the DAT tables, `iscript.bin`, `aiscript.bin` and `bwscript.bin`, CV5, VF4 and WPE, the LO files, the dialog GRPs, PCX and SMK files, the CHK chunks. The rest is deterministic and can be built in C: the original itself builds the walk raster, the regions and the contours when a map loads (`0x490d80`). A user needs Python, Pillow, StormLib through ctypes, FFmpeg and oggenc today, and a build carries the data, so it cannot be shared.

## Decision

1. **The game reads an install directly**, into its own structures in memory, with no KPF sections between and no cache on disk:
   - a 1.17.0.1 install through **StormLib 9.40** (its MPQ archives in the profile's order, `defs/profile/bw-1.17.0.1.json`);
   - a StarCraft: Remastered install through **CascLib 3.0** (the converter's `ScrSource` rules: prefixes, moved files, `.vx4` from `.vx4ex`, the tilesets' 1.17 prefix, Remastered's rebuilt files computed when read).
   Both are MIT; they share one **zlib 1.3.2** and one **bzip2 1.0.8** instead of their bundled 1.2.5 / 1.2.11 and 1.0.5, and StormLib's Jenkins hash (`third_party/data/kp_data.cmake`). `tools/toolchain/fetch.sh` fetches them by default (`data`), pinned by SHA-256.
2. **Every file read from an install is checked** against the input manifest (`defs/scr/inputs-<profile>.json`: size and SHA-256, `kp_sha256.c`): a 1.17 file that differs stops the game with its name; a Remastered file keeps the converter's statuses (exact, derived, differs, approximation). Nothing is cached: the check costs less than the read (below). Since 2026-11-11 (after phase D) a hash is kept where it decides something:
   - a 1.17 file the simulation is built from is hashed (the DAT tables, the scripts and dialog BINs, the missions' CHK, the tilesets' CV5 and VF4, the GRPs and LO files grpmeta reads, the string tables; `simulation_input` in `kp_res.c`): a different one would play another game, silently;
   - a 1.17 file that only shows or plays (sounds, movies, pictures, the tilesets' VX4, VR4 and WPE, fonts, texts) is checked by its size;
   - Remastered's files are hashed: the digest picks the copy that is the 1.17 file, whether it is rebuilt and which palette donor is exact;
   - a repack's file is checked like a 1.17 file, against its listing (item 3): hashed when the simulation is built from it (since 2026-11-11, after the review: a damaged copy would play another game too, whatever its source), else by its size;
   - `kp_data_probe` (the CI step) still checks every exact or derived file to the byte.
3. **A repack has priority over the install.** The converter writes `koprulu*.mpq` (StormLib), the files the game reads in their original formats plus Remastered's rebuilt 1.17 files, with a `(koprulu)` listing that names the profile and each file's size and SHA-256 (stage D1: SHA-256 rather than `(attributes)`' MD5, which StormLib checks by reading a file a second time). A file that is not its listed size (one the simulation is built from: its listed SHA-256 too), or a repack of another profile, falls back to the install. A file that only shows or plays is not hashed when read (since 2026-11-11): the converter wrote it from files it checked, Android reads its groups in place from its APK, whose signature covers them (`KpResConfig.repack_file`: a group is a slice of the APK StormLib reads, its file streams patched for that), the web fetches a group whole over HTTP, and StormLib's decompression fails on most damage. The listing (stage D8a: `koprulu repack 2`, [the format](../formats/repack.md)) names each file's status, the source's (exact, derived, differs and Remastered's rebuilds' statuses); an exact or derived file whose listed digest is not the manifest's is read from the install instead. The repack is split into groups for the web, one file (`--single`) for desktops. The groups (stage D8a): the core, what the program reads when it starts; a group per mission directory (its CHK and speech); the music; the 1.17 cinematics. The races' art is not a group of its own, unlike the plan's: the program reads every GRP's frames and every portrait and sound header when it starts (grpmeta, the interface's data), so they are the core's. **Sounds may be stored as Ogg Vorbis** when that is smaller than the WAV (the user's rule, 2026-11-10); the runtime tells them apart by their bytes (`RIFF`, `OggS`). The listing keeps an Ogg's WAV header and size, which `kp_res_head` answers for it: the game computes the sounds' durations from the WAV's header.
4. **Videos without conversion:** the Smacker movies through `kp_smk.c` with an audio decoder of our own (libsmacker is LGPL-2.1: no copyleft dependency); Remastered's WebM played as is (nestegg and libvorbis, both permissive, with the libvpx already built), its palette movies mapped to the screen's palette as KPV1 was. KPV1 goes away (stage D6: KPW1, the WebM itself behind the SMK's header and its screen's palette, `kp_smk.h`; libvpx's VP8 decoder and nestegg are built on every platform). Stage D7 needs no libvorbis: the cinematics' Vorbis packets go into Ogg pages of our own and SDL3_mixer's stb_vorbis decodes them.
5. **The converter stays** for the repack and what a platform needs built for it: the HD pages (BC, ETC2, ASTC), the phones' and the web's bundles. Stage D8b: the bundles carry the repack instead of the SD containers (a computer's one `koprulu.mpq`, a phone's and the web's groups, never the cinematics' group: the packs show the movies), and the app reads its SD data from a repack or an install only. The web preloads the core and fetches each other group whole before it is needed (a mission's before it starts, the music's from the start); Android copies the groups out of its APK, since StormLib reads files. Stage D8d: the converter writes no SD container (its builders run in memory to record the manifest's reads and as the languages' base, computed from the install a language is converted from) and the runtime has no loader of one; what stays a container is the console's pieces, the HD files, the cinematics' packs and the languages' and the speech's overlays. The C suites' fixtures are original files at their MPQ paths.
6. **Old saves are refused.** Only their data check breaks: it compares CRC-32s of the KPF files (`kp_host.c`, `kp_session.c`). The new identity is the profile and the CRC-32s of the original inputs the simulation reads, so a save carries over between a 1.17 install, a Remastered one and a repack.

## Measurements (stage D0)

`kp_data_probe` reads every file of the input manifest (4,384) from an install and checks it; macOS on an M-series Mac, one thread, release build:

| Source | Kind | Files | Equal to the manifest | MB | Read | SHA-256 |
|---|---|---:|---:|---:|---:|---:|
| 1.17 MPQ | core (everything but the two below) | 3,259 | 3,259 | 155.5 | 1.07 s | 0.39 s |
| 1.17 MPQ | missions' speech | 1,105 | 1,105 | 415.2 | 4.17 s | 1.09 s |
| 1.17 MPQ | music | 20 | 20 | 340.8 | 3.85 s | 0.85 s |
| Remastered CASC | core | 3,259 | 2,380 | 149.7 | 0.66 s | 0.34 s |
| Remastered CASC | missions' speech | 1,105 | 451 | 415.3 | 1.64 s | 0.94 s |
| Remastered CASC | music | 20 | 0 | 279.9 | 0.90 s | 0.66 s |

- The CASC counts are the copies under the converter's prefixes with the manifest's digest (its "exact"); the others are moved, rebuilt or Remastered's own (stages D1 and D6).
- A spike read the 4,286 CASC names the converter reads through CascLib and through `converter/casc/storage.py`: all equal byte for byte. CascLib opens the storage in 0.04 s.
- In wasm under node: MPQ core 1.21 s, CASC core 0.80 s. On Linux (GCC 15.2, Docker on the same Mac) the MPQ read passes; SHA-256 runs at about 185 MB/s there against about 400 MB/s with clang.
- The game reads the core in parts (its start, then a mission's packs), so these are bounds.
- The 1.17 WAVs (2,248) are all PCM, 16 bits: 22,050 Hz mono 2,189, stereo 30; 44,100 Hz mono 21, stereo 1; 11,025 Hz mono 7. SDL3_mixer's WAVE decoder plays them as they are.
- A repack in the original formats, without the music, compressed file by file: 598.5 MB raw, 512.7 MB with zlib, 476.5 MB with bzip2. The WAVs hardly shrink (the missions' speech 435.4 to 359.3 MB, the sounds 95.5 to 84.1 MB), hence item 3's Ogg Vorbis.
- Built: macOS (clang), Linux (GCC 15.2), Windows (mingw-w64, linked), Android (NDK 29, API 24, linked), iOS (arm64, linked), wasm (run under node).
- Stage D5: a mission's packs built from the 1.17 install when it starts (the GRPs read through `kp_res`, decoded, equal frames shared, packed into 1024-pixel pages as `converter/emit/pages.py` packs them): 130 ms for terran01's five packs (8 pages), 148 ms for six (9 pages), the same macOS release build.
- Stage D6: the 549 KPW1 movies (Remastered's portraits and glue overlays, 6,603 frames) decoded by libvpx and mapped to their palette in 2.39 s, 0.36 ms a frame with the opening; the portraits equal the converter's FFmpeg frames, the 30 glue movies (VP8 4:2:0 with alpha) 94.7% of their pixels (YUV to RGB rounding against swscale's). Remastered's 3,243 core files read and rebuilt (DDS, `dds.grp`, XML, WebM) in 1.1 s; the app loads its data from Remastered in about 2.9 s (2.25 s from the 1.17 install). The HD portraits as raw WebM: 72.8 MB against 281 MB as KPV1.
- Stage D8a (`converter repack`): the 1.17 install's 1.2 GB of archives give a 742 MB repack, the core 49.8 MB, the music 28.9 MB, the 68 missions' groups 61.2 MB together, the cinematics 605 MB; 2,236 of 2,244 WAVs smaller as Ogg Vorbis, 101.5 MB for 888.0 MB. Remastered's repack is one 131 MB `koprulu.mpq` (its WebM cinematics not repacked). Written in 45 s with the encoding, 18 s with the Oggs cached.
- Stage D8b: a computer's bundle carries 140 MB of SD data (`koprulu.mpq`) for the containers' 184 MB; the web's preload holds the 49.8 MB core, the 90 MB of mission and music groups lie beside the page.
- 2026-11-11, the hashes kept where they decide (item 2), `kp_data_probe` over every file of the manifest, the same Mac, two runs each: the repack's core 0.39 to 0.19 s, its missions' speech 0.15 to 0.005 s, its music 0.07 to 0.002 s; the 1.17 install's core 1.51 to 1.22 s, its speech 5.4 to 4.5 s, its music 4.9 to 4.1 s (the install's reads are mostly decompression). A movie (up to 79 MB) is no longer hashed when it loads, about 0.2 s. The repack's simulation inputs hashed again against its listing (the same day, after the review): its core 0.19 to 0.26–0.29 s.
- Stage D7: the cinematics played from the installs as they are (`--cine-check`): the 1.17 install's 28 Smacker movies (30,211 frames) in 21 s with 0 failures, each read whole, checked against `CINM` (its size since 2026-11-11) and its sound decoded when it begins, the longest (79 MB) in 0.31 s; Remastered's SD set (30,211 frames) and HD2 set (31,156 frames) with 0 failures, a WebM demuxed and its Vorbis put into Ogg pages in at most 29 ms. kp_smk's frames, palettes and sound equal FFmpeg's decodes of all 28 movies byte for byte; the WebM's packets equal the converted packs', their sound's too but the Vorbis comment header. libvorbis is not needed: SDL3_mixer's stb_vorbis decodes the Ogg the runtime writes.

## Consequences

- CascLib.h includes C++ headers: C reaches it through `native/kp_app/kp_casc.cpp` (`kp_casc.h`). StormLib.h includes `windows.h` on Windows, whose macros rename fields of the project's headers (`near`): it is included last, and stage D1 keeps it in files of its own.
- StormLib and CascLib handles are not shared between threads: the music, the movies and the HD page thread open their own.
- The CI step "data readers" runs `kp_data_probe` with `KOPRULU_ORIGINAL` and `KOPRULU_SCR`.
- Remastered's rebuilds exist twice, the converter's (`converter/casc/rebuild.py`, for the repack and the platforms' builds) and `kp_res`'s (`kp_scr.c`, `kp_res_scr.c`): `kp_data_probe --digests` and `converter scr-digests` list each file's status and SHA-256, and the CI step compares the lists over a Remastered install.
