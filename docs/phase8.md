# Phase 8 progress

Plan: `IMPLEMENTATION_PLAN.md` §7 phase 8 (full campaign compatibility). Started 2026-10-18, after the user approved the design (inline design document, 2026-10-18):
- the acceptance (user's choice) is a scripted player win in the full-game emulator for every one of the 64 playable campaign rows (57 selectable, 7 hidden); helper cheats are allowed (power overwhelming, show me the money, operation cwal, the gathering, medieval man, modify the phase variance, food for thought, black sheep wall), the cheats that end a mission are not; Koprulu equals the emulator along each whole play, with the trigger and AI traces and the transition to the next row;
- the fog of war is drawn as the original draws it (atlas P23, P24), checked pixel for pixel against new emulator captures taken after the fog pass; a view wider than 640×400 generalizes the original's grids (an ADR, `approximation`);
- the campaign manifest lives in `defs/campaign/` (the executable's tables, checked against it), the converter writes `campaign.kpd`, `game/campaign.lua` holds the progression rules of `uiSingle.cpp`; the native save stays version 1 and a game save (`game/save`) adds the manager's pending commands, the campaign and the profile id;
- the frame stays strictly sequential; a mechanism a play reaches without a port fails with its address and is fixed as a general engine rule (D18).

## Notes

- The original keeps some globals from one game to the next in the same process (InitTriggerState `0x4be240` resets neither the pending results, the trigger pass's player, the result dialog's delay nor the objectives; InitAiRegions `0x4b0640` leaves the sources of the reach cache, which decide whether the cache is rebuilt). Koprulu's next game takes them from the game before (`KpCarry`); the first game of a process takes zeros. The menus' turn counter before RunGame resets it is not modelled outside the oracle (`KpStartInput.turn`, 0 in Koprulu's own campaign): nothing reads it before the reset.

- The viewer's play mode drew a game's units where they were created, walking in place: the draw list reads the image bounds, which only a draw refreshes (RefreshAllSpriteBounds `0x415700`, RefreshRowSpriteBounds `0x4165d0` in the original's redraw), and the play mode never refreshed them (the map scenes do). The viewer refreshes a game's bounds after its steps now, before the draw list (`test_play_world` checks a walked Marine's bounds).
- The twin of a two-unit egg joins a local selection that holds the first unit within the object step (AddUnitToLocalSelection `0x43c090` from `0x43b5e0`), before the first unit's main image is replaced; Koprulu makes it in the core (`hatch_twin`). The emulator logged it as an interface selection, so the replay applied it a second time after the step: the health bars came from their pool in another order (`zerg01` at step 16401, sprite 2397's bar 5010 for the original's 5011). The emulator no longer logs that caller (`GAME_SELECTION_CALLERS`); the Zerg plays recorded before were recorded again.
- A computer's budget refresh (RefreshAiBudget `0x4823d0`) takes off the price of every building a town's worker is placing (SubtractPendingConstructionCosts `0x487730`), with the worker's first queue entry; a worker whose queue has emptied gives 228, and CheckUnitCost `0x4086b0` reads units.dat's arrays without a bound, which lie one after another: the mineral price of 228 is the first gas price (0), its gas price the first build time (360), its supply the padding before the space column (0). Koprulu read no price there and took nothing off (`zerg06` and `zerg09`, 360 gas at their first such refresh); `kp_production.c` reads those words now. The writer was found with a write watch on the budget in the emulator (`0x4877ab`).
- A map unit with the hallucinated state (a trigger's unit properties, `0x46a420`) becomes one through ConvertUnitToHallucination `0x430a00` (`kp_convert_to_hallucination`: uncounted, button set 244, its drawing, timed life, end order; its subunit, a Carrier's fighters released, a Reaver's Scarabs converted), which `zerg06` reached.
- A hidden computer unit's order ComputerAI (156) runs Order_BunkerGuardIfInside `0x48d2d0` every 9 steps: inside a Bunker it guards from it, otherwise nothing (`protoss09`).
- Order_ComputerReturn `0x41e370` sends a unit of any AI but a guard's back to ComputerAI once its move is requested; Koprulu looked only for a guard record and left the others (a detector the computer sends to an undetected enemy, `0x4ae3e0`) returning to their point (`expprotoss03`).
- AddSelectionCircle `0x423060` of an invincible type (a Beacon the play's Civilians walk onto, `expterran02`) adds only the circle (`0x415340`: image 561 when the sprite's circle bit is clear) and marks the sprite selected with the slot, without a health bar; Koprulu stopped there with a `kp_game_fail` (`kp_add_selection_circle`).
- The map's technology and upgrade settings (`TECS`/`TECx`, `UPGS`/`UPGx`: costs, research times and energy) were computed (`kp_rules_effects`) but never written into the DAT columns, which the original does at load (`0x468250`, `0x468340`, `0x468430`, `0x468500`); `expterran06` sets Psionic Storm to 200 energy, so Koprulu's computer High Templar cast it at 75 (`apply_rules`).
- OrderCompletingArchonSummon `0x42f9e0` ends with QueueOrder `0x429eb0`, which is the append of `kp_order_append` (an equal order at the queue's tail goes first), not a plain queue push; the neutral Archon of `expterran06` left a second Guard order behind.
- OnHitChangeTarget `0x420190` asks IsGuardAtHomeOrNotGuard `0x4b2720` before a computer's unit flees: a unit without a guard record flees as before, a guard flees only while it stands exactly on its home (it takes the new home at the point it flees to); away from home it stays (`kp_combat.c`; reached by the Brood War Zerg plays from `zerg02` on).
- The Brood War Zerg plays found "power overwhelming" stalling every scripted kill the computer has to make (the opening nukes of `zerg02`, the Lurkers of `zerg05`, the endings of `zerg08` and `zerg09`): the cheat zeroes the damage of every computer player, so those plays type it later or turn it off again (`campaign_plays_xzerg.toggle_po`). The `zerg03` branch is the number N of Infested Command Centers held with at least 10,000 minerals (triggers T11–T16 set Zerg04a–f for N = 0..5); the `zerg09` branch is the countdown mark of trigger T18 (the 1800-second countdown at 299 seconds or less).
- `0x526526` (the next scenario's name) is cleared when a map loads (`0x46b5c0`'s data reset, atlas P23), so a retried mission starts without the name its lost game set; the campaign takes the name from the game that ended (`g:next_scenario()`).
- The template's cheats byte `0x67294e` (AreCheatsEnabled `0x447640`) is 1 in every campaign game the emulator dumped; Koprulu does not keep it.
- The emulator's games start with the cheat word `0x200` (Ophelia, from the warp command line), which no simulation code reads; Koprulu's start with 0 unless the game before carried bits.
- The native save keeps version 1 although phase 8 added the portraits' generator section (`PRTR`): as in phases 4-7 the format grows at version 1, because no save has shipped (ADR 0008).
- The minimap's fog reaches its GUI script as messages (`presentation/minimap_chunks.lua`): a GUI script runs in a Lua context of its own, which shares no module state with the game script, and a message carries about 2 KB.
- A loaded quick save only raises the profile's campaign progress (`campaign.merge_profile`, saved at once); the profile is the player's, not the game's.
- The viewer's campaign: only the catalog's missions start a run (a scenario on a catalog map plays no campaign), the run's expansion byte is the game's (a Brood War mission starts with 1), and a game with a result takes no quick save (the original saves no game behind its result dialog, and the run has moved on).
- `save.write_file` renames the new save onto the old one (atomic where the platform allows); only where the rename refuses an existing file is the old one removed first, and a rename that still fails keeps the new save in its `.tmp` file.
